# Council review of docs/core.md (2026-10-28)

Reviewed revision: docs/core.md @ e3eeac8. Copied from the coordinator's synthesis; the three reviews follow it. Status of each item: `docs/core.md` §10 and `docs/ledger/core.md`.


Council: GPT-6 Astra, Claude Opus 5.5, Claude Fable 5.1 (Gemini 4 Argon was unavailable). Full reviews: review-astra.md, review-opus.md, review-fable.md in this directory. Lead decisions (Max): existing R scripts must run unchanged on robigo and it must be the fastest R; effort is no argument; packages may be recompiled from source for robigo (source compatibility with GNU R's C API, not binary layout compatibility); no new package manager — install.packages()/R CMD INSTALL run on robigo against robigo's headers + Makeconf + R CMD front end.

Verdict: the direction (thin one-pointer SEXP, non-moving mark-region heap, C-confined setjmp, interned CHARSXPs, ALTREP as node with class table) is endorsed by all three. The doc and first code have correctness holes that must be fixed before code piles up.

## Unanimous (all three) — do these

1. **Base-package natives inline GNU R's layout** (Defn.h -> USE_RINTERNALS; stats.so reads payload at +48, alt bit at byte 0 bit 7; census rows 142-154). Resolved by the lead's source-compat decision: rebuild `src/library/*/src/*.c` from R 4.5.0 sources against robigo's headers (a robigo `Defn.h` mapping internals to robigo's layout or to functions), in a `robigo-base-natives` build; provide the ~25 non-API internals they need (R_print, Rf_PrintDefaults, Rf_begincontext/endcontext with robigo's RCNTXT, R_execMethod, R_set_standardGeneric_ptr, ptr_R_* hooks, R_InputHandlers, getConnection, Rconn_fgetc, R_PPStack*/R_signal_protect_error, R_CStack*, utf8locale & co.). Rewrite core.md §1, §6:226-229, §8.
2. **Immortal objects are never traced** (gc.rs:420-428; SYMSXP arm dead): a symbol's SYMVALUE/INTERNAL/ATTRIB or a mortal stored into a constant gets freed. Decision: IMMORTAL = never freed, not never traced — trace the symbol table's and mutable immortals' children every collection (GNU R does; robust to C code that SET_ATTRIBs constants); additionally debug-assert suspicious stores (Fable).
3. **Context record is incomplete** (shim.c only keeps jmp_buf): every try/context must save+restore R_PPStackTop, vmax (R_alloc stack), gc_inhibit, R_PPStackSize red zone, R_Visible, eval depth, handler/restart stacks, interrupt suspension (context.c:170-240, 783-820); continuations keep target + jump kind.
4. **R_UnwindProtect / token lifecycle**: pop the context before cleanfun; cleanfun may longjmp away (Rcpp/cpp11) and R_ContinueUnwind is called later from another frame/.Call; the token (GC-visible) owns the pending condition. Add a small cpp11 and a small Rcpp package to the G2 gate.
5. **Most exports can jump**, including Rf_warning (warn=2, calling handlers) and allocation/PROTECT overflow: treat every export as may-jump.
6. **Sexps held off the machine stack are invisible** (Vec<Sexp> in the bridge, VM registers, JIT caches): write the rooting rule (local / protected / traced object / registered rooted container) and add a gctorture mode (collect on every allocation, poison freed slots in debug) — run core tests + capi corpus under it in CI.
7. **Thread binding**: Core::new captures the creating thread's stack but the interpreter runs on a spawned thread (robigo-cli main.rs:85-88; capi state.rs:19-25 lazily creates it): bind the core to the evaluator thread explicitly, set R_CStackStart/R_CStackLimit/R_CStackDir from it, port the "C stack usage is too close to the limit" check, assert thread in collect(); API calls from other threads fail with a diagnostic, never UB.
8. **Barrier hook now**: full-heap marking will lose to GNU R's generational GC on large live heaps; route every SEXP store into a heap object through one inline store()/barrier-capable setter (make raw setters crate-private) and reserve a header state bit, so sticky-mark generational/incremental marking stays possible after G3.
9. **Measure first, against GNU R's libR**: a C microbenchmark .so under callgrind (allocVector small/medium, cons/lang3, PROTECT, mkChar hit/miss, install, INTEGER loop, SET_STRING_ELT, preserve churn, Rf_eval trivial closure, no-op .Call with 3 scalars, R_UnwindProtect without jump, Rf_error caught); plus GC workloads: medium vectors, a large live pointerful heap (2 GB STRSXP + churn) with pause/GC share vs gc.time(), deep stacks (5000-deep recursion). Record in docs/ledger/core.md before freezing the design.
10. **CHARSXP table**: code (HashMap<u32, Vec<Sexp>>, byte-keyed symbols) diverges from doc; use a flat open-addressing table of (hash, Sexp), header hash compared first; make doc and code agree. ATTRIB(CHARSXP) must return R_NilValue.
11. **Bridge is a thin G2 scaffold with listed limits**: identity (data.table .internal.selfref, rlang cells/promises), SET_STRING_ELT on args, promise PRCODE/PRENV/PRVALUE via HOST proxies, cross-heap cycles leak and their finalizers never run, encodings. Nobody hill-climbs G4 packages on the bridge.

## Majority (two of three) — do these

12. **Allocation failure must be an R error**, not abort/panic (heap.rs:151-154, gc.rs:223/239): fallible path with GNU R's messages ("cannot allocate vector of size %0.1f Gb", memory.c:2920-2928; :2330). (Astra, Fable)
13. **Medium objects**: >2 KiB objects each get a 64 KiB chunk (300 doubles reserve 64 KiB); chunk Vec O(n) insert/remove + per-GC clone + binary search; live_bytes vs alloc_since_gc accounting inconsistent so the 1.5x trigger is inflated. Add size-classed medium pages up to ~256 KiB, a LARGE header bit, consistent accounting. (Opus, Astra)
14. **Native vs UTF-8 encoding**: keep CE_NATIVE distinct (Encoding() "unknown"); translateCharUTF8 rejects bytes; locale data exports. (Fable, Opus; Astra on translation semantics)
15. **No dlsym double build; one heap via linkage**: Opus — the runtime lives inside libR.so behind a thin `robigo` executable (GNU R's R -> libR.so model; enables embedding: reticulate/rpy2). Fable — the executable exports the ABI (-rdynamic + version script) with a stub libR.so. Both: version script exporting exactly the API set, -Bsymbolic-functions, RTLD_NOW. **Coordinator decision: Opus's shape (runtime inside libR.so + thin executable)** — it is GNU R's own model, gives one heap and direct linking for the runtime, and keeps embedding possible; Fable's objection (no dlsym on hot paths, LTO) is met by it.
16. **Weak refs/finalizers**: classify all dead-key weak refs before retaining keys (gc.rs:525-534 vs memory.c:1863-1871) (Astra); queued finalizable weak refs must stay rooted (on R_weak_refs) and be drained under a toplevel context at safe points, never inside allocation (Fable, Opus); release callbacks must not run inside collect(&mut self) (gc.rs:604, aliasing UB) (Opus).
17. **Non-local exits never cross Rust frames**: C trampolines around every callback that can longjmp (ALTREP methods, finalizers, R_init_<pkg>, device callbacks, R_UnwindProtect fun) so Rust sees an error result; outward R errors jump from a C export wrapper; every Rust extern entry point catch_unwind -> R error; callback types extern "C-unwind" for C++ exceptions. With that, keep panic=unwind (G7 needs panics -> R errors). (Astra, Opus; Fable flags the panic=unwind/longjmp UB this resolves)

## Single-reviewer findings — verified or cheap, do these

18. **Allocator overrun** (Astra, verified): alloc_small bumps by requested granules, free-list reuse within a class can overrun a smaller dead slot -> allocate at SIZES[ci]; test all request-size pairs per class; re-measure the bake-off.
19. One-past-the-end pointers: scan_stack also resolves w-1 for words exactly on a granule boundary (Fable).
20. 48-byte nodes with a 4th word (NODE_SIZE 40 wastes 8 B); fix only ENCLOS in the env body (FRAME() materializing shim) so G3 can use slot frames (Fable).
21. alloc_node refcount-increments car for BUILTINSXP/SPECIALSXP -> port TRACKREFS exactly (Fable).
22. Foreign/read-only buffers as a built-in ALTREP class (data.table writes into non-ALTREP), EXTDATA only for robigo-owned writable storage; drop zero-copy EXTDATA bridge args (Opus).
23. Console output through C stdio (packages' printf interleaving) (Opus); signal ownership (SIGSEGV alt stack, SIGINT/R_interrupts_suspended/Rf_onintr, SIGPIPE) (Fable, Astra).
24. A G3-facing safe accessor layer spec: borrowed reads only, no &mut [T] across C/R calls (Fable).
25. Start G3 once the core accessor layer and the fastmap gate exist, not after 20/20 corpus cases (Opus, Fable).

*Opus 5.5 council review of docs/core.md @ e3eeac8 — saved by the coordinator; full text in the T3 thread "council: core design (Opus 5.5)"*

Headline: agree with the thin-pointer custom layout for CRAN binaries (they never import layout-internal symbols such as ALTREP_LENGTH/ALTVEC_DATAPTR/R_PPStack — only GNU R's own packages do), BUT GNU R's base .so files inline GNU R's layout via Defn.h/USE_RINTERNALS. Checked installed stats.so: 131 inline ALTREP_LENGTH sites; at 0x381b4 `lea 0x30(%rax)` (payload at +48) and `cmpb $0,(%r15); js` (alt bit = bit 7 of byte 0). Under robigo's layout these read garbage -> §6:226-229 and the §8 base-natives track cannot work as written. Rf_begincontext/Rf_endcontext (tools, utils) put a GNU R RCNTXT on the package stack, so its size must match.

Recommended alternative: build the base packages (stats, utils, graphics, grDevices, methods, tools, parallel, grid, splines) from R 4.5.0 sources against a robigo-shipped Defn.h/Rinlinedfuns.h whose macros use robigo's offsets (G6 has to ship base packages anyway). Other option: adopt GNU R's sxpinfo bit layout + 48-byte vector header (+16 B per vector forever).
