# G3: robigo's runtime rebuilt on a new heap

Status: draft v4 after council round 5 (2026-11-13); lead decisions L1–L7 taken. Merged from three
council rounds (GPT-6 Astra, Claude Fable 5.2, Claude Opus 5.5, Muse
Wonder Full; designs, reviews and syntheses go into `docs/g3-council.md`
with this doc's pull request) and the lead's decisions. Everything here is
a requirement unless §15 lists it as a decision the prototype measures.
Spec: `docs/design.md` §5.6 (G3), `docs/core.md` (G2). `R462/` below is
GNU R 4.6.2's source tree.

## 0. Goal and ground rules

**The goal: the fastest R runtime, fully compatible. Nothing else
suffices** (lead, 2026-11-13).

- *Fully compatible*: every behaviour GNU R 4.6.2 makes observable, as
  bytes: output, messages, warnings, errors, exit status; reflection
  (`body`, `formals`, `environment`, `sys.*`, binding kinds,
  `.Internal(inspect)`, `object.size`, `tracemem`, `gc()` (its cell and collection counts too: L7)); the C API at
  the source level (`docs/core.md` §1). Inherently variable values
  (addresses, elapsed times) are not compared, but every *relation* GNU R
  makes observable on them is: identity, whether an object changed
  address, whether a copy was traced. §12 inventories the observables the
  new design touches.
- *Fastest*: faster than every other R runtime (GNU R 4.6.2
  byte-compiled, Ř, FastR) on every workload class, by the rule of §13.
  Beating GNU R is a floor.
- **Effort is free** (lead): no users, no backwards compatibility; the end
  state wins. Risk counts only where it threatens correctness or the
  ability to verify.
- Measurement decides between sound designs. An inexact variant is never
  a candidate, only a control.

## 2. The object API and the isolate capability

### 2.1 Layers

| layer | types | users | what guarantees safety |
|---|---|---|---|
| raw | `robigo_heap::Sexp` | heap, rtapi, the evaluator core | audited `unsafe`, core rules (§3) |
| branded | `Ref<'g>`, `View<'g>`, typed views, `FreshVec`, `Unique` | builtins, printing, coercion, attributes | the borrow checker bounds every read interval; the root implementation proves reachability across safepoints |
| rooted | `Root<'s>`, `Out<'s>`, `Args<'a>`, `Global` | anything held across a safepoint | precise roots in the value stack |

### 2.2 `Cx`, re-entry and minting

- `Cx` is a `!Send + !Sync` capability over `*mut Isolate`; the isolate's
  fields live in `UnsafeCell`s behind audited accessors. `&mut Cx` is a
  short-lived reborrow token: every entry into R or C code consumes it,
  ends all field borrows, and re-creates it from the raw pointer on
  return. A C callback into an export obtains its capability from the
  isolate pointer while the outer one is suspended, so no two live `&mut`
  references to the isolate ever exist (the rule
  `crates/robigo-capi/src/state.rs:124` states in prose today, made a type
  rule).
- `Ref<'g>` is an 8-byte `Copy` pointer branded by `&'g Cx`. A `Ref` may be
  minted only from a `Root`, `Args`, a `Global`, a field of an object so
  reached within the same interval, or a fresh allocation within the same
  interval. Anything that can collect, run R or C code, call a package
  ALTREP method, force a promise, touch an active binding, signal a
  condition or mutate an existing object (except an own ALTREP class
  filling its private cache, §2.4) takes `&mut Cx` and ends every `'g`.
- What the borrow checker does *not* prove: that allocation never collects
  (an audited heap invariant, checked by `ROBIGO_GC_MOVE=1`), anything in
  the raw layer, and same-isolate use (§2.3).
- Compile-fail tests (`trybuild`): a `Ref` across `&mut Cx`, a slice across
  a callback, a `Ref` escaping its scope. Miri runs the non-FFI parts.

### 2.3 Roots

- Roots live in the isolate's **value stack** (§9), never on `R_PPStack`:
  C may `UNPROTECT` across a callback, and context unwinding restores
  `R_PPStackTop` (`R462/main/context.c:R_restore_globals`).
- `Root<'s>` is an index into that stack branded by a generative scope;
  slot addresses are stable because the range is reserved, not grown.
  Every builtin and native dispatch and every unwind saves and restores the
  stack top; a scope's roots die when its top is restored, on every path
  including `Err`. Every safe operation that reads, mints from, publishes
  or rebinds a handle enforces matching isolate ownership, by an invariant
  isolate brand or an owner check enabled in every build; debug-only
  checks suffice only where another enforced invariant already proves
  ownership. Clearing or replacing a root requires the owning `&mut Cx`
  and ends outstanding read leases. Root scope storage stays live
  independently of a temporary capability borrow. Output is written into
  the caller's `Out` slot before callee roots are released. M1 tests
  cross-isolate operations in release builds, root reset with a live view,
  scope escape and nested native re-entry.
- Dead VM slots are cleared at last use or masked by a liveness map at
  each safepoint (D9): a registered dead root delays a finalizer as surely
  as a stale stack word.

### 2.4 Reads, vectors, writes

- Token-free reads are header and node fields of non-ALTREP objects and of
  robigo's own ALTREP classes, whose methods are Rust, never collect,
  signal or run R code, may allocate (§3), and may write only their own
  private cache (the expanded data, as GNU R's deferred string class does,
  `altclasses.c:ExpandDeferredStringElt`) through the heap's barrier. A
  slice exists only for storage no method will write again (standard
  storage, or an own class once fully materialized). **Length, data pointer and element access on any other
  ALTREP take `&mut Cx`** on a root (`R462/main/altrep.c:340`
  `ALTREP_LENGTH` dispatches to the class's C method). `Ref::len()` returns
  `Option<usize>` (`None` for a package class); `cx.xlength(root)` calls the
  method. `Args` records whether any argument is a package ALTREP object,
  so builtins take one branch.
- `as_slice() -> Option<&'g [T]>` for standard storage and materialized
  own ALTREP. `regions_into(&mut [T; N])` fills a caller buffer for
  generated classes (GNU R's `ITERATE_BY_REGION` shape);
  `cx.read_regions(&mut self, root, f)` for package classes.
- Writes: `FreshVec<'g, T>` for unpublished objects (new-edge counts only,
  no barrier, no old-value decrement); `cx.unique_mut(root)`
  (`MAYBE_SHARED` → `shallow_duplicate`, reporting to `tracemem`);
  `cx.edit_pair(x, y, kernel)` with an aliasing check.
- Builtins in Rust: `fn(cx: &mut Cx, call: Root, args: Args, env: Root,
  out: Out) -> RResult<()>`; `Args` is a window of the value stack rooted
  by the caller. They live in a crate with `#![forbid(unsafe_code)]` whose
  safe facade sits below `robigo-rt` (no crate cycle: heap → rt-core facade
  → builtins → rt → rtapi).

## 3. Collection and rooting

**Collection happens only at safepoints** (Opus, Fable; Muse's
auto-rooting allocator is the fallback if E4 fails).

1. The heap's allocation path never collects. Its slow path updates GNU R's
   counters (R_NSize/R_VSize, `heapsize.rs`) and sets `cx.poll |= GC_DUE`
   when the trigger is crossed. (Heap change: split today's allocation,
   which collects when due, `crates/robigo-core/src/gc.rs:571-604`, into a
   poll-only path; collection is entered only from `Cx::safepoint` and from
   allocating C exports.)
2. Safepoints: R entries (`eval`, `apply_closure`, `force`, VM entry,
   `call_native`, the finalizer runner, `do_gc`), VM back-edges and calls
   (merged with the interrupt poll), builtin return, `cx.poll_alloc`, and
   allocating C API exports.
3. `&Cx` allocation is for objects below `LARGE` (measured; start at
   1 MiB). Larger objects go through `cx.alloc_rooted(&mut self, size)`,
   which tests `due(size)` for the prospective request, the configured
   limits, and collects first if needed (as `R462/main/memory.c:2709-2714`
   collects before allocating). A `&Cx` request above `LARGE` while
   `GC_DUE` is set is counted (`ROBIGO_GC_STATS`) and fails CI.
4. Any Rust loop whose allocation is not bounded by a constant calls
   `cx.poll_alloc(bytes)` per chunk, with its inputs in roots and slices
   reacquired after it. The chunk bound is part of E4; a builtin that cannot
   name its chunk does not merge. Interrupt latency in long kernels uses the
   same poll.
5. Allocation failure (`R_MaxVSize`, `R_MaxNSize`, a refused mapping)
   returns the allocator's own `Result<_, NeedGc>` (not the zero-sized
   `RResult` token, whose record lives in the pending-exit stack that
   `&Cx` code must not write); nothing runs under `&Cx`. The caller
   releases views, keeps its state rooted and retries only the failed
   allocation through `&mut Cx` (collect, then GNU R's "cannot allocate
   vector of size ..." / "vector memory limit ... reached"), converting to
   `RResult` at the first `&mut Cx` frame; no committed effect is replayed.
   A whole builtin may be re-run only if no committed observable effect
   (store, warning, callback, RNG draw, native call) occurred before the
   particular failed allocation; having no effect before the first
   allocation does not establish restartability after later ones.
6. C API exports that may collect do so on entry when due, before
   allocating, and **root their `SEXP` arguments precisely for their
   duration** (GNU R's API functions protect their arguments; robigo's
   precise roots must contain GNU R's). This differs from GNU R's
   collect-inside-allocation only for objects reachable solely from
   unprotected C locals (§15.1).
7. Pending finalizers run exactly where GNU R calls
   `R_RunPendingFinalizers` (`eval.c:1096`, the eval-count poll, whose
   unit is GNU R's: one count per `eval` of a language object or symbol,
   which robigo's VM counts at the same points, in both profiles;
   `eval.c:6247`, the byte-code poll at `bcEval`'s interrupt checks;
   `memory.c:3093, 3101`, after `gc()`), in GNU R's list order
   (`memory.c:RunFinalizers`, `R_RunExitFinalizers`).

What a collection marks, in order:

1. precise roots: the value stack (tag-checked, live slots), the protect
   stack, the `R_alloc` stack, the precious set, API globals, the
   isolate's global table, the context chain, handler and restart stacks,
   the pending-exit stack (§6), the list of objects awaiting finalization,
   per-isolate symbol cells. Isolate state that holds objects derives its
   trace (`#[derive(Trace)]`), so a forgotten root is a compile error;
2. weak references to a fixed point and finalizer readiness, on these
   marks alone (`memory.c:CheckFinalizers`);
3. **C segments conservatively, as pins** (decided by experiment A, §15.1):
   each word that points into an allocated object marks it and traces
   from it, so its memory and everything it reaches stay allocated; no
   conservative word decides a weak reference or a finalizer.
   `ROBIGO_GC_STRONG_DLL=<name>`, a diagnostic only, makes one library's
   segments strong roots to confirm a `ROBIGO_GC_PIN_REPORT=1` finding; it
   is never a default, never set by robigo for a package, and no ratchet
   case may depend on it;
4. the CHARSXP cache pruned on the union; sweep.

No Rust frame is ever scanned. JIT code keeps no object pointer, and no
pointer derived from one, in a machine register across a safepoint: it
writes live objects back to their slots and reloads (the contract deopt
needs; no stack maps).

**Collection observables** are a contract of their own. *Exact*,
oracle-tested: finalizer delivery and order, what `gc()` and R-level
`gctorture(TRUE)` make happen (finalizers run, weak references cleared),
`mem.maxVSize()` and the limit errors, `Rprofmem` lines for vectors; if one
of these cannot be kept under safepoint collection, the policy is revised.
*Exact by L7*, too: cell counts in the `gc()` table, trigger sizes, the
number and level of collections, `gcinfo(TRUE)` report contents. They
follow GNU R's object model (a cons cell per binding, a PROMSXP per
argument, three generations), which §5, §6 and §8 replace, so robigo
reproduces them as a report: a logical account of the objects GNU R would
have allocated, and GNU R's generation schedule and trigger rules
(memory.c `R_gc_internal`, `AdjustHeapSize`) simulated over that account.
The account is not on the hot path: counts are derived where they can be
(a frame's slot count gives its bindings, a call's argument count its
promises) and folded in at safepoints, never by allocating; any counter
that remains is measured under §13 like every other cost. The simulated
schedule decides only what is reported; when robigo really collects stays
its own decision, except that R-visible effects of a collection
(finalizers, weak references) follow the rules above. The
debug `ROBIGO_GCTORTURE=1` (collect at every safepoint) is
not by itself evidence of equivalence to R-level `gctorture(TRUE)`.

Checks: `ROBIGO_GCTORTURE=1`; `ROBIGO_GC_MOVE=1`, a debug moving collector
that evacuates every unpinned object at every collection and poisons the
old copy (objects ever handed to C are pinned); `ROBIGO_GC_PIN_REPORT=1`
lists every object a weak reference or finalizer decided dead while a C
word pinned it, with its DLL and routine (a candidate missing `PROTECT`,
not proof; §15.1). All are CI jobs on the `rt` slice.

## 4. Copy-on-modify

GNU R's protocol exactly. `REFCNT` counts heap edges and bindings; locals,
value-stack slots and the protect stack do not. `MAYBE_SHARED`,
`MAYBE_REFERENCED`, `NO_REFERENCES` under GNU R's names at GNU R's call
sites.

- Deferred link counts for stack values, ported from `eval.c:997-1016`
  (`R_BCProtCommitted`, `INCLNK_stack_commit`, `DECLNK`). No eager variant
  is a candidate (D6 is a control only).
- `applydefine`/`evalseq` (with `DISABLE_REFCNT` on `*tmp*`),
  `R_CleanupEnvir` and the slot-world equivalent of `unpromiseArgs`
  (§6.3) ported as written. Dead containers keep their children's counts,
  as in GNU R.
- **Growth**: `EnlargeVector` as written (`R462/main/subassign.c:140-179`):
  GNU R's expansion factor, and the same object exactly when GNU R keeps it
  (unshared, growable, `truelength >= newlen`). Otherwise a new, untraced
  object, as GNU R makes. The reallocation is made cheap instead of
  avoided: a large unshared vector may move by remapping its pages to a
  new address with no copy (measured, D12).
- AGENTS.md's porting rule 5 (`Rc::make_mut`, take by value) is replaced by
  these rules when `robigo-rt` starts.

## 5. Environments

R 4.6 hides `FRAME`, `HASHTAB`, `ENCLOS`, `ENVFLAGS` from installed headers
and adds the binding and dots APIs (`R462/doc/NEWS` 593-708). Packages see
bindings only through functions; the layout is robigo's. The detailed
design is `fable-r2.md` §3.1-3.2 in `docs/g3-council.md` (which lands with
this doc; M0 does not close without it). Its semantics are normative; its
word map is indicative and M1 fixes the final one under three
constraints: the plain-value read stays one test on the key, unbound and
cell go out of line, and the stamp lives outside the key. Deviations
from it, exhaustive: the overflow area is the default for names outside
the shape and shape transitions are the measured variant (D2s); listing
order is per-binding definition stamps, not shape history; `R_varloc_t`
stays GNU R's `{ SEXP cell }` and a varloc binding becomes cell-backed
permanently; the slot kinds add unbound and cell. Any other conflict with
§3.1-3.2 is a bug in this doc.

### 5.1 Slot frames (closure frames; every unhashed environment if D2u wins)

- One ENVSXP with inline typed slots plus an **overflow area** (a slots
  object at a fixed offset, null until first use) for bindings not in the
  shape: `assign`, `eval(quote(v <- 1), env)`, `delayedAssign`, `list2env`,
  `makeActiveBinding`, `<<-` creating in an enclosing frame. A shape
  transition (a new shape that includes the name) is a measured variant.
- A slot is a symbol key with kind bits and a value word: **unbound**
  (reserved by the shape, never defined, or removed by `rm`: lookup
  continues in the enclosure; `exists`, `ls`, `R_envSymbols` do not see
  it), value (pointer or unboxed scalar), missing, missing-default,
  delayed (expression, environment, PRSEEN and missing state; encoding per
  the M1 layout, §5), forced (value plus expression), active, locked,
  and **cell** (the slot points to a GNU R binding cell made for
  `R_findVarLocInFrame`; every read and write through the slot goes to the
  cell; the binding stays cell-backed for its lifetime, because 4.6.2's
  `R_varloc_t` is `{ SEXP cell }`, `Defn.h:2052`, and `R_SetVarLocValue`
  writes through it later, `envir.c:1125`). The tracer traces exactly the
  pointer words each kind holds.
- **Listing order is GNU R's**: `defineVar` prepends on an unhashed frame
  (`envir.c:1998`), so the newest binding lists first and the arguments
  last in formals order. Each binding carries a definition stamp set when
  an unbound slot becomes bound (never on reassignment); enumeration lists
  by stamp descending; formals are stamped in reverse formal order at call
  entry. `rm` then reinsertion moves a binding to the front, as in GNU R.
- **Expand on read**: an unboxed slot read as an object is boxed once and
  stored back (`memory.c:R_expand_binding_value`), so `get`, `as.list` and
  C see one identity.
- `FRAME()` of a slot frame (base natives, `inspect`) is a GNU R-ordered
  read-only pairlist snapshot; `SET_FRAME` on a slot frame is an error.

### 5.2 Hashed environments

Global, namespaces, packages and `new.env(hash = TRUE)` keep GNU R's
logical structure exactly (FRAME pairlist of binding cells, HASHTAB
chains, `HASHPRI` fill count), so `ls(sorted = FALSE)`,
`as.list.environment`, `env.profile()` and `serialize` order are GNU R's by
construction. `env/table.rs` goes.

### 5.3 Symbols, globals, versions

- The symbol arena is **process-shared** (L6): one lock, append-only
  segments never reallocated, 64-byte-aligned symbols, ids by arena
  arithmetic and global. Per isolate: the symbol's value cell, base
  bindings and GNU R's `R_GlobalCache` (`envir.c:616-772`) in tables
  indexed by the global id. Base-environment listing order follows GNU R's
  symbol-table walk (`envir.c:BuiltinNames`).
- Versions: per-frame `fn_version`, per-isolate `search_epoch`; guard memo
  keys never rely on a bare address. `<<-` caches (depth, shape, slot).
- Frame recycling under an ESCAPED bit is a measured variant (D5),
  checked by a quarantine mode (§16).

## 6. Calls, promises, contexts, unwinding

### 6.1 Closures and code

- CLOSXP: FORMALS, BODY, CLOENV, and a code object (private type: constant
  pool traced, shape, both profile variants, weak cache words, JIT entry,
  GNU R's JIT state). **BODY may be a BCODESXP** (from `cmpfun`, lazy-load
  databases, saved closures); its first constant is the source; robigo
  keeps the BCODESXP object for `identical`, `disassemble` and
  serialization, and translates it to the IR on first call.
- Code ownership is traced by every legitimate owner (shared bodies,
  bytecode constants); speculative caches stay weak.
- Invalidation: any write to BODY, FORMALS or CLOENV, R-level or C, and
  `duplicate` of a closure, drop robigo's compiled variants and the frame
  shape. **GNU R's JIT state is not dropped with them**; it changes only
  where GNU R changes it. GNU R's JIT installs the BCODESXP as the BODY of
  the one closure it compiles (`eval.c:1903`, `SET_BODY(fun, BODY(val))`),
  and robigo does the same: whether a closure is compiled is whether its
  BODY is a BCODESXP, with the frozen bindings in that body. So a closure
  `duplicate`d after compilation shares the compiled body, and one
  duplicated before stays uncompiled until its own JIT decision; `NOJIT`
  and `MAYBEJIT` belong to the closure and are copied
  (`duplicate.c:309-310`). R-level `environment<-` returns a compiled
  closure to its source and keeps the two bits (`builtin.c:323-325`); C
  `SET_CLOENV` changes neither. §9.3 has the full mutation contract.

### 6.2 Arguments and binding kinds

- **A slot's kind is the kind GNU R's binding would have at the same
  moment, never the cheapest one.** A lazy argument is a delayed slot. An
  argument the caller evaluated early is still a **delayed** slot with the
  value attached as a precomputed result: `R_GetBindingType`,
  `.Internal(getBindingType)` (`envir.c:807-830`), the delayed-binding
  accessors, `substitute` and materialization see an unforced promise until
  the callee's first read, which makes it forced without evaluating
  anything. A constant argument is a delayed slot under the `Eval` profile
  (`eval.c:promiseArgs`, the final `mkPROMISE`) and a value slot under `Bc`
  (`PUSHCONSTARG`, `eval.c:8042-8050`).
- A PROMSXP is made only when a promise is shared or observed as an object
  (`...` captured, `substitute` on a materialized frame, legacy
  `findVarInFrame`), once, and every alias (including forwarded dots) sees
  that one object. An argument may itself be a PROMSXP (forwarded `...`,
  made by C, `delayedAssign`); binding-kind queries unwrap promise chains as
  `envir.c:780-805` (`promiseUnwrap`) and `BINDING_TYPE` (`:807-830`) do.
- Heap PROMSXPs use GNU R's own unboxed values (`IMMEDIATE_PROMISE_VALUES`,
  defined on 64-bit builds, `Defn.h:34-39`; `PROMISE_TAG`); the tracer
  skips the word by tag.

### 6.3 Binding state transitions

| from \ event | first read (force) | assign in callee | `rm` | C binding query | materialize |
|---|---|---|---|---|---|
| delayed (lazy) | evaluate; → forced (expr kept, env dropped) | → value | → unbound | delayed | PROMSXP unforced |
| delayed (precomputed) | → forced, no evaluation | → value | → unbound | delayed | PROMSXP unforced, value attached on force |
| forced | value | → value | → unbound | forced | PROMSXP forced |
| value | value | value | → unbound | value | (none) |
| missing (no default) | error per `R_isMissing` | → value, MISSING cleared | → unbound | missing | (none) |
| missing-default (a delayed slot: the default expression, the callee frame, MISSING = 2) | evaluate the default; → forced, MISSING stays 2 | → value, MISSING cleared | → unbound | delayed, then forced | PROMSXP, as GNU R binds one (`eval.c:2272`) |
| active | call the function | call the function | → unbound | active | (none) |
| cell | through the cell | through the cell | detach the cell | per the cell | (the cell) |

Each cell is ported from `envir.c`/`eval.c`, and its REFCNT effect is GNU
R's (`unpromiseArgs`'s decrements become the forced-slot release on call
exit). `ROBIGO_MATERIALIZE=1` (§16) checks the table against real
PROMSXPs.

### 6.4 Matching and calls

`matchArgs` (three passes) with memoized permutations per call site and
callee. A memoized plan records which partial matches it used and signals
the same warnings `matchArgs` would under the options in force at that call
(`match.c:277-279`, `warnPartialMatchArgs`). `...` is a DOTSXP forwarded
without copying.

### 6.5 Contexts and unwinding

- **One context chain: GNU R's linked `RCNTXT`** at stable addresses, with
  a `#[repr(C)]` layout robigo's `Defn.h` declares (C/Rust size and offset
  assertions). A trampoline's jump record is a field of its `CTXT_CCODE`
  record; there is no second shim stack. `sys.*`, `parent.frame`,
  `on.exit`, restarts and the browser read the chain. `promargs` is filled
  when a closure context is pushed if any compiled C reads it as a field
  (`util.c:594`, `do_nargs`), else materialized lazily.
- Every exit, a Rust `Err` reaching an export wrapper or a C `Rf_error`,
  runs `R_run_onexits` semantics (`context.c:120-160`, `R_jumpctxt`
  `:215-228`) **before** any `longjmp`: the `cend` and `on.exit` of every
  record above the target, innermost first, with `R_GlobalContext` set as
  GNU R sets it, from the frame about to jump. A Rust `Err` that pops a
  C-pushed record runs the same walk. Otherwise `docs/core.md` §5 holds:
  only export wrappers jump; trampolines turn jumps into `Err`.
- `RResult` carries a zero-sized error token; the exit (kind, target
  context, mask, value, condition, call) is the top record of a
  **pending-exit stack** in the isolate, a precise root. Code that runs
  during an exit (`R_run_onexits`, a `cend`, an `R_UnwindProtect` cleanup,
  a calling handler, a finalizer) parks the record in the context being
  left (GNU R's `jumptarget`, `jumpmask`, `R_ReturnedValue`,
  `context.c:198-244, 298-319`) and restores it afterwards, unless that
  code leaves by its own exit beyond it, which supersedes it as in GNU R.
  Each retained unwind continuation owns its record until resumed or
  released (`context.c:977-993`). Sizes are asserted for the hot-path
  result types, not promised for every `T`.
- **Warnings are signalled where GNU R signals them**, through `&mut Cx`,
  never deferred (GNU R's kernels warn after their loop, `arithmetic.c`
  `naflag`, `coerce.c` `CoercionWarning`).
- Inline caches hold weak words, zeroed after marking when their target
  dies.

## 7. Strings

CHARSXPs throughout; `NA_character_` is the immortal `NA_STRING`.
`Char<'g>`: `bytes()`, `enc()`, `is_ascii()`, `utf8(&cx)` and `native(&cx)`
at GNU R's `translateCharUTF8`/`translateChar` sites. `paste` builds in a
reused scratch buffer and interns once. `match`, `unique`, `duplicated`,
`%in%`, `factor` hash the CHARSXP pointer when encodings agree
(`unique.c`). The symbol of a string may be cached in a spare CHARSXP word
that is not the `TRUELENGTH` scratch `radixsort.c:savetl` overwrites; on a
shared CHARSXP (§8) it is written once, at interning.
Interning cost is measured (D10).

## 8. Vectors, ALTREP, layout

| storage | use |
|---|---|
| inline | default |
| robigo ALTREP (Rust classes) | compact `intseq`/`realseq`, wrappers, deferred coercions; `1:2e8` is one small object everywhere (#460) |
| foreign ALTREP | Arrow/NumPy/mmap; read-only views, writable access materializes once |
| package ALTREP | methods where GNU R calls them, behind `&mut Cx`, in GNU R's call order |
| EXTDATA | only C-owned writable memory |

- `RVal::Range` goes: a compact sequence is one object per loop.
- Attributes: one pairlist (order is observable).
- Layout, measured (D8, D13): a 24-byte vector header (scalars 32 bytes,
  today 48, GNU R 56) and per-type node sizes. **Every variant keeps
  storage for what `TRUELENGTH` holds**: the exact growable capacity, the
  CHARSXP scratch (`radixsort.c`), hash-table fill counts (`HASHPRI`,
  `serialize.c`, `saveload.c`), with `inspect`'s `tl=` reproduced. A
  CHARSXP in the shared segment (`R_BlankString`, `NA_STRING`, every
  symbol's PRINTNAME; `docs/core.md` §10) is immutable: its `TRUELENGTH`
  scratch, and any other word C may write, is a per-isolate word in a
  table indexed by the object's global id, and `TRUELENGTH`/
  `SET_TRUELENGTH` branch on the shared bit (part of D8's bar). The C API
  census against packages built for 4.6 (`tests/capi/symbols-4.6.tsv`,
  `docs/ledger/g3.md` 2026-11-13): 4.6.2's `libR.so` no longer exports
  `SETLENGTH`, `TRUELENGTH`, `SET_TRUELENGTH`, `XTRUELENGTH`,
  `SET_GROWABLE_BIT` or `IS_GROWABLE`, and no 4.6-built package imports
  `SET_PRVALUE` (still exported). Packages reach a vector's growable
  capacity only through the resizable-vector API
  (`R_allocResizableVector`, `R_resizeVector`, `R_isResizable`,
  `R_maxLength`, `R_duplicateAsResizable`). Only GNU R's own C (`src/main`
  and the base-package natives that include `Defn.h`) reads or writes
  `TRUELENGTH`.
- The S4 bit exists from day one (G6).

## 9. Execution

### 9.1 One engine, GNU R's JIT decisions

- Everything runs in the VM; the AST interpreter goes. Two compile
  profiles: `Eval` reproduces `eval.c`'s observable behaviour, `Bc`
  reproduces GNU R's byte-code compiler's (cmp.R semantics, base bindings
  frozen at compile time).
- **Which profile runs is GNU R's decision**, tracked per closure and per
  body (§6.1): a port of `eval.c:R_CheckJIT`, `JIT_score`, `MAYBEJIT`/
  `NOJIT`, `R_JIT_STRATEGY` and the JIT cache (today's
  `crates/robigo-runtime/src/vm/rjit.rs`). `Eval` until GNU R's JIT would
  compile the closure, `Bc` after; `Bc` from the first call for installed
  byte code; `Eval` while the closure is debugged (`eval.c:2359`); top-level
  loops as `do_for`'s `R_compileAndExecute` decides.
- The `Bc` profile's inlining and frozen-binding decisions are cmp.R's,
  made by the port of them in `vm/rjit.rs` (carried over) at the moment
  GNU R's JIT would compile, and checked against recorded GNU R fixtures.
  From M3, a GNU R-shaped BCODESXP is also crystallized at that moment, at
  a call boundary, by running GNU R's compiler package on the closure's
  source in the compile environment, options and base bindings then in
  force, and installed as BODY (§6.1); M1 makes no BCODESXP. Observation (`print`'s `<bytecode>` line, `inspect`,
  `serialize`, `bodyCode`, `disassemble`) only exposes the stored object
  and never runs the compiler; a closure GNU R has not yet compiled has no
  BCODESXP to expose. The `bytecode-fidelity` fixtures carry over.
- A naive reference interpreter over LANGSXP exists only behind
  `ROBIGO_REF_EVAL=1`, as a differential oracle with its own CI job on the
  `rt` slice. Run-once cost is measured (D11).

### 9.2 IR, VM, JIT

- One effect-aware IR shared by the VM and the native tiers, with deopt at
  op granularity to exact VM state (promises, contexts, visibility, pending
  exits); never replaying a warning, callback or visible store.
- Value stack: one per isolate, reserved address range, guard page; slots
  tagged (object, real, int, logical, empty), no NaN-boxing. Layout
  measured (D3).
- Carry over from `docs/ledger/perf-vm.md` "For G3": call-site lookup
  through local frames, pure-closure inlining, caller-forced arguments,
  index promises forced in R's order, guard memoization, static rejection
  memos, the `%*%` row-vector kernel, the measurement method; and
  `vm/rjit.rs`'s JIT-decision port.
- JIT: Cranelift tiers on the IR; header offsets from heap constants; a
  feedback-directed tier with per-op type profiles; LLVM for the hottest
  code if it pays (G8).

### 9.3 Mutation contract for compiled code

Code, match plans and dispatch caches validate every mutable dependency:
BODY and FORMALS spines, class vectors, bindings, numeric policy. Pointer
identity alone is never a validity guard. Tracked writes (R-level and the
C API's setters) invalidate dependent code before its next use; foreign
effects that cannot be tracked (raw C writes) conservatively invalidate
assumptions at native entry, at callbacks and on return. A suspended
compiled activation whose assumption broke deopts at its next uncommitted
operation.

## 10. Builtins and GNU R's sources

The end state: every builtin in Rust, exact and faster than any rival; no
GNU R C in robigo (L4). GNU R's sources remain the spec.

- **Designed away** (one implementation, no second fallback): the
  language specials (`if`, `for`, `function`, `<-`, `{`, `&&`, `quote`,
  `switch`, `return`, `UseMethod`, `on.exit`, `substitute`, ...: about 30)
  are VM ops whose builtin object only compiles a call to the op; the
  kernels the VM and JIT own (arithmetic, comparison, logic, `math1/2`,
  summaries, `:`, `seq_len`, `length`, `is.*`, `as.*`, `c`, `list`, `rep`:
  about 120) have one Rust implementation shared by the op and the builtin
  object. Every builtin stays callable (`do.call`, `match.fun`,
  `sapply(x, "[", 1)`).
- **Ported as functions**: subsetting and assignment first (tied to the
  link-count protocol), then the rest, ordered by measured share of
  package-suite time. The evaluator-owned files (`eval.c`, `envir.c`,
  `errors.c`, `context.c`, `debug.c`, `memory.c`, `objects.c`, `match.c`,
  `main.c`: about 176 `names.c` entries) are Rust from M3.
- **The C crutch is decided by D0**, before M3: count the distinct builtins
  a base boot needs (on the old runtime) that are not already Rust at M3
  (the evaluator-owned and designed-away ones above); prototype the
  adapter (VM `Args` → GNU R's `(call, op, args pairlist, env)` signature,
  promise-shaped cells for evaluated builtins, visibility, a per-call
  trampoline) for `attrib.c`, `bind.c` (on `unlist`, `cbind`, `rbind`) and
  `paste.c` (files the crutch would serve); measure instructions per call
  against a Rust port of the same functions written on `robigo-rt`'s API
  for the pilot. Bar, written now: adopt `robigo-cbase` only if that boot
  set is at least 150 builtins *and* the adapter costs at most 1.10x that
  Rust port's instructions per call on all three files; otherwise port the boot set to
  Rust and delete this bullet. If adopted: only files the evaluator does not own;
  an ABI manifest of every internal function and global they need, served
  by `robigo-rtapi`; robigo's `Defn.h` defines `FRAME`/`HASHTAB` (read-only
  snapshot of slot frames), `TRUELENGTH` (onto §8's storage) and `RCNTXT`;
  `scripts/check-cbase.sh` fails on any use of `FRAME(`, `HASHTAB(`,
  `TRUELENGTH`, `->promargs`, `->cloenv`, `->callfun` not in its allowlist.
  (The stats precedent, fastr 30,576 vs 30,311 cases, is package natives
  behind `.Call`, not `src/main` builtins: it shows the build technique,
  not this adapter.) The vendored C is never edited; the count of builtins
  served by C only goes down.
- **Differential mode**: the registry gives each builtin an effect class.
  Same-process dual execution (`ROBIGO_BUILTIN_DIFF=1`, both
  implementations on duplicated arguments, warnings and errors captured as
  records) is restricted to operations proven effect-free for the actual
  inputs and execution path. Callback-capable inputs or paths (package
  ALTREP, dispatch, a promised `.Random.seed`, user RNGs,
  `RNG.c:GetSeedsFromVar`/`USER_UNIF`), RNG operations and anything
  unclassified are compared out of process: the case runs once per
  implementation in a fresh process, and results, post-state (final RNG
  state included), output, warnings, callback order and external effects
  (fixtures for non-replayable inputs) must be identical. Capturing
  warnings or restoring RNG state is not an effect rollback.
- **Base-package natives** (stats, utils, graphics, ...): built from GNU R's
  sources now; each replaced by a Rust port that is exact and faster, in
  order of measured share of package-suite time, all of them by M8.
- Builtins below `rt` reach the evaluator (`eval`, `apply`, dispatch,
  `force`) through a hook table in the rt-core facade that `rt` installs in
  `Cx` at startup; its indirect-call cost is measured on `lapply` and `[`
  dispatch (E6).
- **GNU R's R code** is observable as content: each base closure's
  formals, body tree, environment, the calls it makes and its argument
  forcing order show through `body`, `deparse`, `trace`, `debug`,
  `sys.calls`, condition calls, `Rprof` and dispatch from inside base. So
  the content stays; speed comes from compiling it, inlining `.Internal`
  wrappers and guarded intrinsics that fall back to the closure whenever
  an observer is possible. **The checked-in copy goes**: the pinned GNU R
  4.6.2 tarball (by hash) is the one build input; robigo runs GNU R's own
  package build (`makebasedb.R`, `tools:::makeLazyLoading`, `cmp.R`) to
  produce `base.rdb` and the other packages' databases with GNU R's
  insertion order and installed byte code. `rlib/` and the copy from a GNU R
  installation in `scripts/robigo-home.sh` are deleted; robigo needs no GNU
  R installation at run time (G6).

## 11. The isolate

One `Cx` per isolate holds the heap (embedded: allocation is two loads off
`cx`), symbol cells, contexts, handler and restart stacks, the value stack,
the protect stack, the pending-exit stack, options, connections, RNG,
`R_Visible`, `R_Srcref`, eval depth, numerics policy, epochs, the JIT
module and the console. None of today's 69 runtime `thread_local!`s
survive. Rust and JIT code receive `cx` explicitly; C API exports read one
thread-local (initial-exec model in C, L6). Per-isolate C globals
(`R_GlobalEnv`, `R_PPStackTop`, ...) are macros over that accessor in
robigo's headers; unedited C that takes their address is served through
the crutch's ABI manifest (§10). The `libR.so` shape is re-measured after
the flip.

## 13. Performance targets

**The rule**: one-process runs are compared by instructions (callgrind, N
vs 2N) and wall time; warmed peak by wall time. Wall time: the shipped
(PGO) build, batched to at least 0.05 s, at least 10 interleaved runs per
runtime, median compared; two runtimes within 2% tie, and a tie does not
count as fastest. Instructions also
remain the repository's per-PR regression gate (0.5%). Each run names the
binaries, versions and machine. Rivals: GNU R 4.6.2, Ř, FastR
(`scripts/rivals.py`); C floors where they exist (`scripts/idiom-vs-r.py
--idioms`).

Bars (robigo fastest of all runtimes unless stated):

- every program in `benchmarks/benchmarks.toml`, one-process and warmed
  peak (2026-11-03, plain release: fastest on 72 of 76 one-process, 29
  warmed peak);
- idioms with a C floor: ÷floor reported; the gap closed or explained cause
  by cause (`callgrind-diff.py --causes`);
- general calls (`calls.R`): ≤ 0.6x GNU R's instructions on the plain-call
  idioms; zero allocations per call after frame recycling;
- cold and run-once code: `Rscript -e 1`, `library(p)` for the named
  packages, a run-once `eval` loop;
- the C boundary, per crossing: `.Call`, `.External`, `Rf_eval` from C,
  `R_tryEval`, `PROTECT`/`UNPROTECT`, `Rf_allocVector`, ALTREP `Elt`
  (experiment A: 7,511 instructions for a no-op 3-argument `.Call` with
  the stub removed);
- object systems: S3, S4 dispatch, reference classes, R6;
- vector and data-frame work: element-wise chains, reductions, `order`,
  `[.data.frame`, grouping, with parallel kernels (#378) and fusion (#380);
- I/O, regex, serialization: `read.csv`, `readLines`, `gsub`, `sprintf`,
  `format`, `saveRDS`/`readRDS`, `parse`, `deparse`, mixed-encoding
  strings;
- large live heap: 4 GB live with steady allocation; GC time and total
  time ≤ GNU R's (decides M8's generational collection); p99 and max pause;
- package suites: aggregate time below GNU R's for every package (today
  0.7-1.0x), with rlang, dplyr, data.table, vctrs as named rows; long
  sessions plateau in memory;
- startup and memory: startup and peak RSS ≤ GNU R's; `1:2e8` in constant
  memory.

## 15. The prototype: decisions by measurement

### 15.1 Experiment A (done on today's main, 2026-11-13)

Switches on `4cff0ceb` (uncommitted): `ROBIGO_GC_PIN_ONLY=1` (weak
references and finalizers decided before the conservative scan) and
`ROBIGO_CALL65_PLAIN=1` (no `.Call` stub: no scan narrowing, no 1 KiB
zeroing).

- capi `native_call_frames_keep_nothing` (a dead pointer planted in every
  word of a native call's frames): fails with the stub off and the old
  order, passes with the stub off and pin-only.
- Stress script (a finalizer-carrying `.Call` at R depth a, C churn at b,
  a, b ≤ 24), 30 runs x 625 pairs per tier (interpreter / VM / VM+JIT):
  baseline 0/0/0; pin-only 0/0/0; stub off, old order 30/0/0; pin-only and
  stub off 0/0/0.
- `cargo test --release -p robigo-core -p robigo-capi` with both switches:
  65 of 65, including the tests that objects held only by C stack words
  survive.
- Conformance, all tiers, both switches: no regression (natives disabled
  locally, so few C frames ran).
- Cost: 7,631 → 7,511 instructions per no-op `.Call` (−1.6%) without the
  stub; pin-only adds nothing per call.

**Decision: pins** (§3 step 3), with the export rooting rule (§3 item 6).
The council split 2-2 on safety. Astra and Muse: a pinned external
pointer's finalizer can release a resource an unprotected C local still
uses. Answer: GNU R decides finalizers on precise reachability too
(`memory.c:CheckFinalizers`), so such an object is finalized by GNU R at
the same collection and its memory freed; pins give GNU R's finalizer
decision in every case with memory that lives longer, and exact timing for
correctly protected packages, which strong roots cannot give (the 30/0/0
misses). The experiment shows compatibility on the tested cases; it does
not prove resource safety for unprotected C, which GNU R does not give
either. Still to run before the heap adopts it: the capi corpus and the
package suites with natives built, under gctorture, with
`ROBIGO_GC_PIN_REPORT=1`; a premature-finalization probe (an unprotected
external pointer passed to an allocating export is not finalized during
the call, as in GNU R); an external-buffer probe documenting the
resource-safety limit (a pin-only external pointer whose finalizer frees
a buffer a C local still names, compared with GNU R); narrowing and
zeroing measured as separate switches. These runs belong to M0.

Adoption rule, written before those runs: `robigo-heap` adopts pins only if
no capi-corpus or package-suite case that passes today fails under pins
and the premature-finalization probe passes; any failure reopens this
decision (strong roots are not a per-package escape hatch: they bring back
the stale-word misses). A `ROBIGO_GC_PIN_REPORT=1` hit is a candidate
missing `PROTECT` to investigate (a stale word and a live unprotected
pointer look the same to the scanner), confirmed with
`ROBIGO_GC_STRONG_DLL`. Narrowing and zeroing are removed only on their
separate measurements, each leaving both probes unchanged. The stub and
the zeroing go in `robigo-heap`; `robigo-core` is frozen (L2).

| D12 | growth reallocation | copy; page remapping | M3 |
| D13 | node sizes | per type (40-byte LISTSXP); uniform 48 | M2 |

### 15.3 Exit criteria for M1

- E1 `calls.R` (one process, JIT off), M1 rows: plain, defaults, named,
  `e$f`, `<<-`, S3 ≤ 1.0x GNU R's instructions, the plain-call idioms
  ≤ 0.6x; wall time below Ř's and FastR's one-process. M3 adds `tryCatch`.
- E2 fib, binarytrees: ≤ today's robigo (JIT off) in instructions and
  estimated cycles; binarytrees peak RSS ≤ today's and ≤ GNU R's.
- E3 determinism: the stress script misses nothing in 30 ASLR runs per
  tier; `weak-keys-collections.R` passes; gctorture and `ROBIGO_GC_MOVE=1`
  clean.
- E4 overshoot: bytes allocated between `GC_DUE` being set and the
  collection that serves it never exceed max(32 MiB, 10% of the live heap)
  on the slices M1 runs; peak RSS ≤ GNU R's on the memory benchmarks.
  Extended to every corpus and package suite as coverage grows.
- E5 torture identity: under `ROBIGO_NO_INPLACE=1` and
  `ROBIGO_MATERIALIZE=1`, semantic values and effects are identical on the
  prototype cases where the debug transformation is unobservable.
  Deliberate native alias-mutation cases, trace counts, `inspect` fields
  and allocation diagnostics have separate production-mode oracle
  expectations; neither control weakens the production gate. And
  `getBindingType` matches the GNU R oracle before and after the first
  read for a constant, a symbol, a call and a defaulted argument, on a
  closure's first call and after GNU R's JIT threshold (a mode comparing
  robigo with itself cannot catch a table wrong in both modes).
- E6 the API: three builtin modules (arithmetic, `paste`/`nchar`,
  `assign`/`get`/`exists`) with no `unsafe`, reviewed for ergonomics by a
  council member who did not write them; the capi cases `eval`,
  `pairlist`, `unwind`, `extptr` pass over the minimal `robigo-rtapi`;
  the hook table's indirect-call cost (§10) recorded on `lapply` and `[`
  dispatch; regression cases pass for a package ALTREP Length callback
  that allocates and re-enters R, in-place mutation of BODY/FORMALS
  children, and mutation during a callback while compiled code is
  suspended.
- E7 strings: `paste`/`match`/`unique` loops ≤ today's instructions, or the
  regression recorded in `docs/ledger/g3.md` with its cause and the lead's
  acceptance.
- E8 unwinding: `on.exit` that catches its own error during an unwind
  returns the outer condition; `R_UnwindProtect` cleanup that catches an
  error resumes the original continuation; a C context's `cend` runs before
  the jump; all in every tier and across a C frame.
- E9 allocation failure: the M1 slices pass under a small `R_MAX_VSIZE`,
  and an injected allocation failure after a visible effect neither loses
  nor repeats the effect.
