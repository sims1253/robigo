# G3 ledger

The G3 runtime rebuild (`docs/g3.md`): every experiment and measurement,
kept or rejected, with what was tried, why, and the result. Sections are
dated and only appended, so parallel G3 pull requests merge cleanly.

## 2026-11-13: the C API census against packages built for R 4.6 (M0)

- why: `docs/g3.md` §8 and §14.2 (M0) require the census re-run against
  packages built for 4.6 before layout decisions rest on it. Today's
  `tests/capi/symbols.tsv` is R 4.5.0's.
- what: `scripts/capi-census.py scan` now writes one census per R
  version, chosen by the R on `PATH`: `symbols.tsv` stays 4.5's (the
  frozen runtime's `crates/robigo-capi` reads it), `symbols-4.6.tsv` is

  no longer exists on any machine we have, so the CRAN side cannot be
  matched package for package. The libR-side findings below do not
  depend on the population (exports and `tools:::funAPI()` of 4.5.0's

- result: 831 symbols, weight 5339 → **834 symbols, weight 4910**.

## 2026-11-13: M1 decision bars: D1, D2, D2s, D3, D4, D5, D6, D9

Written before any variant is built past a compile check. Signed off by the
foreman in the pull request that adds this section. A bar is fixed once a
run cites it; a change is a new dated section that says which bar it
replaces and why, committed before the runs it governs (§15.2: "bars are
written before the runs"). Finalizes the proposal
in the M1 plan (§C) with the foreman's answers (memory benchmarks: answer 4;
variants on branches only: answer 6).

### Protocol (every bar below)

- **Binary.** `robigo-rt`, built with `cargo build --release --locked -p
  robigo-rt` (never `--quick`). Every variant of one decision is a branch
  from the same base SHA, named below; the decision PR merges the winner,
  and controls never merge (no cfg-gated second layout, §14.1).
- **Admission.** A variant is measured only after it passes the rt slice on
  its branch: CI's `rt` job and, once it exists, `scripts/rt-conf.py` over
  `tests/rt/passing/`. A variant that fails it is an inexact variant, so it
  is a control (§0), not a candidate.
- **Instructions** per iteration: `scripts/idiom-vs-r.py --rows
  benchmarks/rt/calls-rows.toml --robigo BIN --no-r --json OUT`, callgrind,
  N against 2N with each row's `n`, so startup and the base load cancel.
- **Estimated cycles** per iteration: the same command with `--cycles`
  (callgrind's cache and branch simulation; Ir + 10·D1m + 100·LLm, the
  model of `scripts/perf.py --metric cache`).
- **Allocations** per iteration: objects by SEXPTYPE and bytes, from the
  heap's counters (`ROBIGO_GC_STATS=1`, H2 item 4), N against 2N on the
  same rows' scripts.
- **Peak RSS**: `scripts/rss.py --runs 5`, the median `ru_maxrss` in KiB.
- **Geomean**: the geometric mean of a metric over the named rows. A
  difference is variant ÷ default − 1.
- **Tie band**: ±1% on the decision metric. Inside it, the variant named
  first (the simpler one, the design's default) wins.
- **Rows.** The row sets below name rows of `benchmarks/rt/calls-rows.toml`:
  - CALLS: `plain`, `defaults`, `named`, `env-fn`, `superassign`, `s3`
    (E1's M1 rows; `trycatch` joins at M3);
  - PLAIN: `plain`, `defaults`, `named`, `env-fn` (§13's plain-call
    idioms);
  - SUITE: `fib` (`fib(18)` per iteration), `binarytrees` (one depth-8
    tree per iteration);
  - D2S: `d2s-assign`, `d2s-eval`, `d2s-callee-assign`, `d2s-delayed`.

  Every row a bar names must run on `robigo-rt` at the base SHA before the
  decision is made. A run that leaves rows out (because the base cannot
  run them yet) is preliminary evidence: it is recorded, it lists the
  missing rows, and it decides nothing. The rows file only grows: a row a
  bar cites is never edited.
- **Memory benchmarks** (E2, E4; foreman answer 4), each a whole program
  run with `R_DEFAULT_PACKAGES=NULL`: `benchmarks/suite/binarytrees.R`
  (`bt(10)`), `benchmarks/rt/mem/listgrow.R` (a list grown by `l[[i]] <- x`
  to 200,000 elements) and `benchmarks/rt/mem/churn.R` (200 iterations that
  each make and drop two 1e6-element double vectors). E2 compares
  binarytrees with today's robigo and GNU R 4.6.2; E4 compares all three
  with GNU R 4.6.2.
- **Machine.** All runs of one decision on one machine, named in the run
  entry with the valgrind version. Instruction counts depend on the C
  library's CPU dispatch, so runs from two machines are never compared.
- **Reproduction.** Every table is run twice before its entry is written.
  A row whose two runs differ by more than 0.1% in instructions or 0.5% in
  estimated cycles is run three more times and reported as the median of
  the five with its range. Callgrind is exact, but a runtime need not be:
  today's robigo varies by up to 0.3% on `e7-paste` from run to run, with
  ASLR off too (section "M1 baselines"). A difference between two variants
  smaller than the larger of their ranges on a row is a tie on that row.
- **Records.** The run entry gives the base SHA, each variant's SHA, the
  commands, and the raw JSON (inline, or as files under `docs/ledger/g3/`).
  The decision entry gives the verdict and the PR that deletes the losers'
  branches.
- **Failed premise.** A control that comes within the margin a bar names
  goes to the lead before anything is adopted.

### D1: collection (built by T1; the fallbacks only if needed)

- Question: does collection at safepoints only (§3) keep E3 and E4 at an
  acceptable cost?
- Variants: `safepoint` (H2's design, the default on main). Control:
  `g3/t1-d1-nopoll`, the poll and the safepoint check compiled out. For
  the instruction runs, both run with the same heap settings, chosen so
  that neither collects (0 collections in `ROBIGO_GC_STATS` for both, or
  the run is void): the difference is then the poll and safepoint cost
  alone, with no collection work in it. E3 and E4 run separately, with the
  default heap. Fallbacks, built only if `safepoint`
  fails: `g3/t1-d1-autoroot` (Muse's auto-rooting allocator), then
  `g3/t1-d1-out` (Astra's `&mut Cx` allocation into an `Out` slot).
- Workloads: instructions on SUITE and CALLS; E3 (the stress script, 30
  ASLR runs per profile; the rt variant of `weak-keys-collections`;
  gctorture and `ROBIGO_GC_MOVE=1` on the rt slice); E4's overshoot on
  every slice M1 runs.
- Rule: `safepoint` is adopted if E3 is fully clean, E4's overshoot never
  exceeds max(32 MiB, 10% of the live heap) on any slice, and its geomean
  instructions over SUITE and CALLS exceed the control's by at most 1.0%.
  Otherwise build the first fallback and apply the same three conditions,
  then the second.
- Deleted: the control branch, and every fallback branch not adopted.

### D2: closure frames (X1)

- Question: inline typed slots with an overflow area (§5.1), against a
  separate frame object, with GNU R's pairlist as the control.
- Variants: `inline` (N1b, the default), `g3/x1-d2-frameobj` (an ENVSXP
  plus a separate frame object), and the control `g3/x1-d2-pairlist` (GNU
  R's frame pairlist of binding cells).
- Design: run as a factorial with D3: {`inline`, `frameobj`} × {`slot16`,
  `split`} (four builds), plus `pairlist` at `slot16` only.
- Workloads: CALLS and SUITE.
- Metric: geomean instructions per iteration.
- Rule, in order:
  1. At each D3 level, the D2 variant with the lowest geomean wins; inside
     the tie band, the one with fewer bytes allocated per iteration
     (geomean over the same rows), then lower binarytrees peak RSS, then
     `inline`.
  2. If both D3 levels pick the same D2 variant, that is D2's verdict, and
     D3 is decided by its own bar at that variant.
  3. If they pick different ones, the joint verdict decides D2 and D3
     together and replaces D3's own bar: of the four factorial cells
     (`pairlist` is not eligible), the one with the lowest geomean
     estimated cycles over the same rows. Inside the tie band of that
     cell, the tied cells rank in this fixed order and the first wins:
     `inline`/`slot16`, `inline`/`split`, `frameobj`/`slot16`,
     `frameobj`/`split` (most defaults first; between one-default cells,
     D2's default first).
  4. If `pairlist`'s geomean instructions are within 5% of the D2 winner's
     at `slot16` (≤ 1.05 × the winner's), the result goes to the lead
     before adoption.
- Deleted: the losing D2 branches and the control.

### D2s: names outside a frame's shape (X1, on D2's winner)

- Variants: `overflow` (the default) and `g3/x1-d2s-shapes` (shape
  transitions).
- Workloads: D2S, and CALLS as a guard.
- Rule: `shapes` is adopted if its geomean instructions over D2S are at
  least 5% below `overflow`'s and no CALLS row is more than 0.5% slower;
  otherwise `overflow`.
- Note: the plan named "`<<-` creating" as a microbench case. `<<-` creates
  a variable only in the global frame, never in a closure frame, so
  `d2s-callee-assign` (a callee's `assign(envir = parent.frame())`)
  stands in for it.
- Deleted: the losing branch.

### D3: value-stack slots (X1)

- Variants: `slot16` (R1's tagged 16-byte slots, the default) and
  `g3/x1-d3-split` (tags and payloads in split arrays).
- Workloads: SUITE and CALLS, in the D2 factorial.
- Metric: geomean estimated cycles per iteration.
- Rule: at D2's winner, the lowest geomean wins; inside the tie band,
  `slot16`. When D2's rule 3 applies, its joint verdict decides D3
  instead.
- Deleted: the losing branch.

### D4: arguments (X2)

- Variants: `slots` (C1's delayed and forced slots, the default) and the
  control `g3/x2-d4-promsxp` (`args::bind` allocates a PROMSXP per
  argument, as `eval.c:promiseArgs` does).
- Workloads: `plain`, `defaults`, `named`, `fib`.
- Rule: `slots` is adopted if its geomean instructions over the four rows
  are at least 10% below the control's, and argument binding allocates
  nothing on each of them (no promise is observed in these rows). The
  allocation counters establish the second condition per iteration, row
  by row, against the control, which differs only in `args::bind`:
  `slots` allocates no PROMSXP; for every other SEXPTYPE it allocates no
  more objects than the control; and its bytes are at most the control's
  bytes minus the control's PROMSXP bytes. So a variant that trades
  promises for any other allocation fails. Otherwise §6.2's premise goes
  to the lead, and X2 adopts nothing.
- Deleted: the control branch.

### D5: frame reuse (X2, after D2 is decided)

- Variants: `none` (the simpler, named first) and `g3/x2-d5-recycle`
  (LIFO frame recycling under an ESCAPED bit, with the quarantine mode of
  §16: recycled frames poisoned and held back).
- Workloads: PLAIN and `binarytrees`; the quarantine mode on the rt slice.
- Rule: `recycle` is adopted if (a) its geomean instructions over PLAIN are
  at least 2% below `none`'s, or `none` allocates per call on a PLAIN row
  where `recycle` allocates nothing (§13: zero allocations per call), and
  (b) the quarantine mode is clean on the rt slice, and (c) `binarytrees`
  is not slower than `none` beyond the tie band. Otherwise `none`.
- If `recycle` is adopted, its quarantine CI step merges with it.
- Deleted: the losing branch.

### D6: link counting (X2; a control only)

- Variants: `deferred` (§4, the design) and the control `g3/x2-d6-eager`.
  `eager` is never adoptable.
- Workloads: every CALLS row.
- Rule: record the instruction delta per row. If `deferred` is slower than
  `eager` by more than 0.5% on any row, that row's cause is found and
  recorded before P1 starts.
- Deleted: the control branch.

### D9: dead roots (V1; the liveness-map variant on a branch)

- Variants: `lastuse` (dead VM slots cleared at last use, the default) and
  `g3/v1-d9-liveness` (liveness maps masking dead slots at each safepoint).
- Workloads: V1's dead-root finalizer test (§2.3, last bullet: a
  finalizer whose object's last reference is a dead VM slot), in both
  profiles; `fib` and CALLS.
- Rule: a variant whose finalizer does not run at the same `gc()` call as
  in GNU R 4.6.2 (the recorded output, exactly) is out. Of the rest, the
  lower geomean instructions over `fib` and CALLS wins; inside the tie
  band, `lastuse`.
- Deleted: the losing branch.
