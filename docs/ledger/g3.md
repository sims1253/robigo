# G3 ledger

The G3 runtime rebuild (`docs/g3.md`): every experiment and measurement,
kept or rejected, with what was tried, why, and the result. Sections are
dated and only appended, so parallel G3 pull requests merge cleanly.

## 2026-11-13: the C API census against packages built for R 4.6 (M0)

- why: `docs/g3.md` §8 and §14.2 (M0) require the census re-run against
  packages built for 4.6 before layout decisions rest on it. Today's
  `tests/capi/symbols.tsv` is R 4.5.0's.
- what: `scripts/capi-census.py scan` now writes one census per R
  version, chosen by the R on `PATH`: `symbols.tsv` stays 4.5's (the
  frozen runtime's `crates/robigo-capi` reads it), `symbols-4.6.tsv` is
  new. `coverage` and `symbols` take `--census 4.5|4.6` (default 4.5).
  Packages come from `.libPaths()`, first copy wins, and GNU R's own are
  those of priority base or recommended. The build recipe is in
  `tests/capi/README.md`. GNU R 4.6.2's tarball sha256 is
  `c297040f6392b1dac6e5c0eb398422cfdaedf540ae2205edb9ad0d10cb10ee00`
  (two CRAN mirrors and Arch's PKGBUILD agree).
- population: 4.5 had 24 GNU R + 79 CRAN shared libraries; 4.6 has
  24 GNU R (the same set: 11 libraries of 10 base packages, among them
  `tcltk.so` and grDevices' `cairo.so`, and 13 recommended) + 59 CRAN,
  from the workstation's `~/R/library`. The 4.5 census's CRAN library
  no longer exists on any machine we have, so the CRAN side cannot be
  matched package for package. The libR-side findings below do not
  depend on the population (exports and `tools:::funAPI()` of 4.5.0's
  and 4.6.2's own builds). The package-side findings were cross-checked
  against a second workstation's 4.6 user library (70 packages, 18 not
  in this one): no package there imports the promise accessors, `ATTRIB`,
  `Rf_allocSExp`, `Rf_findVarInFrame3`, `REFCNT`, `R_NamespaceRegistry`,
  `LEVELS`, `SET_OBJECT`, `UNSET_S4_OBJECT`, `R_BindingIsActive` or the
  environment accessors either. Population-dependent exceptions:
  matrixStats there imports `R_qsort_I`, `R_qsort_int`, `R_qsort_int_I`
  and `Rf_iPsort`. That workstation's 4.5-built library (139 shared
  libraries) shows who used the symbols that 4.6 hides or that packages dropped.
- result: 831 symbols, weight 5339 → **834 symbols, weight 4910**.
  libR exports 1204 (4.5.0 oracle image) → 1254 (4.6.2): 29 gone, 79
  new.

### Gone from libR in 4.6.2 (no package can import them)

From the 4.5 census (weight): `SETLENGTH` (5, incl. grid), `SET_TRUELENGTH`
(4), `SET_GROWABLE_BIT` (4), `TRUELENGTH` (1), `XTRUELENGTH` (1),
`IS_GROWABLE` (1), `SET_BODY`, `SET_CLOENV`, `SET_FORMALS` (1 each),
`Rf_memtrace_report` (1), and `mbcsValid`, `utf8Valid`, `utf8clen` (1
each, renamed to `Rf_mbcsValid`, `Rf_utf8Valid`, `Rf_utf8clen`, which
the 4.6 census has). Also gone, unused by both censuses: `EXTPTR_PTR`,
`EXTPTR_TAG`, `EXTPTR_PROT`, `SET_FRAME`, `STDVEC_DATAPTR`, `PRSEEN`,
`SET_PRSEEN`, `VECTOR_PTR`, `R_nchar`, `Rf_GetOption`,
`Rf_lazy_duplicate`, `R_shallow_duplicate_attr`, `Rf_NonNullStringMatch`,
`Rf_isValidStringF`, `dchdc_`, `ddfind`.

The replacements packages use instead: the resizable-vector API
`R_allocResizableVector` (5), `R_resizeVector` (5), `R_isResizable` (4),
`R_maxLength` (1), `R_duplicateAsResizable` (1), imported by data.table,
lobstr, rlang, vctrs and vroom. In 4.6, packages see a vector's
growable capacity only through these functions. They cannot read or
write `TRUELENGTH` at all, including the CHARSXP scratch data.table's
sort used to keep there. In the second workstation's 4.5-built library, `SET_TRUELENGTH`
was imported by data.table, qs, rlang, vctrs and vroom, `TRUELENGTH` by
data.table, `SETLENGTH` by base64enc, data.table, rlang, vctrs and
vroom, and `SET_GROWABLE_BIT` by data.table, rlang and vctrs.

### Still exported, imported by no 4.6-built package

The promise accessors `SET_PRVALUE` (5 in 4.5), `SET_PRCODE` (5),
`SET_PRENV` (5), `PRVALUE` (4), `PRENV` (3), `R_PromiseExpr` (3),
`Rf_allocSExp` (6) (R CMD check WARNINGs since 4.6.0); `ATTRIB` (7,
incl. Matrix); `Rf_findVarInFrame3` (4); `REFCNT` (2);
`R_NamespaceRegistry` (2); `LEVELS`, `SET_OBJECT`, `UNSET_S4_OBJECT`
(1 each); `R_BindingIsActive` (3, eapi). In the second workstation's 4.5-built library,
`SET_PRVALUE` was imported by bever, dplyr and magrittr, `PRVALUE` by
bever, dplyr, ellipsis and rlang, and `ATTRIB` by 19 packages, among
them data.table, dplyr, rlang and vctrs. The other 18 symbols that left
the census are still exported, mostly Rmath and utility functions
(`R_qsort*`, `Rf_lbeta`, `Rf_bessel_*`, `Rf_log1pexp`, `Rvprintf`,
`dqrqy_`, ...). The packages that used them are not in the 4.6
population.

`FRAME`, `HASHTAB`, `ENCLOS`, `ENVFLAGS`, `SET_ENCLOS`, `SET_HASHTAB`,
`SET_ENVFLAGS`, `NAMED`, `OBJECT`, `LEVELS` and `IS_S4_OBJECT` lost
their declarations in the installed headers (NEWS 4.6.0, "marked as
hidden"), but 4.6.2's `libR.so` still exports them: the environment
accessors' `attribute_hidden` is commented out (`memory.c:4684-4697`).
None of them is in the 4.6 census. In the 4.5 census only `LEVELS` was
(weight 1).
GNU R's own natives read them inline through `Defn.h`, so the census
cannot see those reads.

### New in 4.6 and imported (weight; all `eapi`)

- bindings: `R_GetBindingType` (4: dplyr, lobstr, rlang, vctrs),
  `R_MakeDelayedBinding` (4: dplyr, lobstr, magrittr, rlang),
  `R_MakeForcedBinding`, `R_MakeMissingBinding`,
  `R_ForcedBindingExpression`, `R_DelayedBindingExpression`,
  `R_DelayedBindingEnvironment` (2 each), `R_envSymbols` (2).
- dots: `R_DotsExist`, `R_DotsLength`, `R_DotsNames`, `R_DotsElt` (3
  each: backports, lobstr, rlang), `R_GetDotType`,
  `R_DotDelayedExpression`, `R_DotDelayedEnvironment`,
  `R_DotForcedExpression` (2 each). `R_findDotsEnv` is exported and
  unused.
- resizable vectors (above); `R_getRegisteredNamespace` (6),
  `R_mapAttrib` (5), `R_getAttribCount` (1), `R_altrep_class_name`,
  `R_altrep_class_package`, `DATAPTR_RW` (1 each), `Rf_eval_with_gd`
  (2), `GEcreateDD`, `GEfreeDD`, `R_GE_glyphFontNumVar`,
  `R_GE_glyphFontVarFormatted` (1 each). `Rf_strchr_const` (1) is new
  and not API.

Already API in 4.5 and now used by GNU R's own packages: `R_getVar`
(12 → 15; Matrix, grid, rpart and stats migrated), `R_ClosureFormals`,
`R_ClosureEnv`, `R_mkClosure` (stats), `R_ParentEnv` (methods).

### API status changes (`tools:::funAPI()`, 4.5.0 → 4.6.2)

Newly documented: `Rf_asBool` (api); `R_chk_memcpy`, `R_chk_memset`,
`optif9`, `R_new_custom_connection` and the hash-table API
(`R_mkhashtab`, `R_gethash`, `R_sethash`, `R_remhash`, `R_numhash`,
`R_typhash`, `R_maphash`, `R_clrhash`, `R_isHashtable`, `R_asHashtable`,
`R_HashtabSEXP`) (eapi); `R_checkActivity`, `R_runHandlers` (emb). No
longer listed: `R_Interactive`, `R_PolledEvents`, `R_wait_usec` (were
emb).

### Non-API symbols GNU R's own packages still import in 4.6.2

`R_PPStackTop` (8 base packages), `SET_ATTRIB` (stats), `DATAPTR`
(graphics), `R_findVarLocInFrame` and `R_GetVarLocMISSING` (methods).
Matrix stopped importing `ATTRIB` and `SET_ATTRIB`.

### Consequences for `docs/g3.md`

- §8's parenthetical is corrected: 4.6.2 no longer exports `SETLENGTH`
  or `SET_TRUELENGTH`, and no 4.6-built package imports `SET_PRVALUE`.
- For the lead, not changed here: §8 still requires that
  `TRUELENGTH`/`SET_TRUELENGTH` branch on the shared bit for shared
  CHARSXPs. In 4.6 only GNU R's own C can reach those calls (the
  `robigo-cbase` crutch, if D0 adopts it, and `inspect`'s `tl=`). No
  package can.
- §5's "R 4.6 hides `FRAME`, `HASHTAB`, `ENCLOS`, `ENVFLAGS` from
  installed headers" is accurate. They are still exported, but no
  package imports them.
- coverage of the capi corpus (built with the 4.5.0 toolchain; it does
  not compile against 4.6 headers): 4.5 census 427/831, 91.4% weighted;
  4.6 census 404/834, 88.1% weighted. Its heaviest uncovered 4.6
  symbols are the new APIs (`R_getRegisteredNamespace`,
  `R_allocResizableVector`, `R_mapAttrib`, `R_resizeVector`,
  `R_GetBindingType`).
