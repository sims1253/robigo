## 2026-11-13: B1, the builtin layer, the hook table and E6's three modules (`robigo-rtbuiltins`)

- What: m1-plan §B B1; docs/g3.md §2.4, §7, §10. New in
  `crates/robigo-rtbuiltins` (`#![forbid(unsafe_code)]`, still no `unsafe`):
  - `registry.rs`: the builtins as names.c rows (`R_FunTab`): name, the
    function, `code` (`PRIMVAL`), the eval column `XYZ` verbatim
    (`visibility()`, `is_internal()`, `evaluates_args()` decode it),
    arity (`check_arity` is `Rf_checkArityCall` with its two messages),
    `PPinfo` for deparse, and an `Effect` class for differential mode.
    A row's index is its `PRIMOFFSET`.
  - `kernel/`: arithmetic.c's, complex.c's, relop.c's and logic.c's element
    operations on plain data, no `Cx` (§10's one implementation; the VM's
    ops call the scalar functions, the builtins the vector loops).
  - The three E6 modules: `arith.rs` (`+ - * / ^ %% %/%`: `do_arith`,
    `R_binary`, `R_unary`, with `integer_binary`, `real_binary`,
    `complex_binary` and their attribute rules), `relop.rs` (`== != < <= >= >`),
    `logic.rs` (`& | !`); `paste.rs` (`paste`, `paste0`), `character.rs`
    (`nchar`); `envir.rs` (`assign`, `get`, `get0`, `exists`, `mget`) over
    N1a's entry points.
  - Their support: `attrib.rs` (attribute reads, and a builder that
    reproduces `installAttrib`/`copyMostAttrib`/`dimgets`/`classgets` in GNU
    R's order), `coerce.rs` (`coerceToString` over `robigo-text`), `text.rs`
    (`Seql`, `Scollate`, `translateChar`, `translateCharUTF8`), `util.rs`.
- In `robigo-rtcore` (additive, plus one replacement):
  - **The hook table** (`hooks.rs`): one `Hooks` value in the isolate,
    `eval`, `apply`, `dispatch`, `force` and `warning`, plain function
    pointers that `rt` installs with `cx.install_hooks`. **It replaces N1a's
    `cx.set_eval`** (the evaluator cell in the environments' state is gone;
    `cx.eval` reads the table, and N1a's tests install a table). Before `rt`
    installs one, `eval`, `apply`, `dispatch` and `force` raise "robigo: ...
    is not implemented yet"; `warning` collects into GNU R's deferred list
    (`R_Warnings`, at most `R_nwarnings` = 50, a traced precise root), which
    is `vwarningcall_dflt` with no handler and `warn = 0`, the only state
    possible before S1. S1 replaces the hook and keeps the list as its
    default path.
  - `cx.try_dispatch(&'static Generic, call, args, env, out)`: GNU R's
    pre-test (`DispatchGroup`: neither of the first two arguments is an
    object; `DispatchOrEval` with evaluated arguments: the first is not) runs
    inline in rtcore, so a non-object makes no indirect call. The result is
    `Dispatched::Done` or `Dispatched::Default(out)`, which hands the `Out`
    back to the builtin's own code. `Generic` is a static descriptor
    (name, group, `dropmissing`, `argsevald`) passed by reference.
  - `cx.error(msg)`, `cx.warning(msg)`: GNU R's `error()`/`warning()`,
    reported against the context's call once C2 provides it (no call until
    then; N1a's `env_error` now calls `cx.error`): one place to change.
    `cx.warning_call(call, msg)` is `warningcall`.
  - `Locale` in `Options` and the isolate (`cx.locale()`,
    `cx.set_locale`): a UTF-8 `LC_CTYPE` or C, and whether `LC_COLLATE` is
    C. Default `C.UTF-8`, the oracle's.
  - `FreshVec::{set_attrib, set_object, set_s4}`, `cx.cons_tagged`,
    `Ref::as_ints` (`INTEGER_RO` on logical or integer storage),
    `cx.exit_call` (the call a pending error reports),
    `cx.collected_warnings`/`clear_warnings`/`collect_warning`.
- `robigo-text`: `utf8toucs`, `utf8toucs32`, `is_high_surrogate`,
  `mbrtowc_utf8` and `ri18n_wcwidth` are public (`nchar`'s width and
  counts).
- Decisions, each where g3.md or the plan left a choice:
  - **No `op` in the builtin signature** (§2.4's `fn(cx, call, args, env,
    out)`): a `do_*` that serves several names is one Rust function per
    name, generic over its names.c `code` (`do_arith::<PLUSOP>`). What GNU R
    reads from `op` is static: the registry row, and for dispatch a
    `&'static Generic`.
  - **Effect classes** (§10 differential mode): `Pure` (result, warnings and
    errors depend on the argument values and the locale), `Env` (reads or
    changes bindings: active bindings and promises run R code), `Calls`,
    `Rng`, `External`. `Builtin::same_process_ok(cx, args)` allows
    same-process dual execution only for `Pure` rows on arguments none of
    which (nor any element of a list argument) is an object or a package
    ALTREP vector: dispatch and `paste`'s `as.character` are the callbacks.
  - **NaN payloads** (NA against NaN is observable in R): `kernel/nan.rs`
    gives `+ - * /` x86-64 SSE's result for every NaN outcome in safe code:
    the destination operand's payload when both are NaN, the quieted NaN
    operand's, or the "indefinite" `0xfff8000000000000` for an invalid
    operation (LLVM folds `Inf - Inf` on constants to the positive default
    NaN, and may commute `+` and `*`: the repair runs only for NaN results).
    Which operand GNU R's compiled loops make the destination is the old
    runtime's measured rule (`x_is_dest`), confirmed on 4.6.2 by the
    oracle cases; flipping one branch of it fails 4 of them.
  - **Complex** `* / ^`: the old runtime's ports of libgcc's
    `__muldc3`/`__divdc3` and glibc's `clog`/`cexp` (gcc 14's operand
    orders), moved to safe code over `kernel/nan.rs` (the old one used
    inline assembly). 4.6.2 makes an integer or logical NA complex as
    `NA + 0i`, not NA in both parts (`NA_TO_COMPLEX_NA` is not defined).
  - **Attributes**: a result's attribute list is always new cells (GNU R's
    `installAttrib` writes cells in place, so sharing a list would leak
    writes), in GNU R's order: `attributes(1:2 + structure(1:2, a=3, c=4))`
    after `x`'s `b`, `names`, `a` is `a c b names` (the oracle checks the
    order; swapping `copyMostAttrib`'s two calls fails 5 cases). GNU R's
    `getAttrib` marks the value not mutable; the reads here do not, since no
    value goes back to R code (the builder counts the reference it adds).
  - **Not reused**: GNU R writes the result into an argument with no
    references (`R_allocOrReuseVector`, `NO_REFERENCES` in `-x`). That
    needs R1b's `cx.unique_mut`; until then every result is fresh, which
    shows only in `.Internal(inspect())` addresses and `tracemem`.
  - **Warnings around the computation in GNU R's order**: the plan of
    `R_binary` (types, lengths, attributes) is plain data computed first, so
    the array-of-length-1 and recycling warnings come before, the overflow
    and `myfmod` precision warnings after the `&Cx` computation, and the
    `tspgets`/`classgets` errors last, as in GNU R. `R_pow`'s `(-Inf)^y`
    path warns through `myfmod` too (found by the oracle).
  - **`paste`** builds each element in one reused buffer and interns once
    (§7). GNU R stores each coerced element back into the argument list
    (`SET_VECTOR_ELT(x, j, ...)`); here they are held in roots, so a list a
    caller passes to `.Internal(paste(...))` is never changed.
  - **`!NULL`** is GNU R's "invalid argument type", not `logical(0)`:
    `XLENGTH(R_NilValue)` reads CAR(R_NilValue) as a length (found by the
    oracle; the code says why).
  - **Not implemented yet**, each an error that says so (AGENTS rule 6),
    found by a case or the C: ordering strings under ICU (the oracle's
    `C.UTF-8` collates with ICU's root collator: `"a" < "B"` is TRUE; C
    collation is implemented and checked); comparing a call (deparse, B3);
    comparing a list (`coerceVectorList`; `1 == list(1)` is TRUE in GNU R,
    the one allowlisted case); complex to character (`formatComplex`, B3);
    lists and calls in `paste` (deparse); package ALTREP arguments (R1b's
    `cx.xlength`); a frame number as `envir` (`R_sysframe`, C2); S4 objects
    as environments; `_R_COMPARE_LANG_OBJECTS` other than its default; the
    condition class of `get`'s missing-argument error (S1; the message is
    GNU R's). Number formatting uses the default `options()` (`scipen`):
    options are B2b's.
- Proof (WSL2 workstation, Ryzen 9 5900X, 24 threads, rustc 1.100.0; GNU R
  4.6.2 from the oracle image via `~/.cache/robigo-oracle/4.6.2/bin/Rscript`,
  never the host's 4.6.1):
  - `tests/oracle.rs`: 4648 cases recorded by `tests/oracle/record.sh`
    (arithmetic 2830, comparison 1338, logic 377, paste 50, nchar 53), each
    replayed through the registry with the same inputs and call; value,
    warnings in order with the call each reports (the builtin's own or the
    context's), and error compared, doubles bit for bit and strings byte
    for byte with their encoding mark. All match but `1 == list(1)`, which
    the test requires to be robigo's not-implemented error (a list of such
    cases per file, so a new gap fails too). Inputs cover NULL, the four
    number types, NA against NaN in every loop shape, recycling, names,
    matrices with dimnames, 1-d arrays, time series with and without a
    class, classes without methods, latin1/UTF-8/native/bytes strings,
    every argument check.
  - The same cases again with a hook table that runs a full collection at
    every warning and dispatch a builtin makes (466 collections, under
    `ROBIGO_GCTORTURE=1`'s poisoning in CI): all match.
  - `tests/envir.rs`: the 79 steps of `tests/oracle/envir.R` (assign with
    and without inherits, the global environment, modes and the type
    classes, promises, `mget`'s `ifnotfound` and modes, locked bindings and
    environments, the empty environment, every message).
  - `tests/hooks.rs`: dispatch only for objects (and `nchar` on its first
    argument), the not-implemented default without a dispatcher,
    `paste`'s `as.character` through `eval`, `get`/`mget` forcing promises
    through `force` and `exists` not, `mget` calling an `ifnotfound`
    function, warnings collected with their call and capped at 50, a
    warning hook that errors ending the builtin, the registry's columns,
    `same_process_ok`.
  - `scripts/rt-ci.py` (release tests, then `ROBIGO_GCTORTURE=1`): pass.
    `scripts/lint.sh`: clean.
- **E6, the hook table's cost**: instructions per iteration, callgrind,
  N = 10^5 against 2N, the ignored test `tests/hook_cost.rs`
  (`ROBIGO_HOOK_COST=mode:N`), release, at `ae6318b3`. The stand-ins read
  their arguments and write a value (a stand-in that ignored one let LLVM
  drop it from the direct call only, which no real evaluator allows). Each
  iteration includes its root scope and `Out`.

  | mode | through the table | called by name | inlined |
  |---|---|---|---|
  | `cx.eval(expr, env, out)` | 91 | 88 | 81 |
  | `lapply` over 16 elements, `cx.apply` each | 4039.56 | 3959.56 | |
  | `[`'s dispatch on an object (no method) | 216 | 206 | |
  | `[`'s dispatch on a non-object (pre-test only) | 191 | | |

  So a call through the table costs 3 instructions more than by name,
  10 more than inlined; `lapply` 5 per element; a dispatch that reaches the
  dispatcher 10, and none reaches it for a non-object. (With stand-ins
  that ignored their arguments, `Generic` passed by value, five words, cost
  22 against 16 by `&'static` reference: hence the reference.) Until V1 there is no
  evaluator, `lapply` or `[` to measure: V1 re-runs the four rows with the
  VM's.
