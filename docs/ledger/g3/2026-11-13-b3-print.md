## 2026-11-13: B3's rt glue: printing, deparse, cat and the isolate's console

- What: m1-plan §B B3, second bullet (the `robigo-text` half is on main);
  docs/g3.md §7, §11 (console). Built on L1 (`g3/l1-loader`, PR #656),
  replacing its three stand-ins: the attribute-free-vector printing, the
  one-line `deparse1s` of error calls and the console threaded through
  `repl::Io`. New in `robigo-rt`: `deparse.rs` (deparse.c), `print.rs`
  rewritten (print.c, printvector.c), `builtin.rs` (`cat`, `list`,
  `invisible`, `stdout()`, `stderr()`, `.Internal(deparse())`); in
  `robigo-rtcore`: `console.rs`; in `robigo-rtbuiltins`: `is.rs` (coerce.c
  `do_is`), the fixed environments (envir.c), `registry::pp_info` (names.c's
  PPinfo for every primitive) and `StringFromComplex`; in `robigo-text`:
  `format_complex`, `encode_complex`, `encode_raw`. Base: `g3/l1-loader` at
  `a14d19de`.
- Decisions, each where g3.md, the plan or the foreman left a choice:
  - **The console is a field of the isolate** (§11): `Console` holds the
    output and error streams; `Cx::rprintf`/`reprintf` are GNU R's
    `Rprintf`/`REprintf`, what A1's exports call; `Cx::replace_console`
    lets the binary, tests and embedders choose them; `Console::capture`
    writes into buffers. `REprintf` flushes the output first, as L1's `Io`
    did. Printing now writes as it goes (L1 buffered a value's text and
    wrote it after the top level returned): output before an error inside a
    print is GNU R's.
  - **Deparse runs under `&Cx` and returns lines.** It allocates nothing on
    the heap, so the error report (`error_text`, `&Cx`) uses the real
    `deparse1s`. Where GNU R's deparse runs code it does not here: a forced
    promise deparses as its value, an unforced one says "not implemented"
    (GNU R forces it); `SYMVALUE(op)` of a call is read from base without
    forcing (GNU R forces a lazy base binding only to test for the closures
    `::`/`:::`, which are primitives in 4.6.2, so the text cannot change).
    S4 objects, srcrefs and the `hexNumeric`/`digits17`/`S_compatible`
    number encodings say "not implemented".
  - **`PPINFO(SYMVALUE(op))` for primitives the subset does not bind.**
    GNU R binds every names.c primitive in base; robigo-rt's base binds the
    subset's. Deparse reads an unbound names.c primitive as bound, with
    names.c's PPinfo (`registry::pp_info`, one table; a test ties B1's rows
    to it): without it `~`, `:::` and `@` printed as function calls. A
    primitive's name comes from its object (`prims::prim_name`).
  - **`<bytecode>` lines.** GNU R prints `<bytecode: %p>` for a closure
    whose body is byte code: every closure of base (byte-compiled when base
    is built), and a closure GNU R's JIT has compiled (`R_CheckJIT`: a
    top-level closure on its second call when small, ...). robigo-rt prints
    it for closures of the base namespace; the JIT's decision is V2's port
    of `R_CheckJIT`, and until then other closures print as not compiled,
    which is GNU R's output for a closure called fewer than twice. The
    address in the line is the body's (GNU R's varies from run to run too).
  - **Printing a function or an object at the top level goes through
    `print()`** (`PrintObject`: `print(x)` evaluated in a new environment,
    print.default's arguments forwarded), which needs `UseMethod` (S1):
    until then it says "the primitive 'UseMethod' is not implemented yet".
    Inside a list a closure prints through `PrintValueRec`, as in GNU R.
    `isMethodsDispatchOn()` is false (no `methods`).
  - **Not ported, each saying so where GNU R would print:** matrices and
    arrays (`printMatrix`, `printArray`: printarray.c), array-like lists,
    primitives (`PrintSpecial` reads `.ArgsEnv`, which the subset does not
    bind), the expansion of a compact `row.names` attribute. `options()`
    does not exist (B2b), so `PrintInit` takes GNU R's defaults.
  - **Outside print/deparse/cat, the minimum that makes them reachable
    from R code**, each a whole port of its C function: `list`
    (builtin.c `do_makelist`, the file of `do_cat`), `invisible` (print.c),
    the `is.*` family (coerce.c `do_is`: `cat`'s body calls
    `is.character`), `globalenv()`/`baseenv()`/`emptyenv()` (envir.c, to
    print environments), `stdout()`/`stderr()` (connections.c: the three
    standard connections are all robigo-rt has, so `getConnection` of any
    other number is GNU R's "invalid connection"; `cat(file = stderr())`
    writes to the console's error stream, as GNU R's sink to connection 2
    does). B2a no longer needs to port `do_is` and `list`.
  - **Coercion of a list or call to character** (`coerceVectorList`'s
    `deparse1line_ex`) still says "not implemented": robigo-rtbuiltins sits
    below robigo-rt's deparse and needs a hook for it (follow-up).
    Complex numbers now coerce (`StringFromComplex`).
