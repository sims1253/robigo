## 2026-11-13: C1a, arguments as slots: binding, matching plans, promises, binding kinds, frame cleanup (`robigo-rt`, `robigo-rtcore`, `robigo-heap`)

- What: the argument half of C1 (m1-plan §B C1; docs/g3.md §4, §6.2-6.4),
  replacing V1a's stand-in (a PROMSXP and a cons per argument, D4's
  control). New: `robigo-rt`'s `args.rs` (`args::bind`: actuals, `matchArgs`'
  three passes, memoized plans, the frame's slot states, the `...` list, the
  lazy `promargs` filler, `ROBIGO_MATERIALIZE=1`), `robigo-rtcore`'s
  `env/promise.rs` (`forcePromise` on a PROMSXP and in place on an argument
  slot, the pending-force stack, `R_GetBindingType`, `R_CleanupEnvir` on a
  slot frame, the per-call argument-list residues), `.Internal(getBindingType())`
  in B1's registry, GNU R's `PROMISE_TAG` in the heap (the PROMSXP trace
  arm skips an unboxed PRVALUE). Base: main `4ed839e0` (V1a #652).
- Not in this PR (C1b, next): the code object's own layout (both profile
  variants, weak cache words, JIT entry and state), the BODY/FORMALS/CLOENV
  and `duplicate` invalidation rules (§6.1, §9.3), the deferred link-count
  protocol (eval.c:997-1016: the bodies of V1b's `links.rs`, agreed with
  V1b, which ports `applydefine`/`evalseq` in `assign.rs`), and a producer
  of tagged promises (a forced slot holding an unboxed value: it pays only
  once the VM returns unboxed values from a code object, P1's work).
- How an argument is bound (§6.2), per profile:

  | actual | `Eval` | `Bc` |
  |---|---|---|
  | an expression | delayed slot, the caller's environment | delayed; a constant is a value slot, marked not mutable (`PUSHCONSTARG`) |
  | empty, or nothing matched | the default (delayed in the frame, MISSING 2) or R_MissingArg (MISSING 1) | same |
  | an element `v` of the caller's `...` | delayed slot with expression `v` (GNU R's double promise `mkPROMISE(v, rho)`, with no object made) | same (DODOTS) |
  | an element of a promise list (C, the `apply` hook) | bound as that object | same |

  The `...` formal gets a DOTSXP built from the call site directly (one cons
  and one promise per element, GNU R's; no intermediate argument list).
- Decisions, each where g3.md left a choice:
  - **Forcing in place.** The VM's variable read finds a delayed slot
    (`RawBinding::Thunk(ArgLoc)`) and forces it in place
    (`Cx::force_arg`): PRSEEN in the slot's meta bits, GNU R's two
    messages against `R_GlobalContext->call`, the value written back as a
    forced slot, the caller's environment released. A forced slot reads as
    its value (`RawBinding::Forced`), off the slow path. `findFun3` forces an
    argument through a new hook (`Hooks::force_arg`: `eval`'s count and depth
    for the promise, then the force), as GNU R's `eval(vl, rho)` does.
  - **The pending-force stack** (`R_PendingPromises`): if a slot is
    materialized while its own expression runs (C's `findVarInFrame`,
    `get`), GNU R's binding held that promise all along, so the force
    completes the promise object, not the slot. An exit through a force
    marks the slot or promise PRSEEN 2 as the `Err` passes, which is
    `R_restore_globals`' marking (every exit that passes a force in Rust
    passes its GNU R frame).
  - **Reference counts per §6.3 cell are GNU R's, including the argument
    list GNU R keeps.** GNU R's supplied argument is a promise held by both
    the call's argument list and the binding; `unpromiseArgs` clears it at
    the call's end, and a promise that loses its last reference keeps its
    children's counts (they leak). A slot frame has no list, so the counts
    that list implies are kept where they differ from the slot's: while the
    call runs (a `CALL_LIVE` header bit on the frame), an argument that is
    overwritten or removed leaves a *residue* (its value, expression and
    environment, counted) that the call's end clears, and a materialized
    argument's promise gets the list's reference (a *ghost*). After the call,
    or for a default (no list holds it), the promise that loses its binding
    is dead and its counts leak, exactly as GNU R's: oracle-verified, a
    forced default that is reassigned leaves its value at REF 2, and an
    unforced default that is reassigned leaks its frame's own count, so the
    frame is never cleaned (a supplied argument then keeps REF 2). An
    argument that loses its binding during its own evaluation still
    completes (its value counted, its environment released). An exit that
    jumps past the call skips the cleanup, and the residues leak, as GNU R's
    abandoned argument list does.
  - **One caller word per frame.** The caller's environment is counted once
    per frame while any delayed slot needs it (N1b's word), against GNU R's
    once per unforced promise. The count is zero exactly when GNU R's is,
    so `R_CleanupEnvir`'s decisions agree; only its magnitude while several
    arguments are unforced differs (an `inspect` of the caller from the
    callee would show it; T2's report adds the delayed slots).
  - **`R_CleanupEnvir` on slots.** The walk is GNU R's (listing order, stop
    at the first shared binding cell, unboxed values left, `countCycleRefs`
    on promises, closures and the frame itself); a frame without a
    cell-backed slot cannot stop early, so it is walked in slot order with
    no allocation. A default's delayed slot counts no edge to the frame, so
    it needs no cycle discount (GNU R counts and discounts it).
  - **Match plans** are memoized per call site (`Op::Call`'s `c`, a
    64-byte entry in a RAWSXP of plain data in the caller's code object)
    when the call has no `...`, keyed on the callee code object's stamp: a
    per-isolate counter that never repeats (docs/g3.md §9.3: never an
    address). A plan holds which actual each formal gets, the `...` list's
    actuals and the partial matches, which it replays as warnings under
    `options(warnPartialMatchArgs = TRUE)` (`Cx::warn_partial_match_args`,
    the isolate's `R_warn_partial_match_args`; B2's `options()` sets it).
    Errors are not memoized.
  - **`promargs`** stays lazy (C2's interface): its filler builds GNU R's
    argument list from the frame, each element the promise the slot
    materializes into (or its residue's, or the `...` list's), with cells
    that count nothing (the ghosts carry the list's references).
  - **`ROBIGO_MATERIALIZE=1`** materializes every argument slot at call
    entry: GNU R's representation through the same transitions. The C1
    tests run every case in both modes; `scripts/rt-ci.py` runs robigo-rt's
    whole suite under it. T2 completes the mode (observers, comparison).
  - **`ENSURE_NAMEDMAX` does nothing under reference counting**
    (`Defn.h:337-340`): `eval`'s self-evaluating case, `forcePromise`'s
    value and `mkPROMISE`'s code no longer set REFCNT to the maximum (V1a
    did); bcEval's `LDCONST` marks a constant that is not a simple scalar
    (`MARK_NOT_MUTABLE`), so the `Bc` profile still does.
