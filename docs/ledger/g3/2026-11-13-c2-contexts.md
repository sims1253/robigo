## 2026-11-13: C2, contexts, the pending-exit stack and unwinding (`robigo-rtcore`, `robigo-heap`)

- What: GNU R's context chain in `robigo-rtcore` (docs/g3.md §6.5, §12's
  rows on `on.exit`, `cend`, depth and C stack): `RCNTXT` as a `#[repr(C)]`
  record that robigo's `include/Defn.h` declares, exits that travel the
  chain with GNU R's `R_jumpctxt`/`R_run_onexits`/`endcontext` semantics,
  the pending-exit stack's parking, superseding and continuations, the
  native entries (`.Call`, six-argument callbacks, `R_ToplevelExec`,
  `R_UnwindProtect`/`R_ContinueUnwind`, `R_ExecWithCleanup`), the frame
  walks (`sys.*`, `parent.frame`, `nargs`, `on.exit`, `sys.on.exit`), and
  GNU R's limits with its messages. In the heap: the trampolines set the
  jump record they are given instead of keeping a list; both C
  thread-locals of the shim are gone (L6); the six-argument entries open a
  C segment. Base: `g3/r1a-cx-api` (`afa730f7`, R1a on H2). Nothing
  depends on the crate yet, so the `robigo` binary and the perf gate are
  unchanged.
- Decisions, each where g3.md left a choice:
  - **Exits travel in legs.** GNU R's `R_jumpctxt` is split where the
    Rust frames are: a leg starts where GNU R would call `R_jumpctxt` (the
    first record owner the `Err` reaches, or an export wrapper before it
    jumps, or after an intermediate stop's exit code), computes the stop
    (`first_jump_target`: the first record with `on.exit` code or of type
    `CTXT_UNWIND`, else the target) and runs the `cend` of every record
    above it, innermost first, while `R_GlobalContext` is still the
    innermost record and every frame is still there, as `R_run_onexits`
    does before the `LONGJMP`. Records above the stop are then inert and
    their owners pop them as the `Err` passes; at the stop, GNU R's globals
    are restored (`R_restore_globals`) and the owner lands the exit or runs
    its exit code. This holds for records in Rust frames too, so a `cend`
    in a Rust-pushed record also runs before any frame unwinds. The leg's
    stop is a field of the pending record (`ExitRecord::stop`).
  - **Records live in the frames that push them**, at stable addresses:
    a Rust driver's local (`Cx::function_context`, `with_context`, the
    native entries; closure-scoped, unlinked on every path including a
    panic) or a C frame (`Cx::begin_foreign`/`end_foreign`, GNU R's
    `begincontext`/`endcontext` for C compiled against `Defn.h`). Rust
    reaches a record only through a raw pointer (`Rec`), never a
    reference, because C and the collector read and write records too.
  - **One chain, and it is the list of jump targets.** A native entry's
    record is flagged `LANDING`; the heap's trampoline (`robigo_heap_try_*`)
    `sigsetjmp`s its `cjmpbuf`; an export wrapper calls
    `Cx::prepare_jump` (the leg's walk, then `R_GlobalContext` = the
    innermost landing record) and, once its capability has ended,
    `Landing::jump`. The heap keeps no context list: `robigo_heap_top`
    (the shim's C thread-local) and `robigo_heap_try_depth` are gone, and
    the `.Call` switch's `_Thread_local` is `Core::call65_plain`, read when
    the core is made.
  - **Hidden records** for native entries GNU R makes no context for (a
    package ALTREP method, a `cend` called during a walk): inert in every
    walk (type `CTXT_CCODE`, no environment, no `cend`), skipped by every
    R-level walk (`Cx::global_context`, `CtxRef::next`), so `sys.*`,
    `parent.frame` and GNU R's `error()` see GNU R's chain. `Cx::error`
    skips hidden records, then one `CTXT_BUILTIN` record, as `Rf_error`
    does.
  - **Parking moves the exit into the record** whose exit code runs
    (GNU R's `jumptarget`/`jumpmask` plus robigo's parked kind, value,
    condition and call in the record's extension, traced with it), so the
    pending-exit stack holds only exits that are travelling. An exit out
    of the exit code supersedes the parked one by dropping it; a `return`
    in `on.exit` code lands in its own record and cancels the error being
    unwound, as in GNU R. An `R_UnwindProtect` continuation owns its exit:
    robigo's `R_MakeUnwindCont` is the pairlist `(value, condition, call,
    info)` with `info` a 16-byte raw vector (kind, mask, target), from the
    jump to its record until `R_ContinueUnwind` pushes it back.
  - **An exit recorded with target 0 targets `R_ToplevelContext` as it
    is then** (`Cx::exit`, and R1a's `error_call`, which recorded 0), so
    an error inside `R_ToplevelExec` lands at its record.
  - **`R_GlobalEnv` and `R_BaseEnv` are parameters** of the APIs that need
    them (`sys_parent`, the native entries' records), not C2 state:
    environments are N1's.
  - **`on.exit` code is evaluated by the record's owner**
    (`OnExitEval`, a `&mut dyn FnMut(&mut Cx, expr, env)`): the evaluator
    is V1's and sits above this crate (B1's hook table can supply it).
  - **`promargs` is lazy** (`Promargs::Lazy { nargs, fill, data }`):
    `nargs()` counts without making it, `Cx::materialize_promargs` calls
    C1's filler once, and `Cx::set_eager_promargs` makes records fill it
    when pushed (compiled C that reads the field is loaded).
  - **The raw layer's function record** (`Cx::function_context_raw`,
    objects already rooted in the caller's slots, no root bound), next to
    the safe one: the VM's call path. The body writes the caller's `Out`
    directly; it is rewritten only when a landed `return` leaves another
    value.
  - **Layout**: GNU R 4.6.2's fields in its order (byte-code fields kept
    for V1, `cstacktop`/`vmax`/`gcenabled` for A1 and the heap), then
    robigo's 72-byte extension: 504 bytes on x86-64 (GNU R's 432). The
    heap's `JmpBuf` is the platform's `sigjmp_buf` (200 bytes on Linux
    x86-64; per-platform constants in `unwind.rs` and `shim.c`,
    `_Static_assert`ed in C). `src/context.c` exports C's size, alignment
    and every offset; `check_layout` compares them with Rust's when an
    isolate is made and in the tests (under Miri the Rust table stands in).
  - **Limits**: `Cx::eval_depth_enter`/`leave` (GNU R's
    `INCREMENT_EVAL_DEPTH`, "evaluation nested too deeply: infinite
    recursion / options(expressions=)?", `R_Expressions_keep + 500` while
    handled), `check_c_stack` (`R_CheckStack`, the thread's stack at 95%,
    "C stack usage  N is too close to the limit", the limit divided by 0.95
    while handled, back to the whole stack as `R_SignalCStackOverflow`
    does, and restored at the next stop), `check_value_stack`
    (robigo's value stack reports GNU R's "node stack overflow" against the
    current call), `check_user_interrupt` (an `Interrupt` exit to the top
    level; suspended interrupts wait). The condition objects of these
    errors (`expressionStackOverflowError`, ...) are S1's.

- Proof:
  - `cargo test -p robigo-rtcore`: `tests/contexts.rs` (24, pure Rust, a
    small test language evaluated over the real API: `fn`, `catch` as an
    exiting handler targeting its record as S1's will, `stop`, `onexit`,
    `return`, `gc`, ...) and `tests/native.rs` (11, C stand-ins for package
    code in `src/test_routines.c`, reaching the API through hooks that jump
    as export wrappers do). E8's cases: `e8_an_on_exit_that_catches_its_own_error_returns_the_outer_condition`,
    `e8_an_unwind_protect_cleanup_that_catches_resumes_the_original_continuation`
    (and cpp11's shape, `a_continuation_owns_its_exit_until_it_is_resumed`:
    the cleanup `longjmp`s to the routine, which resumes the unwind
    later), `e8_a_c_contexts_cend_runs_before_the_jump` (the `cend` sees
    its frame and its record still there). GNU R's rules: a `return` in
    `on.exit` supersedes the error; an error in the first `on.exit`
    expression leaves after the rest ran; `add`/`after`; innermost-first
    across closures; a `cend` that raises supersedes and the outer `cend`
    runs once, and the superseding exit's leg decides `R_Visible`;
    `R_ExecWithCleanup` runs its cleanup once, once (in the
    walk) and twice (when it fails) as GNU R does; `R_ToplevelExec` lands
    errors and restores `R_ToplevelContext`; `error()` reports the
    closure's call below a `.Call` record; hidden records are invisible;
    `findcontext`/`R_JumpToContext` messages; loops land `break`/`next`;
    the frame walks against a three-deep chain (`sys.call`, `sys.frame`,
    `sys.parent`, `parent.frame`, `nargs` with lazy `promargs`); limits
    and their restoration at a stop; the layout. `tests/heap.rs` adds
    `a_six_argument_entrys_locals_are_roots`,
    `six_argument_entry_frames_keep_nothing` and
    `jmpbuf_is_the_c_librarys`; `trampolines_and_jump` uses jump records.
  - Sensitivity, by breaking the code: records not traced, or one of
    `returnValue`, the parked value or `conexit` not traced: the roots test
    fails (a freed slot reads as another object; `conexit` segfaults);
    no leg walk before an export's jump: the two `cend` tests fail; an exit
    out of `on.exit` code not superseding: the `return`-in-`on.exit` test
    fails; a `cend`'s exit not superseding: its test fails; a continuation
    not keeping its exit: both `R_UnwindProtect` tests fail. The
    six-argument stub without its segment top: the locals test fails; with
    the top 4 KiB too high: the frames test fails.
  - `scripts/rt-ci.py` (release, then `ROBIGO_GCTORTURE=1`): all pass.
    Miri (`cargo +nightly-2026-11-02 miri test -p robigo-rtcore`): the 22
    pure context tests (the roots test collects, so it is not under Miri)
    and R1a's, no undefined behaviour. `cargo clippy --all-targets -D
    warnings` on both crates: clean.
- For other packages:
  - A1: export wrappers call `prepare_jump` inside their callback and
    `Landing::jump` after it, with their C segment reopened.
    `R_UnwindProtect`'s export calls the cleanup from its own frame
    (`Cx::unwind_protect` returns whether it jumped, then
    `continue_unwind`); a cleanup that `longjmp`s past the export (cpp11)
    leaves the heap's open segment top as the export set it, so the export
    must call the cleanup with its caller's segment reopened (the export's
    own Rust frame is then inside that segment: scanned, pins only), or the
    heap must learn to repair a stale top at the next export entry; g3.md
    does not settle which. `begincontext`/`endcontext` exports map to
    `begin_foreign`/`end_foreign`; the protect and `R_alloc` stacks add
    their save and restore to `Cx::begin`/`restore_globals`.
  - C1: closure application through `function_context(_raw)` with the
    `promargs` filler; `endcontext`'s `INCREMENT_LINKS` of the return value
    is done here. V1: loops through `with_context`, `eval_depth_enter` and
    `check_c_stack` at each `eval`, `R_Srcref` around calls, its VM state in
    the byte-code fields. S1: condition objects for the limit errors, the
    handler stack's entries (`R_UnwindHandlerStack` is ported and clears
    them), `R_FixupExitingHandlerResult` (its token does not exist before
    S1), `signalInterrupt` before the interrupt exit. B2: the `sys.*`
    builtins shape the walks' results (`getCallWithSrcref`, `duplicate` in
    `sys.function`, `MARK_NOT_MUTABLE` in `returnValue`).
  - Not supported: `on.exit` code in a record C pushed (`end_foreign`
    panics with a message), and C that `SETJMP`s a record it pushed itself
    (`begin_foreign`'s contract: only native entries land jumps). Not
    done: `R_run_onexits(NULL)` at `R_CleanUp`.
