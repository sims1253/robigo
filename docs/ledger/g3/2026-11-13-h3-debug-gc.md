## 2026-11-13: H2 step 6 and H3, pins as the only order and the debug collectors

- What: m1-plan §B H2 step 6 and H3 in `robigo-heap`, after lead decision
  L8 (docs/g3.md §1, §3 item 6, PR #655) adopted pins with export rooting
  and allocation parity.

### H2 step 6: pins are the only order

- `Core::mark_rest`: precise roots, weak references and finalizers decided
  on them alone, then the C segments as pins, then the CHARSXP prune. The
  `ROBIGO_GC_PIN_ONLY` switch and its `else` (C words as strong roots) are
  gone. The weak pass is three steps now (`weak_fixpoint`,
  `classify_weak_refs`, `keep_weak_fields`), so that the pin report can
  scan between the decision and the keeping; their marks are those of the
  one pass (marking is monotone).
- Experiment A's probes at the heap's level (the export-level cases are
  A1's): `pin_extbuf_a_key_only_a_c_local_names_is_finalized_while_named`
  (a key only a C local names is decided dead in the collection its own
  call makes, as GNU R decides it, and its memory stays valid while named;
  after the call nothing pins it), and
  `pin_premature_an_export_that_roots_its_argument_finalizes_nothing_early`
  (an export that roots its argument precisely, §3 item 6, finalizes
  nothing early; the same export without that rooting decides the argument
  dead during the call, experiment A's `Rf_cons`/`Rf_lang2`/`Rf_setAttrib`
  failure).
- The frame-hygiene tests (`native_call_frames_keep_nothing`, the
  six-argument and export ones) checked finalization, which pins no longer
  tie to C words; they now check memory: a dead object that only a stale
  word would pin is freed.

### H3: `ROBIGO_GC_MOVE=1`

- `gc/mover.rs`. A collection marks as always; then, before the sweep:
  1. **evacuate**: every marked object that may move is copied (a small one
     into a fresh slot of its class, a large one into a chunk of its own),
     the copy marked, the old copy given a forwarding header (type `0xFE`,
     the new address at +8);
  2. **forward** every edge through H2's `Visitor`: the embedder's roots
     (`Trace`, so the value stack, contexts, globals, the environments'
     state and the per-isolate symbol cells follow without code of their
     own), the precious set, the weak-reference lists and every weak
     reference's elements, the finalizer queue, the barrier's log, the
     CHARSXP cache, and every live object's fields (`trace_fields`, slot
     frames' arms included), immortal ones too;
  3. **retire**: an old small copy is poisoned (`POISON_TYPE` 0xDB, flags
     0, `0xDB` bytes) and freed by the sweep; an old large chunk leaves the
     heap's list `mprotect`ed to no access, until the next collection gives
     it back.
- What does not move: immortal objects, and every object ever handed to C,
  marked by a sticky header bit (`extra::SEEN_BY_C`, bit 4 of the `extra`
  word). The segment scan sets it on every object a C word pins, and
  robigo-rtcore's `.Call` entry sets it on its arguments (under `GC_MOVE`
  only: one load when off). For the six-argument entry, only the caller
  knows which words are objects; A1 and the ALTREP code mark theirs.
- The CHARSXP cache is forwarded in place, not rehashed: a slot's position
  comes from the content hash in the CHARSXP's header, which a move does
  not change. Weak cache words: there are none yet (V1a's code objects are
  plain VECSXPs); V1 forwards or zeroes them when it adds them.
- The heap sizes do not change: a copy is the object (its cells stay
  counted once), and a poisoned old copy counts none when the sweep frees
  it. `GcStats::moved` counts the moves; the `ROBIGO_GC_STATS` report
  prints them.
- The poison holds until the old slot is reused (the sweep of the same
  collection frees it). That is where a stale use lands in practice: right
  after the safepoint.
- Proof, the plan's: `a_stale_sexp_in_a_rust_local_reads_poison` (heap) and
  `a_raw_sexp_kept_across_a_collection_reads_poison_under_gc_move`
  (rtcore, through `Cx::collect`). For large objects,
  `a_large_object_moves_and_its_old_chunk_faults` reads the stale copy in a
  forked child, which dies with SIGSEGV. Also: `a_move_forwards_every_edge`
  (three collections in a row, every root moved, the cache, a symbol's
  value, the precious set, weak references, a slot frame),
  `objects_c_has_seen_or_pins_do_not_move`,
  `a_moved_extdatas_release_runs_once`,
  `a_panic_while_forwarding_releases_a_moved_extdata_once` (a forwarding
  header leaves the old copy without flags: review, below),
  `weak_references_keep_their_order_across_moves`.
- The rt slice under `ROBIGO_GC_MOVE=1 ROBIGO_GCTORTURE=1` (a moving
  collection at every safepoint after an allocation): every test of the rt
  crates passes. Under `ROBIGO_GC_STATS=1`, robigo-rt's `closures_and_fib`
  made 43,793 collections and moved 7,589,328 objects, `calls_rows` 938 and
  219,982. One rtcore test compared an address kept across `unique_mut`
  (which may collect) with a later one; it compares the list's two slots
  now. Conformance under the modes is T1's, and is not meaningful yet:
  `robigo-rt` runs no script before L1 (0/5 of `tests/rt` in every mode,
  the plain one included).
- The heap's own tests read objects through addresses kept in Rust locals,
  so they build a non-moving heap whatever the environment says (`core()`).
  The moving collector's tests turn it on.

### H3: `ROBIGO_GC_PIN_REPORT`, `ROBIGO_GC_STRONG_DLL`

- `gc/diag.rs`, ported from experiment A's robigo-core versions (#649):
  the same rule (a weak reference decided dead on the precise marks whose
  key a C word reaches), the same line format (`mode=` dropped: one order
  is left), once per reference, key and routine; `STRONG_DLL` scans its
  library's segments before the decision.
- Attribution: a native entry records its callee with the open segment's
  top (`scan_top_slot` points at two words now; both trampolines save and
  restore them), and a closed segment keeps it. A segment holds one
  routine's frames, so this replaces experiment A's C stack of running
  routines, a thread-local the isolate rule (L6) does not allow.
- Proof, the plan's: `the_pin_report_names_an_unprotected_c_local`. A
  support library built by build.rs (`src/test_probe.c` as
  `librobigo_heap_probe.so`, loaded with dlopen) keeps a key in an
  unprotected local across a collecting export. The report names
  `dll=librobigo_heap_probe routine=robigo_heap_probe_unprotected`, and the
  key is finalized while named. `the_strong_library_keeps_what_its_frames_name`
  confirms with `STRONG_DLL`: nothing finalized, nothing reported.

### A finding: Rust registers reached C segments

- A value a Rust caller kept in a callee-saved register passed through the
  native entry. C code that leaves the register alone hands it on to the
  export it calls, and the export's machine entry pushes it into the
  segment as C's value. Under pins that only kept memory, but it pinned
  objects against `GC_MOVE` and would attribute a Rust value to a package
  routine in the pin report (found by
  `objects_c_has_seen_or_pins_do_not_move`).
- Fix: both x86-64 stubs save `rbx` and `r12`-`r15` above the segment and
  zero them before the call. `a_rust_callers_registers_reach_no_segment`
  enters with a dead object's address in all five (a C helper loads them).
  It fails without the zeroing and passes with it. Elsewhere there is no
  stub, and the registers pass as before.
- Cost per six-argument native entry, robigo-rtcore's `native6_entry`
  probe (callgrind, 10^5 against 2·10^5 calls, release, WSL2 workstation,
  Ryzen 9 5900X, rustc 1.100.0): main `18bb69ff` 321 instructions; this
  branch without the zeroing 327 (+6, the routine slot); with it 340 (+13
  more). The `.Call` entry gets the same 19.

### Not done here

- The `.Call` stub's narrowing and zeroing stay. Experiment A found both
  probes unchanged without them under pins, so they could go, but that is
  a measured decision of its own.
- Under `GC_MOVE`, the six-argument entries' object arguments are marked
  by their callers (A1's ALTREP and finalizer paths), not by the entry.
- On AArch64 the native entries have no stub: the segment opens at the
  trampoline's frame address, and a Rust caller's registers still reach
  the segment there.
