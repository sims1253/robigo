## 2026-11-13: L1, the reader, the base loader and the `robigo-rt` CLI

- What: m1-plan §B L1; docs/g3.md §10 last bullet, §14.2 M1 row. New in
  `robigo-rt`: `reader.rs` (`R_ParseVector` over robigo-syntax and V1a's
  `lower.rs`, no srcrefs), `base.rs` (the loader), `repl.rs` (Rscript's
  top level: the console loop, error and warning reports), `print.rs`
  (top-level printing for the first cases), and `main.rs` (`robigo-rt
  [--vanilla] FILE | -e EXPR ...`). In `robigo-rtbuiltins`: `seq.rs`, `:`
  (seq.c), which every N/2N row's loop needs. Base: main `4ed839e0`.
- Decisions, each where g3.md, the plan or the foreman left a choice:
  - **The bound is persisted.** `scripts/base-subset.sh` now also writes
    `crates/robigo-rt/proto/base-bound.txt`: the union of the trace and the
    static bound (foreman: bind every closure of the static bound), 86
    closures, 85 primitives, 57 internals, each closure with the file whose
    last top-level assignment defines it. `--check` diffs both files. The
    generator's "which file defines it" now walks base's files in the
    Makefile's order (`R/*.R`, then `R/unix/*.R`, each by bytes) instead of
    one radix sort of full paths, which put `unix/` among the `u` files; no
    bound name is defined twice, so neither file changed.
  - **The sources are read at run time, not embedded at build time.**
    `robigo-rt` reads the 41 files from the tree `scripts/r-src.sh`
    extracts (`ROBIGO_RSRC`, else r-src.sh's cache path; the tree's
    `.rsrc-pinned` stamp must be the pinned sha256, and a test ties the
    Rust constant to r-src.sh's pin). A `build.rs` would have needed the
    tarball (a CRAN download) in every job that builds the workspace
    (`build`, `test`, `lint`, ...), the old runtime's included; run-time
    reading needs it only where robigo-rt runs: CI's `rt` and `test` jobs
    now restore the tarball from an `actions/cache` (`r-4.6.2-tarball`,
    saved on main) and run `scripts/r-src.sh`. M3's database build moves
    this to build time with the rest of g3.md §10's package build.
  - **Bindings are lazy, as GNU R's are.** GNU R loads base from its
    lazy-load database: every base variable is a promise until first use.
    The loader binds each closure of the bound to a promise of its
    definition's right-hand side in the base namespace, so loading runs no
    R code, and a function literal becomes the closure GNU R stored
    (environment `namespace:base`, checked for all 86). One definition is
    not a literal: `dyn.load <- if (.Platform$OS.type == "windows") ...`
    runs when `dyn.load` is first used (and fails today: no `.Platform`).
  - **Not-implemented stubs.** Each primitive and internal of the bound that
    robigo-rt does not define is bound to a builtin that raises "robigo: the
    primitive 'x' is not implemented yet" / "robigo: .Internal(x()) is not
    implemented yet" against its call (AGENTS rule 6), so reaching one says
    so instead of "could not find function"; a later definition (B2, V1b)
    replaces it simply by being installed first. 72 stubs today. The stubs
    are BUILTINSXPs (the VM compiles calls to SPECIALSXPs only for its own
    specials), so a stub for a special evaluates its arguments first.
  - **Top-level stand-ins**, each where its owner takes over: the error
    report is `verrorcall_dflt`'s text (the 75-column rule, `R_WarnLength`)
    written when the error reaches the top level, without
    `show.error.locations` and without the "Calls:" traceback (S1 reports
    at the error, before `on.exit` code runs, and adds the traceback: most
    errors raised inside a function print one in GNU R); `PrintWarnings`
    is ported (one, up to ten, more; "In addition:" after an error), except
    `last.warning`; calls in both are deparsed by a one-line stand-in for
    `deparse1s` (symbols, scalar constants, function-call syntax, PP_BINARY
    with its line break, PP_BINARY2, assignment, unary, `(`, `[`, `[[`,
    `args2buff`'s line break; anything else says "not implemented"), which
    B3's deparse replaces; printing is `PrintValueEnv`/`printVector` for
    NULL and attribute-free logical, integer, double and character vectors
    over robigo-text (B3's glue replaces it; objects and functions say
    "not implemented"). The lexer's warnings at the top level need the
    condition system and say "not implemented".
  - **`:`** returns an ordinary vector where GNU R returns a compact ALTREP
    sequence (`R_compact_intrange`): same values, type and length; the
    VM's `for` does not take ALTREP yet. Factors, character, complex and
    raw operands and environments say "not implemented".
  - **The runner's `empty_ratchet_ok` is gone** (G1b's note: false once L1
    adds markers). Both columns now fail an unfiltered gated run whose
    ratchet lists nothing; the runner's fixture tests that ran an unmarked
    rt tree mark it or filter.
