## 2026-11-13: the GNU R 4.6.2 oracle and per-version expected files (M0)

- why: L3 and §14.3. `robigo-rt` is gated on GNU R 4.6.2's recorded
  output, the old runtime on 4.5.0's, with case identities kept across
  versions. M0 needs the 4.6.2 oracle and its recordings.
- oracle: `robigo-oracle:4.6.2`, the CI image's target `oracle-4.6.2`
  (`.github/ci-image/oracle.Dockerfile`). It compiles the tarball that
  `scripts/r-tarballs.sha256` pins (sha256 `c297040f…10ee00`, the value
  the census above found too; CRAN's `R-4.6.2.tar.xz` matches Debian's
  `r-base_4.6.2.orig.tar.xz` from the 4.6.2-2 `.dsc`, and the two
  tarballs hold the same tar) on Debian trixie (glibc 2.41-12+deb13u4,
  gcc 14.2.0-19, tzdata 2026f-0+deb13u1, reference BLAS/LAPACK 3.12.1).
  The configuration follows Debian's `debian/rules` for r-base. Why not
  Debian's 4.6.2-2 package: it is only in unstable, which moves and has
  another glibc. Against the 4.5.0 image, `R.home()`, `.libPaths()`,
  `capabilities()`, `extSoftVersion()`, `La_library()` and
  `grSoftVersion()` are the same; only the version differs, and 4.6
  adds zstd. Two builds of the image had the same package set and
  byte-identical `base.rdb` and `stats.rdb`. The build takes 3 minutes
  on 24 cores.
- recording: `scripts/oracle-run.sh 4.6.2 ...`: `regen-expected.sh --all`,
  `corpus.py record NAME` for fastr, gnur-tests, gnur-examples,
  gnur-demos, r-intro and cran-purer, 2 runs per case as always.
  Recorded: all 632 `tests/r` scripts and 32,656 corpus cases. Not
  recorded: capi (below). Docker's default seccomp filter changed the
  output: 4.5.0 and 4.6.2 alike gain `attr(,"errmsg") "Function not
  implemented"` on a failing `system(intern = TRUE)`, from an errno that
  a filtered syscall leaves behind. So the recordings ran with
  `--security-opt seccomp=unconfined`, which reproduces the committed
  4.5.0 output.
- result: **316 cases** whose recorded output differs between 4.5.0 and
  4.6.2 (`scripts/oracle-diff.py`): conformance 35 of 632, fastr 199 of
  31,374, gnur-tests 17 of 58 (`reg-large` unstable), gnur-examples 62
  of 1,153, gnur-demos 1 of 16, r-intro 2 of 13, cran-purer 0 of 41.
  **301 of them are R's changes.** A control re-recorded 4.5.0 in its
  image on the same platform, and those cases differ from that control
  too. The other 15 differ only because the committed 4.5.0 recordings
  came from other machines:
  - `env/env-profile.R` (the committed 4.5.0 output calls `str`, which
    is unavailable with `R_DEFAULT_PACKAGES=NULL`, so it was not
    recorded as `regen-expected.sh` records) and
    `subset/pairlist-matrix-assign.R` (it reads an uninitialized index,
    as its comment says).
  - fastr `TestBuiltin_extract_replace/2d3f74f6c25fd37a`: whether a
    16.8 GB allocation fails depends on the machine.
  - gnur-tests `reg-examples3`, `reg-tests-1b`, `reg-translation` and 9
    gnur-examples (`base/timezones`, `methods/inheritedSlotNames`,
    `stats/toeplitz`, `utils/{demo,help.search,maintainer,
    packageDescription,vignette,warnErrList}`): the 4.5.0 recordings
    had the recommended packages (Matrix, MASS, survival, nlme, rpart)
    installed and tzdata 2026c, and they show the recording day's date
    and the host's name width. Neither oracle image has recommended
    packages.
- what changed (the 301): serialization headers carry the writer's
  version (157 fastr `TestBuiltin_serialize` cases, the `serialize/`
  and `vec/compact-seq-serialize` scripts); `.Internal` signatures (fastr
  `list.files` gained an argument); error and warning texts
  (`dwilcox(0, 10, Inf)` now errors `n(inf) > INT_MAX`; argument checks
  in `basics/`); dataset titles and the new `penguins` dataset; new
  base functions and S3 methods (`gnur-demos` `base/is.things`: 1405 →
  1406 base objects); `R.version` strings. Each case still needs a
  minimized reproduction with a NEWS entry (§14.3). That is not done
  here.
- the old runtime against 4.6.2 (diagnostic, not a gate): conformance
  passes 577 of 628 (`ROBIGO_R_VERSION=4.6.2`), against 606 of 628
  for 4.5.0 on the same machine and binary.
- parse oracle: no per-version files. Under 4.6.2, all 23 `tests/parse`
  dumps and the 32,586 committed corpus parse dumps (fastr, gnur-tests,
  gnur-examples) are byte-identical to 4.5.0's, recorded in C.UTF-8.
- remains:
  - capi: 34 of its 75 C sources do not compile against 4.6.2's headers.
    They use entry points that 4.6 removed from the API headers:
    `Rf_findVarInFrame` (17 sources), `ATTRIB`/`SET_ATTRIB`, the promise
    accessors, `Rf_allocSExp`, `Rf_allocVector3`, `SETLENGTH`,
    `TRUELENGTH`, `SET_TYPEOF`, `ENCLOS`, `R_nchar`, the S4-bit setters
    and others. `build.sh` stops at the first failure, so no capi case
    has a 4.6.2 recording. The cases are written against 4.5's API,
    and `robigo-rtapi` needs them restated against 4.6's (the census
    above).
  - gnur-tests, gnur-examples, gnur-demos and r-intro are still 4.5.0's
    scripts, now run on both versions. Importing 4.6.2's own tests and
    examples would add new cases, not re-record these.
  - Cases that print the checkout's path (`R_LIBS_USER` is
    `<checkout>/.robigo/empty-lib`: gnur-tests `reg-tests-1a`,
    `reg-examples1`; gnur-examples `base/libPaths`, `base/library`,
    `base/Sys.getenv`) pass only where they were recorded, on both
    versions.
