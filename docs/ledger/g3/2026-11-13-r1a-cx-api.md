## 2026-11-13: R1a, the isolate, `Cx`, handles and the value stack (`robigo-rtcore`)

- What: `crates/robigo-rtcore`, the safe facade of docs/g3.md §2 over
  `robigo-heap` (H1's fork, PR #632). Types
  first: `Isolate`, `Cx`, `OwnedIsolate`, `Reentry`; `Ref<'g>`, `View<'g>`
  and the typed views (`Vector<'g, T>`, `Char`, `Sym`, `Cons`, `Clo`,
  `Prom`, `EnvRef`, `ExtPtr`, `AltVec`); `FreshVec<'g, T>`, `Unique`;
  `Scope<'s>`, `Root<'s>`, `Out<'s>`, `Args<'a>`, `Global`; the value
  stack; `RResult` with a zero-sized `RError`, the pending-exit stack,
  `NeedGc`. Nothing depends on the crate yet, so the `robigo` binary and
  the perf gate are unchanged.
- Decisions, each where g3.md left a choice:
  - **Isolate ownership by owner checks, not an invariant isolate brand.**
    A `Cx<'id>` brand would put a second lifetime on every handle and every
    builtin signature; §2.3 allows "an owner check enabled in every
    build". Handles (`Root`, `Out`, `Args`) are slot pointers, checked to
    lie in this isolate's value-stack reservation (a subtraction and a
    compare); `Global` names its isolate. Objects that are rooted, stored
    or written to an `Out` are checked to be this isolate's heap's:
    `Sexp::heap_id` (new in `robigo-heap`) is one load from the block
    header (the heap's remembered-set pointer, which every block and large
    chunk header already has), compared with `Core::id`. Reads through a
    `Ref` are not checked: a `Ref` of another isolate is still live while
    its own brand holds. A failed check panics. The costs are not measured
    yet (no rt workload exists); X1/P1 see them in the calls rows.
  - **Scopes are closures** (`cx.scope(|cx, s| ...)`, generic over `'s`):
    a `Root<'s>` cannot leave (compile-fail case), and the top is restored
    by a guard on return, `Err` and panic. **Only the innermost open scope
    takes roots**, checked by a per-scope serial number (not the base
    address: two scopes opened at the same top share it), so restoring a
    scope never drops a root of a scope still open. A callback starts with
    no scope open, so a suspended scope cannot root into the callback's
    frame.
  - **An `Out` fills an empty slot once**: `set` consumes it and panics if
    the slot already holds a value (so a second `Out` for the slot, made
    by `Root::reset`, cannot replace the first one's value under `&Cx`);
    `Root::reset` (replace a root's value) takes `&mut Cx`. `Out::root`
    reads the result after the callee returns; an empty slot reads as
    R_NilValue.
  - **Re-entry**: `cx.call_out(|reentry| ...)` suspends the capability and
    restores the value-stack top after; `reentry.enter(|cx| ...)` makes a
    fresh `Cx`. An `active` flag in the isolate allows one running
    capability per isolate, checked in every build (a second `enter`
    without `call_out` panics). `enter_raw(*mut Isolate)` is A1's way in
    from a C export. `Cx` caches nothing, so a resumed capability needs no
    reload. **`Cx` is unsized** (`Capability<[()]>`, a zero-length slice
    tail), so `std::mem::swap`, `replace` and `take` cannot move a
    capability out of its owner or a callback's frame (compile-fail case
    `capability_swap`): a capability can never name another owner's
    isolate, outlive it, or become a second running capability. The price
    is a two-word `&mut Cx` whose length word is always 0.
  - **Allocation never collects; `cx.need_gc` does.** On H2's heap (PR
    #643) `&Cx` allocation is the poll-only path: it returns
    `Result<_, NeedGc>` (H2's `NeedGc`, re-exported) for vectors, nodes
    (`cons`, `lcons`), CHARSXPs (`mk_char`, which asserts NUL-free input:
    GNU R's "embedded nul in string" is the caller's to raise) and symbols
    (`install`). `cx.need_gc(e)` is the `&mut Cx` answer: H2's
    `Core::make_room` with the isolate's roots (a `Retry` safepoint), then
    `Ok` to retry or GNU R's error from H2's `AllocError::message()`
    ("vector memory limit ... reached", "cons memory ...", "cannot
    allocate vector of size ..."), recorded with no call. Collecting there
    is sound because `&mut Cx` has ended every `Ref`, view and slice, so
    everything Rust code still needs is in a root. The isolate's roots
    (value stack, global table, pending-exit stack) are one
    `#[derive(Trace)]` struct (the value stack's `Trace` shows its live
    object slots only), so a root added there is traced or does not
    compile. The convention for builtins is `cx.build(out, |cx| ...)`: it
    reruns the `&Cx` closure after each `need_gc` that allows a retry and
    writes the result; the same request refused again after that is GNU
    R's "cannot allocate vector of size ...". A rerun is always allowed,
    because under `&Cx` the closure can commit no observable effect, and
    it reads its inputs afresh through roots or `Args`. Plain-data vectors
    are zeroed (`alloc_vector`) or written once (`alloc_with`,
    `alloc_copy`), never handed out uninitialized. `FreshVec::set` on a
    list keeps exact counts (old value decremented), no barrier.
    `Options::max_vsize` is GNU R's vector memory limit (`R_MAX_VSIZE`).
  - The heap stays boxed in the isolate (`Core::new` returns a `Box`):
    §11's embedded heap is a heap API change for M2.
  - `Sym<'g>` is branded while symbols are per heap (M1); M2's shared
    arena makes it unbranded.
  - `Ref::len()` is `Some` only where no code runs: standard vectors,
    CHARSXP, NULL and pairlists; `None` for package ALTREP, environments
    and other types (`cx.xlength`, R1b and N1). Every ALTREP object is a
    package one until robigo's own classes exist.
  - `Args` windows hold object slots only (`Scope::args`, or the VM's
    `Args::from_raw`); unboxed arguments are V1/B1's to add.
  - Exits: `ExitKind` (error, jump, restart, interrupt), `cx.exit`,
    `cx.error_call(call, msg)` (`errorcall`; `None` is
    `errorcall(R_NilValue, ...)`), `cx.exit_info`, `cx.resolve_exit`. C2
    owns parking, superseding and `error()`'s context call; S1 the
    condition objects.
  - Value stack: 16-byte slots (tag word, payload word; the payload is a
    pointer so object slots keep provenance), 1 Mi slots reserved by
    default (`mmap` with `MAP_NORESERVE`, then one `PROT_NONE` guard page).
    A push past the end panics, the last resort: R entries compare
    `cx.stack_headroom()` with their margin first (C2, V1).
- **Unsized `Cx` against a one-word `Pin<&mut Cx>`** (foreman's question
  before filing): both forbid `swap`/`replace`/`take` (`Pin<&mut T>` with
  `T: !Unpin` gives safe code no `&mut T`, and `Pin::set` needs an owned
  `Cx`, which only this crate can make), so both are equally sound.
  Measured on a standalone program (below) with the two capability shapes
  and one call chain: a dispatcher calls a builtin twice through a function
  pointer, and the builtin calls a push and an allocation-like helper twice
  with an isolate read between. Instructions are callgrind's N vs 2N
  difference (N = 1e6, 2e6); release, `codegen-units = 1`, thin LTO, Rust
  1.100.0, the WSL2 workstation.

  | case | unsized `&mut Cx` | `Pin<&mut Cx>` |
  |---|---|---|
  | dispatcher + 2 builtin calls + 4 helper calls | 114.0 | 111.0 |
  | builtin loop, per iteration (2 helper calls, 1 isolate read) | 21.0 | 21.0 |

  The unsized design pays about 1.5 instructions per indirect builtin call:
  `xor esi,esi` for the length word at each call site, and one more
  argument register. Pin pays elsewhere: rustc gives `&mut T` no `noalias`
  when `T: !Unpin`, so LLVM reloads `cx.iso` from memory after every store
  or call (four loads in the builtin, two per loop iteration), where the
  unsized `&mut Cx` keeps it in a register. Pin also costs every builtin
  author: stable Rust does not reborrow `Pin<&mut _>`, so each `&Cx` use is
  written `&cx` and each `&mut` use after the first `cx.as_mut()`, also when
  passing `cx` to another function. Kept: unsized. Its cost is about 0.15%
  of a 1,000-instruction call and disappears where calls inline.

```rust
//! The capability's ABI: an unsized `Cx` (two-word `&mut Cx`) against a
//! sized `!Unpin` `Cx` behind `Pin<&mut Cx>` (one word). Same isolate, same
//! call chain: a dispatcher calls a builtin through a function pointer, the
//! builtin calls two helpers that touch the isolate (a value-stack push and
//! an allocation-like bump), with `&Cx` reads in between.
use std::cell::Cell;
use std::hint::black_box;
use std::marker::{PhantomData, PhantomPinned};
use std::pin::Pin;
use std::ptr::NonNull;

pub struct Iso {
    top: Cell<usize>,
    bump: Cell<usize>,
    nil: usize,
}

// ---- unsized ----
pub struct Cap<T: ?Sized> {
    iso: NonNull<Iso>,
    _p: PhantomData<*mut Iso>,
    _u: T,
}
pub type CxU = Cap<[()]>;
impl CxU {
    #[inline(always)]
    fn iso(&self) -> &Iso {
        unsafe { self.iso.as_ref() }
    }
    #[inline(always)]
    fn nil(&self) -> usize {
        self.iso().nil
    }
}
#[inline(never)]
pub fn push_u(cx: &mut CxU, v: usize) -> usize {
    let i = cx.iso();
    let t = i.top.get();
    i.top.set(t + v);
    t
}
#[inline(never)]
pub fn alloc_u(cx: &CxU, n: usize) -> usize {
    let i = cx.iso();
    let b = i.bump.get();
    i.bump.set(b + n * 8);
    b
}
#[inline(never)]
pub fn builtin_u(cx: &mut CxU, a: usize, b: usize) -> usize {
    let x = alloc_u(cx, a) ^ cx.nil();
    let r = push_u(cx, x);
    let y = alloc_u(cx, b);
    r.wrapping_add(push_u(cx, y))
}
#[inline(never)]
pub fn dispatch_u(cx: &mut CxU, f: fn(&mut CxU, usize, usize) -> usize, a: usize) -> usize {
    let r = f(cx, a, a + 1);
    r ^ f(cx, r, a)
}

// ---- Pin, !Unpin ----
pub struct CxP {
    iso: NonNull<Iso>,
    _p: PhantomData<*mut Iso>,
    _pin: PhantomPinned,
}
impl CxP {
    #[inline(always)]
    fn iso(&self) -> &Iso {
        unsafe { self.iso.as_ref() }
    }
    #[inline(always)]
    fn nil(&self) -> usize {
        self.iso().nil
    }
}
#[inline(never)]
pub fn push_p(cx: Pin<&mut CxP>, v: usize) -> usize {
    let i = cx.iso();
    let t = i.top.get();
    i.top.set(t + v);
    t
}
#[inline(never)]
pub fn alloc_p(cx: &CxP, n: usize) -> usize {
    let i = cx.iso();
    let b = i.bump.get();
    i.bump.set(b + n * 8);
    b
}
#[inline(never)]
pub fn builtin_p(mut cx: Pin<&mut CxP>, a: usize, b: usize) -> usize {
    let x = alloc_p(&cx, a) ^ cx.nil();
    let r = push_p(cx.as_mut(), x);
    let y = alloc_p(&cx, b);
    r.wrapping_add(push_p(cx, y))
}
#[inline(never)]
pub fn dispatch_p(mut cx: Pin<&mut CxP>, f: fn(Pin<&mut CxP>, usize, usize) -> usize, a: usize) -> usize {
    let r = f(cx.as_mut(), a, a + 1);
    r ^ f(cx, r, a)
}

/// A builtin with a loop over a helper (paste's shape: one interning call
/// per element), reading isolate state each iteration.
#[inline(never)]
pub fn loop_u(cx: &mut CxU, n: usize) -> usize {
    let mut acc = 0;
    for i in 0..n {
        acc ^= alloc_u(cx, i) ^ cx.nil();
        acc = acc.wrapping_add(push_u(cx, acc));
    }
    acc
}
#[inline(never)]
pub fn loop_p(mut cx: Pin<&mut CxP>, n: usize) -> usize {
    let mut acc = 0;
    for i in 0..n {
        acc ^= alloc_p(&cx, i) ^ cx.nil();
        acc = acc.wrapping_add(push_p(cx.as_mut(), acc));
    }
    acc
}

fn main() {
    let which = std::env::args().nth(1).unwrap_or_default();
    let n: usize = std::env::args().nth(2).and_then(|s| s.parse().ok()).unwrap_or(1_000_000);
    let iso = Box::leak(Box::new(Iso { top: Cell::new(0), bump: Cell::new(0), nil: 7 }));
    let isop = NonNull::from(&*iso);
    let mut acc = 0usize;
    match which.as_str() {
        "unsized" => {
            let mut cap = Cap { iso: isop, _p: PhantomData, _u: [(); 0] };
            let cx: &mut CxU = &mut cap;
            let f = black_box(builtin_u as fn(&mut CxU, usize, usize) -> usize);
            for i in 0..n {
                acc = acc.wrapping_add(dispatch_u(cx, f, black_box(i)));
            }
        }
        "pin" => {
            let mut cap = Box::pin(CxP { iso: isop, _p: PhantomData, _pin: PhantomPinned });
            let f = black_box(builtin_p as fn(Pin<&mut CxP>, usize, usize) -> usize);
            for i in 0..n {
                acc = acc.wrapping_add(dispatch_p(cap.as_mut(), f, black_box(i)));
            }
        }
        "loop-unsized" => {
            let mut cap = Cap { iso: isop, _p: PhantomData, _u: [(); 0] };
            let cx: &mut CxU = &mut cap;
            acc = loop_u(cx, black_box(n));
        }
        "loop-pin" => {
            let mut cap = Box::pin(CxP { iso: isop, _p: PhantomData, _pin: PhantomPinned });
            acc = loop_p(cap.as_mut(), black_box(n));
        }
        _ => panic!("unsized|pin|loop-unsized|loop-pin"),
    }
    println!("{acc}");
}
```

- Heap changes (small, additive, on top of H2): `HeapId`, `Core::id`,
  `Sexp::heap_id`; `impl Drop for Heap`, which returns every chunk (a
  dropped isolate gave none back; Miri reported the leak);
  `thread_stack()` returns an empty stack under Miri (it cannot call
  `pthread_getattr_np`).
- Proof (WSL2 workstation, 24 threads, Rust 1.100.0):
  - `cargo test -p robigo-rtcore`: 24 API tests (owner checks across two
    isolates, innermost-only rooting, root reset, scope restore on `Err`
    and panic, nested re-entry three deep, a callback that panics, globals,
    exits, value-stack overflow, the guard page faulting in a forked child,
    roots equal to the live object slots, a second `Out` for one slot,
    `build`, and `need_gc` collecting the garbage under a vector limit
    while a rooted vector survives), the sample
    builtins in the crate doc (`rev`, and `lapply` holding results across
    calls back), and 8 `trybuild` compile-fail cases (capabilities swapped
    between owners, a `Ref` across
    `&mut Cx`, a slice across a callback, a `Ref` escaping its scope and
    its isolate, a `Root` escaping its scope, root reset with a live
    `Ref`, the capability types `!Send`). CI's `rt` job runs them in
    release, then under `ROBIGO_GCTORTURE=1`.
  - Miri (`cargo +nightly miri test -p robigo-rtcore`, nightly 2026-11-01):
    the 22 API tests that neither fork nor collect (the collector calls the
    heap's C shim) and the doc test, no undefined behaviour; the value
    stack's `mmap` is replaced by the allocator under Miri, and the heap's
    allocation runs as is (it is std-alloc based). Added to the CI miri
    job.
  - `cargo test -p robigo-heap` on H2's heap: all pass, the new
    `every_object_carries_its_heaps_id` among them.
- Review (sol-loop, gpt-6.1-sol), round 1: S1 (blocker) safe code could
  `std::mem::swap` a callback's capability into another owner, which then
  freed the wrong isolate. Round 2 found my first fix (owners keep their
  own pointer and refuse a swapped capability) incomplete: a capability
  already handed out could still be swapped, leaving it naming an isolate
  its new owner frees. Fixed by making `Cx` unsized, as above; both swap
  sequences are a compile-fail case. S2 (node, CHARSXP and symbol
  allocation could not report `NeedGc`) and S3 (a second `Out` from
  `Root::reset` could replace a value under `&Cx`) fixed as above. The
  sample `rev` returned `cx.need_gc(e)` directly, which would report
  success without a result once R1b allows a retry; it now uses
  `cx.build`. Round 3: approved, no new findings. Round 4, on the
  adaptation to H2's heap (`need_gc` collecting with the derived-`Trace`
  roots, `build`'s retry): approved.
  - Rejected for S1: `Cx` as a zero-sized token at its isolate's address
    (swapping two zero-sized values moves nothing), the isolate recovered
    from the address with exposed provenance. At the workspace's
    `opt-level = 1` nine API tests failed (roots pushed through one
    capability reference were not seen through another): LLVM optimizes
    across the address round trip under the reference's `noalias`. Not
    pursued: soundness must not rest on that.
