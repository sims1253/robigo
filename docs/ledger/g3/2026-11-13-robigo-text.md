## 2026-11-13: B3, the `robigo-text` crate (M1, wave 0)

- why: `docs/g3.md` §7 and §14.4 ("continues"); m1-plan.md B3, first
  half. The rt glue (print.c, deparse, `cat`) builds on it later.
- what: `crates/robigo-text`, pure ports from GNU R 4.6.2's C
  (`~/.cache/robigo-research/rsrc/R-4.6.2`) over `f64`/`i32`/`&[u8]`, no
  R objects, `#![forbid(unsafe_code)]`: format.c's `scientific`,
  `formatReal`, `formatInteger`, `formatLogical`, `formatString`;
  printutils.c's `encodeReal0`, `EncodeRealDrop0`, `EncodeInteger`,
  `EncodeLogical`, `Rstrwid`, `Rstrlen`, `EncodeString`, `IndexWidth`;
  util.c's `utf8toucs`/`utf8toucs32`; rlocale.c's `Ri18n_wcwidth`
  (R's table, generated from `rlocale_widths.h` with its Win32 branches
  removed); sysutils.c's `translateChar`. The global state the C reads
  (`R_print`, the locale) is one `PrintParams` value; strings are
  `Str { bytes, enc }`, with `mkCharLenCE`'s rule that ASCII carries no
  mark. Encoders append to a caller's `Vec<u8>`. Depends only on
  `robigo-numerics` (x87 `long double` for `scientific`). Not wired into
  `robigo-runtime` (frozen) and outside the `robigo` binary, so the perf
  gate is unaffected.
- proof: 3464 cases recorded from GNU R 4.6.2
  (`~/.cache/robigo-research/R-4.6.2-build/bin/Rscript`, machine
  DESKTOP-FVJ95BU, glibc 2.44) by `crates/robigo-text/oracle/record.sh`:
  1768 number cases (every digits 1..22 over 50 edge values: ±0,
  denormals, 1e±300, `.Machine` extremes, ties such as 0.15 and 2.675,
  rounding-widens values like 9996 and 99999.5; NA/NaN/±Inf mixes;
  scipen -9..300; nsmall; widths; decimal marks `,`, `·`, `dec`; a
  seeded sweep over magnitudes; integers, logicals, `as.character`) and
  848 string cases each in C.UTF-8 and C (native, UTF-8, latin1 and
  bytes marks; quotes `"`, `'`, `` ` ``; ANSI and octal escapes;
  combining, zero-width, wide and astral characters; unassigned and
  non-printable code points; invalid, truncated, overlong, surrogate and
  above-U+10FFFF UTF-8; CP1252's unassigned bytes; all four justifies;
  `NA_character_`). All pass. Mutating `roundingwidens`, the `powl`
  scaling or the `format_via_sprintf` cut-off fails 7 to 71 cases each.
- 4.5 → 4.6: format.c is unchanged. printutils.c: `EncodeLogical`
  gained a fast path that returns the NA string unpadded when
  `w == na_width`, so an NA string with fewer bytes than its width
  (e.g. `na.print = "\t"`, one byte, width 2) no longer pads (ported,
  unit-tested; the oracle data has only the default NA). `vnsprintf` →
  `vsnprintf` in `Rcons_vprintf` changes nothing.
- findings the C sources alone do not show (each now in the data):
  - glibc's UTF-8 `mbrtowc` accepts five- and six-byte forms and values
    above U+10FFFF, but not overlong forms or surrogates; for such a
    native string `Rstrlen` counts a `\U` escape (10) while
    `EncodeString` prints `\x` escapes.
  - glibc's iconv drops the tag characters U+E0000..E007F when the
    target has none: in the C locale `print()` of U+E0001 prints ten
    spaces (the width of the UTF-8 string, padding an empty text).
  - CP1252 (R's iconv source for latin1) leaves 0x81, 0x8D, 0x8F, 0x90
    and 0x9D unassigned: they print as `<81>`.
  - `EncodeString` reads past the end of a string in two places (a bytes
    string with `"` and a quote; an overlong printable character in a
    string marked UTF-8, e.g. `\xc1\x81` prints `A\0`); the port reads
    NUL there, which is what R 4.6.2 prints for one byte past the end.
  - The bytes escapes are themselves escaped: `"caf\\xc3\\xa9"`.
- platform dependency: `iswprint` is glibc's. The table is generated by
  scanning every code point through GNU R 4.6.2's `encodeString()` in
  C.UTF-8 (`oracle/iswprint.R`). glibc 2.44's table has 4803 more
  printable code points than robigo-syntax's (`dump.rs`, taken from the
  4.5.0 oracle image) and none fewer. When the 4.6.2 docker oracle
  lands, re-run `RSCRIPT=… oracle/record.sh` under it; the result is
  the oracle's glibc.
- against `robigo-runtime/src/format.rs` (the frozen port): it measures
  display width with an approximate East Asian table rather than R's
  `Ri18n_wcwidth`, decodes native strings through libc, and has no 4.6
  `EncodeLogical` fast path; robigo-text replaces all three with the C's
  behaviour as data.
- not covered (follow-ups for the B3 glue): `formatComplex`/
  `EncodeComplex`, `EncodeReal2`, `EncodeElement`; Latin-1 and CJK
  locales (`Locale` has only UTF-8 and C, so a caller cannot ask for
  them); the `OutDec` global (the caller passes `dec`, and calls
  `decimal_mark_warning` where `EncodeReal0` warns).
- CI: `cargo test --workspace` (the `test` job) runs the crate's tests.
  PR #633's `rt` selection rule is not on main yet; the crate is to be
  added to it when it lands.
