- Decisions, each where g3.md, the plan or the foreman left a choice:
  - **An error is reported where it is raised** (§6.5's rule for
    warnings, applied to errors as GNU R does): `Cx::error_call` and
    `Cx::error` call the isolate's `error` hook, which is S1's port of
    `verrorcall_dflt`: `vsignalError` walks the handler stack (a calling
    handler runs on top of the erring frame, an exiting one is
    `findcontext` to its `tryCatch` frame, with its `on.exit` code), then
    the report ("Error in <call> : ", the line break at `LONGWARN`,
    "Calls:" from `R_ConciseTraceback`, `options(show.error.messages)`),
    then `jump_to_top_ex`. The report is written before any `on.exit`
    code runs, as GNU R's is. L1's stand-in report at the REPL is gone; the
    REPL only halts. A call holding unforced promises (`NextMethod`'s
    `fixcall` puts `...`'s promises in the method's call) has them forced
    before it is deparsed, as `deparse2buff`'s PROMSXP case evaluates them.
  - **Warnings are signalled where they arise** (§6.5): `warning()` and
    `Cx::warning` call `.signalSimpleWarning` when base binds it (calling
    handlers see the warning at once; `muffleWarning` is a restart), else
    `vwarningcall_dflt` directly. `options(warn)` 0 collects up to
    `nwarnings` for the top level's "Warning message(s):", 1 prints at
    once ("Warning in <call> :"), 2 turns the warning into an error
    "(converted from warning) ...", as errors.c does.
  - **`options()` is base's `.Options` pairlist**, as options.c keeps it.
    The options GNU R keeps in C globals (`warning.length`,
    `show.error.messages`, `showErrorCalls`, `showWarnCalls`,
    `showNCalls`) are mirrored into the isolate's condition state when
    set; `warn` and `warning.expression` are read from `.Options` where
    errors.c reads them. Setting `nwarnings` raises "not implemented yet"
    (the default 50 holds).
  - **`UseMethod` hands off from the VM as a special over its call**
    (V1b's `Kind::Fn`): the generic's record is marked `CTXT_GENERIC`
    while the method runs (the method's `sysparent` is the generic's
    caller), and the value leaves the generic by
    `findcontext(CTXT_RETURN, env, ans)`. Internal generics (`[`, `[[`,
    `$` and their setters, `length`, `as.character`, `print` through its
    closure, the `Ops`, `Math` and `Summary` groups) dispatch through the
    isolate's dispatch hook, `DispatchOrEval`/`DispatchGroup` as written;
    `dispatch_special` is V1b's signature.
  - **The dispatch caches are validated by versions** (§9.3).
    `R_LookupMethod`'s search from the generic's top environment on is
    memoized, direct mapped by the method's symbol. An entry holds every
    object it compares (top environment, defining environment, version
    boxes, S3 methods table, value), so no address is reused while it
    lives and a moving collection keeps it right. It depends on the
    function bindings and enclosure of the top environment and of each
    environment searched after it (their version boxes, taken before each
    is searched and checked again after the search), and on the defining
    environment's S3 methods table (its binding read again; the table's
    box when the method was found there, else the method's absence read
    again). A search that meets an active binding of the method, or a
    promise still to force, is not kept. The calls' frames below the top
    environment are searched every time. `installS3Signature` keeps the
    last symbols by name (symbols are immortal).
  - **`R_USEMETHOD_FORWARD_LOCALS` is read once**, when a generic first
    has a local that is not a formal (objects.c's `static int option`);
    "none", the default, forwards nothing; the other modes raise "not
    implemented yet" only when such a local exists.
  - **`do.call` lives in `robigo-rt`**: its `.Internal` check needs
    `PRIMNAME`, which `robigo-rtbuiltins` cannot see.

  The memo takes 1,337 instructions (3.9%) off the s3 row. What is left
  of dispatch's own cost, by callgrind (exclusive, per iteration): the six
  dispatch variables defined into the method's slot frame, which only
  holds its formals, so each goes to the frame's overflow (`define_var`
  2,371 plus its `malloc`/`free`); `topenv` of the calls' frames (1,252
  for three calls, two frame lookups each); the frame lookups of the calls
  below the top environment. `topenv` reads non-function bindings
  (`.packageName`, `.__NAMESPACE__.`) and a `name` attribute, which no
  version box tracks, so it is not memoized. For P1: shape room for the
  dispatch variables (or a frame made with them), and `topenv` memoized
  once those reads are versioned.
