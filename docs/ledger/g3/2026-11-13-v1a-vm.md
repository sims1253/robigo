## 2026-11-13: V1a, the IR, the compiler from LANGSXP and the VM core (`robigo-rt`)

- What: G3's evaluator (m1-plan §B V1, first half; docs/g3.md §9.1-9.2,
  §3 items 2 and 7, §10 "Designed away"): one engine, every call compiled
  to an IR and run by a VM over the isolate's value stack. New in
  `robigo-rt`: `ir.rs` (instructions, effect classes), `code.rs` (code
  objects), `compile.rs` (LANGSXP to IR), `vm.rs` (the loop),
  `call.rs` (closure application, builtins, loop regions), `eval.rs`
  (`eval`, variables, `forcePromise`, the polls), `missing.rs`, `fin.rs`
  (`RunFinalizers`), `ops.rs` (scalar fast paths over B1's kernels),
  `prims.rs` (the primitive table), `lower.rs` (robigo-syntax's tree to
  language objects, for L1 to build on). Base: R1a (#642), N1a (#645), C2
  (#646), R1b (`g3/r1b-alloc-api`), B1 (#648) and N1b (#647) merged.
- Decisions, each where g3.md or the plan left a choice:
  - **Code objects are heap objects**: a VECSXP that counts no references
    (`NO_TRACKREFS`, so compiling never changes an R-visible `REFCNT`, §4)
    holding a RAWSXP instruction blob (16-byte plain-data instructions), the
    source, a closure's formals and frame shape, and the constant pool. A
    collection frees them with their last user. They hang off the 4th node
    word of the call they compile (as GNU R's byte code hangs off a body)
    and of the closure, which nothing R-visible reads. The VM derives raw
    pointers into one only between safepoints and reloads them from the
    rooted code register after every instruction that may collect (§3: no
    derived pointer across a safepoint; what deopt and a moving collector
    need).
  - **The `Eval` profile keeps `eval.c`'s observables, compiled.** A call's
    function is found at run time, as the AST interpreter's `findFun3` does:
    the compiler inlines a base primitive (a special as VM code, `+`/`<`/
    `!`/`&` as B1's scalar kernel) behind a guard that checks, running no
    code, that the symbol still names it from `rho`, and falls back to the
    generic call (a user's `if` or `+` wins, tested). Every instruction that
    stands for one of `eval`'s calls carries GNU R's evaluation count tick
    and its static depth, so `evalcount` (the finalizer and interrupt poll,
    eval.c:1091) and `R_EvalDepth` (the "evaluation nested too deeply"
    error) are GNU R's, per node, without an `eval` per node. Checked
    against the 4.6.2 oracle with the JIT off and `options(expressions =
    200)`: the recursion depth reached before the error is GNU R's for four
    shapes (98, 66, 98, 98 levels), and the eval-count poll runs a pending
    finalizer exactly before the 1001st evaluation. `R_Visible` is set only
    on the paths whose value leaves a code object (the only place it can be
    read).
  - **The `Bc` profile** (`ROBIGO_RT_PROFILE=bc`): no per-node counts or
    depth; the depth rises once per code object and `bcEval`'s poll runs at
    entry, at back-edges and every 1024 `for` iterations (eval.c:6252,
    6261, 7539); a constant argument is bound as its value (`PUSHCONSTARG`).
    The inlining and JIT decisions (cmp.R, `R_CheckJIT`) are V2's: GNU R
    compiles a closure at its second call, so its JIT-on depth counts mix
    one AST level with byte-code levels (oracle: 198/197/198/198), which the
    forced profile does not try to match.
  - **Calls recurse in Rust** (the perf-vm ledger measured a non-recursive
    VM call as no faster): a closure call is C2's `function_context_raw`
    around a new activation; a loop is a region run inside C2's
    `with_context(CTXT_LOOP)` (GNU R's AST always pushes one); `break` and
    `next` inside the region are jumps, and through a promise or `eval`
    they are `findcontext` exits that land at the loop's record (a `next`
    re-enters the region); `return` leaves a closure body directly and is
    `findcontext` anywhere else.
  - **Argument binding is C1's seam** (`call::apply_closure`,
    `promise_args`): GNU R's `promiseArgs` (a PROMSXP per argument, `...`
    expanded, double promises) and a port of `matchArgs`' three passes
    (with side arrays for `ARGUSED`, no allocation for up to 16
    arguments), bound into N1b's closure frame of the closure's shape (its
    formals, then the locals its body assigns; cached with the code):
    supplied arguments as their promises, defaults as delayed slots
    (MISSING 2). That is D4's control representation for supplied
    arguments; C1's delayed slots replace it. `unpromiseArgs` is ported;
    `R_CleanupEnvir` of a slot frame is C1's (§4), so until then a call
    leaves its values' counts as raised as GNU R does before that release.
  - **Builtins through B1's registry**: `PRIMOFFSET` is the row of B1's
    `BUILTINS`, then the evaluator's own primitives (the specials, `(`).
    The hooks are installed into B1's table (`eval`, `apply`, `force`);
    `on.exit` code runs through the evaluator passed to C2's function
    records. An inline kernel's slow path (another type, attributes, an
    integer overflow's warning) calls B1's builtin.
  - **Safepoints**: `Entry` at every activation, closure application and
    promise force; `Loop` at back-edges; `Return` after each builtin. The
    interrupt check and pending finalizers run at GNU R's points (the
    eval-count and `bcEval` polls), not at every safepoint.
  - **D9: clear at last use.** An instruction clears the operand registers
    it reads last; a call's argument window and a discarded statement's
    value are cleared; a loop's state when it ends. Sensitivity: without
    the clear of a loop body's value, `for (i in 1:1) keep(mk()); gc()`
    delays the finalizer past the `gc()` (GNU R 4.6.2 runs it there).
  - **Unboxed scalars**: registers hold doubles, integers and logicals
    unboxed; `<-` of one stores it unboxed in a slot frame (N1b's
    `define_scalar`), and a read of such a local is unboxed.
- Integration of the bases (in `robigo-rtcore`): B1 and C2 each defined
  `Cx::error`; C2's (the context's call, `Rf_error`) stays, and B1's
  `warning()` now reports that call too (`error_context_call`). The raw
  layer added for the VM: `Scope::frame` (an activation's registers),
  `Root::from_raw`, `alloc_node_raw`/`alloc_vector_raw`, the two eval
  counters, `eval_depth_at`, `var_lookup_raw`/`fun_lookup_raw`/
  `frame_arg_raw` over N1b's slot kinds, `set_cell_value_raw`
  (`SET_BINDING_VALUE`), `collect`, the finalizer queue and
  `new_weak_ref_raw`, and `DDVAL` set by `install` (`isDDName`).
- Not in V1a (each raises "robigo: ... is not implemented yet" where
  reached): complex assignment, `on.exit`, `switch`, `substitute`,
  `UseMethod` (V1b, S1); a special applied to evaluated arguments; the
  "unused argument" message (deparse is B3's); partial-match warnings
  (`options()` is B2b's; GNU R's default is off).
- Not done: **D9's liveness-map variant** (`g3/x-d9-liveness`). Its bar's
  workloads are the dead-root test, `fib` and CALLS through `robigo-rt`
  under `idiom-vs-r.py`, which needs L1's CLI; the variant also needs the
  collector to see each activation's code and pc at a safepoint (a frame
  walk the value stack does not have). Building it before L1 would give a
  run that "decides nothing" (bar protocol).
- Cost, as a baseline (WSL2 workstation, Ryzen 9 5900X, rustc 1.100.0,
  release; callgrind N against 2N; robigo-rt by the ignored test
  `tests/cost.rs` with the profile forced, GNU R 4.6.2 from
  `~/.cache/robigo-research/R-4.6.2-build` with `R_DEFAULT_PACKAGES=NULL`;
  each row's body in `g <- function() for (i in 1:N) { BODY }`, fib per
  call of `fib(18)`), on the integrated base (B1's kernels, N1b's frames):

  | row | robigo-rt `Eval` | robigo-rt `Bc` (forced) | GNU R AST (JIT off) | GNU R byte code (JIT 3) |
  |---|---|---|---|---|
  | fib (per call) | 5,512 | 5,411 | 5,157 | 2,762 |
  | plain `tag(i * 0.25, "bc")` | 8,677 | 7,923 | 8,718 | 4,473 |
  | defaults `scale_by(i * 0.5)` | 10,372 | 10,183 | 9,354 | 5,644 |
  | named `weigh(y = 2, x = i)` | 8,219 | 7,495 | 7,984 | 4,374 |

  The `Eval` profile runs at about GNU R's AST interpreter's cost
  (0.99-1.11x), which is its job; E1/E2's bars are against GNU R's byte code
  and today's robigo, which V2's `Bc` decisions (inlined base functions with
  no guards), C1's argument slots (no promise per argument, no `promiseArgs`
  list) and P1 reach. Two steps measured on the way (fib per call): no
  allocator call in argument matching (stack buffers), 5,438 to 5,117
  before the B1/N1b integration; after it (N1b frames, B1's kernels), 5,961,
  then 5,512 by forcing the promise the raw lookup found instead of walking
  again with `find_var`, and 8-element stack buffers.
- Proof: `cargo test -p robigo-rt` (`tests/vm.rs` 16: arithmetic,
  variables, `if`/`{`, closures and fib, the calls.R rows without S3 and
  tryCatch, partial matching and its errors, `...` and `..N`, loops with
  `break`/`next` through promises, `return` from a promise, `&&`/`||`,
  a user's `if` and `+`, promise order and the recursive-default error,
  GNU R's depth counts and eval-count poll, the `Bc` profile;
  `tests/finalizers.rs` 5: dead registers in both profiles, a live
  binding, the eval-count poll). Every error message and call checked
  against the 4.6.2 oracle. `scripts/rt-ci.py` (release, then
  `ROBIGO_GCTORTURE=1` with `ROBIGO_GC_STATS=check`): all pass. Clippy
  clean.
