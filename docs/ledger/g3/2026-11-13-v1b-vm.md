## 2026-11-13: V1b, subsetting and its setters, complex assignment, the remaining specials (`robigo-rt`)

- What: m1-plan §B V1, second half (docs/g3.md §4, §9.1-9.2, §10). New in
  `robigo-rtbuiltins`: `subscript.rs` (subscript.c: `makeSubscript`,
  `get1index`, `OneIndex`), `subset.rs` (subset.c: `do_subset_dflt`,
  `do_subset2_dflt`, `R_subset3_dflt`, `vectorIndex`), `subassign.rs`
  (subassign.c: `EnlargeVector`, `SubassignTypeFix`, `VectorAssign`,
  `do_subassign_dflt`, `do_subassign2_dflt`, `R_subassign3_dflt`), the
  `coerceVector` cases these reach, and `names`/`names<-` (attrib.c), with
  registry rows for `.subset`, `.subset2`, `names`, `names<-`. New in
  `robigo-rt`: `specials.rs` (`[`, `[[`, `$`, `[<-`, `[[<-`, `$<-`,
  `switch`, `on.exit`, `substitute`), `assign.rs` (`applydefine`,
  `evalseq`), `links.rs` (link counts of stack values), `dispatch.rs` (S1's
  hand-off points). In `robigo-rtcore`, the writes to existing objects these
  need (below). Base: main `18bb69ff`, then L1 (#656) merged in.
- Decisions, each where g3.md, the plan or the foreman left a choice:
  - **Subsetting is ported as functions** (§10, "Ported as functions:
    subsetting and assignment first"): the default methods live in
    `robigo-rtbuiltins` over the safe facade, shared by `.subset`/`.subset2`
    and the specials. A subscript is a Rust value (1-based positions, NA,
    new names as positions into the subscript), not GNU R's INTSXP with a
    `use.names` attribute; the results are GNU R's.
  - **Specials that are functions over their call** (`Kind::Fn`):
    `PRIMFUN(op)(call, op, args, rho)` as GNU R calls a SPECIALSXP. A
    compiled call runs one behind the same guard as an inlined primitive
    (`Op::SpecialFn`, no `findFun`); a call through a value, a call made at
    run time and the `apply` hook (`R_forceAndCall`'s SPECIALSXP case, so
    `sapply(x, "[", 1)` works once `lapply` exists) apply it to its call. A
    language special reached the same way compiles its call (V1a's
    `compile_special`), which is §10's "builtin object compiles a call".
  - **Complex assignment is `applydefine` and `evalseq` as written**
    (§4): the right-hand side is the compiled code's, then one
    `Op::ComplexAssign` binds `*tmp*` (its cell `DISABLE_REFCNT`ed), makes
    the target local (`EnsureLocal`; `<<-` finds it with `R_findVarLoc`),
    sets `ASSIGNMENT_PENDING` on its cell, evaluates the getter calls with
    `*tmp*` bound one level in, and calls each replacement function as
    `` `f<-`(`*tmp*`, args..., value = <promise>) `` (marked
    `MARK_ASSIGNMENT_CALL`, so `[<-` and `names<-` write in place) inside a
    `CTXT_CCODE` record whose call is the assignment: `error()` in a setter
    reports `x[[5]] <- 1:2` as GNU R does, and `errorcall` the built call
    (`` `[[<-`(`*tmp*`, 1:2, value = 1) ``). The record's `cend`
    (`tmp_cleanup`) runs in Rust as the exit passes the record: C2 runs the
    `cend`s of the records above a leg's stop at the leg's start and V1b's
    unbinding happens when the `Err` reaches the record, which is still
    before any `on.exit` code of a record below. The calls built at run time
    are new each time, so they are evaluated without being compiled
    (`call::eval_call`, `eval`'s LANGSXP case); their arguments are the
    source's expressions, compiled once. Checked against the 4.6.2 oracle:
    `*tmp*` holds the target while an index is evaluated and is unbound
    after, a getter that does not exist is "could not find function" against
    the assignment call, `<<-` assigns in the enclosure, a closure's argument
    is copied before it is written.
  - **Link counts of stack values** (`links.rs`, C1's module by agreement:
    V1b wrote `applydefine`, C1 owns the protocol): `commit` is
    `INCREMENT_BCSTACK_LINKS` plus `INCLNK_stack_commit` over the value
    stack (every activation's registers and every root are GNU R's node
    stack; `R_BCProtTop`/`R_BCProtCommitted` are slot indices), `release`
    is `DECREMENT_BCSTACK_LINKS`, on every path out of `applydefine`. An
    operand pending in a register is therefore shared when an assignment
    runs (`list(x, { x[1] <- 5; x })[[1]]` is `c(1, 2)`, the oracle's).
    `evalList` (V1a's `call_builtin_list`) now raises each value's link
    until all are evaluated, as GNU R's does; it did not.
  - **Growth** (§4): `EnlargeVector` as written: in place when the vector
    is unshared, growable and has room, else a new vector `R_EXPAND_FRAC`
    (1.05) larger, growable, its names enlarged with `""`. The facade grows
    in place (`Cx::grow_in_place`) and makes growable fresh vectors
    (`FreshVec::set_growable`). Checked against the oracle by address: 200
    list elements appended one at a time move 59 times, 1000 doubles 91
    times, in both, at the top level and in a closure.
  - **The facade's writes to existing objects** (`robigo-rtcore`, all
    `&mut Cx`): deep `duplicate`; `installAttrib`/`removeAttrib` on an
    object the caller may write; OBJECT and S4 bits; `MARK_NOT_MUTABLE`;
    `MARK_ASSIGNMENT_CALL`/`IS_ASSIGNMENT_CALL`; `SETCAR`/`SETCDR`/
    `SET_TAG`; list and string element copies (`UniqueList::copy_from`,
    `set_na`, `set_blank`); `ASSIGNMENT_PENDING` and `DISABLE_REFCNT` of a
    binding cell; the value stack's link walk (`Cx::stack_links`).
  - **`substitute` materializes**: its frame lookups are
    `R_findVarInFrame`, which turns an argument slot into the promise GNU R
    binds (a default's expression for `function(y = 2.5) substitute(y)`).
  - **`on.exit`** matches its arguments (`matchArgs_NR`) and hands the code
    to C2's function record (`Cx::on_exit`); **`switch`** is `do_switch`
    (alternatives evaluated by `eval`, so `next` and `return` in one leave
    through their records).
  - **`UseMethod` and internal-generic dispatch are S1's**:
    `dispatch::do_usemethod` and `dispatch::dispatch_special` (called with
    the promise `R_DispatchOrEvalSP` makes for an object) raise "not
    implemented yet" rather than take the default (AGENTS rule 6).
  - L1's one-line deparse stand-in learned `$`/`@` and a forced promise
    (a replacement call's `value`), which the new error cases print.
- Not in V1b (each raises "robigo: ... is not implemented yet" where
  reached, or is noted): matrix and array subscripts (`x[i, j]`, `x[m]`
  with a matrix `m`, `x[i, j] <- v`); `[[<-` on a pairlist; S4 objects;
  the subscript errors' condition classes (`subscriptOutOfBoundsError`,
  ...: S1 makes the conditions; the message and call are GNU R's);
  `R_shallow_duplicate_attr`'s ALTREP wrapper (the copy is made at once);
  `options(check.bounds)` and `options(warnPartialMatchDollar)` read as
  their default FALSE (B2b's options); `names<-` of a value that is not a
  character vector (`as.character`, B2a); the errors that deparse
  (duplicate `switch` defaults, "unused argument": B3).

  Unlike V1a's calls (0.99-1.11x of the AST), these paths are
  1.3-2.0x: the same steps as GNU R's, each through more layers (a rooted
  scope per special, `eval` per argument, the setter call built and looked
  up at run time, `*tmp*`'s binding cell, the link walk over the whole value
  stack, about 360 per assignment). One step measured: evaluating a
  special's arguments into a window of value-stack slots instead of root
  vectors copied into one, and the raw function lookup first in
  `eval_call`, about -450 per row. GNU R's byte code is 10-20x cheaper on
  assignment because cmp.R compiles it (no `*tmp*` binding, no built call,
  `VECSUBASSIGN`): that is V2's `Bc` profile. For `Eval`, the next steps
  are compiled subset arguments (registers, no `eval` per argument) and a
  link walk over activations only.
