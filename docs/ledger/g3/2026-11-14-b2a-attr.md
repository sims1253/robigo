## 2026-11-14: B2a-attr: the attribute writers, and V1b's review fixes

- What: the foreman's B2a-attr package: the attribute writers B2b (#661)
  left "not implemented", ported from GNU R 4.6.2's attrib.c, coerce.c and
  objects.c (`// R: file.c:function` on each, messages verbatim); first,
  the nine OpenCodeReview findings on V1b (#660). Base: main `3b85d458`
  (V1b merged), with B2b's open `g3/b2b-internals` (`f50cdf02`) merged in
  for its `coerceVector`, attribute readers and `dispatch_or_eval`: this
  branch stacks on #661 and shrinks to its own diff once #661 merges.
- First commit `af8f65f6`, the V1b review fixes:
  - Links raised on stack values (`evalList`'s values,
    `evalListKeepMissing`'s, `R_DispatchOrEvalSP`'s object, `$`/`$<-`'s
    object, `applydefine`'s right-hand side) are dropped on every path out
    by a guard, `links::Linked`, as GNU R's jumps reset the stack's
    protection (`R_BCProtReset`). Test `links_are_dropped_on_an_early_exit`
    (`tests/subset.rs`, a `refcnt` probe): with the guard's drop removed,
    each of the three paths leaks one link.
  - Allocation retries are bounded (`Cx::retry_alloc`, `Cx::install_rooted`):
    the same request refused again after a collection is GNU R's "cannot
    allocate" error, as R1a's `cx.build` does. `remove_attrib` propagates
    the `dimnames` symbol's refusal instead of skipping the strip. No test
    fails without these two: a small request refused after `make_room`
    needs a heap a collection cannot relieve, and `dimnames` is interned
    whenever a dimnames attribute exists. Both now take the one bounded
    path every allocation takes.
  - `links::release` asserts the marks' LIFO order; one `run_builtin`
    (PRIMPRINT/`R_Visible` and the Return safepoint) for the three builtin
    call paths; the replacement-function cache keyed by `SymId`; the test
    `c()` refuses mixed kinds; one constant for the assignment-call gp bit.
    (The `repl.rs` finding went away with B3's deparse in `569f61c2`.)
- `c069a32c`: `vm::alloc_retry` and rtcore env's `alloc_retry` were
  `Cx::retry_alloc`'s loop twice more; one function now.
- The writers, `robigo-rtbuiltins/src/attrib/set.rs`:
  - `setAttrib` with its special names' setters: `namesgets`, `dimgets`
    (with `dim2total`), `dimnamesgets` (with `as_char_simpl`),
    `classgets`, `tspgets`, `commentgets`, `row_names_gets`, and
    `installAttrib` with `R_FixupRHS` (V1b's `fixup_rhs`).
  - The builtins: `attr<-`, `attributes<-`, `oldClass<-`, `class<-`
    (`R_set_class`, coerce.c), `unclass` (objects.c), `names<-` (V1b's
    partial version replaced), `dim<-`, `dimnames<-`, `levels<-`,
    `.Internal(comment)`, `.Internal(comment<-)`,
    `.Internal(shortRowNames)`, `.Internal(copyDFattr)`.
  - Each copies its object by its own GNU R rule (`writable`: the setters'
    `MAYBE_SHARED || (!IS_ASSIGNMENT_CALL && MAYBE_REFERENCED)`, shallow or
    deep; `comment<-`'s `MAYBE_SHARED`; `unclass`'s `MAYBE_REFERENCED`;
    `attributes<-`'s own) and writes it in place otherwise.
  - Support: `coerce::vector::as_character_factor` (`asCharacterFactor`;
    unique's `match_transform` uses it now), `unique::any_duplicated_of`;
    rtcore's `shallow_duplicate` copies a closure (`duplicate1`'s CLOSXP
    case, attributes copied shallowly), and `remove_attrib` leaves OBJECT
    unwritten when it is clear (R_NilValue is a shared constant).
  - `names<-` fixes over V1b's: a value other than a plain character
    vector goes through R's `as.character` (dispatching; the call then
    drops its reference to the value, `SETCADR(call, R_NilValue)`), a
    pairlist value, a one-dimensional array's dimnames, and removing the
    names of a pairlist or call with tags (V1b's no-copy shortcut read only
    the attribute).
- Decisions:
  - `R_shallow_duplicate_attr` is a shallow duplicate (GNU R wraps a long
    vector in an ALTREP wrapper instead; the value is the same).
  - Where GNU R reads memory it does not check, robigo says "not
    implemented" instead of guessing: `names<-` from a pairlist with an
    empty element (`STRING_ELT(s, 0)` past the end), the labels of a
    factor that is neither integer nor logical (`INTEGER_ELT` unchecked),
    `copyDFattr` into a non-vector (`SET_ATTRIB` on R_NilValue).
  - `tspgets` reads `getOption("ts.eps")`, which is NULL without stats
    (`R_DEFAULT_PACKAGES=NULL`), so its consistency check never fires: as
    in GNU R run that way.
  - `copyDFattr` is in the `Env` effect class: it writes its argument in
    place.
  - `@<-` (`do_attrgets` with PRIMVAL 1, S4 slots) is not registered;
    `environment<-` is V2's.

- Measurement: callgrind instructions per iteration of `BODY` in
  `g <- function() { for (i in 1:N) { BODY }; NULL }` (N and 2N,
  `scripts/idiom-vs-r.py --rows`); robigo-rt release from `0e32928c`; GNU R
  4.6.2's build from `~/.cache/robigo-research/R-4.6.2-build`, byte code
  (JIT on) and AST (`R_ENABLE_JIT=0`). Machine: AMD Ryzen 9 5900X, WSL2,
  shared with other agents (instruction counts are unaffected). The setters
  errored before this package, so there is no earlier robigo number;
  `match_args`' fast path (`d611649a`, `0e32928c`) took `attr-set` from
  11,493.

  robigo-rt is 1.9 to 2.9 times GNU R's AST and 2.4 to 5.5 times its byte
  code. Where it goes, `names-set` (callgrind, per iteration):
  `applydefine` 6,260, of which `evalseq` 1,007 and the setter call's
  evaluation 3,568 (`evalList` of its arguments about 1,600, `names<-`
  itself 1,522); the rest of `applydefine` (the calls built, `*tmp*`
  defined and removed) about 1,700; the VM around the statement about
  3,400. The setter is under GNU R's whole byte-code iteration; the
  complex assignment around it is not (Open, below).

- Review: Sol (gpt-6.1-sol, high), 3 rounds, approved. Round 1 approved
  with a nit (`copyDFattr` refused environments and closures; now only
  the shared constants). Round 2 found that `match_args`' fast path
  assumed distinct formal names, which `match.call`'s closure formals need
  not have; fixed, with `tests/match_args.rs` (fails without the fix).
- Open, for the reviewers and the lead:
  - The setters' cost is mostly the complex assignment around them:
    `applydefine` builds the setter call and evaluates it (`*tmp*`
    defined, the arguments evaluated by `evalList`) where GNU R's byte
    code runs `SETTER_CALL` on stack values. That is the bytecode
    profile's (V2), and V1b's `applydefine` path for the AST.
  - In the setters: `set_attrib` interns the attribute's symbol and a
    special name's setter interns it again (about 200 instructions per
    call); rtbuiltins has no table of GNU R's well-known symbols
    (`R_NamesSymbol`, ...) to read them from.
  - S1: the internal-generic setters (`names<-`, `dim<-`, `dimnames<-`,
    `levels<-`) on objects reach the dispatch stub ("not implemented").
