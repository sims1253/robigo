What each variant swaps:

- `split` (D3): `crates/robigo-rtcore/src/vstack.rs`. The payloads are
  one array of 8-byte words and the tags an array of bytes (9 bytes a slot
  against 16). A slot's handle (`SlotPtr`) is its payload word's address;
  the tag's address is computed from it alone, because the payload array
  starts at an address aligned to `SPAN` (2^27) with the tag array ending
  where it starts. The VM's activation keeps its tag base beside its
  payload base, so a register's tag is one indexed byte load. Every
  `NonNull<Slot>` of the API became `SlotPtr` (`root.rs`, the VM, the call
  windows, `links.rs`); the compile-fail expectation names the new type;
  two empty slots compare equal whatever their payload words hold (only an
  empty slot's tag is zeroed). Miri is not supported on the branch (no
  aligned reservation). The other split form, 8-byte tags at a fixed
  distance from the payloads, was not built: it keeps the default's 16
  bytes a slot and adds a second cache line per slot access, so it has no
  way to win on estimated cycles.
- `frameobj` (D2): `robigo_heap::slots` (the word map) and rtcore's
  `env::frame::layout`. A frame is a plain ENVSXP node (`+16` the frame
  object, `+24` ENCLOS) with the header flags SLOTS and FRAMEOBJ; the frame
  object is a slot block (the same object as an overflow block) holding
  the frame words and the inline slots. `slots::body` resolves a frame to
  its frame object, and every frame-word and slot access in `layout` goes
  through it; the heap allocates the block and the node, and traces the
  node as a plain node. Two rtcore tests that read frame words at raw
  offsets read them through `body`.
- `pairlist` (D2's control): closure frames are GNU R's: an ENVSXP whose
  FRAME is a pairlist of binding cells, the formals in formal order
  (`NewEnvironment`), a default a `mkPROMISE(CAR(f), newrho)` with MISSING
  2 (`make_applyClosure_env`), `R_CleanupEnvir` on the pairlist; N1a's
  unhashed frame restored beside the slot frames as a fourth environment
  kind (`env/pairlist.rs`). A pairlist cell cannot hold a delayed slot, so
  arguments are D4's control (`g3/x2-d4-promsxp`'s two commits
  cherry-picked: GNU R's `promiseArgs` list, a PROMSXP and a cons per
  argument). Locals are boxed (`define_scalar` defines a boxed value
  outside slot frames). `new.env(hash = FALSE)` stays a slot frame.

### Where the cost goes (`plain`, per call, `scripts/callgrind-diff.py` at 8,000 against 4,000 iterations)

- `split` (+309): no one function; the tag address is computed from the
  payload address outside the VM's registers (`apply`'s scope +83, the VM
  loop +53, `new_closure_frame` +40, `force_arg` +28, `run_function` +25,
  ...).
- `frameobj` (+477): the second allocation and the indirection on every
  frame word and slot.
- `pairlist` (+437):
  - spent: `alloc_node` +410 (a promise, two list conses, two frame
    cells), `force_promise` +199, `define_var` +155 and
    `set_binding_value` +70 (boxed locals defined through the cell path),
    the argument list's build and `unpromiseArgs` (+154 in `apply`'s
    scope, +100, `clear_promise` +63);
  - saved: the slot force (`force_arg` 229, `force_slot` 39,
    `release_caller` 48), the slot frame's allocation (`alloc_slot_frame`
    124), `R_CleanupEnvir`'s slot walk (127), and **`frame::bindings` (97)
    with its `malloc`/`free` (63)**, which the default runs on every call:
    `Cx::env_has_no_special_symbols` collects and sorts the frame's
    bindings into a `Vec` to ask whether any is a special symbol. The
    lookups are also cheaper on a two-cell pairlist than on the slot frame
    (`loc_in_frame` 257 against 343, `var_lookup_raw` 230 against 308).
