## 2026-11-14: D4 runs: delayed/forced slots against a PROMSXP per argument

The runs D4's bar governs (docs/ledger/g3.md, "M1 decision bars", D4).
Machine, harness and the default's runs: `2026-11-14-x-base-runs.md`.

- Variants, both from base `e2207b4d386a4e00d875955af33b203e7fd5beec`:
  - `slots` (the default, C1's `args::bind`): the base itself,
    `~/.cache/x1-bins/robigo-rt-base-e2207b4d`.
  - the control `g3/x2-d4-promsxp` at
    `31b94318c8eda9c36a4dfd68012b997b723c0c57`,
    `~/.cache/x1-bins/robigo-rt-d4-promsxp-31b94318`. It changes
    `crates/robigo-rt/src/args.rs` alone (one module, as the bar asks):
    - a call's own arguments become GNU R's argument list, one tagged cons
      per supplied argument holding a PROMSXP (`promiseArgs`, and bcEval's
      MAKEPROM, DODOTS and PUSHCONSTARG, which make the same list: a `Bc`
      constant is the value itself, a `...` element a double promise);
    - the formals are bound to the list's objects, so the slots hold
      PROMSXPs as values, and the list goes to `unpromiseArgs` at the
      call's end, as for a promise list from C;
    - each defaulted formal becomes a PROMSXP in the new frame with
      MISSING 2 (`make_applyClosure_env`'s `mkPROMISE(CAR(f), newrho)`);
    - the match, and its memoized plan per call site, are unchanged.
    GNU R's second list (`matchArgs`' actuals, which become the frame's
    cells) is not made: the frame is D2's default slot frame in both
    variants.
- Superseded control: the first build of the branch, `e31558b2`, made the
  default promises by a pass over every formal (a no-op on formals that
  are not defaults), which cost the control 48 instructions per call on
  `plain`. `31b94318` passes over the defaulted formals only (`defaults`
  rose from 9,707.2 to 9,769.3 with it, the others fell). The first
  build's runs are kept for the record; they decide nothing. Under them `slots` was
  9.34% below the control (geomean ratio 0.9066), so the verdict does not
  depend on the fix.
- Admission: `scripts/rt-ci.py` on `g3/x2-d4-promsxp` passes (exit 0), on
  both `e31558b2` and `31b94318`: release tests, conformance 201/207 with
  the same 6 unratcheted failures as the base, gctorture,
  `ROBIGO_MATERIALIZE=1`, `ROBIGO_GC_MOVE=1`, `ROBIGO_GC_PIN_REPORT`. So
  the control is exact on the rt slice.

The control pays for two allocations, the list's walk at the end and a
second pass over the actuals. The slots pay more to force an argument in
place (`force_arg` + `force_slot` 268) than the control pays to force a
promise object (`force_promise` 199). The slots' S3 path is 3.1% more
expensive than the control's (`s3` row): `UseMethod` reads `promargs`,
which the slots fill lazily from the frame, while the control already has
the list.
