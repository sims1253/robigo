## 2026-11-14: D5 runs: LIFO frame recycling against none

The runs D5's bar governs (docs/ledger/g3.md, "M1 decision bars", D5:
after D2 is decided). D2 is decided (`inline`, the lead's decision in
`2026-11-14-d2-d3-decision.md`), and these runs are at `inline`: the base
`e2207b4d`, whose runs are `2026-11-14-x-base-runs.md` (machine, harness,
the default `none`).

- Variants, both from base `e2207b4d386a4e00d875955af33b203e7fd5beec`:
  - `none` (the simpler, named first): the base,
    `~/.cache/x1-bins/robigo-rt-base-e2207b4d`.
  - `g3/x2-d5-recycle` at `c77bcb8552d31088742f90a1237b0f76e70a306a`,
    `~/.cache/x1-bins/robigo-rt-d5-recycle-c77bcb85`. It adds
    `robigo-rtcore`'s `env/recycle.rs` and its three call sites:
    - when a closure call returns (`args::apply`, after `R_CleanupEnvir`
      and the argument list's cleanup), its frame goes to a per-isolate
      pool, one LIFO list per inline capacity (at most 32 slots, 64 frames
      a list), if nothing can reach it: REFCNT 0, not the value returned,
      no attributes, no overflow block, version box or caller word, no
      cell-backed or active slot, and neither ESCAPED nor `SEEN_BY_C`;
    - ESCAPED (header `extra` bit 7) is set on a slot frame whenever a
      context record's `cloenv` or `sysparent` is read as a value
      (`environment()`, `sys.frame()`, `parent.frame()`,
      `as.environment()`, `UseMethod`, ...): R code that held the frame
      may keep it where no count shows it (a register, a `CONS_NR` list,
      `*tmp*`);
    - `new_closure_frame` takes a pooled frame of its capacity and
      rewrites it as a fresh one (header bits, ENCLOS, every slot unkeyed)
      instead of allocating;
    - the pool is weak: every collection empties it;
    - quarantine mode (`ROBIGO_FRAME_QUARANTINE=1`, docs/g3.md §16): a
      frame that would be pooled is poisoned instead (neither a slot frame
      nor a hashed one, so any environment operation on it panics) and
      held as a root, so its memory is never reused; two rt-ci steps run
      the rt crates' tests and the conformance under it.
- Admission: `scripts/rt-ci.py` on the branch passes (exit 0), with its
  two quarantine steps: conformance 201/207 with and without quarantine,
  the base's 6 unratcheted failures. A sensitivity check (the ESCAPED
  marking switched off by a temporary environment switch, not committed)
  found no R path in robigo-rt's base subset that reaches the pool with
  only an uncounted reference: a frame returned by `environment()` is the
  call's value, and every other holder tried counts it; `reg.finalizer`,
  which would keep the frame through a weak reference, is not bound in
  robigo-rt yet. So the quarantine mode is clean, but nothing on the rt
  slice yet shows it catching an escape.
- The heap's `CALL_LIVE` and `SEEN_BY_C` bits were one bit when these runs
  were made (fixed after, in #672). The runs measure the plain release
  binary, never `ROBIGO_GC_MOVE` (only the admission's rt-ci step runs
  that), and the fix changes which bit a frame's call sets, not the work
  of these rows, so it does not touch the numbers.

Recycling removes every frame allocation on these rows (`fib`: 0.3 ENVSXP
per iteration are left, the frames a collection emptied the pool of). The
REALSXP left on the PLAIN rows are boxed values: the forced argument's and
the call's value, which stay objects until the VM passes unboxed values
through calls (C1's "tagged promises", P1's work).

Where the instructions go on `plain` (per call, `scripts/callgrind-diff.py`
at 8,000 against 4,000 iterations): `Core::alloc_slot_frame` −124 (no
allocation), `Cx::recycle_frame` +90 (the checks before a frame is
pooled), `Cx::new_closure_frame` +61 (the pool and the rewrite): +27 in
these three, +18 per call in all. The estimated cycles fall (−2.4% on `plain`) because the reused frame
is still in the cache.
