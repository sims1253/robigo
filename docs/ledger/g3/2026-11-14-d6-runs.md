## 2026-11-14: D6 runs: deferred link counts against eager ones (a control)

The runs D6's bar governs (docs/ledger/g3.md, "M1 decision bars", D6).
Machine, harness and the default's runs: `2026-11-14-x-base-runs.md`.

- Variants, both from base `e2207b4d386a4e00d875955af33b203e7fd5beec`:
  - `deferred` (the design, §4: GNU R's `INCLNK_stack_commit` protocol in
    `crates/robigo-rt/src/links.rs`): the base,
    `~/.cache/x1-bins/robigo-rt-base-e2207b4d`.
  - the control `g3/x2-d6-eager` at
    `1ca483ea95e2c63436543eb618008f050108b11e`,
    `~/.cache/x1-bins/robigo-rt-d6-eager-1ca483ea`. Every value-stack slot
    that holds an object holds a link to it: `INCREMENT_LINKS` when an
    object is stored into a slot (`vstack::Slot::write_counted`, which
    every slot write now goes through: `ValueStack::push`/`write`, the VM's
    registers, the evaluator's and the call windows' direct writes),
    `DECREMENT_LINKS` when it is overwritten or its slot is popped
    (`ValueStack::restore`). `links::commit`, `links::release` and
    `Linked::link_next` (the deferred commits) do nothing, since every
    stack value already holds its link. The `CONS_NR` list guard of
    `evalList` keeps its links: those values are not stack values.
- Admission: `scripts/rt-ci.py` on `g3/x2-d6-eager` fails (exit 101):
  the release tests fail `tests/args.rs`'s
  `reference_counts_follow_gnu_r_per_transition` ("force, frame dies:
  start": REF 2 against GNU R's 1, the stack's link on the value), and the
  conformance step alone (`cargo test --release -p robigo-rt --test
  conformance`) passes 186 of 207 cases, 15 fewer than the base; the 13
  failures beyond the base's 6 include two ratcheted cases
  (`tests/r/lang/on-exit.R`, `tests/r/subset/assign-list.R`), and the rest
  are conditions, `lapply`, `options/strings` and `summary/math`. So
  `eager` is an inexact control as well as a slower one. It was measured
  before its slice run; it is never adoptable, so neither the order nor
  the failure changes its standing (the bar records the delta only).

Allocations per iteration: `eager` allocates one more INTSXP per
iteration on every row (48 bytes: `plain` 4 objects and 276 bytes
against 3 and 228). It is the `for` loop's
index: with its register's link the loop variable's value looks shared,
so each iteration makes a new INTSXP where GNU R (and `deferred`) writes
the old one in place. That is an observable difference from GNU R
(`tracemem`, `.Internal(inspect)` counts), so `eager` is an inexact
control as well as a slower one.
