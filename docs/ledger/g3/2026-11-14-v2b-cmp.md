## 2026-11-14: V2b, cmp.R's complex assignment, constant folding, `switch` and subsetting in the `Bc` profile (`robigo-rt`, `robigo-rtcore`)

- What: the follow-ups V2's entry (`2026-11-14-v2-bc-profile.md`, "Not
  ported") listed, on `main` at `e2207b4d`. The `Bc` compiler
  (`compile.rs`) now takes these cmp.R decisions, and the VM runs the
  bcEval operations they compile to:
  - **Complex assignment** (`cmpComplexAssign`, `cmpSetterCall`,
    `cmpGetterCall`, the `$<-`/`[<-`/`[[<-` setter and `$`/`[`/`[[`
    getter handlers). New `bcassign.rs` runs `Op::BcAssign` as
    `STARTASSIGN`, the getter calls from the inside out (with `SWAP`'s
    duplication rule), the setter calls from the outside in, then
    `ENDASSIGN` (`STARTASSIGN2`/`ENDASSIGN2` for `<<-`). Subset and
    subassign calls dispatch through `tryDispatch`/`tryAssignDispatch`,
    else run the default method. `$` and `$<-` are `DOLLAR`/`DOLLARGETS`.
    A builtin, special or closure setter gets `` `f<-`(`*tmp*`, args,
    value = <expr or *vtmp*>) `` as its call, and no `*tmp*` is bound.
    `error()` in a setter reports the inflated assignment call
    (`inflateAssignmentCall`, through rtcore's new final bc expression).
  - **Constant folding** (`constantFold`, `constantFoldCall`,
    `constantFoldSym`, `getFoldFun`, `checkConst`, `foldFuns`,
    `constNames`). New `fold.rs`. A folded value joins the `identical()`
    constant already in the pool (`putconst`'s `R_compute_identical(x, y,
    16)`, so 0 and -0 are one). The `if` handler compiles only the branch
    a folded logical test takes.
  - **`switch`'s handler**: `EXPR` and the arms compiled into the code.
    The new `Op::Switch` is bcEval's `SWITCH`, followed by its two jump
    tables as `Jmp`s. A string matches a name exactly, so NA matches "NA";
    the `EXPR` tag is ignored; an empty numeric alternative is
    `stop("empty alternative in numeric switch")`; the default is an
    invisible NULL in tail position.
  - **`[`, `[[` and `$` handlers** (`cmpSubsetDispatch`, `cmpDispatch`,
    `cmpIndices`, the `$` handler). New ops: `StartSubset`
    (`STARTSUBSET_N`/`STARTSUBSET`: dispatch on the evaluated object; a
    method keeps its own visibility), `DfltSubset` (`VECSUBSET`,
    `MATSUBSET`, `SUBSET_N` and their `[[` forms, `DFLTSUBSET`:
    `do_subset(2)_dflt` on a register window, `R_Visible` on), `Dollar`
    (`DOLLAR`) and `GetVarMissOk` (`GETVAR_MISSOK`, `DDVAL_MISSOK`: an
    index bound to a missing argument is an empty index).
  - **A builtin reached by compiled code's generic call** (another name,
    `...`, an empty argument: `cmpBuiltin` declines) evaluates its argument
    calls by their compiled code (bcEval's `MAKEPROM` runs `bcEval(code,
    rho)`), compiled with the enclosing compile. An empty argument is
    reported only after all are evaluated (`checkForMissings`).
  - Fixed on the way: `..0` and `..-1` raise ddfind's "indexing '...' with
    non-positive index %d" (rt read `CAR` of `...`'s binding); bcassign's
    `GETVAR_MISSOK` finds a promise of a missing argument missing
    (`R_isMissing`), and an empty `..N` element too (`DDVAL_MISSOK`).
- Decisions, each where g3.md, the plan or the foreman left a choice:
  - **Folds are evaluated between compile tries.** The compiler runs
    under `&Cx` and evaluates nothing. A foldable call whose value is not
    known yet is a request, compiled as not folded for now. When a try
    ends with requests, the retry loop (`compile::attempt`) evaluates them
    and compiles again with their values in view. One round per level of
    nesting; values are rooted as globals for the rest of the compile. A
    try that failed (`Need::Fail`) with requests also gets its round,
    since a folded test may drop the code that failed. While an `if`
    test's fold is not known, the try compiles neither branch, so a fold
    in the branch the test drops is never evaluated (GNU R folds the test
    first).
  - **A fold runs in a helper closure of base's namespace, never
    JIT-compiled, built only from primitives and internals.** It
    establishes exiting handlers for `error` and `warning`
    (`.addCondHands`, as `tryCatch` does) and calls `.Internal(do.call(f,
    args, env))`; its frame comes from `.Internal(environment(NULL))` in a
    closure it calls. This is cmp.R's `tryCatch(checkConst(do.call(ffun,
    args)), error =, warning =)`, but it works while base's `tryCatch`,
    `do.call` and `environment` are lazy bindings not yet forced, are being
    compiled, or are absent (the unit tests' isolates). As in GNU R, a
    fold's error sets the last error message (`geterrmessage()`), and its
    warning is never signalled.
  - **Under a forced profile (`ROBIGO_RT_PROFILE`), compiles made while a
    fold is evaluated fold nothing.** There `eval` compiles the call
    `do.call` builds, and folding that would evaluate it again without
    end. GNU R evaluates that call as the AST, so this changes nothing in
    GNU R's mode.
  - **Only value constants are shared by `identical()`.** GNU R's
    `putconst` compares every constant: a quoted call identical to another
    call in the pool shares its object. That is observable only through
    object identity, so rt shares the constants that `LdConst` and
    `LdScalar` load, among themselves.
  - **The right-hand side's link is dropped on every exit** of a compiled
    complex assignment, as main's `applydefine` does. GNU R's bcEval
    leaks it on an error (REFCNT 1, 2, 3 across three failing
    assignments, probed on 4.6.2); rt keeps one rule for both profiles.
  - **`cmpIndices`' `INCLNK`/`DECLNK` are not emitted.** In rt every
    value on the value stack, registers included, gets its link when an
    assignment commits (`links::commit`), which covers what `INCLNK`
    protects.
- Not ported, each observable only where stated:
  - cmp.R's `::`/`:::` handler (`cmpCallSymFun` with the names as
    strings: the call record differs) and `.Call`'s `DOTCALL`; `cmpIs`,
    `cmpPrim1/2`, `cmpMath1`, `:`, `seq_along`, `seq_len`, which differ
    from the builtin call only in speed. Loop contexts only when cmp.R
    needs them (no call report differs, as V2 found).
  - From V2's list, still open: code compiled lazily for a promise of a
    compiled top-level loop sees the global frame's bindings, and promise
    code is kept per expression rather than per promise (M3's BCODESXP).
