## 2026-11-15: D9 runs: dead registers cleared at last use against liveness maps

The runs D9's bar governs (docs/ledger/g3.md, "M1 decision bars", D9).
V1a left the liveness-map variant unbuilt (`2026-11-13-v1a-vm.md`); it is
built here.

- Base: main `af7a7f19dc65c56b36c8952e823d2704164b2538`, the base of
  `2026-11-15-d2s-runs.md`, whose runs of main are also the `lastuse` runs
  here (the same JSON is archived with this entry). Machine, valgrind and
  toolchain as in `2026-11-14-x-base-runs.md`.
- Variants, both from that base:
  - `lastuse` (V1a's default): main, `~/.cache/x1-bins/robigo-rt-main-af7a7f19`.
    The compiler marks an operand's last read (`F_CLR_B`, `F_CLR_C`) and
    emits `Clear`/`ClearRange`; the VM clears those registers, a builtin's
    argument window after the call, and a loop region's temporaries when
    a `break` or `next` lands.
  - `g3/v1-d9-liveness` at `4fbe3c6e6dd6ebb0b95fb9d6ebae5c3caa8f4d3d`,
    `~/.cache/x1-bins/robigo-rt-d9-liveness-4fbe3c6e`:
    - no clear at last use (`ir::CLEAR_AT_LAST_USE` false: none of the
      flags, ops or VM clears above; the clears of a complex assignment's
      right-hand side stay: by `links.rs`'s reading, they keep
      `INCLNK_stack_commit` from linking that value twice, which no test
      here exercises);
    - `crate::liveness`: a backward dataflow over each code object's
      instructions (uses and defs per op, successors including jump
      targets, `Switch`'s table and a loop region's landing points), stored
      in the code object as the registers each instruction keeps (live-in,
      live-out and what it writes);
    - two fixed registers per activation: `R_PC` (the instruction, written
      before each one) and `R_LINK` (the outer activation), so the
      collector finds every activation in the value stack with no
      allocation per call;
    - a mask (`vm::mask_dead`) that clears every register outside its
      activation's map, run by every collection before it traces the value
      stack (a hook in `robigo-rtcore`'s `ValueStack`) and by
      `links::commit` before the stack's values get their links (a dead
      register's value must get none: bcEval's stack holds live values
      only).
- Admission: `scripts/rt-ci.py` on the branch passes (exit 0), gctorture
  (a collection, so a mask, at every allocation) and `ROBIGO_GC_MOVE`
  included; conformance 211/216, main's 5 unratcheted failures.
- The bar's exactness condition: `crates/robigo-rt/tests/finalizers.rs`
  (V1's dead-root tests, the expected order GNU R 4.6.2's; four run in
  both profiles, `a_live_binding_keeps_its_object` and
  `the_eval_count_poll_runs_pending_finalizers` in `Eval` only,
  `next_polls_like_a_back_edge` in `Bc` only) passes 7/7 on the variant. Sensitivity: the same build with the
  mask not installed (a temporary switch, not committed) fails 4 of the 7
  (`a_dead_register_does_not_delay_a_finalizer`,
  `statement_values_and_operands_are_cleared_at_last_use`,
  `a_loop_bodys_dead_value_is_cleared`,
  `break_and_next_clear_the_temporaries_they_abandon`): the masks are what
  deliver the finalizers at GNU R's `gc()`.

Where the instructions go (`scripts/callgrind-diff.py`, per `plain`
iteration and per `fib` call): `vm::run` −59 and −37 (the clear flags'
tests and the `Clear` ops gone, against one `R_PC` store per

unlinked, its `R_PC` and `R_LINK` set), +14 in the stack's zeroing of the
two extra registers. The masks run only at collections and complex
assignments, which these rows rarely reach.
