## 2026-11-16: C1c: the link walk counts GNU R's node stack, not the Rust roots

Package C1c (M1, C1's follow-up). Before an operation that may write an
object in place (`applydefine`, `STARTASSIGN`), GNU R links every value on
its byte-code node stack (`INCREMENT_BCSTACK_LINKS`, `INCLNK_stack_commit`,
eval.c:997-1016). robigo-rt's `links::commit` linked every object slot of
its value stack. Builtins keep their Rust roots on that stack too, so their
roots were counted, and GNU R counts no C local. The result was a copy
where GNU R writes in place. The witness is `vapply` (apply.c:do_vapply).
It holds `X` in a C local while `FUN` runs and then names its result by
`X`. On 4.6.2, `FUN`'s `x[2] <<- "Z"` on an `x` that only its binding
references shows in the names (`a Z c`); robigo-rt printed `a b c`.

Now the walk counts only GNU R's node stack: the registers of the live VM
activations, from `R_FIRST` on, less the argument registers of a builtin
one of them is running. Taking the roots out of the count exposed robigo
code that had copied correctly only because the full walk over-counted:
lapply, vapply, env2list, mget, paste and rep. Each now counts what GNU R
counts (the audit below).

- **Tree:** branch `g3/c1c-link-walk`, from main `c536597d`.
- **Oracle:** GNU R 4.6.2, `~/.cache/robigo-oracle/4.6.2`. Every case was
  recorded with `scripts/oracle-run.sh 4.6.2 scripts/regen-expected.sh`.
  Each case was also run with the JIT off, by prepending
  `compiler::enableJIT(0)`: the oracle's Rscript ignores
  `R_ENABLE_JIT=0` (`enableJIT(-1)` still returns 3 under it). Every
  case gives its recording then, except `link-walk-subset.R`, which
  records the two evaluators' difference on purpose.

### The design

- **Frame marks** (`crates/robigo-rt/src/links.rs:60-100`). `vm::exec` heads
  each activation's registers with `FRAME_HEAD` (2) value-stack slots
  (`crates/robigo-rt/src/vm.rs:166-173`):
  - a mark holding the register count;
  - a slot for the registers that a builtin the activation runs holds its
    arguments in.

  A mark is a new slot tag (`crates/robigo-rtcore/src/vstack.rs:89-105`,
  `Slot::mark`). Nothing traces it (the collector and `for_each_object_in`
  test for the object tag), and no register or Rust root holds one.
- **The walk** (`links.rs:150`, `INCLNK_stack_commit` and `DECLNK_stack`)
  scans the committed range. Activation frames do not nest: an inner
  activation's frame lies above its caller's registers, past the roots of
  whatever the caller runs. The walk counts the registers that follow each
  mark and steps over everything else. For a range that starts inside a
  frame, it first finds the nearest mark below the start. Like the old
  walk, it visits each slot of the range once.
- **A running builtin's arguments** (`links.rs:87-100`). `invoke_builtin`
  writes the argument registers into the activation's second head slot
  before the builtin runs and clears the slot afterwards
  (`crates/robigo-rt/src/call.rs:343-346`). This is GNU R's
  `BUILTIN_CALL_FRAME_ARGS` (eval.c:5971), and `evalList`'s
  `DECREMENT_LINKS` before `PRIMFUN`. The slot needs no guard: an
  activation runs one builtin at a time and stops while it does, and an
  unwind past the activation pops its frame.

#### First design and why it went

The first design kept a list of activations on `exec`'s Rust frames, under
a guard, with the argument window set through a guard type. The perf-rt
gate against main failed. Instructions per iteration:

| row | change |
|---|---:|
| plain | +9.08% |
| defaults | +8.75% |
| named | +9.42% |
| env-fn | +8.02% |
| superassign | +2.81% |
| s3 | +2.07% |
| binarytrees | +4.23% |

Bisecting with callgrind found three costs:

- The guard type's `Drop` in the builtin call path changed how LLVM
  inlined `vm::run`, at ~170 instructions per iteration.
- `prims::state(cx)` is a linear TypeId search, paid on every activation.
- Smaller edits there moved `run`'s inlining by ±8 instructions per
  iteration.

The marks need no list, no guard and no state lookup. They cost two slots
and one store per activation, and two stores per builtin call.

#### The default subset's operands

`vm::dflt_subset` runs `do_subset_dflt` and `do_subset2_dflt` with their
operands on the node stack (`vm.rs:1329`), as GNU R's byte code does.
`DO_STARTDISPATCH` (eval.c, `STARTSUBSET2` and the rest) leaves the
object on the stack below the call frame, and `DO_DFLTDISPATCH`'s
`BUILTIN_CALL_FRAME_ARGS` drops only the links of the argument list.
Under the AST, `R_DispatchOrEvalSP` drops the object's link before the
default (robigo-rt's `specials.rs:341` does the same).

Sol found a case that shows it. `x[["foo", exact = NA]]` warns of the
partial match before it reads the element, and a calling handler can
write the list. `link-walk-subset.R` records the result: 99 2 (in place)
before GNU R's JIT compiles the caller, 1 2 (a copy) after it.
robigo-rt's default profile prints that sequence, `eval` prints the AST's
answer and `bc` the byte code's. The index operands are on the node
stack here and not in GNU R. The difference could show only if a handler
wrote an index in place after `get1index` had read it.

`crates/robigo-rt/tests/links.rs` covers what no ported builtin shows from
R. `.Internal(hold(x, f))` calls `f()` and then reads its own `x`. The
first test expects 99: the builtin's argument registers hold no links.
This is GNU R's `rapply`, which gives 99 on the oracle with JIT on and off
and with `compiler::cmpfun`. The second test expects an operand still
pending while `f()` runs to keep its link. Both run in the Eval and Bc
profiles. Under `ROBIGO_NO_INPLACE` the first test checks the mode's side
(3).

The tests catch the bugs they target. With the walk disabled,
`link-walk-register.R` fails in both profiles. Without the window,
`hold` gives 3.

`link-walk-eval-call.R` also records something robigo-rt will have to
match: GNU R's `{` walks its call as it evaluates it (eval.c:do_begin), so
a call that rewrites itself in place runs its new third element.

failed once the roots were excluded.

### Also fixed on the way

- Evaluating the empty symbol `R_MissingArg` gave `object '' not found`.
  GNU R's `mkSymMarker` makes the symbol its own value, so the error is
  "argument is missing, with no default" (`crates/robigo-rt/src/eval.rs:497`).
  `rep(, 2)` reaches it now. `rep()` gives NULL, and `h <- function(...)
  rep(...); h()` does too; both used to fail.

### Follow-ups

- The four unrunnable cases (sapply, mapply/Map, Reduce/Filter, evalq) are
  ratcheted when robigo-rt's base slice binds those closures and
  `forceAndCall` and `.Internal(mapply)` are ported. `link-walk-eval-call.R`
  is ratcheted with `[[<-` on a call and an evaluator that walks `{`'s call
  live, as `do_begin` does.
- `dispatchMethod`'s builtin `evalList` links (above).
- `do_rep`'s object case still evaluates every argument before it
  dispatches. GNU R calls the method with the rest as promises.
