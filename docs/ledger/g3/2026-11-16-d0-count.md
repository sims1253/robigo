## 2026-11-16: D0's count (D0c): 80 builtins, so D0 is decided "port"

- What: package D0c of the M2/M3 plan (m2m3-plan.md §B "D0c", §C row D0;
  g3.md §10, §15.2 D0). It counts the distinct names.c builtins that GNU
  R 4.6.2 reaches when it builds base and compiler and boots from the
  databases, less what is already Rust at M3 under lead decision F4 (A).
  The count is **80**. That is below 150, so **D0 is decided "port"**:
  §10's bar is a conjunction, so the adapter pilot (D0p) is skipped and
  `robigo-cbase` is not adopted. The per-file list below replaces
  `crates/robigo-rt/proto/base-subset.txt` as B5's contract.
- What follows from the decision: lead decision F7a (A) now applies. With
  the crutch rejected, no GNU R C in robigo can reach `TRUELENGTH`, so
  §8's per-isolate `TRUELENGTH` words for shared CHARSXPs are dropped. A
  4.6-built package cannot reach them either (4.6.2's `libR.so` exports
  neither `TRUELENGTH` nor `SET_TRUELENGTH`), and the Rust radix sort
  keeps its own scratch. The foreman confirmed D0's outcome and F7a.
- Tree: main `c9e820e9`; M1's rows are those of
  `crates/robigo-rtbuiltins/src/registry.rs` there (188). GNU R: the local
  4.6.2 build `~/.cache/robigo-research/R-4.6.2-build` (`-g -O2`, gcc
  16.2.1, `--enable-R-shlib`), from the pinned tarball's sources in
  `~/.cache/robigo-research/rsrc/R-4.6.2`. Only GNU R runs; nothing of
  robigo is built. Tools: gdb 18.1, valgrind 3.25.1. Machine: AMD Ryzen 9
  5900X (24 threads), WSL2 Linux 6.18.
- Scripts and data: `2026-11-16-d0-count/`. `run.sh --callgrind`
  reproduces every number here from a build tree, in about 50 minutes.

### Method

**The runs.** The scripts copy the build tree and replace its `bin/R` with
a tracer (`tracer.sh`). In the copy, `build-steps.sh` runs the R target of
`src/library/Makefile.in` with GNU R's own Makefiles, unedited:
- `make all` for profile, translations, base, tools and compiler;
- then `make mklazycomp` for base and tools.

Each R process that these Makefiles start is traced. There are six, in
this order:

| # | invocation | base from | JIT | path |
|---|---|---|---|---|
| 000 | `tools:::sysdata2LazyLoadDB` (tools' `sysdata`) | source | 0 | other step |
| 001 | `tools:::.install_package_description` (tools) | source | 0 | other step |
| 002 | `tools:::.install_package_description` (compiler) | source | 0 | other step |
| 003 | `tools:::makeLazyLoading("compiler")`, `_R_COMPILE_PKGS_=1` | source | 0 | 2 |
| 004 | `makebasedb.R`, `_R_COMPILE_PKGS_=1` | source | 3 | 1 |
| 005 | `makeLazyLoad.R`, then `makeLazyLoading("tools")`, `_R_COMPILE_PKGS_=1` | base.rdb | 0 | 2 |

The databases made in the copy are GNU R's. The only difference from the
original build is the recorded path of compiler's namespace (`dynlibs`
path), which comes from the copy's location. Path 3 is
`R_DEFAULT_PACKAGES=NULL R --vanilla --no-echo --no-restore -e 1`, run
on a pristine copy. It loads base and compiler (lead decision F1).

**The trace** (`split.gdb.py`). gdb sets a breakpoint at the entry address
of each of the 494 C functions in names.c's Unix table (766 rows):
- A function that serves one row is recorded at its first call, and then
  its breakpoint is deleted.
- A function shared by several rows (59 of them, such as `do_arith`,
  `do_paste` and `do_sys`) records `PRIMNAME(op)` on each call. It reads
  `op` from `%rsi` at the first instruction, as
  `R_FunTab[op->u.primsxp.offset].name`. The breakpoint is deleted once
  all of the function's rows have been seen. No call reached a shared
  function with an `op` that was not a builtin or a special.
- A breakpoint at `run_Rmainloop` marks the end of startup
  (`setup_Rmainloop`). For a run with base from source, startup is
  stage 0: base's collated files through `R_ReplFile`, then the profiles,
  the JIT's compiler (for 004) and `.First.sys`.

The function and row of each first call are recorded in order
(`traces/`). Only one names.c function shares its name with another
function: nmath's static `do_search`. gdb's `*do_search` resolves to
envir.c's function, which is the right one.

**The cross-check with callgrind.** Each of the seven runs was also
profiled with callgrind (`cg-dofuns.py`). In every run, the set of names.c
functions that executed is identical to the gdb trace's:

| run | 000 | 001 | 002 | 003 | 004 | 005 | `-e 1` |
|---|---|---|---|---|---|---|---|
| names.c functions | 201 | 202 | 202 | 214 | 170 | 207 | 123 |
| instructions (G) | 1.30 | 1.43 | 1.42 | 20.8 | 42.9 | 91.3 | 0.0877 |

These are the functions that ran, whether they were called through
`PRIMFUN` or directly from C. Byte code reaches some builtins through
`bcEval`'s inlined opcodes, which never call the `do_*` function:
arithmetic, comparison, `&`, `|`, `!`, math1, `:`, `seq_along`,
`seq_len`, `is.*`, the subsetting fast paths and `DOTCALL`. All of these
are designed away or M1's, except subsetting and `.Call`. Those two are
also reached through their `do_*` functions, so the count has them.

A.2's "188 distinct `do_*`" at `-e 1` counted more than names.c's
functions. The run reaches 123 names.c functions, which serve 146 rows.

### The rule (F4, A)

A row is already Rust at M3, and is not counted, if any of these holds:
1. **M1:** the row is in the registry (188 rows).
2. **Evaluator-owned:** its C function is defined in one of the files
   §10 names: eval.c, envir.c, errors.c, context.c, debug.c, memory.c,
   objects.c, match.c or main.c. names.c has 155 such rows. (§10 says
   about 176; A.1 says about 150.)
3. **Designed away** (§10's first bullet; `f4rule.py`):
   - the **language specials**: `if`, `while`, `for`, `repeat`, `break`,
     `next`, `return`, `function`, `<-`, `=`, `<<-`, `{`, `(`,
     `.Internal`, `quote`, `substitute`, `missing`, `on.exit`, `switch`,
     `&&`, `||`, `UseMethod`, `NextMethod`, `::` and `:::`. These are
     §10's examples plus the rest of cmp.R's language handlers;
   - the **kernels**, by C function:
     - arithmetic, comparison and logic: `do_arith`, `do_relop`,
       `do_logic` and `do_logic3`;
     - math1/2, names.c's "Mathematical Functions" families: `do_math1`,
       `do_trunc`, `do_abs`, `do_log`, `do_log1arg`, `do_Math2` and
       `do_math2`;
     - the summaries: `do_summary` and `do_range`;
     - `:`, `seq_len`, `seq_along` and `length`;
     - coerce.c's `is.*` and atomic `as.*`: `do_is`, `do_isna`,
       `do_isnan`, `do_isfinite`, `do_isinfinite`, `do_isvector`,
       `do_asatomic` and `do_asvector`;
     - `c`, `list` and `rep`: `do_c`, `do_makelist`, `do_rep`,
       `do_rep_int` and `do_rep_len`.

   Outside the evaluator-owned files, this covers 136 names.c rows.

Everything else counts, including rows that robigo-rt already implements
outside the registry. Those rows are marked `*` below. They are subsetting
and its setters, `environment<-`, `invisible`, `deparse`, `.Primitive`,
`.Call` and `dyn.load`, from `rt/prims.rs` and `rtapi/dotcode.rs`. F4's
rule names the registry, so they stay in the count.

**The cross-check on the old runtime (4.5.0)**, as §10 first framed the
count. The old runtime's builtins are Rust functions named in its DEFS

- Booting from base.rdb (`robigo -e 1`): 110 rows, 34 of them counted.
  Three of the 34 are artifacts: the old runtime serves `gzfile`,

bound. It is far from 150, as GNU R's count is.

### Reproducing

```
docs/ledger/g3/2026-11-16-d0-count/run.sh --callgrind   # GNU R only; WORK=.robigo/d0-count
# the old runtime's cross-check, with a release robigo binary:
R_DEFAULT_PACKAGES=NULL valgrind --tool=callgrind --callgrind-out-file=old-e1.out robigo -e 1
ROBIGO_BASE=src R_DEFAULT_PACKAGES=NULL valgrind --tool=callgrind --callgrind-out-file=old-src.out robigo -e 1
D=docs/ledger/g3/2026-11-16-d0-count
python3 $D/old-defs.py crates/robigo-runtime/src/builtins > old-defs.tsv
python3 $D/old-runtime.py old-defs.tsv old-e1.out .robigo/d0-count/funtab.tsv .robigo/d0-count/registry.txt
```

The directory holds:
- the driver, `run.sh`;
- `tracer.sh`, `build-steps.sh`, `split.gdb.py`, `cg-dofuns.py`,
  `funtab.py`, `f4rule.py`, `report.py`, `table.py`, `old-defs.py` and
  `old-runtime.py`;
- the traces, `traces/`;
- `boot-set.tsv` and `report.txt`.
