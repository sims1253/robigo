## 2026-11-16: D1, collection at safepoints only: the run and the decision

- What: D1's bar (`docs/ledger/g3.md`, "D1: collection"), built by T1:
  does collection at safepoints only (docs/g3.md §3) keep E3 and E4 at an
  acceptable cost? The bar's three conditions, each measured.
- Base: main `7af7704e`. Variants: `safepoint` (main itself, H2's design)
  and the control `g3/t1-d1-nopoll` at `e09f0171` (one commit on the base:
  `Cx::safepoint` compiled out, so no poll-word load at any of its call
  sites). Binaries: `cargo build --release --locked -p robigo-rtapi`
  (`robigo-rt`; the binary moved from `robigo-rt` to `robigo-rtapi` in A1,
  after the bar was written) in a private target directory each.
- Machine: AMD Ryzen 9 5900X (24 threads), WSL2 Linux 6.18, rustc
  1.100.0, valgrind 3.27.1.
- Admission: `safepoint` is main, which passes the rt slice (CI's `rt`
  job). The control is inexact, as a control may be (§0): with the poll
  gone nothing collects but `gc()`, so `weak-keys-collections` and the
  stress script miss finalizers on the default heap (the slice on T1's
  branch, 225/235; its other three differences are T1's new cases, which
  main lacks). It only serves the instruction runs, where neither collects.

### Instructions (SUITE and CALLS)

Heap settings for both: `R_NSIZE=50000000 R_VSIZE=16G`. Under them
neither binary collects on any of the eight rows at 2N (`ROBIGO_GC_STATS=1`
on each row's 2N loop: `collections 0` for all sixteen runs), so the
difference is the poll and the safepoint check alone.

```
scripts/idiom-vs-r.py --rows benchmarks/rt/calls-rows.toml \
  --filter '^(plain|defaults|named|env-fn|superassign|s3|fib|binarytrees)$' \
  --robigo BIN --robigo-env R_NSIZE=50000000 --robigo-env R_VSIZE=16G --no-r --json OUT
```

### E3 and E4 (the default heap)

From `2026-11-16-t1-collection.md`, on T1's branch (main plus E3/E4/E9's
tools and the builtins they needed; the collector is main's but for a
report line and the inactive injection knob):

- E3: the stress script missed nothing in 30 ASLR runs per profile (Eval,
  Bc); weak-keys-collections passes; the rt slice under gctorture and under
  `ROBIGO_GC_MOVE=1` with gctorture prints what the plain run does.
- E4: no overshoot passed max(32 MiB, 10% of the live heap) on any of 247
  programs in either profile; the largest is 0.24 of the bound.

### Decision

**`safepoint` is adopted** (it stays): E3 is fully clean, E4's bound holds
on every slice, and its geomean instructions over SUITE and CALLS exceed
the control's by 0.312%, within the bar's 1.0%. No fallback is built
(`g3/t1-d1-autoroot`, `g3/t1-d1-out`). Deleted: the control branch
`g3/t1-d1-nopoll`, after this entry merges.
