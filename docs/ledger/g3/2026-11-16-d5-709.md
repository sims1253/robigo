## 2026-11-16: #709: an address observer under the moving collector, and `.Last.value`'s count

Corrects the open case in `2026-11-16-d5-recycle.md` (Sol's second review):
with `ROBIGO_FRAME_QUARANTINE=1`, `ROBIGO_GCTORTURE=1` and `ROBIGO_GC_MOVE=1`
all set, `tests/rt/capi/inline-reshape.R` printed TRUE where GNU R prints
FALSE. Issue #709 tracked it after D5 merged.

- The case: the block "and forced first" of `inline-reshape.R`
  (`ovf <- function(a = NULL) { b <- a; a <- 1; 0 }`). After the calls,
  `x[1] <- 5` is written, and the address C reads after the write is
  compared with the one it read before.
- Reproduced at main `f21d8b57` and `17f10bf8`:

  ```sh
  ROBIGO_GCTORTURE=1 ROBIGO_GC_MOVE=1 ROBIGO_FRAME_QUARANTINE=1 \
    ROBIGO_CONF_FILTER=tests/rt/capi/inline-reshape.R \
    cargo test --release -p robigo-rtapi --test conformance -- --exact rt_conformance --nocapture
  ```

### The cause: the copy takes the dead original's address

The write copies in every mode, as GNU R's does. Only the observer was
wrong.
- **Counts.** A trace of `x`'s count gives the same values in every mode:
  1 at the assignment, 2 after the first call, 2 more per later call, 9 at
  the end. Recycled, fresh and quarantined frames therefore leave the
  counts that `R_CleanupEnvir` and `clearPromise` leave in GNU R: a dead
  promise's references stay. So the earlier entry's "its count is lower
  than GNU R's in that combination" is wrong.
- **Addresses.** In the three-mode run, the object `evalseq` writes is a
  fresh copy with count 1 at `0x…1d30`, while `p` (the original) was at
  `0x…0830`. The second `rt_addr` returns `0x…0830`. The original died at
  the write. A collection before the second `.Call` (gctorture) freed it,
  and the moving collector moved the copy to that address.
- **Check.** A script that reads the copy's address right after the write,
  before any collection, prints FALSE in the three-mode run too.
- **Why all three settings.** The moving collector moves the copy.
  gctorture collects between the write and the read. Quarantine holds
  poisoned frames as roots, so it changes which blocks are free. Not
  measured: with any two of the three, the copy just doesn't land on that
  address. The case is an artifact of its observer, not of combining the
  modes.

### The fix: an observer that holds the original

`rt_assign_copies(sym, expr, rho)` (`tests/rt/capi/support/identity.c`)
evaluates the assignment from C. While it compares the bound object before
and after, it holds the original on the protect stack, which counts
nothing. Two live objects never share an address. Under `ROBIGO_GC_MOVE=1`
a value handed to C is never moved either.
- `inline-reshape.R`'s three comparisons use it. Recorded on GNU R 4.6.2,
  all three print TRUE (the write copies).
- `inplace-identity.R`'s top-level writes use it too (Sol's review): FALSE
  for each write GNU R makes in place, TRUE for the shared one. Its other
  binding keeps the old object alive, so its address is still compared.
  The first write comes right after a top-level assignment.
- One comparison keeps the address reads: `inplace-identity.R`'s closure,
  whose later calls write in byte code. C cannot evaluate a compiled
  write. That comparison is exact without the moving collector; with it,
  a copy could move to the address of an original that died, which the
  case's comment says.

### Found by the control: `.Last.value` held a count

`inplace-identity.R`'s first write failed in production. Right after a top-level `x <- c(1, 2,
3)`, robigo-rt copied at the next write where GNU R writes in place.
- GNU R's `.Last.value` binding counts no reference: names.c's
  `R_initAssignSymbols` calls `DISABLE_REFCNT(R_LastvalueSymbol)`, "to
  avoid creating an additional reference that would require duplicating on
  modification".
- `Rf_ReplIteration` instead raises the count of a value nothing
  references (`if (NO_REFERENCES(value)) INCREMENT_REFCNT(value)`). So a
  variable later bound to `.Last.value` shares it.
- robigo-rt bound `.Last.value` with `define_var`, which counts. So every
  value of a top-level assignment had one count more than in GNU R.

The fix (`robigo-rtcore`):
- The `.Last.value` symbol tracks no references (`NO_TRACKREFS`, GNU R's
  TRACKREFS).
- A base binding's store counts only for a symbol that tracks them, which
  is `FIX_BINDING_REFCNT`'s `TRACKREFS(x)` test.
- `Cx::set_last_value` is `Rf_ReplIteration`'s store plus the raise, and
  robigo-rt's console loop calls it.
- `tests/rt/toplevel/last-value-counts.R`, recorded on GNU R 4.6.2, binds
  `.Last.value` to a variable and writes that variable before the next
  top-level statement. Without the raise, `.Last.value` changed with the
  variable in all three of its blocks.

### rt-ci: no step for the three settings together

The whole conformance, with the three settings together and
`ROBIGO_CONF_TIMEOUT=600`:
- main `17f10bf8`: 259/265. `inline-reshape.R` is its one ratcheted
  regression; the other five failures are main's unratcheted ones.
- This change: 261/266, with `last-value-counts.R` new, and no regression.
- 170 s each, the two run side by side on this machine.

Recommendation: no step for the three together.
- The combination found an observer that compared a dead object's
  address, not a defect. Every observer that C can run holds the
  original now (the closure case above cannot), and
  `docs/verification.md` states the rule.
- That such a step would find nothing more is a judgment, not a
  measurement (Sol's review says so too).
- Quarantine catches an escaped frame at its next use whatever the
  collector does.
- The moving collector's step runs with recycling on, and every
  collection empties the pool, so a pooled frame never lives through a
  move.
- Cost: on CI (`rt` job of main `7849ccf9`, 530 s), the conformance under
  `ROBIGO_GC_MOVE` with gctorture takes 124 s and its crates' tests 16 s.
  A three-setting copy of the two would add about 140 s, +26%.
