## 2026-11-16: E8's unwind cases recorded on GNU R 4.6.2

The lead's decision (b) of `2026-11-16-m1-exit-lead-decisions.md`: E8's
expectations come from GNU R, not only from hand-written Rust assertions.
These cases block M1's sign-off, not the exit evidence's merge (#732). The
Rust tests stay.

- **Base:** main `c536597d`. Branch `g3/a1-e8-oracle`.
- **The bar** (`docs/g3.md` §15.3, E8): "`on.exit` that catches its own
  error during an unwind returns the outer condition; `R_UnwindProtect`
  cleanup that catches an error resumes the original continuation; a C
  context's `cend` runs before the jump; all in every tier and across a C
  frame".

### The cases

- **`tests/rt/conditions/onexit-unwind.R`, in R:** `f`'s `on.exit` code
  catches its own `stop("inner")` during the unwind of `stop("outer")`.
  It also covers:
  - the condition and call that leave (`outer`, `f()`);
  - an outer calling handler: the exiting handler inside it gets the
    condition first, so the calling handler never runs;
  - two levels of `on.exit`;
  - a warning muffled in `on.exit` code during the unwind;
  - the uncaught error at the top level (`Error in f() : outer`,
    status 1).
- **`tests/rt/capi/e8-unwind.R`, across a C frame:** its C is
  `support/e8_unwind.c`, with the three E8 functions of
  `crates/robigo-rtapi/tests/support/capi_test.c` logging with `Rprintf`.
  `scripts/regen-expected.sh` builds it for GNU R
  (`scripts/rt-capi-build.sh --gnur`), and the conformance test builds it
  for robigo-rt. The cases:
  1. `on.exit` code that catches its own error, with a C routine between
     the error and the catcher;
  2. an `R_UnwindProtect` cleanup that catches an error of its own;
  3. `R_ExecWithCleanup`'s cleanup running before the jump.

  A closure, `cases()`, runs all three, three times. GNU R's JIT runs its
  first call as the AST and the later ones as byte code, so both tiers are
  recorded. The recording shows which tier ran, because GNU R's message
  differs between them (below).

### What GNU R says that the Rust tests do not

- **The message that reaches `tryCatch` in case 2** is
  `"Error: the cleanup's own\n"`, not the original error's.
  - For an error raised in C (`error()`), the exiting handler's
    condition is built after the jump, from `geterrmessage()`
    (`conditions.R`, `tryCatchOne`).
  - The cleanup's own error, caught by `R_ToplevelExec`, has overwritten
    that buffer by then.
  - The Rust test (`capi.rs`, E8 2) asserts robigo-rt's own error,
    "original", at the Rust level, which is a different observation.
- **`R_ToplevelExec` prints the errors it catches** on stderr ("Error:
  inner", "Error: the cleanup's own").
- **The message depends on the tier.** In byte code the cleanup's error
  names the `.Call`: `Error in .Call("e8_unwind_catching_cleanup") : the
  cleanup's own`. In the AST it names none.
  - The reason is `getCurrentCall()` (`errors.c:380`). When
    `R_BCIntActive` is set, it returns the byte-code interpreter's
    expression.
  - In the AST, `.Call` gets a `CTXT_BUILTIN` context (`eval.c:1255`).
    In byte code, a builtin gets one only when profiling.

robigo-rt matches all three in both tiers.

### Runs

| mode | `onexit-unwind.R` | `e8-unwind.R` | `capi/unwind.R` |
|---|---|---|---|
| GNU R's JIT decisions (the default) | pass | pass | pass |
| the same, `ROBIGO_NO_INLINE=1` | pass | pass | pass |
| `ROBIGO_RT_PROFILE=eval`, inlining on and off | pass | differs | pass |
| `ROBIGO_RT_PROFILE=bc`, inlining on and off | pass | differs | pass |

- **The forced profiles** differ from GNU R's decisions by design. A
  forced profile is a test switch that overrides them, and GNU R has no
  such mode.
- **Where `e8-unwind.R` differs** under them, the difference is GNU R's
  tier-dependent message, and only that line:
  - forced `eval` prints the AST's message on the runs GNU R compiled;
  - forced `bc` prints the byte code's message on the run GNU R did not
    compile.

  So robigo-rt gives each tier GNU R's message for it.
- **rt-ci:** the full run passes. Conformance is 296/297 in production
  and under each mode:
  - `ROBIGO_MATERIALIZE=1`, the frame quarantine and the small vector
    limit: 296/297;
  - both gctorture steps: 295/296 (`radix-volume.R` skipped);
  - `ROBIGO_NO_INPLACE=1`: 294/295 (two cases skipped).

  The one failure is `args/binding-types.R`. Both new cases are ratcheted,
  so every conformance step runs them.

### Review

Sol's first round found that `e8_unwind.c` built each `.Call` with
`lang3(install(".Call"), mkString(...), mkString(...))`. Each `mkString`
result was left unprotected while the other allocated. GNU R 4.6.2 under
`gctorture(TRUE)` corrupted case 3: it returned `"e8_error"` instead of
`"from the body"`.
- **The fix:** each string is protected before the next allocation.
- **The checks:**
  - The re-recording is unchanged.
  - GNU R under `gctorture(TRUE)` prints exactly the recording.
  - robigo-rt passes the cases under every mode above.
- **A follow-up:** `crates/robigo-rtapi/tests/support/capi_test.c`, whose
  E8 functions these mirror, has the same pattern in three places. It is
  outside this change.

### What stays open

- **The base subset:** `scripts/base-subset.sh` traces the `conditions`
