## 2026-11-16: P1 step 14, the real call's fixed costs, round 2: frame setup in one pass, and an owner check of one compare

Round 2 of the foreman's item, the real call's fixed costs
(`2026-11-16-p1-call-1.md`): the parts of the call path outside
`args.rs`, while S1's fix 4 (#718) was in review.

- Base: round 1, `g3/p1-call-path` at `bce786da` (#717). Change: branch
  `g3/p1-call-path-2`, measured at `41c80fad` (`robigo-rtcore`).
- **Step 1, frame setup in one pass** (`24a10360`). `new_closure_frame`
  took a recycled frame and cleared it slot by slot (`recycle::reinit`),
  keyed every slot, then filled each argument's slot, writing its meta
  word four times (the stamp, MISSING, two flags). Now `reinit` resets the
  header alone, and one pass writes each slot's key, value, aux and meta
  word, the meta word composed once.
- **Step 2, the owner check** (`41c80fad`). Every bind and reset of a
  root, every `Out` written and every `Args` read checks that its slot is
  this isolate's value stack's (docs/g3.md §2.3, in every build): its
  offset from the base below the stack's span, and aligned. Rotated right
  by the slot size's bits, the offset is the slot index when aligned, and
  has its high bits set when not (or below the base, which wraps), so one
  compare against the slot count gives the same answer.
  - The check stays in every build, and cross-isolate misuse still
    panics (`tests/api.rs`, `handles_and_objects_of_another_isolate_are_refused`).
  - A unit test compares the old and the new test at every edge: the
    first and last slot, the limit, each misaligned byte, below the base.
  - Checking once per scope, the foreman's other option, is not sound
    today. Two isolates' capabilities can be used interleaved on one
    thread (that test does), and a `Root` binds with any `Cx`, so the
    scope's brand does not prove the isolate. `Cx` would have to carry
    the brand.

- Not done, and why:
  - **Cleanup's and recycling's passes.** Profiled, `cleanup_envir`'s
    own lines are about 100 instructions per call. Fusing its scan for a
    cell, its release and the pool's scan would save perhaps 25-50. The
    rest of those functions' cost is counted stores and owner checks.
  - **A counter for `release_caller`** (44 per call, its scan for a
    delayed slot that evaluates in the caller). Seven places end such a
    slot, and the cleanup and an argument's materialization change several
    without calling it. An undercount would release a caller frame a slot
    still needs. The counter would save about 25 per call; left to the
    foreman.
