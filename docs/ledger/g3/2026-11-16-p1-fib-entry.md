### The gap, for the exit review: E2 `fib` is not reachable in M1 this way

After step 2, an inline `fib` call costs 1,317 instructions against today's
robigo's 1,008 (1.31x). What is still visible in the profile, with
estimates:

| cut | per call (est.) |
|---|---:|
| memoize the callee's and the argument code's verification (the code-object checks at every `CALL_FUN` and every force) | ~60 |
| specialize each call's argument shapes when its body is decoded, so a force reads them from the step instead of the argument code's attribute word | ~80 |
| the frame's setup (its `args` array) and the entry's prologue | ~30 |

Together that is about 1,147 per call (1.14x), not 1.0x. The rest of the
difference is structural:
- **Today's robigo evaluates a nested call's arguments eagerly**, at the
  call site, as leaves (constants, variables, registers, arithmetic of
  leaves), before the callee runs (`robigo-runtime`'s `nested_call_inline`).
- **robigo-rt forces them lazily in the callee**, as GNU R does. Each force
  makes GNU R's evaluation counts (`early_force`: the force's `bcEval`
  count and depth) and can give up where GNU R would warn or err. This
  costs about 245 instructions per call (`Frame::eval` and its reads).
- **Eager evaluation would be sound only where it is proven unobservable.**
  The same counts would have to land at the same points (the 1000-eval
  poll), and no warning or error could move: integer overflow's warning,
  an unused argument that errs.

The two ways to 1.0x are that proof and the native tier for hot pure
closures (G8, fix 4 of the gap entry's plan), which M1 does not have.
Recommendation for the exit review: record E2 `fib` as unmet at about
1.3x in M1, owed to the native tier. The three cuts above are worth
taking only if they cost little elsewhere (about 13% of `fib`).

Found on the way (Sol's review): robigo-rt has no R-level
`options(expressions = ...)` setter. Sol's depth checks set the limit
through `Cx::set_expressions` from a test driver.
