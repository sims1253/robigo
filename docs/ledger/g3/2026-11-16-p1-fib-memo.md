## 2026-11-16: P1 step 17, E2 `fib`: a call site remembers the callee code it ran inline

The foreman asked to go on with `fib` after step 15
(`2026-11-16-p1-fib-entry.md`), which recorded E2 `fib` as out of reach in
M1 and listed the cuts still visible. This is the first of them, the
code-object checks at every inline `CALL_FUN`.

- Base: `g3/p1-fib-entry` at `5efca7a2` (#722, merged into main since).
  Change: branch `g3/p1-fib-entry-2`, measured at `a9b4cb71`
  (`robigo-rt`).
- **What a call paid.** Every fused `CALL_FUN` of an inline run judged its
  callee in full before entering it (`inline_code`), about 90 instructions
  per `fib` call by callgrind's per-line attribution:
  - the isolate's inline, forced-profile and byte-code switches;
  - the closure's debug bits, JIT state and NO_INLINE bit;
  - its 4th word checked to be a code object (type, flag, length, blob,
    magic, profile), current, for its formals, with a shape;
  - `candidate`'s verdict.
- **The change.** The fused step keeps the stamp of the code it judged (its
  `imm` word, unused by `CALL_FUN`), and the next call through it takes
  that code when the closure's 4th word still holds it (`memo_code`).
  - Stamps are never reused, so an equal stamp stands for the checks that
    cannot change for a code object: its structure, profile, shape and
    verdict.
  - What can change is tested again on every hit: the switches, the
    closure's debug, JIT and NO_INLINE bits, and the code's currency and
    formals (`code::is_still_closure_code`).
  - A closure's 4th word is R_NilValue or a code object (only `jit` and
    `call` write it), so the stamp is read after a nil test.
  - A miss judges in full and remembers.
- `tests/rt/capi/inline-call-memo.R`, recorded on GNU R 4.6.2: between two
  calls of one site, the callee redefined, its default written from C, and
  a formal renamed from C. A counting build showed 7 memo hits and 6 full
  judgments in it, and thousands of hits in `tests/rt/inline`.
- Per `fib` call (whole process, callgrind): 1,316.8 on the base,
  1,289.4 on the change.
- A variant that computed the step's address only in `CALL_FUN`'s arm made
  the same counts: the compiler already does.
- Admission at `a9b4cb71`: `scripts/test-rt-ci.py` and `scripts/rt-ci.py`
  pass every step (conformance 285/290, 284/289 in the modes whose
  `.requires` leave a case out; main's 5 unratcheted failures).
  `cargo +nightly-2026-11-02 miri test -p robigo-rtcore`, `scripts/lint.sh`
  and `cargo fmt --check` pass too.
- Commands as in step 2 (`rt-bars.sh` twice, `s3` three more times,

- Raw JSON: `data/2026-11-16-p1fibmemo-a9b4cb71/run{1,2}-*.json` and

### The gap, for the exit review (updated from step 15)

E2 `fib` is still not reachable in M1. What the profile still shows, with
estimates:

| cut | per call (est.) |
|---|---:|
| the force's check of the argument's code (`code::cached` on the call's 4th word, the shape's cell) | ~30 |
| the inline frame's setup (its `args` array, the code's view) | ~30 |
| the register file, zeroed in full per call (16 slots) | ~10 |

Together that is about 1,220 per call (1.21x). The rest is step 15's
structural difference: the lazy, count-exact forcing of each argument
(about 245 per call), which today's robigo skips by evaluating leaf
arguments eagerly. The recommendation stands: record E2 `fib` as unmet at
about 1.3x in M1, owed to the native tier (G8).
