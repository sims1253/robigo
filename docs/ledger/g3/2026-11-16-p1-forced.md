## 2026-11-16: P1 step 2, caller-forced arguments: compiled callers compute pure arguments early

The second P1 family (base and bars: `2026-11-15-p1-base.md`; step 1:
`2026-11-15-p1-frames.md`): forcing an argument. On the frames base a
`plain` argument's force cost about 600 instructions (the promise code's
byte-code entry, `eval_in`, `expr_code`, its VM run). perf-vm's
caller-forced arguments and its static rejection memo are the carry-overs
taken here.

- Base: `g3/p1-frames` at `602edd43`, the binary of step 1's table
  (`data/2026-11-16-p1frames-602edd43/`). Change: branch `g3/p1-forced`
  (`robigo-rtcore`, `robigo-rtbuiltins`, `robigo-rt`), measured at
  `2ae5dbf1`. That commit is `d90a7a7b` after the branch's rebase onto step
  1's test-only commit `92c589dc`; the rebase changed `tests/jit.rs` alone,
  and `2ae5dbf1` is not on the branch. The branch's last code commit,
  `aa4a70db`, only moves a `SAFETY` comment for clippy: `plain` measures
  5,954 and 5,955 instructions per iteration on the two builds (one
  `callgrind-diff.py` run each).
- What changes:
  - **Early values** (`robigo-rt`'s `early.rs`, docs/g3.md §6.2's
    precomputed arguments). Some arguments of compiled code are computed by
    `args::apply` and bound delayed with their value
    (`SlotInit::Delayed { value: Some }`). One kind is a symbol bound to a
    value. The other is a call whose cached byte code only loads constants,
    reads such variables and does arithmetic on its fast path, without a
    warning. The isolate keeps that frame as its early frame. The first of
    these drops every value it holds (`Cx::note_effect`):
    - a closure call (`args::apply`);
    - a builtin or special call (every place the evaluator calls one:
      `call::run_builtin`, `bcassign`'s and `dispatch`'s calls, `apply`'s
      specials, `Builtin::invoke`);
    - a binding write in any environment other than the early frame itself
      (`define_var`, `define_scalar`, `set_var`, `set_var_super`,
      `set_var_loc_value`, `remove_variable`, the slot-indexed store).

    A value still there when the callee reads the argument is the value
    GNU R's evaluation gives at that read. The force takes it and makes the
    evaluation's counts through `Hooks::early_force`: `R_Visible`, the
    depth check, and `eval`'s count for a symbol or `bcEval`'s entry count
    for a call. When either count would poll, or the depth would pass
    `R_Expressions`, it evaluates the expression as before.

    Nothing is compiled early: a call's code comes from the cache an earlier
    force filled. A promise made from such a slot (materialization) does not
    carry the value, and a call's end drops values its callee did not take.
  - **A formal's first read** forces the slot its compiled index names
    (`Cx::force_arg` on the activation's frame). Before, `GetVar`'s slow
    path looked the variable up again.
  - **The VM's boxed operands**: `vm::num` reads a non-ALTREP length-1
    double, integer or logical without attributes from its words, not
    through `ops::plain_num`'s view.
  - **Rejection memo**: early values dropped before they were taken stop
    their call site computing them. Drops come from an effect, a
    materialization such as `UseMethod`'s promise list, or an assignment
    over the argument. The site's match plan keeps a per-formal mask
    (`Plan::no_early`) for that callee's stamp. A call keeps an outer call's
    record of dropped values while it runs.
  - `apply` reads the evaluator state's fields once. `Root::bind`, the
    `apply` wrapper and `ops::arith2` are always inlined (measured: without
    that, `s3` stayed 0.6% above the base).

- New conformance case `tests/rt/args/early-values.R` (GNU R 4.6.2's
  recording, ratcheted). Between the call and the read, the callee:
  forces another argument that assigns in the caller; assigns the caller's
  variable with `<<-`, `assign` or `e$v <-`; calls a closure that does;
  captures its frame and returns; never reads the argument; reads it through
  `substitute`; reads it in a default or through a promise chain;
  dispatches it with `UseMethod`, before or after an assignment; assigns
  over it. Also covered: missing arguments, integer overflow (not computed
  early: its warning is the force's), visibility, and recursion. It passes
  under `ROBIGO_COMPILE=0` and `1`; the frames binary passes it too.

The first full measurement, at `b2f37580` (the first three changes),
had `s3` 2.0% above the base. `area(sq)`'s value was computed early, then
lost to `UseMethod`'s promise list, and `apply` read the state once more
and lost some inlining. The memo and the last row of the table above
brought it back to the tie band (+0.11%).

E1 and E2 after this step: `plain` 1.33x GNU R 4.6.2's instructions (bar
0.6x), `fib` 4.53x today's robigo (bar 1.0x). A `fib` call is now 4,564
instructions (`scripts/callgrind-diff.py` on the `2ae5dbf1` binary). About
2,540 of them are the call itself: `args::apply` 925, the frame 305 and
its allocation 118, the context 178, `R_CleanupEnvir` 205, `vm::exec` 147,
and about 760 more (the actuals, the JIT check, the special-symbol check,
`end_call` and the rest). The early pass itself is 403, the VM loop 944.
