### superassign: 8,836 against GNU R's 7,480 (1.18x; bar 1.0x)

The iteration is `a$dep(i %% 7)`, where
`dep <- function(x) { bal <<- bal + x; invisible(bal) }`. `dep` cannot
run inline: `<<-` writes its enclosure's binding, and `invisible` is a
builtin call. So every iteration makes a real call.

| cause | instructions | largest |
|---|---:|---|
| call | 2,471 | `args::apply` 916, `early_args` 454, `new_closure_frame` 314 |
| VM | 2,095 | `vm::run` 2,013 |
| builtins | 1,238 | `invisible`'s `builtin_evallist` 499, `$` 351, `%%` 137 |
| lookup | 895 | `fun_lookup_raw` 334, `loc_in_frame` 309 (`<<-`'s walk) |
| alloc | 438 | |
| assign | 257 | `<<-`'s `set_var` and `set_binding_value` |

GNU R spends its 7,480 in `Rf_eval` (1,225), `bcEval_loop` (697),
lookups (`findVarInFrame3` 332, `findFun3` 261), matching (237) and
allocation (`allocVector3` 248, `CONS_NR` 226).

Planned fix: run `dep` inline.
- `<<-` becomes a buffered write. The inline run logs it, its own later
  reads see it, and the commit applies it as `setVar` would. A give-up
  discards the log, so nothing is written twice.
- A short list of pure builtins (`invisible`) is called inline.

That removes the call and most of the lookups: about 3,000 by step 7's
numbers.

### s3: 32,138 against GNU R's 18,497 (1.74x; bar 1.0x)

| cause | instructions | largest |
|---|---:|---|
| dispatch | 7,118 | `define_var` 2,379 (the method frame's variables), `lookup_method` 1,479, `add_missing_vars` 1,124, `install_s3_signature` 739, `topenv` 480 |
| call | 4,992 | `args::apply` 1,815 (the generic's and the method's calls), `match_args` 664, frames, contexts, cleanup |
| alloc | 3,436 | `alloc_node` 1,251, malloc/free about 1,300, `Vec` growth 404 |
| lookup | 1,953 | `loc_in_frame` 1,473 (the method search) |
| VM | 1,579 | |
| other | 1,217 | `DefaultHasher` 267 |

GNU R spends 2,709 in its collector, then `bcEval_loop` (1,027),
`findVarInFrame3` (938), `SETCAR` (840), `matchArgs` (795) and
`R_LookupMethod` (452).

Planned fixes, in order of size:
1. **A dispatch cache per call site.** Memoize (generic, class vector,
   method table versions) to the method found, so `lookup_method`, its
   frame walk and `topenv` run once: about 3,400.
2. **Lazy dispatch variables.** `.Generic`, `.Class`, `.Method`,
   `.GenericCallEnv` and `.GenericDefEnv` are made, as `define_var` and
   `add_missing_vars` do, only when something reads the method's frame
   (as §6.2's lazy promargs): about 3,500.
3. **Less allocation.** Dispatch's pairlists and `Vec`s built per call,
   and a hasher on the dispatch path.
4. **Dispatch from slot frames.** D4's and D2's re-runs
   (`2026-11-16-p1-reruns.md`) measure `s3` 967 instructions lower with
   promise arguments and 2,001 lower with pairlist frames than with
   slots. `UseMethod` rebuilds the generic's arguments (`promargs`) and
   the method's frame from the slot frame, and those two controls hand
   it the objects it needs as they are. Reading the slots directly would
   recover that.

### E2 fib: 2,123 per call against today's robigo's 1,008 (2.11x; bar 1.0x)

In estimated cycles: 17.88M per `fib(18)` against today's 8.47M
(2.11x). After step 6, 8,209 of every 8,361 calls of `fib(18)` run
inline. The other 152 make real frames, per the bars' allocation counts:
calls the 12-call budget does not reach. The inline run's cost:

| part | instructions per call |
|---|---:|
| `inline::enter`: the body's 8.5 ops on average, entry, matching | 1,465 |
| `Frame::eval`: forcing `n - 1`, `code::cached`'s checks, then the argument code over the generic pure interpreter | 497 |
| `Frame::read` | 62 |
| `ops::relop2` | 43 |

Today's robigo's own inliner spends 451 in `run_inline_args` and 229 in
`nested_call_inline`, with argument forms specialized at the call site.

Planned fixes:
1. **Decode a qualifying body once,** at its verdict, into a compact form.
   Operand kinds are resolved, and an op without evaluation-point flags
   does no flag test.
2. **Memoize a site's argument shape** (a symbol, a constant, `x op k`),
   so a force skips `code::cached` and the interpreter.
3. **Keep typed scalars** through the run, without `vm::num`'s
   re-dispatch per operand.
4. **Then the native tier** for hot pure closures (G8).

Fixes 1-3 target about 2,000 instructions of fixed overhead, the size
of the gap. That is an estimate until they are measured.

### E2 binarytrees: 6,224,507 per iteration against today's robigo's 4,110,191 (1.51x; bar 1.0x)

In estimated cycles: 6.69M against today's 4.41M (1.52x). Neither
closure qualifies: `make` builds `list(...)`, and `check` reads
`t[[1]]` and calls `is.null`. The iteration makes 1,022 real calls, about
6,200 instructions each against today's 4,000:

| cause | instructions | largest |
|---|---:|---|
| call | 2,776,122 | `args::apply` 965,253, `early_args` 363,403, `new_closure_frame` 306,018, `exec` 231,503, context 195,475, forcing 172,101 |
| VM | 1,608,960 | |
| builtins | 844,086 | `[[` 383,896 with `SubArgs` and `get1index`, `list` |
| alloc | 305,360 | |
| lookup | 218,708 | |

Planned fixes:
- run `check` inline: `[[` on a plain list (no class, no dispatch) and
  `is.null` as pure reads;
- let `make` allocate in an inline run, which needs the run to root what
  it makes;
- the real call's fixed costs (frame, context, early arguments), the
  remaining P1 call-path work that all non-inlinable rows share;
- frame recycling, if the lead adopts it (D5's re-run): it removes the
  1,022 frames per iteration, lowers estimated cycles 2.5% and peak RSS
  22%, and costs 0.2% in instructions.
