## 2026-11-16: P1 step 4, lookups: a name the frame's shape lacks skips the frame; promise and argument code read their frame's slots

The fourth P1 family (base and bars: `2026-11-15-p1-base.md`; steps 1-3:
`2026-11-15-p1-frames.md`, `2026-11-16-p1-forced.md`,
`2026-11-16-p1-call.md`). This is the work list's per-site function lookup

- Base: `g3/p1-call` at `ae7dfe38` (step 3's measured binary; its data
  `data/2026-11-16-p1call-ae7dfe38/`). Change: branch `g3/p1-funmemo` at
  `3b664616` (`robigo-rtcore`, `robigo-rt`).
- What changes:
  - **A name the frame's shape lacks.** A `GetFun`, or a `GetVar` without
    a slot, of a name the code's shape lacks passes over a frame of that
    shape with no overflow block that is not an object
    (`Cx::frame_lacks_raw`: one compare with the code's shape, two loads).
    Such a frame binds nothing of the name. `index_slots` marks such a
    `GetFun` in its free `f`. When the enclosure is the global
    environment, a function found through the global cache is read at
    once (`Cx::fun_lookup_skip_raw`): `findFun3`'s answer there, since the
    cache is `findGlobalVarLoc`'s. Anything else (an active binding, a
    promise, a value that is not a function, a special symbol) takes the
    full lookup from the enclosure.
  - **Promise and argument code read their frame's slots.** Code that is
    not a closure's now carries an index shape (code element 6; the
    constant pool moves to 7). Argument code compiled with a closure gets
    the closure's frame shape once it exists. A promise compiled at its
    first force gets the shape of the frame it runs in
    (`code::set_index_shape`). Its `GetVar`/`SetVar`, and the early pass's
    reads (`early::run`), go to those frames' slots. In a frame of another
    shape (the expression evaluated elsewhere), the one compare fails and
    the full lookup runs.
  - The #681 review's follow-ups: the slot read and the scalar store
    debug-assert that the index is within the shape, and the store that
    the slot's symbol is the one stored. `#[inline]` on
    `Cx::frame_slot_raw` measured cheaper than `#[inline(always)]` (table
    below), so it stays.
