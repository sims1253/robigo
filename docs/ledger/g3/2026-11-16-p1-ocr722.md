## 2026-11-16: P1, #722's deferred reads: code objects and `LdScalar` constants without the EXTDATA test

OCR's three findings on #722 (`2026-11-16-p1-fib-entry.md`), deferred
there so as not to restart its green CI, and assigned to X/P1 in the
M2/M3 plan's deferred items.

- Base: main at `d25d0586`. Change: branch `g3/p1-ocr722`, measured at
  `0437f393` (`robigo-rt`).
- **`formals_stale_bc`** (`code.rs`) read its code object's FORMALS and
  SHAPE words through `std_data`, which tests EXTDATA, while its twin
  `is_closure_code` used `inline_data`. Both read objects `code::build`
  made, whose payloads are inline. Both now use `inline_data` and bind the
  payload pointer once instead of three times.
- **`LdScalar`'s constant** (`inline::scalar`, and the VM's `LdScalar`)
  was read through `std_data` too. The compiler emits `LdScalar` only for
  a plain scalar constant (`compile::plain_scalar_const`), which now also
  refuses an EXTDATA vector, so a C-owned scalar in a body is loaded as a
  constant (`LdConst`) and `LdScalar`'s operand always has its payload
  inline. Nothing in the runtime makes EXTDATA vectors yet
  (`Core::alloc_extdata` has no caller in `robigo-rt`, `robigo-rtcore` or
  `robigo-rtapi`), so no case can reach the refusal today; it keeps the
  guarantee for when `allocVector3`'s allocators make them.
- **Sol's finding at `5acaa120`:** `Comp::operand` checked its own
  constant, but `kv` may return an earlier pool entry `identical` to it,
  and `identical` does not tell storage apart, so a later inline `1` could
  load an earlier EXTDATA `1` with `LdScalar`. `0437f393` checks the entry
  `kv` selects, and loads a constant whose entry is not a plain scalar as
  an object (`const_value`, LDCONST). The pool's deduplication is
  unchanged: GNU R's compiler deduplicates by `identical` as well.
- Admission at `0437f393`: `scripts/test-rt-ci.py` and `scripts/rt-ci.py`
  pass every step (conformance 308/314, and 307/313 or 304/309 in the
  modes whose `.requires` leave cases out; the failures are main's
  unratcheted ones). `scripts/lint.sh` and `cargo fmt --check` pass.
  `robigo-rtcore` and `robigo-heap` are unchanged, so no Miri run.
- Commands: `scripts/rt-bars.sh` twice for each binary, `s3` three more
  times, `scripts/rt-bars-compare.py --a main ... --b ocr ...`.
- Raw JSON: `data/2026-11-16-p1ocr722-0437f393/run{1,2}-*.json` and
