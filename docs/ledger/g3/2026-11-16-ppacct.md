## 2026-11-16: PPACCT, GNU R's protect-stack depths in eval.c's "stack imbalance" warnings on robigo-rt

- What: the foreman's PPACCT package (A1's question (a); its data in
  `2026-11-15-a1-review-follow-ups.md`): a C routine that leaves the
  protect stack unbalanced gets eval.c's `check_stack_balance` warnings at
  the sites GNU R 4.6.2 checks, with GNU R's depths, through both
  evaluators; byte-compiled callers check nothing. Plus #682's two
  deferred lows.
- Tree: branch `g3/ppacct` at `79db627b`, on main `2c6075a5` (#682
  merged). Binaries: `cargo build --release --locked -p robigo-rtapi`
  (`robigo-rt`), main's and the branch's, each in a private target
  directory. Machine: AMD Ryzen 9 5900X
  (24 threads), WSL2 Linux 6.18, rustc 1.100.0, valgrind 3.27.1. GNU R:
  the 4.6.2 oracle image (`scripts/oracle-run.sh 4.6.2`) for every
  recording and probe.

### The account

robigo's `R_PPStack` holds C's protections only; GNU R's also holds its
evaluator's (`PROTECT(op)` in `eval`, `evalList`'s head, `applyClosure`'s
`newrho`, ...). GNU R's top at a point is its evaluator's protections plus
C's, so robigo keeps the evaluator's part, as an excess over `R_EvalDepth`
(`E`, `robigo_rtcore::ppacct`):

- byte code never changes `E`: each transition `bcEval` makes protects one
  object for each level of `eval` it nests (a closure call: `newrho`, then
  `eval` of the body; a promise: `forcePromise`'s `PROTECT(e)`, then `eval`
  of its code), and it calls builtins and specials with neither. A `Bc`
  activation reads and writes nothing.
- the `Eval` profile's positions: the compiler derives each instruction's
  offset from GNU R's per-construct `PROTECT`s (`eval`'s `PROTECT(op)` and
  `PROTECT(e)`; `evalList`'s head and `...`'s `h`; `do_begin`'s four;
  `do_for`'s seven; `do_internal`'s; ...), kept in the code object; an
  instruction that calls out sets `E` from it, and an activation restores
  the `E` it was entered with.
- the builtins that protect before they evaluate add their own around the
  evaluation: `do_internal` 1, `lapply` 6, `vapply` 7 (9 with names),
  `R_forceAndCall` 2 (robigo-rt's `force_and_call` hook, ported for them),
  `do.call` 2, `eval` 2, `UseMethod` 3 + `usemethod` 2 + `dispatchMethod` 5,
  `NextMethod` 8, `DispatchOrEval` 3, `DispatchGroup` 10, `switch` 2,
  `[`'s `R_DispatchOrEvalSP` 1 (4 when an object has no method),
  `forcePromise` 1, `Rf_ReplIteration` 1 (2 for the print).

The checks are where GNU R makes them: the AST's builtin and special calls
(an inlined one's guard saves C's top and an `Op::PpCheck` compares it at
its end; the generic call path; complex assignment's getter and setter
calls), `do_internal` (special internals in both profiles; builtin
internals in the `Eval` profile, byte code calls those directly) and
`applyMethod` (a builtin method). `.Call`'s own check, which warned after
every `.Call` with robigo's depths, byte code's included, is gone.

GNU R's AST leaves by `longjmp`, which restores the top a context saved:
`return` leaving a closure's body and `break`/`next` landing at their loop
now restore C's top as that `longjmp` does (UseMethod's jump and every
exit already did, `restore_globals`). The top level resets the top for
each statement (`Rf_ReplIteration`'s `R_PPStackTop = savestack`).

### Proof

- Probes (`2026-11-16-ppacct/probe{1,2}.R`, the routine `leak.c` there,
  GNU R's stderr beside them): 56 sites, each a leaky `.Call` in one
  construct, run under GNU R 4.6.2 and robigo-rt with the JIT at its
  default and with `R_ENABLE_JIT=0`: stdout and stderr byte-identical in
  all four pairs of runs. On main the probe prints only `.Call`'s own
  warning, after every `.Call` (byte code's too), with robigo's depths,
  which grow through the script (`0 then 1`, `1 then 2`, ...: nothing
  reset the top between statements).
- Cases: `tests/rt/capi/ppacct-{toplevel,closures,loops,calls,dispatch}.R`
  (the routine: `tests/rt/capi/support/ppleak.c`), recorded on 4.6.2:
  top level, invisible, `c`, `+`, `(`, `{`, `if`, `&&`, assignment (simple,
  `$<-`, `names<-`), `[`, `switch`, `.Internal` (also reached through a
  value), closures (AST, then compiled), promises, `return` (AST and compiled), recursion through `if`
  (compiled, AST in a local frame), `for`/`while`/`repeat` (top level
  compiled, local AST with `break`/`next`), `lapply` (also with a
  primitive `FUN`, which `R_forceAndCall` calls with no check), `vapply`,
  `local`, `eval`, `do.call`, `tryCatch`, `withCallingHandlers`, `print`,
  `UseMethod`, `NextMethod`, an internal generic's method, a group method,
  a `[[` method `lapply` calls before `FUN`'s body.
  5/5 pass and are ratcheted. The rt slice: 238/243 (the five failures
  predate the branch and have no marker). `scripts/rt-ci.py` at
  `79db627b`: every step passes (356 s), the slice the same under
  gctorture, the moving collector and the small vector limit;
  `scripts/lint.sh` clean.

### Review

Sol (`gpt-6.1-sol`, high), three rounds. Round 1: `lapply`'s and `vapply`'s
primitive `FUN` got an extra check (`R_forceAndCall` makes none), and an
`.Internal` reached through a value missed `do_internal`'s check of the
inner builtin. Round 2: a closure `FUN`'s first argument was forced in its
body, not before it (a pre-existing difference, robigo-rtbuiltins'
apply.rs said so): `R_forceAndCall` is now ported for both (robigo-rt's
`force_and_call` hook), each with a recorded case. rt-ci under the moving
collector found the `.Internal` wrapper (`NextMethod`) reading its
primitive's name after the call, which can move it; it is read before.

### Not ported

- A routine that unprotects more than it protected is still robigo's error
  ("unprotect(): only N protected items", N C's own), where GNU R goes on
  with its evaluator's entries (the foreman's interim decision).
- The own protections of paths no case reaches yet: `R_tryEval` and
  `R_ToplevelExec` bodies, finalizers, condition handlers, active bindings,
  S4 dispatch, `on.exit` expressions: a leak there gets the warnings at
  GNU R's sites, with depths that leave those functions' `PROTECT`s out.
