## 2026-11-16: S1, an S3 method's arguments as aliases of its generic's argument slots

- What: the foreman's item 2 after #725, approved on X/P1's conditions
  and the foreman's. #725 made a method's write to its argument exact
  (GNU R's method binds the generic's own promise, so a fresh value is
  written in place) by making each argument slot of the generic the
  method gets into that promise: a PROMSXP, a residue entry and a
  `clearPromise` per argument per dispatch, about 600 instructions on
  `s3`. An alias slot shares the generic's slot instead, until something
  needs the promise as an object.
- The slot (`robigo_heap::slots::ALIAS`, `robigo-rtcore`'s `env::alias`):
  `val` the generic's frame (traced, not counted), `aux` the index of its
  argument slot, MISSING 0. The target slot, delayed or forced, has
  `META_ALIASED` (beside `META_LOCKED`), and the residue list holds one
  entry per alias, so `end_call`'s existing test of the list finds a
  method's aliases at no cost to other calls.
  - A read through an alias is a read of the target: `arg_slot_raw`,
    `var_lookup_raw`, `fun_lookup_raw`, `find_fun3`, `frame_arg_raw`
    (`missing()`: the alias's MISSING, the target's expression and
    environment), `binding_type`, and `Cx::slot_lookup_raw`, the VM's
    fallback when `frame_slot_raw` did not read a slot. `force_arg` of an
    alias forces the target in place.
  - `ensure_object` of an alias, or of an aliased target, makes the
    target the argument's promise (the ghost residue as before) and every
    alias of it a value holding that promise, counted: `alias::resolve`.
    Every path that needs the binding as an object goes through it
    (`get`, `as.list(environment())`, `substitute`, a complex assignment's
    cell, `ROBIGO_MATERIALIZE`, `promargs`).
  - A write or removal of the alias itself drops it, counting nothing;
    so does `R_CleanupEnvir` of the method's frame.
- X/P1's conditions and the foreman's, and where each is met:
  1. Writes and removals into an aliased target resolve it first:
     `set_binding_value` (`<<-` with and without D2's memo, `assign`,
     `defineVar` and every C entry to it) in `store_unshared`;
     `remove_variable` (`rm`, `R_removeVarFromFrame`, `unbindVar`) in
     `unshare`. `frame_store_scalar_raw` and `define_scalar` store only
     into value and scalar slots, which no alias targets;
     `frame_store_scalar_raw` tests `META_ALIASED` with the lock and
     pending bits in one mask all the same. X/P1's five probes are the
     first cases of `tests/rt/s3/dispatch-alias.R`, recorded on 4.6.2.
  2. Materialized `promargs` are not an overwrite: NextMethod, a builtin
     method and C's `promargs` make the generic's list through
     `arg_promise`, which resolves the target, so the alias holds that
     promise.
  3. Every `end_call`, a return or a jump, makes the aliases its frame
     still has the promise (`Cx::end_aliases`); only `R_CleanupEnvir`
     drops them, where it clears bindings. `bind_s3_vars`' error path,
     which returned before `begin_call`, now ends the call too.
     `end_call` allocates nothing, so no refusal can reach it (the
     foreman's condition on the first build, which aborted there): its
     promises are nodes from a reserve of one per alias, which
     `apply_with::<true>` tops up before the method's frame is made
     (`Cx::reserve_alias_promises`), where a refused allocation is
     retried or raised as any other. A frame made with an alias the
     reserve does not cover panics (`Residues::push_alias`), and
     `end_aliases` asserts the reserve. The nodes are kept for the next
     method: `s3` allocates one, once. `tests/alias_alloc.rs` refuses
     the reserve's allocation under E9's knob (retried after a
     collection), then arms the knob again before a method's call ends
     by a jump and checks that no allocation was refused: its two aliases
     became the generic's promises.
  4. Forcing through an alias is `force_arg` of the target slot, so its
     early value is taken or lost against the generic's frame
     (`early_taken`, `early_lost`): the wasted bits and the call site's
     `no_early` are the generic's.
  5. An alias of an alias is made of its target, in `alias::bind`, where
     every alias is made (`generic_args` reads only `FILL_ARGS` records,
     whose frames have no aliases, so it does not happen today).
  6. Debug assertions: at every read through an alias
     (`Cx::check_alias`), the entry is there, the target is a delayed or
     forced slot of a slot frame whose call is running, and the target's
     record is live and below the method's innermost one; at every
     `end_call`, no alias entry names the frame as method or target; in
     `R_CleanupEnvir`, no argument slot is still aliased.
     `tests/alias_quarantine.rs` poisons the generic's frame at its end
     under `ROBIGO_FRAME_QUARANTINE=1` and reads the method's frame after
     (it fails with "an alias outlived its method's call" when
     `end_aliases` is skipped).
  7. Built on main after #728 and #726.
- Where the cost went (callgrind, against main `cc5d091e`): reading the
  alias in `frame_slot_raw`'s match cost 0.6% to 0.9% on the plain-call
  rows, which run calls inline (`vm::run` and `inline::Real::read` grew
  with the extra arm), so the alias read is out of line in
  `slot_lookup_raw`. `frame::store_value` and `Loc::store` stopped being
  inlined into `set_binding_value` when a second caller appeared, so the
  aliased store is its own cold function that calls neither, and the
  active and alias kinds share `Loc::store`'s one test. The alias arms of
  `new_closure_frame`, `R_CleanupEnvir`'s walk and `force_arg` sit in
  arms that existed (binarytrees +0.25% before, -0.02% after).
