## 2026-11-16: S1, the `s3` row: the dispatch variables as slots of the method's frame (fix 2 of `2026-11-16-p1-gaps.md`)

- What: fix 2 of the s3 row (`2026-11-16-p1-gaps.md`, "s3"), as the
  foreman ruled it (2026-11-16): the six dispatch variables become slots
  of the method's frame, through a memoized per-method shape, bound in
  GNU R's listing order; no frame flag, pending list or hooks in lookup
  or listing. On main after D5 (#702) and P1's superassign (#704). Fixes
  1 and 3 are `2026-11-16-s1-s3-row.md` (#703).
- The method frame's shape (`dispatch::method_shape`): the code's shape
  (formals, then locals), then those of `.Generic`, `.Class`, `.Method`,
  `.Group`, `.GenericCallEnv` and `.GenericDefEnv` it lacks. The code's
  slot indices keep naming the same symbols. A variable named as a local
  of the code binds that local's slot, which is unbound when the frame
  is made. A variable named as a formal gets no slot, because
  `addMissingVarsToNewEnv` keeps the formal's binding (envir.c: a
  binding later in the frame list has precedence). Shapes never change,
  so the answer is memoized by the code shape's identity: the 16 most
  recent, newest first, each entry holding its two shapes as globals.
- Binding (`Cx::bind_frame_slots`, `robigo-rtcore`, its own commit):
  `addMissingVarsToNewEnv` into the new frame. Each variable binds its
  slot by index, the last first, so `.Generic` has the newest stamp and
  the six list first, in `createS3Vars`' order, before the formals, as
  GNU R heads the frame with them. It does what `defineVar` of each into
  its unbound slot does (the special-symbol bit, the version box for a
  function value) without looking the slot up. `new_closure_frame` is
  unchanged. `createS3Vars`' pairlist is now `S3Vars`, six roots with
  no allocation, passed through `applyMethod` and `applyClosure` to
  `args::apply`. There `add_missing_vars` (six `define_var`s into an
  overflow block) is gone; `args.rs` changes by the shape's choice and
  the call.
- The slot guard (`robigo-rtcore`, its own commit, the foreman's
  conditions). Compiled code reads and writes a slot by index only in a
  frame of the code's own shape (`frame_slot_raw`,
  `frame_store_scalar_raw`: the frame's shape compared by identity). A
  method frame's shape is another shape, so without this change every
  formal and local of a method would take the full lookup. When the
  shapes differ, the guard now also accepts a frame whose slot `index`
  (checked against the frame's slot count first) is keyed by the code
  shape's symbol at `index`. That is sound because a frame keys each
  symbol once, in its shape or its overflow block; the full lookup would
  find the same slot. `frame_lacks_raw` is unchanged: a method frame is
  never passed over, as before, when its overflow block did the same.
  The mismatch branch is marked `std::hint::cold_path()`. A first
  version without the hint cost the same-shape rows +0.4% (its
  fallback's registers spilled in `inline::Real::read`'s prologue); with
  the hint those rows come out cheaper than main (below).
- Listing (`robigo-rtbuiltins`, its own commit): robigo-rt had no
  `.Internal(ls)` or `.Internal(env2list)`, which the recorded cases
  need. `do_ls` is `R_lsInternal3`'s names in listing order, sorted by
  `sortVector` (Shell sort by `Scollate` after `isUnsorted`'s check).
  `do_env2list` is `FrameValues` (a promise forced, an active binding
  called) named in listing order, or ordered by name (`orderVector1`).

  Fix 4 (dispatch from slot frames) is next, a follow-up PR after this
  one merges (the foreman, 2026-11-16). `UseMethod` still makes the
  generic's `promargs` from its slot frame (`materialize_promargs`, about
  1,000 per iteration, counted under call). With it the row would be
  about 20,700 (1.12x). What is left after that is mostly the shared call
  path (X/P1's) and dispatch's own cost (S1's). GNU R's `DOLLAR` also
  duplicates the call before it dispatches `$`, so that copy stays. For
  the 1.0x bar, then: fix 4 (S1) takes about 1,000 of the 3,198. The
  other 2,200 must come from the shared call path (X/P1: `args::apply`,
  `cleanup_envir`, frames, contexts; 8,423 here) and from dispatch's own
  5,563 (S1: `usemethod`, the memo's checks, `topenv`, the variables'
  binding), with what is left of allocation (18 objects per iteration)
  shared between them.
