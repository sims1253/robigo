## 2026-11-16: S1, the `s3` row: dispatch from slot frames (fix 4 of `2026-11-16-p1-gaps.md`)

- What: fix 4 of the s3 row (`2026-11-16-p1-gaps.md`, "s3"), the
  follow-up the foreman asked for once fix 2 (#713,
  `2026-11-16-s1-s3-row-2.md`) left the row at 1.17x. robigo-rt keeps a
  closure call's arguments in its frame's slots and makes the record's
  `promargs` (GNU R's `cptr->promargs`) only when something reads it (C2,
  `args::fill_promargs`). `UseMethod` read it on every dispatch, twice:
  `GetObject` walks it to find the dispatch object, and `dispatchMethod`
  hands it to `applyMethod` as the method's arguments. So every dispatch
  made a promise per argument and the list (`materialize_promargs`, about
  1,000 instructions per iteration of the row).
- The generic's actuals, read as they are (`args::generic_args`): for a
  generic whose `promargs` is still `fill_promargs`' lazy one, its record's
  fill data (the actuals in call order with their tags, and the match) and
  its frame give each element the list would hold. That is R_MissingArg,
  an element of the generic's `...`, or the argument slot it is bound to,
  which is that argument's promise while the slot still holds the
  argument (delayed or forced, `Cx::arg_slot_raw`). A slot the generic's
  body overwrote is not; then the list is made, as before (its residue is
  the promise GNU R's list holds).
- `GetObject` chooses among them by GNU R's rules (exact tag, partial,
  first untagged, first) and forces a delayed slot in place
  (`Cx::force_arg`), which is forcing the promise the list would hold.
- The method's call (`args::Source::Generic`, `call::apply_closure_generic`)
  matches the method's formals against those actuals. A forced slot is
  bound in the method's frame as a forced slot of the same value and
  expression (`Origin::Forced`); into the method's `...` it goes as a
  forced promise of the same value and expression. Any argument still
  delayed falls back to the list: the method must share that promise with
  the generic, so that it is evaluated once and the generic (its `on.exit`
  code, a `sys.frame()` reader) sees the method's value. A builtin method
  gets the list, as before.
- The method's `promargs` (`args::generic_promargs`) is lazy, and its
  filler returns the generic's own list (made then), the object GNU R's
  `dispatchMethod` passes: `NextMethod`, `match.call` and
  `sys.function`'s readers see what they saw before.
- `robigo-rtcore` gains two read-only accessors in their own commit:
  `CtxRef::promargs_filler` (a lazy `promargs`' filler and data) and
  `Cx::arg_slot_raw` (a slot frame's argument slot by index: delayed, or
  forced with its value and expression).
- One body for every call. `args::apply` is one function body (the
  closure it hands `cx.scope`), which every closure call runs. Adding the
  generic source's arms to it cost binarytrees +0.61% instructions, with
  no generic code run. `apply` now picks an instance by source:
  `apply_with::<true>` for a method called with its generic's arguments,
  `::<false>` for every other call, which compiles that code out. The
  helpers are out of line, and `Plan::fill` is marked inline (the split
  had moved it out of line, +48,000 per binarytrees iteration).
  Variants that moved the generic's record into `S3Vars` instead of
  `Source::Generic` measured worse, +0.31% and +0.64%.
- `promise_call_args` (`promiseArgs` for `DispatchOrEval`'s and
  `DispatchGroup`'s methods) gathers its items in args' inline buffer, not
  a heap `Vec`, per dispatch (X/P1's note): -128 per iteration of the row.
- A method's call with partial-match warnings (Sol's review) takes the
  generic's list, made before the warnings are signalled. A calling
  handler may change the generic's frame, and GNU R's list was made
  before the match.
