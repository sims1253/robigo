## 2026-11-16: sort, order and rank on robigo-rt (sort.c, radixsort.c)

- What: the foreman's sort package. robigo-rt had no `sort()` for any
  type (no `sort.default`), and `order()` stopped at `match.arg`'s
  `.Internal(formals())`. Now `sort`, `order`, `sort.list`, `rank`,
  `xtfrm` and `is.unsorted` run GNU R 4.6.2's base R code over ports of
  sort.c, radixsort.c and qsort-body.c, for every type: logical, integer,
  double, complex, character (Scollate, #700), factors and classed
  objects. NA handling, `decreasing`, `ties.method`, the methods and the
  errors all match.
- Tree: branch `g3/sort` on `g3/startup-options` (#706: the startup
  options give `match.arg`'s messages their fancy quotes), merged with
  main `4169b271` (#700, #703) through it. Binary: `cargo build --release --locked -p
  robigo-rtapi` (`robigo-rt`), private target directory. Machine: AMD
  Ryzen 9 5900X (24 threads), WSL2 Linux 6.18, rustc 1.100.0. GNU R: the
  4.6.2 oracle image for every recording.

### The internals

- `crates/robigo-rtbuiltins/src/sort.rs`:
  - `.Internal(sort, psort, qsort, order, rank, is.unsorted, sorted_fpass,
    wrap_meta)` and the `xtfrm` primitive;
  - `orderVector1`, which `options()` now uses too, in place of #700's
    stable sort and its check of the names.
- `sort/radix.rs`: `.Internal(radixsort())`.
- What the base closures reach on the way:
  - `.Internal(formals(), complex(), colSums(), colMeans(), rowSums(),
    rowMeans(), which(), encodeString(), asCharacterFactor())`;
  - the primitives `length<-`, `nzchar` and `prod`;
  - `as.character()` of a list or pairlist (`coerceVectorList`'s: a string
    of length one as itself, anything else `deparse1line`), which
    `stop()`'s `.makeMessage` needs;
  - `NextMethod()` to a primitive special (`[.factor`'s `NextMethod("[")`).
- The base subset traces `tests/rt/sort` too (`scripts/base-subset.R`),
  which binds `sort.default`, `sort.int`, `rank`, `factor`,
  `print.factor`, `[.factor`, `.gt`, `.gtn` and others. Two changes to
  how the bound is made:
  - the static bound walks the bodies of the closures the trace entered,
    not only names in the inputs' text: `print.factor`'s
    `setdiff`/`.set_ops_need_as_vector` names `identity`, which GNU R
    never calls there;
  - it binds the base variables that bound closures name (`variable NAME
    FILE`: `letters`, `..deparseOpts`), lazily, as closures are bound. It
    skips `.GlobalEnv`, whose definition (`environment()`) is the global
    environment only as GNU R's base build evaluates it.

### The algorithms

The sorts are GNU R's own:
- Shell sort with `incs` (`sort2_body`) for `.Internal(sort())`;
- with `sincs` (`sort2_with_index`, `orderVector`) for `order` and `rank`;
- `Psort`'s quickselect;
- Singleton's quicksort (qsort-body.c) for `method = "quick"`.

Their comparisons are total orders only where an index breaks the ties.
`.Internal(sort())` and `psort` move values that compare equal (`-0` and
`0`, strings that collate equal), and `rank` of an object compares through
R (`.gt()`). There only the same algorithm gives the same result:
`objects.R` counts the `>` calls of `rank()` of a classed vector, 16, as
GNU R makes. The shell sorts do not check for interrupts between passes
(`R_CheckUserInterrupt`).

`radixsort` is ported to the order it gives, not to forder's counting and
radix passes:
- **The order:** the stable order of its keys, each read through forder's
  key function:
  - `icheck` for integers and logicals (NA first, or last as `INT_MAX`);
  - `dtwiddle` for doubles (`-0` is `0`, every NaN one value, the last two
    bytes rounded off when grouping);
  - `StrCmp2` for strings (the bytes' `strcmp`, NA first or last).

  Each key is times its own `decreasing`. With `na.last = NA` a row with
  an NA in any key it reads is dropped.
- **Why that is enough:** forder's sortedness shortcuts reverse only
  strictly decreasing runs, so ties stay stable. The passes are one way to
  compute this order.
- **What is kept as forder has it:**
  - the checks and their messages;
  - the first key's encoding check (a native non-ASCII string is an
    error);
  - the column loop's early stop once every group has one row, which never
    type-checks the keys after it;
  - grouping's `ends`, `maxgrpn` and class;
  - strings in first-appearance order (`sortStr = FALSE`, per group, as
    `grouping()` asks). There the shortcut is part of the result, because
    the strings are not sorted. `csorted` keeps a group that is in order
    and reverses one that is strictly in the opposite order; only
    otherwise does `cgroup` number the strings by first appearance.
    `grouping(c("b", "a"))` is `2 1`. Under `na.last = NA`, `cgroup`
    keeps a group's NAs, and only a group of NAs alone is dropped.
- **Evidence:** `radix.R` covers those paths directly.
  `radix-random.R` compares 7,200 generated orders (one to three keys of
  every type, every `na.last` and `decreasing`, both methods) against GNU
  R's by checksum. `random.R` covers 20,000-element vectors.

`wrap_meta` returns its vector unchanged. robigo has no ALTREP wrappers,
and GNU R itself returns the vector unwrapped when it has attributes. One
consequence: `sorted_fpass` never knows a double vector is sorted, where
GNU R's wrapper tells it. Sorting an already sorted vector again gives the
same values, but `method = "quick"` could swap `-0` and `0` where GNU R
returns at once.

### A heap fix: dead slot frames leaked their vector cells

`radix-random.R` failed rt-ci's E9 step (`R_MAX_VSIZE=16M`) with "vector
memory limit of 16.0 Mb reached". The cause predates this branch:
- **The bug:** `alloc_slot_frame` charges a frame's `frame_cells(capacity)`
  to `valloc`, but `object_cells`, which the sweep subtracts for a dead
  object, returned 0 for every ENVSXP. Every slot frame that reached the
  heap stayed in `vecrecs_in_use` for good.
- **Symptoms:** `gc()`'s vector memory grew with every closure call whose
  frame reached the heap, including after collections. Loops of about
  90,000 calls to `parent.frame()`, `sys.function()`, `environment()`,
  `new.env()` or `numeric()` reached a 16 MB limit. `order()`'s
  `match.arg` reaches `formals(sys.function(sysP))` on every call, and
  `radix-random.R` makes 7,200 of them.
- **The fix:** `object_cells` gives a slot frame (or overflow block) its
  `frame_cells` of the capacity in its meta word, which never changes.
  `a_dead_slot_frame_gives_back_its_vector_cells` in robigo-heap's tests
  fails without it.
- **Evidence:** on the fixed binary, `gc()`'s vector memory stays at
  0.1 Mb across 60,000 calls each of `parent.frame()`, `sys.function()`,
  `environment()` and `sys.call()`, and 20,000 each of `new.env()` and
  `numeric()`. 2,000,000 calls to `parent.frame()` run under
  `R_MAX_VSIZE=16M`; before the fix, the 90,946th call stopped.
- Collections now come later, because the trigger no longer counts the
  leaked cells.

### Proof

`tests/rt/sort/*.R`, 13 cases, are recorded on 4.6.2 and ratcheted. They
match byte for byte:
- `integer`, `double` (NA, NaN, `-0`, infinities, and where `-0` lands
  among the zeros), `character`, `complex`, `factor` (ordered too);
- `order` (several keys, `decreasing` vectors), `rank` (every ties method
  and `na.last`), `xtfrm`, `objects`;
- `errors` (25 of the checks), `radix`, `radix-random`;
- `random`: 20,000 integers with ties and NA, 20,000 doubles with NA, NaN,
  `-0` and infinities, and 5,000 strings of mixed scripts, by `sort`,
  `order` and `rank` with every method and several keys, summarized by
  checksums.

`scripts/rt-ci.py` passes every step on `5642cb66`:
- **Conformance:** 270/275 in every mode, and 269/274 under
  `ROBIGO_NO_INPLACE=1`. The five failures predate the branch and have no
  markers: `args/binding-types`, `env/binding-errors`,
  `env/closure-frames`, `env/hashed-env` and `env/unhashed-env`.
- **Other steps:**
  - the crates' tests in release, under gctorture, the moving collector
    and the pin report;
  - the stress script (3 of 3 runs per profile);
  - the overshoot of every slice;
  - E9, with the small vector limit and 400 injected allocation failures.

`scripts/lint.sh` is clean.

### Not in this package

- `rank(ties.method = "random")` calls `stats::runif`, and robigo-rt
  cannot load stats.
- `round()` is still "not implemented yet" (`random.R` makes its ties with
  `%/%` instead).
- An error raised inside a primitive special that `NextMethod()` reached
  names that call with the arguments' values, where GNU R shows their
  expressions. robigo's specials read their arguments from the call they
  report, and the values are right.
- `.Internal(radixsort())` grouping with `na.last = NA`, and
  `.Internal(rank())` of more elements than the vector has, are "not
  implemented yet". GNU R reads past the vector in the second.
