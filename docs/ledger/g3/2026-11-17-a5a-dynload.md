## 2026-11-17: A5a, routine registration, `dyn.unload`, `.External` and `.External2`

- Why: L4's base build loads tools.so and calls its parsers through
  `.External2`. tools' `R_init_tools` registers its routines and forces
  native symbols. The foreman approved the A5 note
  (`~/.cache/robigo-research/a5-dynload-note.md`), with A5a first and
  without tools.so.
- What, in robigo-rtapi:
  - **rdynload.rs (Rdynload.c):**
    - `R_registerRoutines`, `R_useDynamicSymbols` and `R_forceSymbols`
      are exported. `R_registerRoutines` is an entry, because it can raise
      its error; the two setters are leaves.
    - A record holds what C sets through its `DllInfo *` in cells. A table
      that a later `R_registerRoutines` replaces is kept until the record
      goes, because GNU R leaks it and an earlier lookup may still point
      into it.
    - `dyn.load` calls `R_init_<name>` (or the name with `.` → `_`) with
      the record. The call goes through `call_native6` under a hidden
      record, as GNU R calls it directly.
    - `dyn.unload` is `DeleteDLL`:
      - The object's ALTREP classes get their default (null) methods back
        (`R_reinit_altrep_classes`).
      - `R_unload_<name>` is called if `R_dlsym` finds it. An object that
        turned dynamic lookup off, as tools does, is not asked.
      - The library is closed.
      - Then every reference handed out for the object is cleared: its
        `DLLInfoReference`, and each entry of GNU R's weak list
        `SymbolEptrs` (handles and native symbols). The copy a
        "registered native symbol" holds is freed there. Its finalizer
        later sees a null address and frees nothing.
      - Only then is the record freed. `R_registerSymbolEptr`'s
        clean-up every tenth registration is ported too.
  - **dotcode.rs (dotcode.c):** `resolveNativeRoutine`, shared by `.Call`,
    `.External` and `.External2`:
    - **`checkValidSymbolId`:** accepts a string, a "native symbol" or
      "registered native symbol" reference, or a "NativeSymbolInfo".
      A registration of another interface gives "NULL value passed as
      symbol address".
    - **`pkgtrim`:** unchanged.
    - **The calling namespace's DLL:** found by base's
      `getCallingDLLe`, as `R_FindNativeSymbolFromDLL` does. "DLL
      requires the use of native symbols" is raised for an object that
      forces them.
    - **`R_FindSymbol`:** by interface, with GNU R's messages per
      interface.
    - **The registered argument count:** checked ("Incorrect number of
      arguments").
  - **The two new builtins:**
    - `.External` passes the evaluated arguments as a tagged pairlist,
      `.NAME` first and `PACKAGE` dropped.
    - `.External2` passes `(call, op, args, env)`, `op` being the
      `.External2` builtin (`robigo_rt::prims::primitive`), with names.c's
      eval 201.
- **robigo's `.Call` lookup cache** (`Dlls::found`; GNU R on Linux looks
  up every call): dropped whenever a lookup could find something else.
  That is on `dyn.load`, on `R_registerRoutines`, on either lookup
  setter, and in `dyn.unload` after `R_unload_<name>` (which may look
  routines up), before the record is freed.
- **Behaviour changes for `.Call`:**
  - A native symbol reference no longer raises "not implemented".
  - A name called from base's namespace no longer looks in base's DLL.
    GNU R gives `"..." not resolved from current namespace (base)`
    there, checked on the 4.6.2 oracle, and robigo-rt now does too.
- **Layouts shared with C** (the foreman's condition 1):
  - `R_CMethodDef`/`R_FortranMethodDef` are 32 bytes (0, 8, 16, 24), and
    `R_CallMethodDef`/`R_ExternalMethodDef` are 24 (0, 8, 16).
  - These are asserted at compile time in Rust (`rdynload.rs`) and, with
    `_Static_assert` against GNU R's own `R_ext/Rdynload.h`, in the tests'
    object (`tests/support/dynload_test.c`). The same object compiled
    under GNU R 4.6.2 on the oracle, so the numbers are GNU R's.
- **Proof** (`crates/robigo-rtapi/tests/dynload.rs`): 8 tests in both
  profiles, on `dynload_test.c` built twice: `dl_plain`, whose init
  registers, and `dl_force`, whose init forces symbols as tools' does.
  - They cover registration and `getDLLRegisteredRoutines`, calls by name
    and through references, `.External`'s pairlist and `.External2`'s four
    arguments, an error from `.External2`, a call from a namespace, and
    `dyn.unload` with each kind of stale reference afterwards, a
    collection and a reload. One test changes an object's lookup settings
    after calls by name, and the next call by name sees the change.
  - The same object and the same R expressions ran on the GNU R 4.6.2
    oracle (`R CMD SHLIB`, then `Rscript` with `R_DEFAULT_PACKAGES=NULL`).
    Every value and message the tests assert is the oracle's.
