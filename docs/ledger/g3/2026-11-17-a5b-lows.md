## 2026-11-17: A5b's deferred lows, and the library.dynam ratchet

#828's OCR lows, which the foreman deferred to this follow-up:

- **R_alloc** (r4605252973). An empty request (`nelem * eltsize` not above
  0) is NULL, as GNU R's is (memory.c: "One programmer has relied on
  this"). robigo's `R_alloc` export already returned that null to C and
  never dereferenced it. Only `r_alloc_cstr` dereferences a block, and it
  always asks for at least one byte. It now asserts the block is not null.
  Porting the function again found one divergence: robigo's error for a
  request past `R_XLEN_T_MAX` was GNU R's 32-bit text ("%0.1f Gb", at
  `>=`). It is now the LONG_VECTOR_SUPPORT branch's: "cannot allocate
  memory block of size %0.f Tb" for `dsize > R_XLEN_T_MAX`.
  `tests/rt/capi/r-alloc.R` records, on GNU R 4.6.2, the null results, a
  block C writes, and the error ("... of size 8192 Tb", against the calling
  closure).
- **Rf_coerceVector** (r4605252929). A type code too large for robigo's
  `u8` types is no longer clamped to 255. It is GNU R's COERCE_ERROR with
  type2char's fallback, which names the code: the warning "type 999 is
  unimplemented in 'type2char'", then "cannot coerce type 'integer' to
  vector of type 'unknown type #999'". GNU R itself reads past its type
  table for such a code, so `tests/capi.rs` holds the test, not an oracle
  case.
  Left as it was: robigo's `type2char` says "unknown type", with no warning
  and no number, for the codes up to 255 that no SEXPTYPE names. Its
  callers share that.
- **Rf_asBool** (r4605252956). It now calls `util::as_bool`, a port of GNU
  R's public `asBool`. That and `as_bool2` share `as_logical_checked`
  (`asLogical2(x, 1, call)`), so there is no copy. The two keep GNU R's
  difference: `asBool2` reports NA against its call, while `asBool`
  reports it with `error()`, against the context call. OCR's
  `as_bool2(cx, None, x)` would have lost that. `tests/rt/capi/as-bool.R`
  records both errors' calls on GNU R 4.6.2.
- **MB_CUR_MAX** (r4606137241). `R_MB_CUR_MAX` was glibc's number,
  hardcoded: 6 in a UTF-8 `LC_CTYPE` and 1 in C. It now comes from the C
  library itself, as R_check_locale reads it (`R_MB_CUR_MAX =
  MB_CUR_MAX`). `clib::mb_cur_max` makes the C library's `C.UTF-8` or `C`
  locale object current on the calling thread only for the read
  (`uselocale`), then calls `__ctype_get_mb_cur_max`, the function behind
  glibc's and musl's `MB_CUR_MAX` macro. `mbcslocale` is GNU R's
  `MB_CUR_MAX > 1`, not a second constant. glibc's 6 and 1 remain only
  for a C library without the locale, and for Miri.
- **One initial pair** (r4606137259). The per-isolate block started at
  0/1 and the exported statics at 1/6. Both now start from one pair of
  constants, GNU R's own: Defn.h's `INI_as(FALSE)` for `mbcslocale` and
  `R_MB_CUR_MAX` alike, until `set_locale` runs.
- Tests: `clib`'s `mb_cur_max` returns 6 in C.UTF-8 and 1 in C on glibc
  and puts the thread's locale back, and `set_locale` writes the block and
  the statics alike.
- **rt-home.sh** (r4605252985, r4605253000, r4605253011, r4605253023):
  - cargo's stderr is no longer discarded;
  - the layout filter takes exactly one robigo-heap build-script run, and
    otherwise says how many it saw;
  - each header directory must hold a header;
  - the headers are hashed in C order (`find | LC_ALL=C sort`), so the
    stamp does not depend on the caller's collation. Under en_US.UTF-8,
    `config.h` sorted before `Defn.h`.
