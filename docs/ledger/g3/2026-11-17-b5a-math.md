## 2026-11-17: arithmetic.c's math functions of one argument and `log` (B5a)

- What: robigo-rt ports `do_math1`'s rows (`floor`, `ceiling`, `sqrt`,
  `sign`, `exp`, `expm1`, `log1p`, the trigonometric and hyperbolic
  functions, `gamma`, `lgamma`, `digamma`, `trigamma`, `cospi`, `sinpi`,
  `tanpi`), `trunc` (`do_trunc`), `log` (`do_log`, `do_log_builtin`) and
  `log2`/`log10` (`do_log1arg`), with `math1`, `math1_ari` and `math2`
  (`crates/robigo-rtbuiltins/src/math.rs`). `log` is a special in
  robigo-rt (`specials.rs`): it evaluates its arguments with
  `evalListKeepMissing`, as `do_log` does, which the `eval_args` hook
  (DispatchOrEval's evaluation) does not.
- `ceiling` and `log` are outside the D0c boot set. The foreman took them
  early: `ceiling` blocked 317 fastr cases on robigo-rt.
- Known gaps, each raising an error or visible in a case:
  - **The condition classes of a missing `x`** (S1). GNU R raises
    `R_MissingArgError_c("x", call, "log1Error")` (and `"log2Error"`): a
    condition of class `c("log1Error", "missingArgError", "error",
    "condition")`. robigo-rt raises a `simpleError` with the same call
    and message. `tests/rt/math/log-missing-class.R` records GNU R's
    classes and is not ratcheted.
  - **Compiled `log(x, base)`** (the compiler). GNU R's compiler emits
    `LOGBASE.OP` for `log(x, b)`. For two scalar doubles, its NaN warning
    is `warningcall(call, ...)` against `log(v, b)`, while the interpreted
    `math2` warns with `warning()` against the context. robigo-rt's
    compiler compiles the call as a call (cmp.R's inline handlers for
    `log` and the `do_math1` functions are not ported), and the byte-code
    translation refuses `LOG`/`LOGBASE` as not implemented yet.
    `tests/rt/math/log-compiled.R` records the difference and is not
    ratcheted.
  - **Compiled `do_math1` functions** (the compiler). For a scalar
    double, GNU R's `MATH1.OP` calls the C library's function
    (`getMath1Fun`: `sin`, not `Rsin`; `exp`, not `Rexp`), without
    `math1_ari`'s special points or R's small-argument cutoffs, and
    `SQRT.OP`/`EXP.OP` call `sqrt` and `exp`. So in GNU R a compiled
    `1 / sin(-0)` is `-Inf` where the interpreted one is `Inf`. robigo-rt
    calls `do_math1` either way, so its compiled results are the
    interpreted ones, which differ from GNU R's in those cases. This was
    already so for `sqrt` and `atan` on main. `tests/rt/math/math1-compiled.R`
    records it and is not ratcheted.
  - **Complex arguments** (`complex_math1`, `complex_math2`, complex.c)
    raise "robigo: ... is not implemented yet".
- The C library: `sin`, `sinh`, `atanh` and the rest come from the C
  library, as in GNU R, so their last bit follows the glibc version. The
  oracle's image has glibc 2.41 and this host 2.44, whose
  correctly-rounded `sinh` and `atanh` differ by an ulp (`sinh(2)`). The
  cases print these values to 15 digits. GNU R's own cutoffs (`Rexp`,
  `f_x_x`, `Rcos`, the `math1_ari` points) are exact and checked with
  `identical`. `acosh`, `asinh` and `atanh` are the C library's
  (`robigo_numerics`), not Rust's `f64` methods, which use their own
  formulas.
