## 2026-11-17: BW, the wide interim loader

- What: the proposal's BW (`proposal-early-wide-boot.md`), adopted by Max
  on 2026-11-17 with the foreman's review conditions and owned by S1.
  `crates/robigo-rt/src/base.rs` now binds every name GNU R 4.6.2 binds in
  base, not only the bound's 188 closures. Each name is bound lazily: a
  promise in the base namespace whose code fetches the name's definition
  on first use. All of it is `INTERIM(L5)`, and L5 deletes it together with
  `base-subset.txt`, `base-bound.txt` and `base-subset.sh`.
- The index, `crates/robigo-rt/proto/base-wide.txt`, is generated by
  `scripts/base-wide.R`, which `scripts/base-subset.sh` runs in the 4.6.2
  oracle image on the pinned tarball's sources. It reads them in the order
  GNU R evaluates them:
  1. base's R files in collation order (`LC_COLLATE=C`, `R/*.R` then
     `R/unix/*.R`, as makebasedb concatenates them);
  2. `baseloader.R`, the installed `base` file, which runs after the lazy
     load;
  3. the system profile, `profile/Common.R` then `profile/Rprofile.unix`
     (R_LoadProfile, evaluated in base).
  For each form it records the byte range in its file, from the srcref. The
  loader reads only those bytes, parses that one form and evaluates it, so
  startup parses no R code at all. `@WHICH@` is substituted as mkRbase's
  sed does.
  - 1,407 names, every name of `ls(baseenv(), all.names = TRUE)` on GNU R
    4.6.2, which the generator asserts:
    - 1,168 names defined by top-level assignments. The last assignment
      wins, as the lazy-load database keeps it. `.Library.site`'s three
      definitions in the profile are marked `seq` and run in order, since
      each reads the one before.
    - 23 names assigned by two `local()` blocks: `zzz.R`'s deprecated
      `as.data.frame.<class>` methods and `baseloader.R`'s `.C_`/`.F_`
      native symbols. A third block is the profile's `.popath`. Each block
      runs once, on the first fetch of any of its names. Its names were
      found by running it on a scratch base namespace.
    - 7 names bound by GNU R's C at startup: `.BaseNamespaceEnv`, `.Device`,
      `.Devices`, `.Last.value`, `.Machine`, `.Options`, `.Platform`.
      robigo-rt's init binds them. This entry adds `.Device` and `.Devices`,
      as devices.c's InitGraphics makes them.
    - 210 primitives. `as.numeric` and `is.name` are counted twice:
      baseloader.R rebinds them to primitives.
    - 1 unrun name, `.AutoloadEnv` (below).
    - 556 `.Internal`s. Each primitive and internal robigo-rt lacks is
      bound to the not-yet stub.
  - Chains such as `licence <- license <- function ...` bind every name of
    the chain. Each inner name is the rhs at its depth. **M1's loader
    dropped the inner names**: `license`, `objects`, `double`,
    `print.POSIXlt`, `duplicated.array`, `anyDuplicated.array`,
    `unique.array`, `mtfrm.POSIXct`, `mtfrm.POSIXlt` (at depth 2),
    `[.simple.list` and `range.Date`. All 11 are bound now, and
    `tests/rt/base/wide-defs.R` checks two of them against GNU R
    (`identical(license, licence)`, `identical(numeric, double)`).
- The 143 top-level forms that are not assignments to a base name
  (condition (b) of the review): 108 in base's R files, 10 in
  baseloader.R and 25 in the profile. Each is classified in the generator's
  `known` table, which fails on any form it does not classify, and on any
  classification that is out of date:
  - `none`: forms that bind no base name, nothing to do lazily.
    - `parse.R`'s `if (FALSE)`.
    - baseloader.R's lazy load itself and its `force()`s.
    - The profile's `options()` and `Sys.setenv()` calls, whose effect
      robigo-rt's startup makes. Measured: `options()` right after startup
      is identical to GNU R 4.6.2's, all 49 options. The `if`s guard what
      does not apply: interactive sessions, R_BATCH, macOS.
  - `after NAME`: forms that run right after NAME is first fetched.
    - baseloader.R's S3 registration (after `.__S3MethodsTable__.`).
    - The two `lockEnvironment`s (after `.ArgsEnv` and `.GenericArgsEnv`).
    - `zzz.R`'s 106 `assign()`s into `.ArgsEnv` (87) and
      `.GenericArgsEnv` (19), the generator's rule for an `assign()` into
      a base name.
  - `block`: the three `local()` blocks above.
  - `skip`: five profile forms that are not run, with their reason:
    - `profile/Common.R:12`: the Autoloads environment (robigo-rt's
      search path is its own).
    - `:62` and `:64`: R_LIBS_SITE and R_LIBS_USER are not expanded.
    - `:115`: `.Library.site` is a value, not GNU R's active binding.
    - `profile/Rprofile.unix:9`: `.libPaths()` is not initialized from
      R_LIBS_USER.
    `.AutoloadEnv`, which only the skipped Common.R:12 binds, is bound to
    raise when touched, with that form's record:
    "robigo: '.AutoloadEnv' needs base's profile/Common.R:12, which
    robigo-rt does not run: ... (INTERIM(L5))".
  - The skip record is in every failing case's output.
    `robigo-conformance` runs the binary once with `ROBIGO_BOOT_VERBOSE=1`
    (`Column::boot_record`, set for rt only) and appends the record to each
    failing case's report: the `ROBIGO_CONF_DIFF` diff and the
    regression message.
- S3 registration: lazy, measured. The table is filled the first time
  `.__S3MethodsTable__.` is fetched, the first S3 dispatch from base, with
  baseloader.R's `delayedAssign` promises.
  - The foreman's check, on the oracle: all 393 registered methods are
    bound in base under their own names, with identical values, and none
    is registered without being bound. So no base method needs the table to
    dispatch.
  - The empty-table fallback does not help. With the registration skipped,
    s3 measured 19,014 instructions per dispatch, against 19,000 with the
    table filled. Every dispatch on an object without a method still looks
    up the method in the table, and a lookup in an empty hashed environment
    costs as much as one in a full one. So the table is filled, as in GNU
    R.
- What the table cost, and the fixes in code (`dispatch.rs`):
  - The method memo refused a promise, so every dispatch from base ran the
    full search: e7-unique +2.71%, s3 +1.4%. Base's table binding is a
    promise, and so is each registered entry. The memo now reads a forced
    promise's value: it runs no code, and a forced promise's value is fixed
    for good.
  - A method found nowhere is now checked by the table's version box, not by
    a hashed lookup per candidate method per dispatch (`$.sq` and
    `$.default` on s3's object). This is sound for that result only. A
    function-like binding made in the table moves the box. A binding of
    anything else is no method either, because R_LookupMethod returns it
    and every one of its callers (usemethod, NextMethod, DispatchGroup,
    quick_search) passes over what is not a function, as over
    R_UnboundValue. A method found after the table keeps the lookup, since
    a non-function in the table hides it.
  - One dispatch reads the defining environment's table once, not once per
    candidate method (`TableNow`).
  - The memo keeps the table's box version without the box. An
    environment's box is its own for good, and `Cx::env_version`, a new
    read-only rtcore accessor, reads it inline.
  - `tests/rt/s3/method-table.R`, recorded on 4.6.2, covers:
    - non-function, function and promise bindings made in base's table
      between dispatches;
    - a method in the enclosure of a top environment that binds
      `.packageName`, first found, then hidden by a non-function in the
      table, then found again;
    - methods of `length` (an internal generic) and `unique` (a closure's
      `UseMethod`) registered only in the table.
- `$` of an environment by its symbol (`bcassign.rs`). GNU R's
  `R_subset3_dflt` looks up `installTrChar(input)`, and for the PRINTNAME
  of an ASCII symbol that is the symbol itself. The VM's `$` on an
  environment now looks up the member's symbol directly.
  - Before, it converted the name to native bytes, copied them and
    installed them again: a symbol-table hash lookup and an allocation per
    `e$f`.
  - BW's smaller symbol table made that lookup 32 instructions dearer for
    the name `f` (hashbrown probes depend on what the table holds). That
    made env-fn +1.3% before the change. After it, env-fn is −22% against
    main.
  - `tests/rt/env/dollar-env.R`, recorded on 4.6.2, covers ASCII,
    non-ASCII and quoted names, a promise, an active binding, an unbound
    name, partial names, a classed environment, base and the global
    environment.
