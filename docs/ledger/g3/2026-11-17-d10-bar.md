## 2026-11-17: D10 bar: strings, interned results or uncached intermediates (X4)

D10 (docs/g3.md §7, §15.2) asks whether every CHARSXP robigo-rt makes is
interned in the CHARSXP cache when it is made, as GNU R's are, or whether
the results of the string builders stay out of the cache until a use needs
their pointer. This is the bar, as the M2/M3 plan's §C words D10's row. It
is written before the runs and signed off by the foreman in the pull
request that adds it. G2 (A1) does not write D10's bar: the foreman
assigned it to X4 on 2026-11-17, so that D10 can run early (`e7-paste` has
3.6% of headroom under its 2.0x ceiling). A run that cites this bar fixes
it. A change is a new dated section that names this one, committed before
the runs it governs.

### Protocol

M1's protocol (`docs/ledger/g3.md`, "M1 decision bars", "Protocol"), with
the M2/M3 plan's three changes (§C):

1. **Both modes.** Every row runs with inlining on (the default) and with
   `ROBIGO_NO_INLINE=1` (`--robigo-env ROBIGO_NO_INLINE=1`). Each rule
   below must hold in both modes.
2. **D10 is decided on instructions and peak RSS.** Wall time is for D8,
   D13 and D12.
3. **Pinned-model estimated cycles** are reported on every run and decide
   nothing. The model is callgrind's cache simulation with
   `--I1=32768,8,64 --D1=32768,8,64 --LL=33554432,16,64` (the cycles
   study, `2026-11-16-cycles-study.md`: 32 MB, 16-way). If
   `scripts/idiom-vs-r.py` cannot pass those flags yet, the run's branch
   adds the option to it; that changes no count.

- **Tie band:** ±1% instructions, or 2% wall time. Inside it, the variant
  named first wins.
- **Allocations** per iteration (objects by SEXPTYPE, and bytes) are
  reported on every row.
- **Reproduction:** as M1's. Every table is run twice; a row whose runs
  differ by more than 0.1% in instructions is run three more times and
  reported as the median of five.

### Variants

1. `interned`, today's main: every CHARSXP is interned when it is made.
2. `g3/x4-d10-uncached`: uncached intermediates.
   - The results of `paste`/`paste0`, `sprintf`, `substr` and coercion to
     character (`as.character`, `string_elt`) are made without the cache:
     no hash, no probe, no insert, no CACHED bit. `format` is not
     implemented in robigo-rt yet.
   - `""` stays R_BlankString and NA stays NA_STRING.
   - Such a string is interned at its first use that needs pointer
     identity: the CHARSXP itself goes into the cache when no equal one is
     there, otherwise its cached twin replaces it. That use is one of:
     - `match`, `%in%`, `unique`, `duplicated`, `anyDuplicated`,
       `pmatch` and `levels<-`, which hash by pointer;
     - the radix sort's grouping;
     - C's `STRING_ELT`.
   - Comparisons that read pointer equality as string equality compare
     bytes when a string is not cached: scalar `==` in the VM and the
     inliner, and the "same CHARSXP" shortcuts before `Scollate`.
   - Symbols, environment keys, names, `switch` and `identical` compare
     bytes or symbols already.
   - `.Internal(inspect())` is not in robigo-rt yet. When it is, it reports
     GNU R's `[cached]` for every CHARSXP.

### Rows

STRINGS, eight workloads:
- `e7-paste`, `e7-match` and `e7-unique`, the rows of
  `benchmarks/rt/calls-rows.toml` as they are;
- five rows that the run's branch adds to that file with exactly this setup,
  body and `n` (the harness wraps the body in
  `g <- function() { for (i in 1:N) { BODY }; NULL }`, at N and 2N);
- one whole program for peak RSS.

| row | setup | body | n | what it measures |
|---|---|---|---:|---|
| `d10-sprintf` | `q <- 1:100` | `p <- sprintf("s%d_%d", q, i)` | 200 | 100 new strings per iteration, from `sprintf` |
| `d10-paste-match` | `keys <- paste0("k", 1:1000)` | `m <- match(paste0("k", (1:100 + i) %% 1000L + 1L), keys)` | 200 | the penalty case: `paste` results that exist already, then a pointer-identity use |
| `d10-ascharacter` | `x <- 1:100000` | `s <- as.character(x)` | 4 | `as.character(1:1e5)`: 100,000 strings per iteration, the same ones every time |
| `d10-assign` | `e <- new.env()` | `assign(paste0("v", i %% 100L), i, envir = e)` | 1000 | `assign(paste0(...))`: a pasted name to a symbol, then a binding |
| `d10-rss` (program) | `benchmarks/rt/mem/strings1e6.R`: `x <- paste0("u", 1:1000000); cat(length(x), x[1000000], "\n")` (no use that needs pointer identity) | | | peak RSS of 1e6 unique strings, `scripts/rss.py --runs 5` (median `ru_maxrss`) |

Reported alongside, deciding nothing:
- `benchmarks/rt/mem/strings-dup.R`, peak RSS of 1e6 strings with 10
  distinct values: `x <- as.character(rep(1:10, 100000)); cat(length(x), x[1000000], "\n")`.
  The bar's RSS row has unique strings only, so it cannot show what the
  cache's sharing saves.
- The M1 bars' rows (`benchmarks/rt/m1-bars.toml`) as a guard, under
  `perf-rt`'s own rule: no row more than 0.5% worse in instructions
  against main.

### Rule

`uncached` wins if, in both modes, all of these hold:
- `e7-paste` takes at least 15% fewer instructions than `interned`;
- the geomean of the instructions over the seven STRINGS iteration rows
  is at least 3% better;
- no STRINGS row is more than 1% worse;
- the peak RSS of `d10-rss` is not worse, that is, not above `interned`'s
  beyond the larger of the two variants' ranges over their five runs.

Otherwise `interned` wins.

### Admission and adoption

- **Admission.** `uncached` is measured only after it passes the full rt
  conformance and the D10 cases on its branch:
  - `tests/rt/strings/d10-*.R` and `tests/rt/capi/d10-string-elt.R`, recorded
    on 4.6.2;
  - the rest of Std's verification: the full `scripts/rt-ci.py`, Miri on
    rtcore and the heap's non-FFI tests, a Sol review.

  An inexact variant is a control.
- **Adoption.** If `uncached` wins, the decision entry states one
  deviation for the lead to accept or refuse before it merges, under L8's
  allocation parity:
  - When the only CHARSXP with some bytes and encoding is an uncached one,
    C's `mkChar` of those bytes allocates, and may collect, where GNU R's
    finds the cached string and does not.
  - Interning every string before every C entry would mean walking all
    reachable data, and keeping uncached strings findable costs the intern
    this variant saves.
  - No STRINGS row involves C.
- **Deleted:** the losing branch.
