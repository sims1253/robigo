## 2026-11-17: the conservative scan's stack reads are C's (#745, item 3)

- Why (#745, item 3): robigo-heap's conservative scan loaded other frames'
  stack words through integer-made pointers in Rust (`Core::scan_words`,
  and the pin report's copy, `scan_words_diag`). That memory can be
  uninitialized, or borrowed exclusively by a Rust frame suspended above
  the collector: formal UB in Rust's abstract machine, which the code said
  in its SAFETY comment.
- What:
  - shim.c's `robigo_heap_scan_words(from, to, min, max, hit, ctx)` reads
    the word-aligned words of `[from, to)` and calls `hit(ctx, at, v)` for
    each value in `[min, max]`. shim.c already hosts `robigo_heap_spill`,
    the C frame the scan runs behind.
  - Rust sees only those candidate values: `Core::scan_candidates(v)` is the
    old loop's decision (the object `v` points into; the object it is one
    past the end of, on a granule boundary), shared by the collector's
    `scan_hit` and the pin report's `diag_hit` (which keeps the word's
    address for its hits).
  - The granule test is `GRANULE`'s, not a literal 16.
  - `docs/architecture.md`'s unsafe inventory says where the loads are.
- Not changed: robigo-core's copy of the loop (the old runtime, frozen).
  The other items of #745 stay open there.
