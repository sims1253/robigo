## 2026-11-17: L2, the front end's R_HOME

- What (foreman 2026-11-17, a dependency of C1-BC's compiler cases in
  #771): `robigo-rt` now sets `R_HOME` when the environment has none, as
  GNU R's `R` script exports its own (m2m3-plan F7b option A). An
  installed robigo-rt uses `<prefix>/lib/robigo`, when the binary is in
  `<prefix>/bin` and that tree has `library/base`. Otherwise it uses the
  build checkout's `.robigo/rt-home` (`scripts/rt-home.sh`), as an
  uninstalled GNU R uses its build directory.
  - `R_SHARE_DIR`, `R_INCLUDE_DIR` and `R_DOC_DIR` are set under the
    `R_HOME` in effect when unset or empty. An empty `R_HOME` is unset too,
    as the script's `test -n "${R_HOME}"` reads it.
  - `.Internal(R.home())` (C1-BC's port of platform.c's `do_Rhome`, #771)
    reads it, so `R.home()` is the tree. This branch had its own port,
    identical in behaviour, and dropped it on the merge with main.
  - Stage 0 reads base's source under that `R_HOME`, from any working
    directory.
- **Known divergence**, accepted by the foreman: robigo-rt keeps an
  `R_HOME` the environment sets, so that the harnesses can point it
  elsewhere. GNU R's `R` script ignores it ("WARNING: ignoring
  environment value of R_HOME") and exports its own install's. GNU R does
  the same as Rscript: `Rscript` runs `$RHOME/bin/R` (`RHOME` from the
  environment, else the home compiled in), and that script then replaces
  `R_HOME` with the same warning. Both were checked on the 4.6.2 oracle.
  - `R_SHARE_DIR` and the others follow `R.sh.in`'s defaults under
    `R_HOME`. The script assigns all three unconditionally; robigo-rt
    keeps one the environment sets (not empty), as it keeps `R_HOME`.
    The oracle's Debian package has `R_SHARE_DIR` at `/usr/share/R/share`
    instead, which is the packager's choice.
- With C1-BC's `file.path` on main, the profile's `.Library <-
  file.path(R.home(), "library")` is the tree's `library` under stage 0,
  from any working directory. Stage 0 on main `48044290` with this
  branch: 1,308 expressions, 9 fail. None of those is in `R.home()`.
- Proof:
  - `crates/robigo-rtapi/tests/front_end.rs` covers the default and a set
    `R_HOME`;
  - `tests/rt/base/r-home.R` is recorded on 4.6.2.
- **Follow-up** (OCR round 2 on #782, deferred by the foreman):
  - The checkout's tree is the default only when it has `library/base`,
    as an install's is. Without either, `R_HOME` is still exported (the
    checkout's path, where `scripts/rt-home.sh` makes the tree), so
    `R.home()` names it.
  - GNU R's script checks its home at start-up ("R_HOME ('...') not
    found", status 1). robigo-rt checks where the tree is read: M1's
    loader reads none, and CI runs robigo-rt without making it. Stage 0
    with a home that has no `library/base` fails at start-up with GNU R's
    message and how to make the tree (status 2, robigo-rt's start-up
    failure). Before, it failed with the file error of
    `library/base/R/base`, which did not name `R_HOME`.
  - `front_end.rs` runs robigo-rt without the runtime's own controls
    (`ROBIGO_FAIL_ALLOC_AT`, `ROBIGO_GC_STATS`, `ROBIGO_GC_PIN_REPORT`,
    `ROBIGO_BOOT_VERBOSE`, `ROBIGO_RT_BOOT`), as `cli.rs` does, and has a
    case for stage 0 under a home without the tree.
