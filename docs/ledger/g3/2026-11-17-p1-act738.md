## 2026-11-17: #738's activation contract: `Act` sealed, `slot()` bounded by its invariant, `root`/`out` tied to `&self`

Issue #738's first finding (`Act` and `run` unsound), the part the foreman
assigned to X/P1 after H7 (#765) and #768. The verifier half (#738's
`Verified` code type) stays with C1 and V3.

- **`Act`'s fields are private.** H7 had made them `pub(crate)`; now only
  `vm.rs` sees them. Code elsewhere in the crate used one field, `base`
  (`call.rs`, the links walk's argument skip), and now reads it through
  `Act::base()`.
- **An `unsafe` constructor states the invariant.** `Act::new` builds every
  activation, and it is called only from `exec`. Its `# Safety` section, and
  the type's `# Safety invariant`, require that `base` point to `nregs`
  (at least `R_FIRST`) live value-stack slots for the activation's life,
  and that the code run on it name no register at or past `nregs`.
- **`slot()`'s bound.** `slot()` and every register accessor built on it
  index under that invariant. The bound is a `debug_assert!` against the new
  `nregs` field, which fits in `Act`'s padding. In release builds it rests
  on the compiler, as before; #738's verifier is to prove it. A release
  check on every register access would cost the hottest path in the VM.
- **`root` and `out` return `Root<'_>` and `Out<'_>`.** The lifetime was
  unbounded. Exactly one site needed the old lifetime: `call::loop_region`
  hands the environment register to `with_context` while `run` borrows the
  activation mutably. It now makes that root with `Root::from_raw` and
  states why that is sound. Only `exec` writes `R_ENV`, before `run`
  starts, because the compiler allocates registers from `R_FIRST`.
- **`run` is `pub(crate)`.** `exec` stays `pub unsafe fn`. Nothing outside
  robigo-rt calls either.
- **`vm::num`** (#768's review). Its contract now spells out the condition:
  the object is live while `num` reads it, and nothing has collected since
  the slot was read. It names the callers that meet the condition: the VM's
  activation registers, and the local register arrays of the inline runs
  (`inline::pure`, `body_loop`, `fused`) and of early evaluation
  (`early.rs`). Any other caller has to show the same. The inner SAFETY
  comment no longer says "a register's object".

### Sol's review: an empty argument window tripped `slot()`'s check (P1), fixed in `89259cb9`

`call_builtin_regs` and its VM twin took a builtin call's argument window
with `act.slot(base)`. A call with no arguments has its window at
`base == nregs`: one past the last register, which nothing reads or
writes. `slot()`'s new debug check rejected that legitimate position, and
four `loader` and `s3` tests failed in debug builds. The earlier checks ran
release builds only, so they did not catch it.

- **The fix.** `Act::window(base, len)` gives the window's first slot and
  checks `base + len <= nregs`, so an empty window may sit at `nregs`. Both
  sites use it. Register reads and writes keep `slot()`'s strict bound.
- **Checks at `89259cb9`.**
  - `cargo test -p robigo-rt` in a debug build passes, every
    `debug_assert!` included.
  - `cargo fmt --check`, `scripts/test-rt-ci.py`, `scripts/rt-ci.py` and
    `scripts/lint.sh` pass. Conformance is 456/464, as before. The failures
    are main's.
- **Perf.** Not measured again. The new function is the same pointer offset
  as `slot()`, with its debug check, and a release build compiles the check
  out. The bars above are at `349f7748`.
