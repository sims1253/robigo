## 2026-11-17: S3x-a, the rest of errors.c's R-level internals

- What: the first part of S3x (m2m3-plan.md §B), the parts that need no
  namespaces. The `conditions` cases on rt passed 17 of 30 before it.
  - S3x-b, the classed error conditions (`missingArgError`,
    `MissingSubscriptError`, `stackOverflowError`, ...), comes next.
  - S3x-c covers interrupts and on.exit in C-pushed contexts, together
    with the C API's `R_tryCatch`, `R_tryCatchError` and
    `R_withCallingErrorHandler` (`C_tryCatchHelper`), which call package C
    and need the capi harness.
  - S3x-d is the trycatch bar.
- **A script goes on after an error** (main.c:check_session_exit). An
  error that reaches the top level ends an Rscript session only when
  `options(error)` is NULL and `options(catch.script.errors)` is not TRUE.
  Otherwise the console's buffer starts over, so the rest of the failing
  line is dropped and reading resumes at the next line. This holds for an
  evaluation's error, a syntax error and the final "unexpected end of
  input". robigo-rt halted on every error.
- **The traceback under `catch.script.errors`** (errors.c:jump_to_top_ex).
  `.Traceback` is recorded when R is interactive, `options(error)` is set
  or `options(catch.script.errors)` is TRUE. robigo-rt checked only the
  second.
- **`returnValue()`** (eval.c:do_returnValue): in `on.exit` code, the value
  of `R_ExitContext`, marked not mutable; the default otherwise (an error,
  outside on.exit code). rtcore already kept both.
- **`options(nwarnings)`** (options.c, errors.c:vwarningcall_dflt,
  PrintWarnings). The deferred list keeps `R_nwarnings` warnings, and
  setting the option empties it (`R_CollectWarnings = 0`).
  `PrintWarnings`' "There were N or more warnings" form uses it.
  - #652's DEFERRED hooks.rs items are in the same code:
    - the deferred warnings are one Vec of (call, message);
    - a message's allocation is retried after a collection and raised if
      refused, where it was dropped silently;
    - `drop_missing` is documented. GNU R reads `dropmissing` only for
      unevaluated arguments, and `is.na`/`is.nan` set it with evaluated
      ones, where it does nothing.
- **Internal restarts and `.Internal(.addTryHandlers())`**
  (errors.c:do_addTryHandlers, R_InsertRestartHandlers,
  addInternalRestart, checkRestartStacks; context.c:R_JumpToContext).
  - The calling function's record gets its restart bit, an "error" calling
    handler whose handler is `R_RestartToken` (an error goes to the
    default handling), and the internal restart "tryRestart", whose exit is
    an external pointer to the record.
  - Invoking an internal restart is `R_JumpToContext(c, CTXT_RESTART,
    R_RestartToken)`. In GNU R 4.6.2, `R_execClosure` lands that jump as
    any other, so the function returns `R_RestartToken`. The body is not
    evaluated again, as it was in older GNU R.
  - `R_RestartToken` is now what GNU R's is: a symbol named "" outside
    the symbol table (names.c:InitNames, mkSymMarker). The isolate makes
    it once with the heap's new `Core::new_marker_symbol`. It was an empty
    list, which printed as `list()` once a function returned it.
  - The external pointer comes from a new safe rtcore constructor,
    `Cx::extptr(addr, tag, prot)`, so the code needs no `unsafe`. It is
    `#[inline]` (below).
- **`.Internal(traceback(skip))`** (errors.c:do_traceback,
  R_GetTraceback): each call deparsed, from a walk that `.Traceback`'s
  recording now shares. A record with a srcref is refused, not dropped;
  rt's records have none while `keep.source` is not honored. `traceback()`
  itself also needs `[[<-` on a pairlist, which C1-BC ports.
- **`.addGlobHands`** (errors.c:do_addGlobHands), the internal of
  `globalCallingHandlers()`. Its R wrapper needs `utils::removeSource`, so
  namespaces (L2) first; the case calls the internal.
  - The global handlers live on the top level's saved handler stack. GNU
    R's REPL evaluates statements in `R_Toplevel`, the session's record,
    so they last from one statement to the next. robigo-rt's REPL ran each
    statement through `R_ToplevelExec`'s semantics, which empty the stacks
    for the body and restore the old ones after, so global handlers never
    showed.
  - The script's statements and `.Last` now run in `Cx::repl_toplevel`. It
    is a top-level record that saves the stacks as `begincontext` does,
    keeps them while the statement runs, and restores them from the record
    at its end. New rtcore calls `handlers_only_global` and
    `set_global_handlers` do `do_addGlobHands`' check ("should not be
    called with handlers on the stack") and its rewrite of every record
    down to the top level.
- **Every form of a warning's report** already matched GNU R:
  - immediate, deferred by count, converted, ignored;
  - `warning.length`, `warning.expression`, "In addition:";
  - LONGWARN wrapping, conditions, `immediate.` and `noBreaks.`.
  `tests/rt/conditions/warning-forms.R` holds them.
- Cases, recorded on GNU R 4.6.2 and ratcheted, all in
  `tests/rt/conditions/`: `script-continues`, `return-value`, `nwarnings`,
  `try-handlers`, `traceback-internal`, `global-handlers`,
  `warning-forms`. Six `tests/r` cases now pass and are ratcheted:
  `cli/error-catch-continues`, `cli/parse-error-option`,
  `conditions/abort-restart-traceback`, `dispatch/seq-along-length-method`,
  `lang/on-exit-return-chain`, `lang/replacement-error-no-handler`.
- A codegen effect found by the gate, and fixed:
  - The first build measured s3 at +0.32% against main, with the same
    allocations, no collection, and the same machine code for
    `Core::alloc_node`'s first two copies.
  - The third copy, the one rtcore's `cons` and `lcons` use, grew from 438
    to 477 bytes and cost 59 more instructions per iteration.
  - The cause was the new call `Cx::extptr` made in rtcore: a call of
    `alloc_node` with `EXTPTRSXP` there changed how LLVM compiled rtcore's
    copy.
  - With `extptr` `#[inline]`, its allocation is compiled in the calling
    crate (robigo-rt, where `connections.rs` already makes one). The copy
    is 438 bytes again and s3 measures 18,776, as main does.
  - Two other suspects measured no difference: the startup allocation the
    old empty-list token was, and a second marker symbol. Neither changed
    s3's count.
