## 2026-11-17: V4 step 4: the JIT-cost harness, GNU R's side recorded

Package V4, step 4 of 5. The foreman's order is (4), then (5), then (3)
once L5 lands. Step 3 runs cmp.R at GNU R's JIT moment, and the compiler
namespace does not load before L5. The M2/M3 plan's V4 bar: "a JIT compile
costs at most GNU R's instructions per closure, on the calls.R closures".
This step adds the harness and records GNU R's side. robigo-rt's side is
measured when step 3 lands, and the bar becomes a gate then.

- **Tree:** branch `g3/v4-4-jit-cost`, from main `85bf480e`.

### The rows

`benchmarks/rt/calls-rows.toml`'s new `jit` group has one row per closure
of `benchmarks/suite/calls.R` that GNU R's JIT compiles while running it.
The rows were checked on the oracle: after a run of `calls.R`,
`.Internal(bodyCode(f))` is byte code for seven of them. `acct`, the
closures it makes, and `area.default` (never called) stay uncompiled.

| row | closure |
|---|---|
| `jit-scale_by` | `scale_by` (defaults left to their promise) |
| `jit-weigh` | `weigh` (named arguments) |
| `jit-tag` | `tag` (a string argument) |
| `jit-env-fn` | `e$f` |
| `jit-area` | `area` (`UseMethod`) |
| `jit-area-sq` | `area.sq` |
| `jit-safe` | `safe` (`tryCatch`) |

Each row's SETUP is `calls.R`'s definitions. Its BODY is
`compiler:::tryCmpfun(f)`, the call `R_cmpfun1` evaluates for a JIT
compile (`eval.c:1828`). The JIT cache's lookup in `R_cmpfun` is skipped,
so each iteration is a full compile. As every row, they are measured as
callgrind instructions, N against 2N (`scripts/idiom-vs-r.py --rows`),
with N = 40.

### GNU R's side

`benchmarks/rt/jit-bars.toml` holds the numbers and the bars, 1.0x each and
none met yet (`met = false`; the early look below puts robigo-rt at about
1.9x). No CI job reads it yet, and `test-perf-rt-bars.py` checks it as it
checks `m1-bars.toml`: the rt pin, the rows. They were measured with the bars' rival, GNU R
4.6.2's literal default build (`scripts/gnur-stock.sh`). The run was in
the oracle image with Debian's valgrind, as perf-rt measures:
- the desktop, AMD Ryzen 9 5900X, signature `1be0f69f7d2b7252`;
- `libc6=2.41-12+deb13u4`, `valgrind=1:3.24.0-3`.

The two runs agree within 0.00004%.

| row | GNU R instructions per compile |
|---|---:|
| `jit-scale_by` | 6,410,626 |
| `jit-weigh` | 5,861,134 |
| `jit-tag` | 6,246,337 |
| `jit-env-fn` | 3,222,304 |
| `jit-area` | 2,637,218 |
| `jit-area-sq` | 3,877,717 |
| `jit-safe` | 9,713,533 |

### An early look at robigo-rt's side (preliminary, not the bar's)

The compiler namespace loads on robigo-rt with two stand-ins in the
row's setup: `.AutoloadEnv`, which waits on L5's boot, and
`bindtextdomain`, which is not implemented (the foreman has both). With
them, the same rows measured on robigo-rt (main `2a7f3be6`'s release build)
cost:

| row | robigo-rt | against GNU R |
|---|---:|---:|
| `jit-scale_by` | 12,409,572 | 1.94x |
| `jit-weigh` | 11,428,472 | 1.95x |
| `jit-tag` | 12,163,422 | 1.95x |
| `jit-env-fn` | 6,233,091 | 1.93x |
| `jit-area` | 5,185,749 | 1.97x |
| `jit-area-sq` | 6,981,507 | 1.80x |
| `jit-safe` | 18,953,078 | 1.95x |

That is cmp.R, which is R code, run by robigo-rt's VM. Step 3's JIT adds
the byte code's translation (V3) at the next call on top of it. So
crystallization through cmp.R costs about twice GNU R's per compile today.
The M2/M3 plan names this as the risk V4's bar catches ("re-plan before P3
if it fails"). Step 3 measures it for real and takes it from there, either
as robigo-rt's own speed on cmp.R's code or as a change to V4's plan.

### When step 3 lands

- These rows run on robigo-rt without stand-ins, and `jit-bars.toml`'s
  bars join perf-rt. GNU R is measured on the gating runner, as
  `m1-bars.toml`'s are, and `[gnur]` here becomes the local fallback.
- Until then the rows only run where every row runs:
  - `rt-overshoot.py` runs them on robigo-rt; a row that stops on the
    compiler's load still prints the heap's report, the only thing it
    reads;
  - perf-rt's GNU R cache key hashes `calls-rows.toml`, so it measures
    GNU R's side once more.

## 2026-11-17: the jit rows at N = 400, checked to compile

A follow-up to #829, before any run gates the rows:

- **N = 400.** X's profile: at N = 40 the extra N compiles catch 0 or 1 of
  robigo-rt's full collections, ±0.65M instructions per compile, so a
  row's number depends on where the collections fall. At 400 they
  amortize.
- **Each row checks its compile.** `tryCmpfun` returns the closure as it
  is when the compile fails, and a failed compile would read as cheap. A
  row's BODY now stops unless `.Internal(bodyCode(...))` of the result is
  byte code.
- **One setup.** The seven rows share calls.R's definitions through
  `setup_ref = "calls"` and a `[setups]` table, instead of seven copies.
  `scripts/perf.py`'s `rows_with_setups` resolves it for every reader of
  a rows file (perf.py, idiom-vs-r.py, rt-overshoot.py).
- **The bars test** parses each bars file once.

GNU R's side, measured again as above, at N = 400 (the bodyCode check is
in the rows). The two runs agree within 0.00001%:
