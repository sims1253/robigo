## 2026-11-17: V4 step 5c: cmp.R's frameTypes takes a namespace's imports frame

Package V4, step 5, a port the foreman asked for after 5b. cmp.R's
`frameTypes` walks a closure's environments. From a namespace to the
global environment every frame is a namespace frame, and each must be a
namespace or a namespace's imports frame: an environment whose `name`
attribute starts with "imports:". The port allowed namespaces only
("M1 has none"). So the JIT never compiled a package namespace's closures:
every one of them has its namespace's imports frame as the namespace's
parent. Since every package namespace's compiled code changes, this step
also runs the crosscheck and bytecode-fidelity suites.

- **Tree:** branch `g3/v4-5c-imports`, on V4 step 5b's
  (`g3/v4-5b-crosscheck`), filed after it.

### The port (cenv.rs, against cmp.R 4.6.2)

- **frameTypes:** a non-namespace frame below a namespace is a namespace
  frame if its `name` is one string, not NA, starting with "imports:".
  Anything else is still "non-namespace found within namespace
  environments" (the compile fails, the closure stays as it is). This
  includes a name of two strings, where `startsWith` gives `frameTypes`
  a logical(2) and `if` an error.
- **getInlineInfo** (`Cenv::info`): a name found in a namespace frame
  that is no namespace must be in the imports frame of the code's top
  environment (`parent.env(topenv(...))`), else "bad namespace import
  frame". Its package is `nsName(findHomeNS(name, top))`, and only base
  has inline handlers.
- **findHomeNS** (`find_home_ns`): the namespace's own binding; then
  `.__NAMESPACE__.$imports` from the last entry back. An entry of `TRUE`
  goes through the imported namespace's exports (base's namespace for
  base); named imports match by name, and a renamed import is NULL, as in
  cmp.R.
- **isBaseVar** takes the frame getInlineInfo found the name in: base's
  namespace or base's environment. It does not take the home. A name an
  imports frame binds is no base variable, even when its home is base
  (a namespace that imports base whole). getInlineInfo's error is
  isBaseVar's. It fails the compile from `findLocalsList`,
  `mayCallBrowser` and constant folding, which now pass it on. Before,
  the port folded such a `pi` to base's value and swallowed the error.

### Sol's round 1

- **findHomeNS stops where cmp.R's code stops.** The first cut skipped an
  import whose namespace was not registered and returned none for
  missing export metadata. GNU R's `getNamespace` of such a name calls
  `loadNamespace`, which stops when there is no such package, and
  `exists(sym, NULL)` stops too. Either way the compile fails, and
  `find_home_ns` now returns that ([`Need::Fail`]).
  - The other errors of cmp.R's R code fail the compile as well: an
    imports name that is empty or missing ("bad namespace name"),
    exports that are no environment, `if` of an NA name, and a cycle of
    imports (which recurses until R's depth limit).
  - A shape that no namespace has but that R would walk by coercion (a
    named number among the imports, a list of lists) is not ported and
    fails too.
  - Bindings are read as `get` and `$` read them: a promise by its value
    once forced (`Need::Force` before), an active binding not at all.
  - A namespace robigo-rt does not have registered is the one place
    where GNU R would load a package. robigo-rt's compiler loads nothing,
    and every namespace's imports are loaded before it.
- **nsName names the package.** cmp.R's handlers are chosen by package
  name: `getInlineHandler(name, nsName(home))`, the namespace's
  `spec["name"]`. The port tested identity with base's namespace.
  - A namespace whose spec says "base" now gets base's handlers, as in
    GNU R.
  - A spec without a name is NA, so the table's `hinfo$package ==
    package` stops `if`, but only for a name the table has. The same
    holds for `packFrameName` of a frame on the search path.
  - The tables are GNU R 4.6.2's, listed on the oracle and sorted
    (`cenv::BASE_HANDLERS` 233, `STATS_HANDLERS` 46, the getter's 3 and
    the setter's 4); a unit test keeps them sorted. Each caller of
    getInlineInfo reads its own table: tryInline, tryGetterInline and
    trySetterInline.
  - stats' handlers (cmpSimpleInternal of `safeStatsInternals`) are not
    ported. Only a hand-made namespace can call itself "stats" in
    robigo-rt, which has no stats, and it is left uncompiled.

### Cases

`tests/rt/jit/namespace.R`, recorded on GNU R 4.6.2. The namespaces are
built by hand: robigo-rt has no `loadNamespace` and no `parent.env<-`. A
namespace closure with a loop is marked at its first call and compiled at
its second. A constant argument's binding type shows which code ran: a
value in compiled code (PUSHCONSTARG), a promise in the AST's.
- a closure of a namespace with an imports frame: compiled;
- a name the imports frame binds that shadows base's `length`: compiled,
  and the import is called, not base's inlined;
- no "imports:" name; a name of two strings; a name found in an imports
  frame below the top's: uncompiled;
- `pi` bound in the imports frame of a namespace that imports base whole:
  compiled code reads the binding (3). The step's first cut folded it to
  3.14159 there;
- `pi` found in an imports frame below the top's, met first by constant
  folding: uncompiled (the first cut compiled it);
- an import not registered, and a whole import of a registered namespace
  without exports: uncompiled (Sol's round 1);
- a namespace whose spec names it "base": compiled code calls base's
  `length`, not the namespace's own (GETBUILTIN); a spec without a name:
  a call of `length` is left uncompiled, a call of a name without a
  handler is compiled.

Each closure has a body of its own. GNU R's JIT cache gives a closure
whose body it compiled for another top environment no code (NOJIT,
`R_cmpfun`), so in the first recording three cases were uncompiled by
the cache, not by the rule they test. robigo-rt's cache does the same.
