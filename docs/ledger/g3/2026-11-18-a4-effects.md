## 2026-11-18: A4's second step: the Env, Calls and External effect classes

- **Why:** the first A4 PR (`2026-11-18-a4-builtin-diff.md`) covered pure
  builtins and the RNG only. The foreman's order was the other classes with
  their plants, and a row for every builtin landed or in a PR that day.
- **What changed** (docs/verification.md, "Builtin differential"):
  - **The lattice, version 2.** Two fixture pools sit outside `@any`, for
    the rows that name them. `@env` holds environments: with bindings, with
    a locked binding, locked, with an active binding, empty, base and
    global. `@fun` holds closures that log their arguments to `.a4log`,
    plus `sum`. The record gains `.a4log`.
  - **Specials** run when the row says `special = true` (`lapply`,
    `vapply`, `withVisible`, `Recall`, `~`, `@`, `[`, `[<-`).
  - **External rows** run one process per case. Each process gets a fresh
    directory at the same absolute path on both sides, and an environment
    built from nothing. The files a case leaves are compared too (the
    `files` field).
  - **Domain keys must name an argument.** gen.R stops when a `domain` or
    `typical` key names none. This showed that `RNGkind` and `strtoi` in
    the first PR had never had their domains applied: base's wrapper passes
    `as.character(x)`. Rows with such a wrapper now give `args`.
  - **Rows:** 76 (from 23), 40,968 cases. 12 of them are ahead of the
    registry: the bindings and `...` accessors that E's #866 and #878
    register. `[uncovered]` gives a reason for 221 of the 262 registry
    builtins.
- **The bar** (`plant`): the six plants from the first PR, plus three new
  ones. The new plants trip only on a case's own call (first argument the
  symbol `a1`), because the driver calls these builtins too:

  | plant | new failures | field |
  |---|---|---|
  | assign: a second binding | 17 | env |
  | do.call: one more call | 72 | log, conds |
  | Sys.getenv: a file left behind | 26 | files |

  The first `assign` plant also changed `globals` (when the environment was
  the global one) and `value` (when the value was the environment itself,
  or when the second binding failed in a locked, empty or base
  environment), so the check refused it. It now plants only where a binding
  can be added. A `lapply` plant could not
  work: GNU R's raw `.Internal(lapply(...))` errors on its `...`, so every
  case was already an error on both sides. A `mapply` plant could not work
  either: do_mapply refers to the symbol `dots`.
- **Sol's round 1** (six P2s, all fixed): the record held no process
  environment, so a Sys.setenv that set nothing passed (extras now read it
  back); the file tree skipped the directory's own mode (Sys.chmod(".")); a
  zero-length Sys.getenv returned the whole environment and was always
  excluded as unstable (28 cases, now 0); the umask was not fixed (now 022,
  in the key: oracle version 3); mapply and file.append never reached their
  success paths (extras now do).
- **Time:** a full run at 4 jobs takes 192 s warm for 76 rows, plus 312 s
  on GNU R's side when its cache is cold. `ci` takes 294 s with both builds
  warm: its plant check reuses `run`'s results for the planted and control
  rows, so only the plant binary runs them again. The rt job's limit goes
  from 40 to 50 minutes, and builtin-diff-data's from 20 to 40.
