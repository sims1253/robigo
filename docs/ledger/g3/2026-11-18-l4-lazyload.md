## 2026-11-18: makeLazy, loadInfoFromConn2, save.to.file, load.from.file (L4)

- What: the four lazy-load and save/load internals that GNU R's build
  reaches and robigo-rt lacked (`crates/robigo-rt/src/serialize/saveload.rs`):
  - **makeLazy** (builtin.c): each name bound in `assign.env` as a promise.
    The promise holds `expr` with its second element replaced by the value
    of `values[[i]]` evaluated in `eval.env`; base's `lazyLoad`
    (`lazyLoadDBexec`) and baseloader.R bind databases through it. Errors
    as GNU R's, including VECTOR_ELT's for a `values` that is not a list.
  - **loadInfoFromConn2** (saveload.c's do_loadFromConn2, PRIMVAL 1): a
    connection's magic number checked, then `serializeInfo`'s list of what
    follows it. The connection is opened in "rb" and closed again, on error
    too.
  - **save.to.file** and **load.from.file** (do_savefile, do_loadfile,
    R_SaveToFileV, R_LoadFromFile, R_ReadMagic), which cmp.R's `cmpfile`
    and `loadcmp` use: formats 2 and 3, ascii or XDR (binary on reading),
    with GNU R's magic numbers and messages. `R_DEFAULT_SAVE_VERSION` is
    read as GNU R reads it.
- Checked against GNU R's own databases: base's `lazyLoad` of the oracle's
  base, compiler and tools `.rdb`s binds exactly the variables each `.rdx`
  names, and every one forces (`crates/robigo-rtapi/tests/lazyload.rs`,
  under `ROBIGO_ORACLE_LIBRARY` as rdb_roundtrip; CI's rt step and
  `scripts/rt-rdb-roundtrip.sh` run it). Compared object by object with
  GNU R's `lazyLoad` of the same files, using serialize checksums: all 289
  compiler and 915 tools objects agree, closures' environments aside.
  GNU R's are the namespace. robigo-rt's are `R_GlobalEnv`, because base's
  `..getNamespace` falls back to it while compiler cannot load from source
  (it stops at `aperm` today).
- Cases: `tests/rt/serialize/{makelazy,savefile}.R`, recorded on 4.6.2.
- Known gaps: version 1 files (`save.to.file(version = 1)`, reading
  RDA1/RDB1/RDX1) and files from R before 1.4.0 refuse ("not implemented
  yet"). `loadFromConn2` (`load()`'s, PRIMVAL 0) is not here; the build does
  not reach it.
