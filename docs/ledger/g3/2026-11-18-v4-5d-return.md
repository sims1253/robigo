## 2026-11-18: V4 step 5d: return()'s operand compiled outside the tail, as cmp.R does

GNU R's compiled `return(x)` compiles `x` in a non-tail context
(cmp.R's `make.nonTailCallContext`), so `x` is as visible as bcEval leaves
it at RETURN. The port compiled the operand in the tail, so compiled code
returned some values invisibly where GNU R returns them visibly. On the
4.6.2 oracle, compiled, these return a visible value:
- a missing `else`, a switch's miss and a loop (a visible NULL: LDNULL);
- an assignment of any kind: `x <- v`, `x <- y <- v`, `{ y <- v }`,
  `x <<- v`, `names(x) <- v`, `x[1] <- v`, `attr(x, "a") <- v`,
  `x$a <- v`, and a closure setter (bcEval's SETVAR and ENDASSIGN do not
  touch R_Visible);
- `return(x <- invisible(v))` stays invisible.

The AST returns the assignments invisibly. Step 5b's crosscheck carried
the difference as its `return_null` class.

### The port

- **`Tail`** replaces compile.rs's `tail: bool`. It has four values:
  - `No`;
  - `Yes`: cmp.R's tail;
  - `Ret`: `return()`'s operand under `Bc`;
  - `Live`: see below.

  Under `Ret` the shapes are non-tail ones, and every value op the VM
  honours F_VIS on carries it (bcEval's loads and operators set
  R_Visible). An LDNULL is visible (a missing `else`, a switch's miss, a
  loop's value), and an assignment's value carries the context, a complex
  assignment's too (`x$a <- 2`: no step sets R_Visible, so the value's
  load does). Under `Eval`, `return()`'s operand is compiled in the tail,
  as before (the AST's visibility).
- **Assignments leave R_Visible alone**, as bcEval's SETVAR, SETVAR2 and
  ENDASSIGN do. `SetVar`, `SetVar2` and `BcAssign` no longer store it, in
  vm.rs's `set_var`, `bcassign::run` and inline.rs's copies. Their
  invisibility is the code's, where cmp.R puts it:
  - after a tail assignment, a `SetVis(false)` (cmp.R's INVISIBLE). Under
    `Eval` this is do_set's `R_Visible = FALSE`, which is observed only in
    the tail.
  - `Comp::finish` folds a `SetVis` into the `Ret` it falls into, its
    visibility becoming the `Ret`'s `g` (cmp.R's INVISIBLE, then RETURN).
    The fold applies through `Move`s and `Clear`s under `Bc` (the
    translation's RETURN moves its value), and only when no jump lands
    there.
  - under `Eval`, a `{`'s statements before the last are compiled as the
    tail while the `{` is (a write that cuts the list makes one the last,
    `Op::Resume`): `Tail::Live`. A statement that is itself an assignment
    emits no `SetVis`; its `Resume` carries `c` 1 instead, and the cold
    path that runs the rest of a stale `{` makes the value invisible when
    nothing follows. An assignment inside such a statement (an `if`'s
    branch, a nested `{`) emits its `SetVis(false)` as the tail does.
- **A complex assignment's steps set R_Visible as bcEval's do.** An index
  bcEval loads (cmpIndices: LDCONST, GETVAR_MISSOK) sets it, in
  `bcassign::eval_arg`'s own branches. A punt step's constant (empty or
  named arguments: cmpBuiltinArgs' PUSHCONSTARG) does not; that step runs
  an instance of its own (`default_args::<false>`), so the common path
  has no test. A call's code and a setter call set their own.
- **The translation** translates SETVAR and INVISIBLE one to one. It
  used to drop an INVISIBLE after an assignment, which `SetVar` made
  redundant. `returns_after`, which decides that a value reaches RETURN
  and so gets F_VIS, steps over SETVAR and SETVAR2 and over a complex
  assignment from STARTASSIGN to its ENDASSIGN, which keep the value on
  bcEval's stack.
- **5b's `return_null` expected class** is gone. The closure it covered
  now compares as the same.

### Where visibility lives

5b's crosscheck work was partly about having one place where visibility
lives. That place is now:
- the value op's F_VIS;
- `SetVis`;
- the `Ret`'s `g`;
- for an assignment, nothing: the value's visibility stands, as in bcEval.

The first cut of this step added IR state instead: a bit in `g`
(`G_KEEP_VIS`) on SetVar, SetVar2 and BcAssign meaning "leave R_Visible",
because the value's visibility at run time is no constant
(`return(x <- invisible(v))`), so neither an F_VIS nor a SetVis nor the
Ret's `g` can say it. It cost the closure-call rows, and so did every way
of carrying it:
- `g` passed to `set_var`: plain +0.5%, named +0.8%;
- an op of its own (`SetVarKeep`): +1.3%. A second caller of what
  `vm::run` inlines outlined `frame_store_scalar_raw` (+62 instructions),
  and even the variant alone, sharing SetVar's arm, cost +25 instructions
  an iteration in `vm::run`.

The foreman's inversion follows the C instead and removes the store from
the arm: no new variant, no new argument, no new state. The crosscheck
compares SetVar, the SetVis and the Ret as it did, without a special case.

The same lesson held in `bcassign` for the index loads' visibility.
These versions all cost the assignment rows (guard-subassign-dbl, grow-dbl):
- a test per argument in `default_args`: +8;
- with the punt kind as an argument: +25;
- a plan flag `P_VIS` read in `body` and passed down: +42;
- as a raw read: +58.

The stores inside `eval_arg`'s existing GETVAR and LDCONST branches, with
the punt kind a compile-time instance, are flat (guard-subassign-dbl
-6.3 instructions an iteration: `eval_arg` now inlines into
`default_args::<true>`).

### Cases

- `tests/rt/jit/return-vis.R` (recorded on 4.6.2, ratcheted): fourteen
  `return()` operand shapes at their first call (the AST) and compiled,
  plus ten assignment forms compiled, with `x$a <- v` after `invisible()`,
  `x[1] <- invisible(v)` (the index's load) and `x[i = 1] <- invisible(v)`
  (a punt's pushed constant: invisible).
- `tests/rt/bctrans/visible.R`'s nine new cases: translated byte code of
  an assignment, an assignment of `invisible()`, `names<-`, `<<-`, `$<-`,
  `[<-` of `invisible()`, a missing `else`, a loop, and a tail assignment.
- `tests/rt/capi/suspended-body-write.R`'s `ta`, `ts` and `tb`: a callback
  cuts the `{` after an assignment (`<-`, `<<-`, an `if` whose branch
  assigns), which GNU R then returns invisibly. Without the Resume's mark,
  robigo-rt printed `[1] 1`.
- The top-level and REPL visibility of `x <- 1`, `x <- invisible(1)`,
  `(x <- 1)`, `x <<- 2`, `f <- function() y <<- 1; f()`, `names(x) <- "n"`,
  `x[1] <- 3`, a `for` loop, closures ending in assignments (AST and
  compiled), `local(x2 <- 5)`, `if (TRUE) x3 <- 4` and `print(x4 <- 9)`:
  the same as GNU R 4.6.2's, from Rscript and from R's REPL.

### Review

Sol (codex `gpt-6.1-sol`, high):
- Round 1, CHANGES:
  - S1 [blocker]: a complex assignment's visibility. `return(x$a <- 2)`
    after `invisible()` and `return(x[1] <- invisible(3))` are visible in
    GNU R.
  - S2 [nit]: the Resume mark missed an assignment inside an `if` or a
    nested block.

  Both are fixed, with cases.
- Round 2, CHANGES: S1 and S2 resolved. S3 [nit]: a punt step's constant
  is PUSHCONSTARG and must not set R_Visible. Fixed, with case `g24`
  (checked on 4.6.2). Since round 2 found only a nit, no round 3.
