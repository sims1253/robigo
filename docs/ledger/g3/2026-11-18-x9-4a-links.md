# X9-4 step (a): the link walk reads the value stack in place (2026-11-18)

X/P1. The first half of X9-4, from the cmp.R profile
(`~/.cache/robigo-research/x-cmpR-profile/README.md`, "links" bucket).

## What was slow

`links::walk` is GNU R's `INCLNK_stack_commit` / `DECLNK_stack`
(eval.c:997-1056). It runs around every STARTASSIGN (`bcassign::run`) and
`applydefine`, over the VM activations' registers on the value stack. It
read each slot through `Cx::stack_slot`, whose `slot_at` asserts the bound,
and counted links through `Cx::stack_links`, with one `dyn FnMut` call per
object. On one cmp.R compile (`compiler:::tryCmpfun(scale_by)`, main
`eec051b8`, callgrind N = 800 minus N = 400) the walks cost 869k of
12.37M instructions:
- 633k to find activation heads: the loop, `stack_slot`, `slot_at` and
  `as_mark`, over every slot from the committed mark to the top, the roots
  between activations included;
- 236k to count links (`stack_links`).

## The change

- rtcore: one accessor, `unsafe fn Cx::stack_slots(from, to) -> &[Slot]`. It
  makes one range check and returns the live slots in place. Its safety
  contract is that no slot of the range is written while the slice lives;
  a link count is the object's header field, not a slot. It replaces
  `Cx::stack_slot` and `Cx::stack_links`, and vstack's `slot_at` and
  `for_each_object_in`, which had no other users.
- `links.rs`: `walk` takes the slice of `0..depth` once. It finds heads
  with `rposition`/`position` over it and counts links inline. It visits
  the same slots and changes the same counts as before.
- Test: `robigo-rtcore/tests/alloc.rs` `stack_slots_read_in_place` (marks
  and objects read through the slice, a count raised and dropped while it
  lives, a range past the depth panics), run under Miri.

What is left in the walk is the slot loop itself: about 4 instructions per
non-object slot and about 11 per object slot. To go below that, the walk
must not read the root slots between activations at all. That needs a chain
of activation heads kept by `vm::exec`, which is a vm.rs change, so it is
left to step (b): GNU R's byte-code link lifetime, eval.c:7212-7214.
