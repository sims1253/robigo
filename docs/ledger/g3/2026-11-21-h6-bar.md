## 2026-11-21: H6's bar: landing X3's layout, and H's last deferred heap item

This was written before any H6 code, for the foreman's signature in the pull request that adds it. Once a run cites it, it is fixed. A change is a new dated entry that names this one and says why, committed before the runs it governs (§15.2).

H6 is m2m3-plan's "land the winner, plus the heap follow-ups" (X3's dependent, wave 2). The lead has not yet decided X3. The foreman recommends keeping `h32`/`n48` (D8's and D13's signed rules). The one alternative left is `h24-n48`. So this bar covers both outcomes, and each section says which one it is for. Anything for `nT` is left out: X3 showed that a pairlist cell cannot become a call in place under it (`SET_TYPEOF` LISTSXP→LANGSXP, 40 → 48 bytes).

### What H6 changes

**Under either outcome:**
- **The decision entry.** X3's data are under `~/.cache/robigo-research/x3/runs/final` (the four cells' instructions, peak RSS in three runs, GC time on m0pad and the desktop, wall time, and the exactness `.norm` files). The data and the decision go into a ledger entry with its data directory, and D8's and D13's rows in `2026-11-17-m2m3-bars.md` get their outcome.
- **The branches.** `g3/x3-h32-n48`, `-h32-nT`, `-h24-n48` and `-h24-nT` are deleted locally and on origin once the entry has landed. They are based on `4c05e858`, and no commit of theirs merges as it is.
- **The last deferred heap item** (m2m3-plan §A.5): the rise in binarytrees' peak RSS since `060c20af`, re-measured. `2026-11-19-h-heap-lows.md` closed the other five A.5 items (#874).
- **The M2 exit check:** `cargo test --release -p robigo-heap` and gctorture pass in the `rt` job on this PR's CI.

**Under `h32`/`n48` (keep), additionally:** nothing in the heap's layout changes. The layout seam (H4: `vector::OFF_DATA`, `node::size(t)`, `data_off(t)`) and `the_layout_is_h32_n48` stay. Unless the binarytrees item finds a cause, H6 is the entry, the branch deletion and the measurement.

**Under `h24-n48`, additionally:**
- **The port.** `g3/x3-h24-n48` (`5b19d18ef`; 14 files, +411/−98) is ported onto main: the 24-byte vector header; a trailing `TRUELENGTH` word on the vectors allocated with it (`TL_WORD`, `alloc_vector_tl`), found through the size class (`heap::alloc_end`); CHARSXP's 32-byte header unchanged.
- **The C API's `TRUELENGTH`,** which X3's branch did not settle. `SET_TRUELENGTH(x, n ≠ 0)` on a vector allocated without the word aborts there. Package C code (data.table's over-allocation, `SET_TRUELENGTH` on a C-allocated VECSXP and its names) does this. H6 must choose one of:
  - (a) every `allocVector` and `Rf_allocVector3` from C allocates the word, so those vectors keep their 8 bytes and only R-level vectors shrink;
  - (b) a side table keyed by address for C-set true lengths.

  The choice is part of this bar. (a) is the default, because it keeps `SET_TRUELENGTH` a store.
- **The headers.** `Defn.h`'s `TRUELENGTH` becomes a function export, not `ROBIGO_VEC_OFF_TRUELEN` (`crates/robigo-rtapi/src/api.c:85` asserts that offset today). L4's R_HOME tree ships `robigo_layout.h` beside `Defn.h`.

### The bar

Each item is checked on the PR's head against main at the PR's base.

- **rt-bars:** 0 failures at the gate's thresholds (0.5% instructions, 2.0% peak RSS against main), and D13's collection-time line.
- **Under `h24-n48` only, D8's signed rule, re-run on the port, not taken from X3's 4c05e858 runs:**
  - `scalars.R`'s peak RSS at least 10% lower;
  - no MEM program more than 1% higher. `listgrow` read +0.18% to +1.11% (mean +0.56%) in X3. The rule counts the mean over three runs × two builds (noinline and inline), and each run's range is recorded beside it;
  - no workload row more than 1% worse in instructions;
  - the wall geomean over MEM and SUITE better beyond the tie on both machines. X3's cells lost on this, so either it passes on the port or the lead's decision says it is waived;
  - `TRUELENGTH`'s read and write rows (below) within the bound the decision names.
- **Exactness, identical to main:**
  - `memory.profile()`;
  - the `gc()` table (as narrowed by L7, `2026-11-18-h-memory-internals.md`);
  - radix sort on strings;
  - `env.profile()`;
  - growable vectors' values (`x[n + 1] <- v` loops);
  - under `h24-n48`, a C case that sets and reads back arbitrary and negative `TRUELENGTH`s on a CHARSXP, a C-allocated VECSXP and a growable vector.

  Two of the plan's X3 list cannot be run today: `inspect` (`.Internal(inspect())` is not implemented in robigo-rt) and `object.size` (utils, not loaded under `R_DEFAULT_PACKAGES=NULL`). Until they are, they are not part of this bar. `R_maxLength` has no case.
- **Modes:** the full `scripts/rt-ci.py`: release tests, every conformance mode, gctorture, `ROBIGO_GC_MOVE`, overshoot, injected failures, the builtin differential.
- **Miri** on robigo-heap (`layout::`, `heap::bitmap_tests`, `heap::medium_tests`, `arena::`) and on robigo-rtcore.
- **Review:** sol-loop to APPROVE on the final head.

### Rows that would be added under `h24-n48`

- **`tl-read`:** `TRUELENGTH` read 10⁶ times on a growable vector, on a C-allocated vector and on a CHARSXP. Today it is one load at a fixed offset; X3's branch takes about 10 instructions with three or four dependent loads for a vector with the word.
- **`tl-write`:** the same for `SET_TRUELENGTH`.
- **`grow-int`:** `x[i] <- i` to 10⁶, the growable path's cost, which reads the capacity at each growth check.

### Premises that could fail, and each one's test before any build

1. **Main's layout is X3's `h32-n48` cell.** A keep decision means main is the winner. Test: `git diff 4c05e858 main -- crates/robigo-heap/src/layout/defs.rs` changes no size or offset constant (checked 2026-11-21: only #929's assertion width), and `the_layout_is_h32_n48` passes. If it fails, X3's "today" is not today, and its deltas are re-measured before anything lands.
2. **The binarytrees RSS rise is robigo-rt's, not the host's.** `2026-11-16-m1-exit-evidence.md` found CI's 23,704 KiB 2.9% above D5's 23,040 KiB at `060c20af`, and this host 11.7% above CI's. It suggested, but did not establish, that this was WSL2 and glibc 2.44. Test: peak RSS with `scripts/rss.py --runs 5` at `060c20af` and at main, on idle m0pad and in CI's container. If the difference is inside the runs' spread, the item closes with the numbers and no code. If not, its cause is found before H6 changes anything.
3. **(`h24-n48`) X3's gains hold on today's main.** H5's arena, #929, #939 and D5 have changed what the MEM programs allocate since `4c05e858`. Test, before the port: X3's MEM rows (`scalars`, `plist`, `henv`, `listgrow`, `churn`, `binarytrees`) on main against X3's `h32-n48` binary. Any row moved by more than 2% means the port is measured fresh, and X3's deltas are not carried over.
4. **(`h24-n48`) No robigo C sets a `TRUELENGTH` on a vector without the word.** Test: grep robigo-rtapi's C (`api.c`, `include/`), the R_HOME tree's headers and the capi cases for `SET_TRUELENGTH`, `TRUELENGTH` and `ROBIGO_VEC_OFF_TRUELEN`. Every hit is either a CHARSXP, a growable vector, or listed for option (a).
5. **(`h24-n48`) The C API can give every C-allocated vector the word without a measurable cost.** Test: count the allocations made through the C API in the MEM and SUITE programs, from a callgrind count of `Rf_allocVector`. Zero means option (a) costs those rows nothing. Otherwise the bytes are added to the RSS rule's input.
6. **The exactness cases run on robigo-rt.** Test: run each case on main's binary; done 2026-11-21, with `inspect` and `object.size` failing as noted above. A case that fails on main is not part of the bar until it runs.

### What in H6 depends on the header and node sizes

- **Under `h32`/`n48`:** nothing in H6 changes a size. A later change of layout costs this:
  - **the port again**, from wherever the variant branches are then (X3's are on `4c05e858`);
  - **the binary interface**, which is the larger cost:
    - `robigo_layout.h`'s offsets (`ROBIGO_VEC_OFF_TRUELEN` and the vector data offset);
    - `api.c`'s static assertions;
    - every package's native code built against the R_HOME tree once L ships package natives: each would have to be rebuilt, and the C API's cases re-proved;
  - **the heap tests' size constants** (`FILL`, `LARGE_FILL`, which follow the variant), the exactness recordings, and the perf baselines, which the gate re-takes.
- **Under `h24-n48`:** the same list, plus the `TRUELENGTH` path. Its read and write rows, the C API's option (a) or (b), and `Defn.h`'s function export all assume a 24-byte header with a trailing word. Going back to 32 bytes would undo them.
- **The node size (`n48`) is unchanged under both outcomes.** Its retyping property (`node::same_body`) holds, and nothing in H6 depends on it beyond the tests that assert it.
