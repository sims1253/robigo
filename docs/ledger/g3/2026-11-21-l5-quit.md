## 2026-11-21: quit() and .Last (L5)

- `.Internal(quit(save, status, runLast))` (crates/robigo-rt/src/repl.rs
  `do_quit`, main.c's do_quit and unix/sys-std.c's Rstd_CleanUp) was not
  implemented: `quit()` and `q()` were errors on both boots. Now:
  - the arguments as do_quit checks them, its messages verbatim: `save`
    not a string ("one of \"yes\", \"no\", \"ask\" or \"default\"
    expected."), empty (STRING_ELT's "attempt access index 0/0"), or
    unknown ("unrecognized value of 'save'"); `"ask"` without a console
    warns and takes the command line's action; an NA `status` warns and is
    0, an NA `runLast` warns and is FALSE; `status` is asInteger's ("5"
    is 5);
  - the save action: robigo-rt's command-line `SaveAction` is always
    SA_NOSAVE (it refuses `--save`, and R without a console needs a save
    option or a FILE, which implies `--no-save`), so `"default"` and
    `"ask"` do not save; `"yes"` saves the image as R_SaveGlobalEnv does
    (`sys.save.image(".RData")`, after `.Last`), which today ends in
    robigo-rt's "saveToConn() is not implemented yet";
  - with `runLast`, R_dot_Last's `R_GlobalContext = R_ToplevelContext =
    &R_Toplevel` first (robigo-rtcore's `Cx::reset_to_session`, unsafe:
    the records above leave the chain and the call never returns into
    them): `.Last`, `.Last.sys` and the save see no frame of quit()'s
    callers (`sys.calls()` is `.Last()`), a calling handler around quit()
    still runs (the condition stacks are kept), and an exiting one finds
    "no function to return from, jumping to top level" (as the oracle);
    without `runLast` the save runs in quit()'s context, so a handler
    around quit() catches its error (Sol round 1);
  - then the exit finalizers, the deferred warnings, the console flushed
    and the process ended from inside the call (GNU R's `exit`: no
    on.exit, no finally);
  - an error in `.Last` or the save: check_session_exit halts R
    ("Execution halted", status 1, the exit finalizers run). When
    `options(error)` lets the session go on, GNU R goes back to the main
    loop from inside the call, and with `.Last` failing again at the end
    never ends (the oracle loops); robigo-rt has no jump back to the main
    loop from a builtin and refuses that case ("not implemented yet").
  - No browser contexts (robigo has no `browser`), no session temporary
    directory, no devices to close: those steps of R_CleanUp have nothing
    to do.
- Tests: tests/rt/toplevel/quit-*.R, 21 cases recorded on GNU R 4.6.2
  (status, .Last, runLast, an error in .Last, the warnings printed, no
  unwinding, q(), each argument check; the context: `sys.calls()` in
  .Last, exiting and calling handlers around quit(), the save hook in
  quit()'s context and after .Last).
- **One end for every way R ends** (`repl::clean_up(cx, save, status,
  run_last)`, Rstd_CleanUp): quit(), the session's end
  (end_Rmainloop's `R_CleanUp(SA_DEFAULT, 0, 1)`, `.Last` having run in
  run_session), check_session_exit's halt (`SA_NOSAVE, 1, 0`). The save
  action is resolved there (`SA_DEFAULT` the command line's, which
  `repl::set_save_action` sets: E's front-end plumbing; SA_NOSAVE until
  then; SA_SAVEASK without a console the command line's), then `.Last`
  and the save, the tail (exit finalizers, the R_CleanTempDir slot for B's
  tempdir port, the warnings unless SA_SUICIDE), and the exit.
- The process ends without dropping the isolate (GNU R's `exit`), so
  ROBIGO_GC_STATS's report, which the heap prints when it is dropped, is
  printed by the exit itself (`Cx::gc_stats_report`): rt-ci's E4 overshoot
  step reads it for every case, quit()'s included.
- With main ec22e65ba (#942) merged: R_init_jit_enabled's halt and
  R_Suicide (crates/robigo-rtapi/src/main.rs) go through `clean_up`
  (`SA_NOSAVE, 1` and `SA_SUICIDE, 2`). A compiler whose database is gone
  ends the start as GNU R's does (tests/boot_db.rs, recorded on 4.6.2 with
  its compiler's .rdb and .rdx removed, under C.UTF-8): the lazy-load
  errors, then "Execution halted" (1); with options(error) check_session_exit
  lets R go on and R_Suicide says "unable to initialize the JIT" (2); with
  R_ENABLE_JIT=0 the session runs. (An emptied .rdb is not a case: GNU R's
  readRawFromFile then copies the record from past its zero-length cache,
  serialize.c:3146.)
- `ns::find_namespace` on GNU R's boot is R_FindNamespace: `getNamespace(
  info)` evaluated in base, so an error in loading the compiler shows
  GNU R's calls (`getNamespace -> %||% -> loadNamespace -> runHook`);
  M1's loader keeps its own path.
- **After the reset, nothing comes back** (#972's review): what `clean_up`
  does after `reset_to_session` runs under one guard. Its normal end is
  `exit`. An R error lands on a top-level record pushed on the base
  (dot_last's, at_top's), and check_session_exit's halt from there is
  `exit` too: an error in .Last, an error in an exit finalizer (each runs
  in its own top level), a restart around quit() invoked from .Last ("no
  function to return from", as in GNU R), recorded on 4.6.2
  (quit-guard-*.R). A panic is caught at the guard and ends the process
  with `abort` before it could unwind into the abandoned frames
  (`ROBIGO_PANIC_AFTER_RESET=1` makes one: tests/front_end.rs).
  `reset_to_session`'s contract says the caller's every way out, unwinding
  included, ends the process. The detached walk checks what `chain()`
  checks (no popped record, a segment reaches the base).
- B's `R_CleanTempDir` goes in `clean_up_tail`, after the exit finalizers
  and before the warnings: inside the guard on the paths through the
  reset, at the same place on the others.
