## 2026-11-21: setup_Rmainloop after the system profile, and the Renviron files (L5)

- On GNU R's boot (`ROBIGO_RT_BOOT=stage0`/`rdb`, beside M1's loader,
  which keeps its emulation), stacked on #922.
- **The Renviron files** (crates/robigo-rtapi/src/renviron.rs, Renviron.c's
  process_Renviron, findterm, subterm, Putenv): the system one
  (`R_HOME/etc/Renviron`), then unless `--no-environ` the site one
  (`R_ENVIRON`, else `etc/Renviron.site`) and the user's
  (`R_ENVIRON_USER`, else `./.Renviron`, else `~/.Renviron`), read in
  `Rf_initialize_R`'s place: after the options, before the locale, before
  the isolate (the process's own `setenv`; no other thread yet). The
  invalid-line message is R_ShowMessage's, on stdout this early, as the
  oracle prints it.
- **etc/Renviron** in the tree (scripts/rt-home.sh): Renviron.in with the
  oracle build's configure values and the Debian `R_LIBS_SITE` line its
  image applies; byte-identical to the oracle's file.
- **The start-up options** `--vanilla`, `--no-environ`, `--no-site-file`,
  `--no-init-file`, `--no-restore` (`--no-restore-data`) are now kept
  (R_common_command_line), and Rscript's FILE / `-e` imply `--no-restore`.
- **After the system profile and the locks** (crates/robigo-rt/src/base.rs
  `after_profile`, main.c's order): `.OptRequireMethods()`, the site
  profile (`R_PROFILE`, else `etc/Rprofile.site`) in the global
  environment, `.Library.site` removed from it, the user's profile
  (`R_PROFILE_USER`, else `./.Rprofile`, else `$HOME/.Rprofile`),
  `R_InitialData` (`sys.load.image(".RData", R_Quiet)` when restoring),
  `.First()`, `.First.sys()`. Each inside its own SETJMP, as main.c has
  them: an error is check_session_exit's ("Execution halted", status 1,
  no .Last), unless `options(error)` or `catch.script.errors` say go on,
  when the rest of that profile is not read. R_ReplFile has no jump of
  its own, so a profile's error ends the profile; it is read statement
  after statement (R_Parse1File: those before a syntax error run, and the
  error's context is the failing statement's alone,
  `format_parse_error_since`). The startup hooks' lookup is inside the
  same boundary. Not yet: `R_init_jit_enabled` (C1's side).
- INTERIM(L5): base's file and the system profile still record an error
  and go on (stage 0's diagnostic), where GNU R halts; the system profile
  stops at Sys.info and Sys.glob until E's land, then this goes.
- Order as Rf_initialize_R's: the system Renviron before the options are
  read, the site and user ones after them and before any input is read.
  `--restore` is kept in order: Rscript puts `--no-restore` before the
  user's options.
- Start-up state against the oracle (`options()`, `search()`, the global
  environment, with `R_DEFAULT_PACKAGES=NULL`): the same but `pager` (a
  path under R_HOME), `loadedNamespaces()` without `compiler` (the JIT),
  and `.libPaths()` (the profile stops in Sys.glob, E's). Before this:
  `browser`, `pdfviewer`, `printcmd`, `texi2dvi` empty (no Renviron) and
  `.Library.site` in the global environment.
- Tests: `tests/boot_db.rs` checks the options and `.Library.site`, a user
  Renviron and profile read as GNU R reads them (expected output recorded
  on the oracle with the same files), and `.First`'s error halting.
- A profile's lexer warnings go with their statement, up to how far the
  lexer had read when the error was raised: the raise site's frontier
  for an action's error (a repeated formal or an empty tag reduce with a
  lookahead read; a zero-length function name with none), else the
  rejected token, as the console's parse counts them
  (`Parser::error_frontier`); lexical conditions
  (raiseLexError, `(<input>:line:col)`) and R errors are reported as they
  are.
- Deferred (L.md): a parse condition with a call (`x <- _`'s
  invalidPlaceholder, raised with R_CurrentExpr) is refused as "not
  implemented yet", in a profile as at the console (repl.rs's
  parse_error_message): it needs the parse error's call lowered to an R
  object, one change for both.
- #922's eight deferred lows: an unknown `ROBIGO_RT_BOOT` is an error
  (exit 2), not M1's loader; the database tree must hold base.rdb and
  .rdx, not only baseloader.R; `missing_tree` takes the boot (its unit
  test no longer reads the environment); stage 0 keeps its stub count and
  says where `.Device` failed; loader.rs reads the boot forms as the
  loader evaluates them (configure's substitutions made, `form_text`);
  rt-home-db.sh: a usage error for `--robigo-rt` without a value, and a
  lock around the build (two runs cannot interleave their rm and mv).
- #860's deferred lows: `Wide::files`' and `Loaded::files`' docs and
  base-wide.R's header now say the boot forms are read at load;
  base-wide.R stops on a `boot_names` entry no form assigns (the lists
  are unchanged).
- `volume` (crates/robigo-conformance) now also skips a case under retry
  torture (`ROBIGO_RETRY_TORTURE=1`, a collection at every build), as
  under gctorture: the compiler-loading cases that require it
  (`bytecode/cmpfun-ops`, `cmpfun`, `compile`, `fidelity`,
  `serialize/compile-pkgs`) took 599-601 s of the 600 s there on three
  delegates' runs. `bytecode/jit.R` keeps loading and running the compiler
  in both torture steps. The two other `volume` cases
  (`sort/radix-volume`, `alloc/near-vector-limit`) skip there too. To
  move back once the compiler loads from its installed `compiler.rdb`
  (then much cheaper).
- names.rs (robigo-rtbuiltins): names.c's `#ifdef Win32` rows are not
  rows (`shell.exec`, `Sys.which`, `mkjunction`, `tzone_name`): GNU R on
  Linux has no such internals, so `is.builtin.internal(tzone_name)` is
  FALSE and cmp.R does not inline `.Internal(tzone_name())`. This was the
  one base.rdb record that differed from the oracle's only in byte code
  (`Sys.timezone`'s constant pool: our compiler inlined the call as a
  builtin internal). base.rdb from the database boot is now 1186 of 1189
  records the same bytes; the three left are `.Library` (our build's path),
  `.popath` (NA) and env::6's `.lib.loc` (empty: the profile's
  `.libPaths()` stops in Sys.glob, E's #925).
