## 2026-11-21: V4 step 3, design: the JIT installs R_cmpfun1's byte code as BODY

This is a design for the foreman to sign before any code. It is written
ahead of L5. Signed 2026-11-21 with three amendments, added here: P9 (a
translation bar per byte-code op, with the cache as its fallback), P2's
corpus extended to `compiler.rdb` and `tools.rdb`, and bar 4 (which rows
change meaning, none redefined). It says:
- what step 3 changes and what it removes;
- the bar;
- what it needs from L's boot;
- the premises that could fail, and how each is tested before building.

### What GNU R does at the JIT moment

`applyClosure` calls `R_CheckJIT(fun)`. When the JIT decides to compile
(eval.c:1569, already ported in `jit::check`), `R_cmpfun(fun)` (eval.c:1849)
runs:
1. **The JIT cache.** Unless the strategy is NO_CACHE, it hashes the
   closure (`hashfun`) and looks for an entry. When the environment, the
   body and the srcref match, it sets `BODY(fun)` to the entry's code and
   stops. When the environment differs, it marks `fun` NOJIT and stops.
2. **The compile.** Otherwise `R_cmpfun1(fun)` runs, which is
   `compiler:::tryCmpfun(fun)` evaluated in base. A result without byte code
   marks `fun` NOJIT. A BCODESXP is cached and becomes `BODY(fun)`
   (eval.c:1903).
3. **Later calls.** They run `bcEval` on that BODY. `body(f)` gives the
   source back (`R_ClosureExpr`), and `print(f)` shows `<bytecode>`.

### What robigo-rt does today

- `jitcache::cmpfun` ports step 1's cache.
- In step 2 it compiles from **source** with V2's Rust port of cmp.R's
  decisions (compile.rs, the `Bc` profile) and attaches robigo-rt's IR to the
  closure (`jit::set_compiled`). BODY stays the source.
- A BCODESXP body, for base's installed closures and anything that came
  from an rdb, is translated by V3 (compile/bctrans.rs) and cached on the
  BCODESXP (`code::cache_on`).

So two compilers produce IR today. The base.rdb crosscheck keeps them
equal: 999 same, 147 in named expected classes, 0 unexpected.

### What step 3 changes

| place | today | step 3 |
|---|---|---|
| `jitcache::cmpfun` (R_cmpfun) | V2 compile from source, IR attached | `jit::cmpfun1` (exists since 3a); BCODESXP cached by hash and set as BODY; a decline sets NOJIT (already so) |
| a compiled closure's first call | runs the attached IR | translates BODY (V3), cached on the BCODESXP; later calls run the cache |
| promise code | IR per argument code (V2) | each MAKEPROM's BCODESXP, translated per promise (V3, `promise_code`; already the path for base) |
| serialize | compiles a JIT-compiled closure at the write (`jit_compiled`, #890 and #921) | BODY is the BCODESXP: written as it is (serialize.c's WriteItem) |
| `jit::closure_profile` after the JIT's compile | `Bc` when IR code is attached | `Bc` also for a BODY the compile made a BCODESXP: the call that triggers the compile runs the new byte code, as GNU R's does (P2b's first cut missed it) |
| `print`, `body`, `.Internal(bodyCode)`, `identical` | the source | GNU R's, through the paths already used for base's BCODESXP bodies |
| V2's from-source compiler | the JIT's compiler | the cross-check only (`ROBIGO_BC_CROSSCHECK`), and the `Eval` profile's code; no runtime `Bc` compile from source |

### What it removes

- **`tests/rt/jit/serialize-write-shadow.R`'s difference.** The byte code
  is made at the JIT moment, in that moment's environment, so a later
  shadow no longer changes what is written. The case is ratcheted.
- **The refusal to write a promise made by compiled code** (#890,
  residual 2). Translated code's promises hold the BCODESXP as PRCODE,
  which WriteItem writes (`WriteBC`). Premise P5 below checks it.
- **serialize's compile at the write of a JIT-compiled closure.**
  `jit_compiled`, the per-pass memo of #921, and the NOJIT setting on a
  decline there all go. The compile on write under `_R_COMPILE_PKGS_`
  (#856) stays, as serialize.c has it.
- **V2's role as a second compiler.** It stays as the cross-check, so
  `cenv.rs` and compile.rs's `Bc` arms keep their tests but leave the hot
  path. The V3/V4 notes in m2m3-plan §F.9 then hold by construction: "one
  IR source".

### What it needs from L's boot

1. **The compiler namespace from its installed `compiler.rdb`, with its
   closures as byte code.** Today, even on main `267da9c55` with #922's
   rdb boot, robigo-rt's default boot still builds the compiler from source
   (`ns::load_compiler`, INTERIM(L2)): `typeof(.Internal(bodyCode(compiler::cmpfun)))`
   is not `"bytecode"` on robigo-rt, and it is on GNU R. With a source-built
   compiler, step 3's JIT would compile cmp.R's own closures through cmp.R
   at their calls. Each `cmpfun` would then cost the compile of the
   compiler first, and the cost bar could not pass. **Blocking.**
2. **`R_init_jit_enabled` at its place in `setup_Rmainloop`** (main.c:1212,
   after the profiles, under `R_Toplevel`):
   - `.ArgsEnv` forced;
   - `R_ENABLE_JIT` read (default 3);
   - when the level is above 0, `loadCompilerNamespace()` and
     `checkCompilerOptions(level)`;
   - then `_R_COMPILE_PKGS_` and `R_DISABLE_BYTECODE`.

   With the JIT on, `loadedNamespaces()` is `c("compiler", "base")` at
   startup, as l5-compiler-at-boot recorded. robigo-rt reads these
   variables today, but loads the compiler lazily.
3. **`compiler:::tryCmpfun` reachable from base** at any call after the
   boot (`R_cmpfun1` evaluates `compiler:::tryCmpfun(f)` in `R_BaseEnv`).
   `::`/`:::` and the namespace registry must be live then. #860 gives it.

Nothing else in step 3 depends on L. The translation (V3) and `cmpfun1`
(3a) are on main.

### The bar

1. **Equality.** After the JIT threshold, `print(f)` shows `<bytecode>`,
   and `serialize(f, NULL)` equals GNU R's bytes. The `jit/*` and
   `serialize/*` cases are ratcheted, `serialize-write-shadow.R` among them.
2. **A JIT compile costs at most GNU R's instructions per closure** on the
   calls.R closures (`benchmarks/suite/calls.R`). It is measured with
   callgrind as the instructions between a closure's first and second
   calls, minus the second call's run.
   - robigo-rt's cost is `tryCmpfun`'s R code run on robigo-rt, plus the
     translation of the result (≈111k instructions per closure after X's
     #930, from ≈183k).
   - GNU R's is `tryCmpfun` run by GNU R's bcEval.
   - The starting numbers are premise P1.
3. **Steady-state rows.** Every row of `benchmarks/rt/calls-rows.toml` and
   the perf-rt suite is within the 0.5% instruction gate, against main's
   binary at step 3's base. The code those rows run changes source: the
   V2 port's IR becomes the translation's.
   - Same-verdict closures give the same IR (the crosscheck's "same").
   - Closures in an expected class differ by construction. The class
     that matters for the rows is `%%` and `%/%`: cmp.R calls them with
     CALLBUILTIN, while the V2 port emits Arith. Any row whose loop uses
     them may move, and premise P3 measures which rows do and by how much.
   - A row that regresses past the gate is fixed in the translator, by
     emitting what V2 emits where the semantics are equal (one IR, two
     encodings of one op), not by keeping V2.
4. **Which gate rows change meaning.** No row is redefined or
   re-baselined in the step 3 PR. A row past the gate is fixed in the
   translator, as point 3 says: the perf gate has no bypass. What each
   `benchmarks/rt/calls-rows.toml` family measures after step 3:
   - **`jit`** (seven rows, one `compiler:::tryCmpfun(f)` per iteration,
     "as R_cmpfun1 makes it"): unchanged in what they run. They become the
     JIT's real cost on robigo-rt, which today they measure on GNU R's side
     only (the compiler namespace could not load). Bar 2 reads them.
   - **Every other family** (`calls`, `suite`, `e7`, `d10`, `d2s`,
     `layout`, `envs`, `growth`, `cold`, `d0`, `guard`, `conditions`):
     - the harness's `g`, a loop the JIT compiles, now runs translated IR
       instead of V2's;
     - so do the closures a row calls, once the JIT compiles them
       (calls.R's, fib, binarytrees);
     - what the row computes and the number it is judged by are the same.
     - The `cold` rows' new closures are called once each, so the JIT
       never compiles them; only their harness loop changes.
   - **The perf-rt suite's programs**: as the families above.
5. **Peak RSS** of the three memory programs is within 2% of main's: a
   compiled closure now holds a BCODESXP and its translated IR, where it
   held IR only.

translation (V3) and `jit::set_compiled`. No step 3 code is needed. A
failed premise stops step 3 and comes back to the foreman with its number.

**P9's fallback, the translation cache.** If no translator meets P9's
target, the design's answer is a cache of translated code:
- **Key:** a hash of the record's bytes (the closure's serialized BCODESXP
  as the database holds it) and robigo-rt's build id.
- **Place:** outside `R_HOME`, under the user's cache directory. A file
  under `library/` shows in `list.files`, and the databases must stay
  byte-identical to GNU R's.
- **A miss** falls back to the translator, and its result is written for
  the next process.

Two answers stay out, as g3.md §9.1 decides:
- running a closure's first call as AST;
- a second engine that interprets GNU R's byte code.

### P2b's runs, 2026-11-21 (main 267da9c55): failed

**The first cut, 623 of 670.** It was mostly the probe's own fault. The
call at which the JIT compiled a closure still ran as AST:
`jit::closure_profile` returned `Bc` after `cmpfun` only for a closure with
IR code attached, not for one whose BODY is now a BCODESXP. Every JIT
test's compiling call, and anything that reads binding kinds there, then
differed from GNU R, whose compiling call already runs the new byte code.
Step 3 needs the same change (the table of changes above lists it).

**The rerun, with `closure_profile` returning `Bc` for a byte-code BODY:
650 of 670.** Main fails only its unratcheted cases. The crosscheck: 0

### Order

1. P2, then P5, P6 and P7: correctness, cheap, on the probe branch.
   P9's measurement beside them: it needs no step 3 code.
2. P3: rows and perf-rt on the probe branch. If a row moves, the
   translator fixes come first, each its own PR.
3. P1, when L's compiler.rdb boot lands.
4. The step 3 PR:
   - `jitcache::cmpfun` installs `cmpfun1`'s BCODESXP;
   - serialize's JIT path removed;
   - the shadow case ratcheted;
   - V2's `Bc` compile out of the runtime path;
   - its ledger with the bar's numbers.
5. A follow-up: #829's `[setups]` drift test with the jit rows, and V2's
   move to cross-check only, its dead code removed.

### Size

- **The step 3 PR:** M. The JIT's compile call, serialize's simplification
  and V2's removal from the runtime path.
- **Translator fixes:** each S to M, as many as P2 and P3 find. This is the
  part that cannot be sized before the premises run.
- **Measurements:** P1's and P3's are each an afternoon.
