# X9-3: `cleanup_envir`'s passes and `new_closure_frame`'s init stores, tried and dropped (2026-11-21)

X/P1. Recorded so that it is not tried again without new facts. The
patches, the numbers and the traces are in
`~/.cache/robigo-research/x-p1/x93-study/`.

## What was tried

`Cx::cleanup_envir` (GNU R's `R_CleanupEnvir`, eval.c:2128, run after a
closure call) scans a frame up to five times:
- `cycle_refs`'s `walk_bound`: a scan for a cell, then a walk;
- the release `walk_bound`: the same two again;
- `release_caller`'s scan.

A frame with a cell is also listed in stamp order with a sorted `Vec`,
because GNU R's FRAME walk runs newest first and stops at the first
binding cell whose `REFCNT` is not 1.

1. **The cut** (`cut-variant-WRONG.patch`, 72a33d4b). One slot-order pass
   found the stamp of the newest shared cell. The cycle count and the
   release then visited, in slot order, the bound slots stamped above it,
   with no listing and no sort.

   Against main `30b34e0b` it measured trycatch −0.81%, s3 −0.85%,
   trycatch-err −0.96%, `jit-scale_by` and `jit-safe` −0.72% per compile,
   and binarytrees +0.13%.

   **It is wrong.** Sol (gpt-6.1-sol, round 1) found two counterexamples:
   - **S1.** GNU R tests `REFCNT(b) == 1` on each binding when its walk
     reaches it (eval.c:2137-2139, and `countCycleRefs`), after the newer
     bindings have been released. Releasing a promise (`clearPromise`) can
     drop a later binding cell's count from 2 to 1, and GNU R then goes on
     past that cell. A cut computed before any release stops there.
   - **S2.** In a frame with a cell, the release order changes what is
     cleared. `release_value` clears a promise or `...` list only when its
     count is 1 (eval.c:2144-2152). Releasing one binding can make another
     binding's promise unshared. Listing order and slot order then clear
     different objects.
2. **The correct variant** (`correct-variant.patch`, d19cee2c). A frame
   with a cell keeps the listing-order walk with its live refcount test.
   Only the scan for a cell is shared by the two walks, and a frame without
   one skips `release_caller`'s scan.

   Against main `a8e08fdd`: trycatch +88 instructions per iteration,
   binarytrees +4,653 (+0.13%), plain flat. No gain: the gain came from the
   cut.
3. **`new_closure_frame`'s init stores.** The idea was to skip the
   old-value side of the counted store on slots that `clear_raw_val` has
   just nulled. trycatch makes about 11 frames per iteration, at about 570
   instructions each. At most about 3 instructions per store would be
   saved, which is at most about 0.2% of trycatch, and it needs a new heap
   store API (Miri on heap). Not done.

## Left open

S2's order effect exists in main's code for a frame without a cell, which
`walk_bound` releases in slot order ("the order of a walk that cannot stop
early is not observable" is not quite true). It is not yet shown from R.
It is in `delegates/X.md` §8, to be tried with an oracle case when X next
works in that code.
