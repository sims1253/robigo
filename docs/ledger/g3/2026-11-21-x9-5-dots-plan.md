# X9-5: calls into a callee's `...` take the plan path (2026-11-21)

X/P1, the last X9 item. A compiled call site memoizes its argument match
in a `Plan` (crates/robigo-rt/src/args.rs). The fast plan path (`site_plan`
→ `plan_inits`, without the matcher's buffers) refused a plan whose
callee's `...` formal takes some of the call's arguments (`ndots > 0`).
Such calls (`tryCatch(expr, error = …)`, `stop("…")`) ran the matcher path:
the actuals, the formals' tags and defaults collected into buffers, the
cached plan filled into a `Matched`, and `dots_list`.

## The change

- `site_plan` accepts `ndots > 0`.
- `plan_inits` binds the formals as before, with the `...` formal as
  R_MissingArg. When the plan has dots, the out-of-line `plan_dots` copies
  the plan (the site's plan may move when an allocation collects). It then
  builds the DOTSXP under `retry_alloc`, from the rooted call's arguments
  at the plan's dots indices (`plan_dots_list`, with `list_element`, as
  `dots_list` does from the matcher's actuals), and binds it to the `...`
  formal.
- The lazy `promargs` filler (`FillData::each_actual`), which `sys.call`,
  `match.call` and S3 dispatch read, reports those arguments as
  `Went::Dots(k)`. That is done in an out-of-line copy (`each_actual_dots`),
  so that main's loop for the calls without dots is unchanged.

A call whose own actuals contain `...` still takes no plan.

**Two costs found and removed on the way.** The first version copied the
64-byte `Plan` on every plan hit: binarytrees +0.30%, s3 +0.26%, jit
+0.12%. It also searched for dots in the `promargs` loop for every actual,
on S3 dispatch's path too. Both are gone.
