## 2026-11-23: the local slot pool, for builtin-diff and the crates' tests

#982 gave local gates one machine-wide pool of conformance case slots.
#989 adds builtin-diff's robigo-rt drivers and rt-ci's crate-test steps to it
(`scripts/conf_slots.py`).

**Known, not fixed: the default slot count ignores a cgroup CPU quota.**
- Without `ROBIGO_CONF_SLOTS`, the Python tools count the CPUs in the
  process's affinity mask.
- The Rust runner's `available_parallelism` also caps that by a cgroup CPU
  quota. Under a quota the two counts differ.
- This does not break correctness. The slots are the same files, so the
  side with the lower count only ever takes fewer of them.
- This box has no quota and CI has no pool, so it is not worth code now
  (Sol's deferred finding on #989; the foreman's ruling).

**The crate-test thread floor.** A crate-test step runs with
`--test-threads=max(held, 4)` (rt-ci.py's `CRATE_TEST_MIN_THREADS`), and it
never waits for more slots than its first.
- In #989's local gate, at load about 20, five crate-test steps got one
  slot each.
- The debug-assertions shard's crate tests ran at one thread for 3.0 min,
  so the shard took 5.5 min, 110% of its 5-minute budget.

**The threads were not what cost the time.** I timed the same step again
with its tests built beforehand, alternating one and four threads at load
24 to 32:

| `--test-threads` | run 1 | run 2 |
|---|---|---|
| 1 | 0.53 min | 0.71 min |
| 4 | 0.56 min | 0.59 min |

- The 3.0 min in the gate was the step's own build under load, which
  happens before any test runs and is not set by `--test-threads`.
- The floor stays as a bound for long test runs, such as the gctorture
  modes' steps, not as a fix for this shard.
