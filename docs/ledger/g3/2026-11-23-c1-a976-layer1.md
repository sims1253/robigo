## 2026-11-23: C1: #976 layer 1, the translator refuses malformed byte code

Byte code that GNU R's compiler does not make reaches robigo-rt's
translator through `.Internal(mkCode)`/`bcClose`, a crafted serialization
or a lazy-load database. A run of 60 starts of 100 mutations each
(2026-11-23, on #979's binary) ended in a SIGSEGV or a panic in 56 of
them. Layer 1 makes the translator refuse such code before anything reads
it, and the compiler panic on no input. Layer 2 (the verifier's
register-state invariants) follows.

### What layer 1 guarantees, and what it does not

- **Malformed byte code is refused, never misread.** Byte code GNU R's
  compiler does not make, of a shape the translator checks, is refused
  before anything reads it. That covers:
  - an operand out of range, or a constant of another kind;
  - a label going backward where cmp.R's never do;
  - stacks its own jumps disagree about;
  - a translation the verifier refuses.

  The code raises an R error, "robigo: malformed byte code: WHAT", when it
  runs.
- **Well-formed but wrong byte code runs as it says.** Its values are what
  the code computes. A loop it makes polls for interrupts, so SIGINT ends
  it, as an R loop. Nothing more is promised.
- **Not yet: the register-state invariants, layer 2's static check.** The
  VM reads registers through `Act::obj` and similar, which return a bare
  `Sexp` and panic on an unboxed value, and its `for`, subset and loop
  state is read unchecked. Layer 1 closes every case the mutation runs
  found, through the translator's stack checks; a proof waits for the
  verifier's dataflow pass over every code, and only that is one.
  "0 panics in 18,000 mutations" is a measurement, not a proof.
- **The figures are measurements:**
  - the corpus;
  - three seeds of 60 starts of 100 mutations, with no signal, no panic,
    no abort and every loop stopped by SIGINT;
  - the CI step's fixed seed, a regression test, not a search.

  The search is the nightly's (`--seed auto`, failures written out for the
  corpus with `--failures-out`).

### What is refused, and how it says so

- **`Need::Malformed`**, kept apart from `Need::Fail` (byte code not
  translated yet). Malformed code raises "robigo: malformed byte code:
  WHAT" when it runs, never "not implemented yet". The crosscheck reports
  it as a `malformed byte code:` line, an error in rt-ci's report check,
  so a refusal of GNU R's own code fails CI.
- **The operand check** (`compile/bctrans/check.rs`), before the
  translation reads anything:
  - one table gives each opcode's operands, from eval.c's `bcEval`: a
    constant of a kind (symbol, call, tag, names, jump offsets, a
    closure's list), a label or a count. A unit test checks that it
    covers every opcode with operands;
  - a constant index must be within the pool, and the constant of its
    kind; a call must be a proper list;
  - a label must be within the code, and forward, except GOTO's and
    STEPFOR's (cmp.R's other labels all go forward; a jump back from
    another would loop where no poll is); a switch's offsets likewise;
  - a constants vector that is not a list is refused only when an operand
    reads a constant (`mkCode(c(12L, 17L, 1L), NULL)` runs, as in GNU R:
    tests/rt/bctrans/null-consts.R).
- **The decoder:** an instruction code past the table, or cut short.
- **The stack:** the two passes or two paths disagreeing about the stack
  (`mismatch`) is malformed, and no longer a `debug_assert`, which
  mutated code could reach. A back-edge's target, reached first by
  falling in, keeps the stack it was translated with as its label, so the
  back-edge's `meet` checks the stack it brings. A mutated STEPFOR that
  jumped elsewhere ran the loop's step on another stack, and the VM
  panicked on a register (vm.rs:217).
- **The verifier:** a translation, or an argument's, that
  `Verified::new` refuses is malformed byte code, never a panic.

### The compiler on legitimate but enormous input

Each case is against GNU R 4.6.2 on the oracle.

| input | GNU R | robigo-rt before | now |
|---|---|---|---|
| a `switch` of 70,000 alternatives | works | panic | works |
| a `{` of 70,000 assignments (70,000 constants) | works | panic | "robigo: a code object of more than 65535 constants is not implemented yet" |
| 20,000 nested `1 + (...)`, evaluated | "evaluation nested too deeply" | stack overflow | the same as GNU R |
| a closure body of 900 nested `+` | 0.18 s, one constant | 128 s, 900 fold rounds | 0.89 s, one constant |

- **Overflows are flagged, not panicked on.** Past the IR's 16-bit
  operands (constants, registers, a `switch`'s alternatives), `Comp` notes
  it and the root compiles code that raises "not implemented yet". Under
  `Bc` the compile fails instead, as cmp.R's would, and GNU R leaves the
  code uncompiled.
- **Deep nests:** past depth 1,000 the `Eval` profile evaluates the rest
  when it runs (`EvalConst`), so the compiler's recursion stays within the
  stack. The run's own depth count raises GNU R's error where GNU R does.
- **Constant folding is one pass, bottom-up, as cmp.R's.** A fold
  request's argument may name an earlier request of the same try, and a
  round resolves them in order. A nest that took `n` rounds, each a
  recompile, now takes one. The `Bc` depth bound is `CMP_DEPTH = 1477`:
  GNU R 4.6.2's cmp.R compiles 1,477 nested fold calls to one constant and
  fails from 1,478 with "node stack overflow". That is bisected on the
  oracle; derive it again when the oracle changes:
  `scripts/oracle-run.sh 4.6.2 Rscript --vanilla scripts/oracle-cmp-depth.R`.
- **Known difference** (tests/rt/bytecode/cmpfun-node-stack.R, recorded,
  not ratcheted): `compiler::cmpfun` and `compiler::compile` run cmp.R's
  R code, and robigo-rt runs it on a node stack of another size. It
  compiles 1,478 levels where GNU R overflows, and at 20,000 says
  "evaluation nested too deeply" where GNU R says "node stack overflow".
  Closing it needs a node-stack limit of GNU R's size
  (`R_BCNODESTACKSIZE`) in the VM that runs cmp.R. The JIT's compile,
  robigo-rt's own, matches GNU R at every depth
  (tests/rt/eval/deep-nesting.R).

### The proof

- **`scripts/rt-bc-mutate.py`**, the generator in `tests/bc-mutate/gen.R`,
  pinned by its sha256:
  - every start runs under a 2 GB address-space cap, checked in force
    first;
  - a start still running at the limit gets SIGINT and must end within
    3 s;
  - the binary's commit, from its build marker, is printed with the
    results.
- **The corpus** (`tests/bc-mutate/corpus.txt`): the 57 mutations that
  crashed, panicked or hung on 2026-11-23, replayed as found (mutations 1
  to k in one start: alone, none crashes). Seed 300014's mutation 4, a
  CALL whose constant is a symbol, grew by 0.8 GB a second. All 57 now
  end as R code ends.
- **The translation cache's `refused()`**, from #994's bot: a hit the
  verifier refuses is counted always, and reported only where hits are
  compared. `scripts/rt-tcache-mutate.py` checks it on a forged entry:
  the same output, empty stderr, the refusal counted.

### Merged with main: the compile pool, the freeze, the budgets

#1003 took main three times while in review: #988 (E's per-isolate pool
of compile buffers), #992 (the boot heap's freeze on by default), #991
(rt-ci's budgets and step plans), then #1000 and #1004.

- **The pool, a refused translation:** a compile's code is built by the
  Comp that made it (#988), and a translation must refuse code the
  verifier refuses (layer 1). `Verified::try_new` gives the code back
  with the refusal, and `Comp::verify` returns its buffers to that
  compile, as `Comp::build_verified` does for code that passed.
- **An aborted compile leaves the pool clean.** `tests/bc-mutate/pool.R`
  runs as one start of `rt-bc-mutate.py`, under gctorture (7,277
  collections in 1.5 s), and fails the harness if it does not finish:
  - in three rounds it aborts compiles: two malformed codes (a GOTO past
    the code, a constant past the pool) and a closure body past
    `CMP_DEPTH`, whose compile stops at the fold's depth bound;
  - after each round, closures must give their values, among them one
    first compiled after the aborts.

  `Drop for Comp` clears every buffer before the pool takes it back.
- **The back-edge check's cost:** it called `successors()`, which builds a
  `Vec` for each instruction, a second time per pass. On top of the pool,
  that made rdb-nocache +4.6% against main (callgrind: 94.83M against
  90.42M). check.rs refuses a backward label on anything but GOTO and
  STEPFOR, so their label operands are the whole search. The targets are
  now a sorted list with a cursor, and code without a loop allocates
  nothing: 91.05M.
- **A finding of seed 7, there before this PR:** a mutated ADD made OR2ND,
  with no OR1ST before it (corpus 700001 47). The VM's `AndOr2` read its
  first operand as AndOr1's unboxed logical and panicked (vm.rs:820);
  main segfaults on it. It now follows bcEval's AND2ND and OR2ND exactly:
  - the second value replaces the first where it decides (`&&`: FALSE or
    NA; `||`: anything not FALSE);
  - otherwise the first value stays, never read.

  The nine-case truth tables of `&&` and `||` are R's.
- **modes' budget is 14, its job's timeout 28.** #991's rule is the
  measured time plus 20%, rounded up: main's 10.57 min and this step's
  0.6 make 11.17.
