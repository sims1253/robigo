## 2026-11-23: the freeze's recount under L5's default boot (the compiler loaded at boot)

L5 makes the default start GNU R's: with the JIT on, base loads the compiler at boot (eval.c:1465), so `loadedNamespaces()` is `c("compiler", "base")` before the boot boundary. The fold's ledger (2026-11-23-h-freeze-fold.md) counted the compiler's lazy-load promises as 38 notes in jit-area's first compiles, inside one pass, and named this recount as the condition for L's flip. The recount clears it: no pass in any start, none in steady state, and the remaining passes are one-time, as before.

**Base:** L's `g3/l5-flip` at 304f94442 with main 5d961809e (#992, the freeze on by default) merged, built locally (not pushed), with a probe (removed) that logs each dirty note's call site, each collection and each pass.

### The default packages: a projection, not a measurement

With stats, utils, methods (and the rest of `R_DEFAULT_PACKAGES`) loaded before the boundary, each comes through `lazyLoad(filebase, envir = ns)`: `makeLazy`'s `eenv` is `lazyLoadDBexec`'s frame and `aenv` the namespace, which the counted exemption does not record (it records base's own frame only). So each first use of a package function forces a frozen promise whose PRENV clear is noted:
- thousands of one-time notes for stats, utils and methods, against 387 for the compiler today;
- still at most one pass per collection, falling to none once the session's functions are first used;
- each pass larger, by the frozen set the packages add: perhaps 2–3× today's 4.4M instructions. This is an estimate from the frozen-set ratio, not measured.

### The design question, and its precondition

Extend the counted exemption to the lazy-load frames of namespaces loaded before the boundary, so a package function's first use takes no note while other promises still use its frame. The foreman's decision: do it with the packages present, not before.

The precondition is to redo the exemption's argument (Sol step 2 r5 S18) for a namespace frame. Base's frame is safe because the counted promises are shown directly by the freeze roots. A namespace's bindings are not freeze roots; they are reached through the namespace registry. So a count may hold only while the namespace stays reachable from the registry, and `unloadNamespace` (or any registry write) must unpin with a note. That argument, the count's rebuild in the pass, and a measurement of the notes and passes with the packages present come with the change.
