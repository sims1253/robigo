## 2026-11-23: GNU R's boot the default (L5)

robigo-rt boots base GNU R's way by default: `R_ReplFile` of R_HOME's
`library/base/R/base`, the installed `baseloader.R`, which lazy-loads base
from `base.rdb` (scripts/rt-home-db.sh's tree). `ROBIGO_RT_BOOT` unset or
empty is that boot (`rdb`); `stage0` boots from base's source tree as
before; `m1` is M1's lazy loader of the pinned sources, INTERIM(L5) until
the PR that deletes it. Any other value is still an error (exit 2), so a
typo never chooses a boot.

### What moves

- `crates/robigo-rtapi/src/main.rs` `boot_checked`: the default. With no
  tree, a default start exits 2 with "R_HOME ('…/.robigo/rt-home-db') not
  found: … (scripts/rt-home-db.sh)", as stage 0's does with rt-home.sh
  (`tests/front_end.rs` `the_default_boot_says_a_missing_tree_is_missing`).
- The harness: `scripts/rt-startup.py`'s `M1_BOOT` is `"m1"`;
  `perf.py rt-bars --boot` defaults to `rdb`. Every start and row names its
  boot for both binaries (X's #996), so the gate never compares two boots.
- `scripts/rt-ci.py`: the default conformance step (no boot named: the
  ratchet and `ROBIGO_CONF_UPDATE`'s markers) runs rdb. M1's loader keeps
  three explicit steps until its deletion: plain, the boot heap's freeze on
  (in the gctorture shard, where its M1 twin was), and the byte-code
  crosscheck. No ratchet marker moves and nothing is recorded again: every
  recording is GNU R's.
- Tests that removed `ROBIGO_RT_BOOT` and so meant M1 (`tests/front_end.rs`,
  `tests/lazyload.rs`) set `ROBIGO_RT_BOOT=m1`; the others take the boot
  rt-ci's step gives them.
- `tools.so` under the default boot: `scripts/rt-home-db.sh` copies
  rt-home.sh's tree, tools' native code with it, but replaces its `.rt-home`
  stamp by `.rt-home-db`, and `tests/conformance.rs`'s `has_rt_home_tools`
  required `.rt-home`; so rt-ci's rdb step ran 763 cases against M1's 766,
  the three `r-home-tools` cases (`tests/rt/dynload/{library-dynam-tools,
  tools-parse-rd,tools-natives}.R`) left out. It accepts either stamp now.
- `scripts/rt-stress.sh` sets `R_DEFAULT_PACKAGES=NULL`, as its case is
  recorded. The other harnesses that run robigo-rt already do:
  robigo-conformance (every case), `perf.py`'s rows (through
  `idiom-vs-r.py`) and peak-RSS runs (`rss.py`), `rt-startup.py`'s starts
  (`BASE`), `builtin-diff.py` (`ENV`), `rt-overshoot.py`, `rt-fail-alloc.py`,
  `rt-tcache-mutate.py`. `base-subset.sh` runs GNU R only; `rivals.py` and
  `perf.py`'s `run_one` do not run robigo-rt.

### What a user sees

- **No default packages, said once.** GNU R's start attaches
  `options("defaultPackages")`; the tree has none of the six, and the
  first run of this branch gave every plain `robigo-rt -e 1` seven
  warnings (`.OptRequireMethods`' for methods, then `.First.sys`'s six).
  The tree now declares what it has, by GNU R's own mechanism:
  scripts/rt-home-db.sh appends
  `R_DEFAULT_PACKAGES=${R_DEFAULT_PACKAGES-'NULL'}` to its
  `etc/Renviron` (the system file every start reads, `--vanilla` too),
  the value being those of datasets, utils, grDevices, graphics, stats and
  methods that have a DESCRIPTION in the tree (none today, so `NULL`).
  It grows as they are built and never names one the tree lacks; a user's
  own value, set or empty, is kept; INTERIM(L5), it goes when the tree has
  all six (GNU R's Renviron has no such line). So a default start says
  nothing and attaches nothing (`getOption("defaultPackages")` is empty,
  `search()` is `.GlobalEnv Autoloads package:base` as GNU R's), and
  `library(stats)` fails as GNU R's does in a tree without stats: "‘stats’
  is not a valid installed package" (find.package's short cut for the
  standard packages gives `.Library/stats`; recorded on 4.6.2 with stats
  removed from the tree). A user's `R_DEFAULT_PACKAGES=stats` gets GNU R's
  "During startup - Warning message:\npackage ‘stats’ in
  options("defaultPackages") was not found". (tests/boot_db.rs, both.)
- **"During startup - " fixed.** robigo-rt printed it, with the warnings
  the start collected, only after a setlocale failure; GNU R's
  setup_Rmainloop (main.c:1197) prints them whenever any are collected,
  after .First.sys and the deferred warnings, so .First.sys's came out
  later without it. `main.rs` now prints them at that point, on every boot.
- **`keep.source` at an interactive start (INTERIM(srcref)).** The default
  boot runs the system profile, whose `options(keep.source =
  interactive())` robigo-rt refuses until it keeps source references
  (rule 6: accepting it without them would have `getOption()` say TRUE
  while functions print deparsed). Once per interactive start, before the
  first prompt, stderr has

      Error in options(...) : 
        robigo: options(keep.source = TRUE) (source references) is not implemented yet

  and the session goes on as GNU R's (the console then parses with
  `keep.source` FALSE, so it says nothing more). M1's loader ran no
  profile, so it never showed. tests/cli.rs's six interactive transcript
  cases run both ways: GNU R's transcript under `ROBIGO_RT_BOOT=m1`
  (ratcheted: the console's tests), and under the default boot GNU R's
  but for that line (`SRCREF`, `SRCREF_LINE`), a check that fails the day
  the line goes, so the cases move without anyone remembering them.
- **`R_KEEP_PKG_SOURCE=yes` halts the start (INTERIM(srcref)).** With the
  JIT on the start loads the compiler, whose `loadNamespace` `sys.source`s
  its loader file with `keep.source = getOption("keep.source.pkgs")`; the
  refusal is printed by loadNamespace's own `try` (GNU R's, not silent),
  then its error, so the cause reaches the user in the same run:

      Error in options(...) : 
        robigo: options(keep.source = TRUE) (source references) is not implemented yet
      Error: unable to load R code in package ‘compiler’
      Execution halted

  Workarounds: `R_KEEP_PKG_SOURCE` unset (or not `yes`), or
  `R_ENABLE_JIT=0`. tests/cli.rs pins this shape and runs the option's
  other checks under `m1`. Source references (E's, scoped now) end both.
- **An error in base's file or the system profile** is recorded and the
  start goes on (INTERIM(L5)); GNU R halts. Stage 0 halting is the next PR
  after this one (or after the default packages: the foreman's ordering).
- **The start's cost** (on main 92d933c4b, #995's harness, this machine):
  the rdb-jit start, now the default, is about 81.5M instructions against
  GNU R's 84.1M (the runner); M1's interim start was about 14.8M, since
  its loader binds base lazily from source without running GNU R's start.

### The tree is the same for every binary of one commit

The question for CI's tree cache (the foreman's, for A1): is a tree built
by one binary valid for another of the same sources? Method: three
binaries of g3/l5-flip (a4a4ac5a7 and work in progress) built in one
checkout, release (64c61e5e…), `-C debug-assertions=on` (691366603…, its
own target) and `--features robigo-rtcore/retry-torture,robigo-rt/poison-dead`
(8f361de1…); each wrote rt-home and rt-home-db in the same home path in
turn (rt-startup.py's `make_trees`); then every record of each tree's
base.rdb (1,189: variables and references) and compiler.rdb (297) was
fetched with `lazyLoadDBfetch` and compared as its ASCII serialization,
each tree's build path (`.rt-home-db-built-at`) mapped to one name.
Result: every record identical. The files differ only in the build path
the databases record (rt-home-db.sh builds in `mktemp -d
.rt-home-db.XXXXXX`, a random name, so one binary twice gives other .rdb
bytes too, as GNU R's record its build tree), DESCRIPTION's and
Meta/package.rds's `Built:` time, the tree's `.rt-home-db`,
`.rt-home-db-builder` and `.rt-home-db-built-at`, and the `-cache/*.rtc`
files, per binary by design (their header holds the build ID and the
tree's stamp, which the reader checks). So the build path and the
`Built:` stamp are the only non-determinism in the tree.

### The shortest path to a quiet default start

GNU R attaches `options("defaultPackages")` in order: datasets, utils,
grDevices, graphics, stats, then methods (`.OptRequireMethods` first).
Each missing package warns once; a quiet start needs all six in the tree.
From src/library (R 4.6.2):

| package | R lines | C (Fortran) | imports | needs in robigo-rt |
|---|---:|---:|---|---|
| datasets | 0 | 0 | - | its data built into a lazy-load data database (`tools:::data2LazyLoadDB`: `load()` of `.rda`, `read.table` of `.csv`/`.tab`, so utils's R code at build time) |
| utils | 22,277 | 2,349 lines, 7 files | - | its R code into utils.rdb (the R target's mklazy), `utils.so` built against robigo-rt's API as tools.so is |
| grDevices | 5,316 | 23,025, 18 files | - | the graphics engine's API (main/engine.c, devices) for its natives |
| graphics | 6,766 | 12,167, 8 files | grDevices | the engine, base graphics' state |
| stats | 33,692 | 23,087, 57 files (15 Fortran) | utils, grDevices, graphics | a Fortran toolchain in the tree build, BLAS/LAPACK |
| methods | 17,006 | 1,553, 7 files | utils, stats | its build-time setup (`..First.lib` dumps the classes and generics into the namespace), robigo-rt's S4 dispatch hooks |

So datasets and utils can each go soonest (two warnings fewer), but a quiet
start waits for the graphics engine (grDevices, graphics) because stats
and methods import them.

The first bench row that proves utils loads: `source5k`
(benchmarks/rt/calls-rows.toml, D11's `source()` of a 5,000-line file)
fails on every boot with "Error: package ‘utils’ does not have a
namespace", since base's `source()` always calls
`utils::localeToCharset()` (X's finding). It is the only one of the 63
rows that errors; no bar or guard cites it, so perf-rt does not measure
it, and X's row check refuses erroring rows by name, so it cannot be
counted by accident. It becomes measurable when the tree holds utils.

### No install layout yet

robigo-rt has no install script. A checkout's binary finds its tree as
`.robigo/rt-home-db` (`ROBIGO_WORKTREE`, `ROBIGO_RT_CHECKOUT`); an
install's would be `<prefix>/bin/robigo-rt` beside `<prefix>/lib/robigo`
(the tree, which `default_r_home` already looks for) and
`<prefix>/lib/robigo-cache` (its translation cache, `<R_HOME>-cache`,
written by the installed binary since the `.rtc` files are per binary).
`scripts/build.sh` builds G2's `robigo`, not robigo-rt.
