## 2026-11-23: GNU R's boot the default (L5)

robigo-rt boots base GNU R's way by default: `R_ReplFile` of R_HOME's
`library/base/R/base`, the installed `baseloader.R`, which lazy-loads base
from `base.rdb` (scripts/rt-home-db.sh's tree). `ROBIGO_RT_BOOT` unset or
empty is that boot (`rdb`); `stage0` boots from base's source tree as
before; `m1` is M1's lazy loader of the pinned sources, INTERIM(L5) until
the PR that deletes it. Any other value is still an error (exit 2), so a
typo never chooses a boot.

### What moves

- `crates/robigo-rtapi/src/main.rs` `boot_checked`: the default. With no
  tree, a default start exits 2 with "R_HOME ('…/.robigo/rt-home-db') not
  found: … (scripts/rt-home-db.sh)", as stage 0's does with rt-home.sh
  (`tests/front_end.rs` `the_default_boot_says_a_missing_tree_is_missing`).
- The harness: `scripts/rt-startup.py`'s `M1_BOOT` is `"m1"`;
  `perf.py rt-bars --boot` defaults to `rdb`. Every start and row names its
  boot for both binaries (X's #996), so the gate never compares two boots.
- `scripts/rt-ci.py`: the default conformance step (no boot named: the
  ratchet and `ROBIGO_CONF_UPDATE`'s markers) runs rdb. M1's loader keeps
  three explicit steps until its deletion: plain, the boot heap's freeze on
  (in the gctorture shard, where its M1 twin was), and the byte-code
  crosscheck. No ratchet marker moves and nothing is recorded again: every
  recording is GNU R's.
- Tests that removed `ROBIGO_RT_BOOT` and so meant M1 (`tests/front_end.rs`,
  `tests/lazyload.rs`) set `ROBIGO_RT_BOOT=m1`; the others take the boot
  rt-ci's step gives them.
- `tools.so` under the default boot: `scripts/rt-home-db.sh` copies
  rt-home.sh's tree, tools' native code with it, but replaces its `.rt-home`
  stamp by `.rt-home-db`, and `tests/conformance.rs`'s `has_rt_home_tools`
  required `.rt-home`; so rt-ci's rdb step ran 763 cases against M1's 766,
  the three `r-home-tools` cases (`tests/rt/dynload/{library-dynam-tools,
  tools-parse-rd,tools-natives}.R`) left out. It accepts either stamp now.
- `scripts/rt-stress.sh` sets `R_DEFAULT_PACKAGES=NULL`, as its case is
  recorded. The other harnesses that run robigo-rt already do:
  robigo-conformance (every case), `perf.py`'s rows (through
  `idiom-vs-r.py`) and peak-RSS runs (`rss.py`), `rt-startup.py`'s starts
  (`BASE`), `builtin-diff.py` (`ENV`), `rt-overshoot.py`, `rt-fail-alloc.py`,
  `rt-tcache-mutate.py`. `base-subset.sh` runs GNU R only; `rivals.py` and
  `perf.py`'s `run_one` do not run robigo-rt.

### What a user sees

- **Seven warnings at a plain start.** `robigo-rt -e 1` (no
  `R_DEFAULT_PACKAGES=NULL`) ends its start with GNU R's
  `package "methods" in options("defaultPackages") was not found` and the
  same for datasets, utils, grDevices, graphics, stats and methods (the
  first from `.OptRequireMethods`): true, since the tree has none of them.
  M1's loader skipped that step; making the rdb boot skip it too would hide
  it (the foreman's ruling: not a blocker).
- **An error in base's file or the system profile** is recorded and the
  start goes on (INTERIM(L5)); GNU R halts. Stage 0 halting is the next PR
  after this one (or after the default packages: the foreman's ordering).
- **The start's cost** (on main 92d933c4b, #995's harness, this machine):
  the rdb-jit start, now the default, is about 81.5M instructions against
  GNU R's 84.1M (the runner); M1's interim start was about 14.8M, since
  its loader binds base lazily from source without running GNU R's start.

### The shortest path to a quiet default start

GNU R attaches `options("defaultPackages")` in order: datasets, utils,
grDevices, graphics, stats, then methods (`.OptRequireMethods` first).
Each missing package warns once; a quiet start needs all six in the tree.
From src/library (R 4.6.2):

| package | R lines | C (Fortran) | imports | needs in robigo-rt |
|---|---:|---:|---|---|
| datasets | 0 | 0 | - | its data built into a lazy-load data database (`tools:::data2LazyLoadDB`: `load()` of `.rda`, `read.table` of `.csv`/`.tab`, so utils's R code at build time) |
| utils | 22,277 | 2,349 lines, 7 files | - | its R code into utils.rdb (the R target's mklazy), `utils.so` built against robigo-rt's API as tools.so is |
| grDevices | 5,316 | 23,025, 18 files | - | the graphics engine's API (main/engine.c, devices) for its natives |
| graphics | 6,766 | 12,167, 8 files | grDevices | the engine, base graphics' state |
| stats | 33,692 | 23,087, 57 files (15 Fortran) | utils, grDevices, graphics | a Fortran toolchain in the tree build, BLAS/LAPACK |
| methods | 17,006 | 1,553, 7 files | utils, stats | its build-time setup (`..First.lib` dumps the classes and generics into the namespace), robigo-rt's S4 dispatch hooks |

So datasets and utils can each go soonest (two warnings fewer), but a quiet
start waits for the graphics engine (grDevices, graphics) because stats
and methods import them.

### No install layout yet

robigo-rt has no install script. A checkout's binary finds its tree as
`.robigo/rt-home-db` (`ROBIGO_WORKTREE`, `ROBIGO_RT_CHECKOUT`); an
install's would be `<prefix>/bin/robigo-rt` beside `<prefix>/lib/robigo`
(the tree, which `default_r_home` already looks for) and
`<prefix>/lib/robigo-cache` (its translation cache, `<R_HOME>-cache`,
written by the installed binary since the `.rtc` files are per binary).
`scripts/build.sh` builds G2's `robigo`, not robigo-rt.
