## 2026-11-23: save(), quit("yes") and load(verbose = TRUE) (L5)

- `.Internal(saveToConn(list, con, ascii, version, environment,
  eval.promises))` (crates/robigo-rt/src/serialize/saveload.rs
  `do_save_to_conn`, saveload.c's do_saveToConn) was not implemented:
  `save()`, `save.image()` and `quit("yes")` were errors on both boots.
  Now, in do_saveToConn's order and with its messages verbatim:
  - `list` not a character vector; `ascii` through `asBool2` (NA is "NA in
    coercion to boolean", against saveToConn's call); `version` NULL
    (`R_DEFAULT_SAVE_VERSION`, else 3), NA or below 1 ("invalid 'version'
    argument"), 1 ("cannot save to connections in version 1 format");
    `environment` NULL or an environment; `eval.promises` NA;
  - a closed connection opened "wb" for the call and closed after it, an
    error included; "connection not open for writing"; XDR to a text-mode
    connection refused;
  - the magic number (`RDA`/`RDX` and the version digit; a text-mode
    connection's through `Rconn_printf`, whose result is not looked at)
    written before the variables are looked up, so an unknown name ("object
    'nosuch' not found") or a version above 3 (R_Serialize's "version 4 not
    supported") comes after it, as in GNU R;
  - the pairlist of the variables, each found from `environment` twice
    as do_saveToConn does (`SETCAR(t, R_findVar(...))`, then the lookup
    again: an active binding runs twice and its second value is saved;
    Sol round 1), a promise forced in it when `eval.promises`, serialized
    to the connection;
  - a version whose digit is a NUL (`'0' + 208`) ends the magic number's
    C string there (Sol round 1).
- What an error leaves written: GNU R's `R_Serialize` streams, so the
  bytes written before a refusal stay written. robigo-rt's writer works in
  memory and may start its walk over at an effect point (a refhook, the
  compile on write), so it has no prefix that is GNU R's to give (Sol
  round 2: a restart rebuilds the bytes from a graph an effect may have
  changed, and writing them after the error was signalled is the wrong
  order). One case is GNU R's exactly: a version other than 2 or 3 is
  refused before any item or effect point, so `serializeToConn` and
  `saveToConn` write OutFormat's line and then raise "version N not
  supported" (serialize/mod.rs `serialize_to_conn`). An error later in
  the walk still leaves nothing of the walk written (INTERIM: GNU R has
  written the items before it). `save.to.file` is unchanged: GNU R's
  stdio buffer is never flushed on an error, and robigo-rt writes nothing.
- `load(verbose = TRUE)` (`loadFromConn2`'s third argument) said it was not
  implemented. Now the reader starts at `R_InitReadItemDepth =
  R_ReadItemDepth = -verbose` (serialize/read.rs `unserialize_at`) and
  prints what GNU R's ReadItem prints while the depth is at most 0: each
  pairlist tag, indented two spaces a level (`PrintValue`), and each list
  element's `[i]`. `lastname` (the name a namespace error reports) is
  taken at depth `init + 1`, and a compact sequence materialized below it,
  as before. `verbose = NA` (GNU R's C negates NA_INTEGER, which
  overflows) says it is not implemented.
- `R_DirtyImage`: `repl::clean_up` saves under SA_SAVE only when the image
  is dirty, read after `.Last` (sys-std.c:1269). robigo-rtcore already
  set it where envir.c does; the start always sets it (the system
  profile's `.Library.site` removed from the global environment), so this
  changes nothing seen today.

### The serializer finding (S1, the foreman's question)

Under the default boot (M1's loader) a save compiles every closure of
base again (`Writer::cmpfun1` → `jit::cmpfun1`, the writer's cache being
per save), because M1's closures are robigo-rt-compiled with no BCODESXP
body. Measured on 13c4694b3's binary, `saveRDS(as.list(baseenv()))` at a
load of about 35:

| boot | one save | two saves |
|---|---:|---:|
| default (M1 loader) | 18.4 s | 27.8 s |
| rdb | 0.14 s | 0.24 s |

Under the rdb boot base's closures come from base.rdb with their byte-code
bodies, so the write never compiles them. The cost goes when L5 makes the
rdb boot the default (item 3 of #942's list); no fix here. User closures
the JIT compiled are still compiled once per save on either boot; C1's V4
step 3 keeps their byte code.
